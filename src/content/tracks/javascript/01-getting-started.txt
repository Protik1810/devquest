## What is a program?

A **program** is a list of instructions for a computer, written precisely enough that there is no room for guessing. A recipe can say "add a pinch of salt"; a computer needs "add 0.5 grams of salt". Learning to program is mostly learning to describe what you want *that* precisely, and then letting the machine repeat it a million times without getting bored.

**JavaScript** is the programming language of the web. Every modern browser runs it, which makes it the one language that runs on practically every computer, phone and tablet without installing anything. It long ago escaped the browser too:

- **Websites and web apps**: every interactive page you use (Gmail, YouTube, Google Docs) is driven by JavaScript.
- **Servers**: **Node.js** runs JavaScript outside the browser, powering the back end of companies such as Netflix, PayPal and LinkedIn.
- **Desktop and mobile apps**: VS Code, Slack, Discord and this very app (DevQuest) are built with JavaScript.
- **Tools**: most of the tools web developers use every day are JavaScript programs themselves.

The program that reads your JavaScript and carries it out is a **JavaScript engine**: V8 in Chrome, Edge and Node.js, SpiderMonkey in Firefox, JavaScriptCore in Safari. In DevQuest, your code runs in the engine of the browser or app you are using right now, so there is nothing to install.

> 💡 **JavaScript is not Java.** The similar name was a marketing decision in 1995. The language's official standard is called **ECMAScript**, and a new edition comes out every year. The big modernisation was ECMAScript 2015 (often called "ES6"); this course teaches modern JavaScript from the start.

## console.log(): making the computer say something

```js
console.log("Hello, World!");
```

- `console` is the **console**: the place where a program writes text messages. In a browser it's a panel of the developer tools; in Node.js it's the terminal; in DevQuest it's the output box under your code.
- `.log` picks one of the console's tools. `console.log` is a **function**: a named action that JavaScript already knows how to do.
- The parentheses **call** the function. What goes inside them is the **argument**: here, what to print.
- `"Hello, World!"` is a **string**: a piece of text. The quotes mark where the text starts and ends; they are not printed.
- The `;` ends the instruction, like a full stop ends a sentence.

JavaScript has **three** kinds of quotes for strings. Pick whichever doesn't clash with the text inside:

```js
console.log("She said 'hi'");
console.log('It is "fine"');
console.log(`It's "fine", she said`);
```

The third kind, with **backticks** (the `` ` `` key, usually left of the 1 key), has a superpower you'll use constantly: `${ }` inside it is replaced by the value of whatever JavaScript you put between the braces.

```js
console.log(`2 + 3 = ${2 + 3}`);
console.log(`A day has ${24 * 60} minutes`);
```

These are called **template literals**. Module 2 covers them in depth.

## Several values in one call

Give `console.log` several arguments separated by commas, and it prints them on one line, **separated by one space**:

```js
console.log("I am", 12, "years old");
console.log("Total:", 19.99);
```

Numbers don't need quotes. `12` is a number; `"12"` is text that happens to contain digits. That difference matters a lot, as you'll see in a few lessons.

Two more useful tricks:

```js
console.log();                          // an empty line
console.log("line one\nline two");      // \n starts a new line
```

`\n` is how you write "new line" inside a string. Each `console.log` call ends with a new line, so the next one starts on a fresh line.

## Semicolons

A **statement** is one complete instruction, and in JavaScript statements end with `;`. If you forget one at the end of a line, JavaScript usually inserts it for you (this is called *automatic semicolon insertion*), but there are a few traps where it guesses wrong. Professional style guides differ: most teams write semicolons, and code formatters such as Prettier add them for you. In this course we always write them.

## Comments

Everything after `//` on a line is a **comment**, and so is everything between `/*` and `*/`. JavaScript ignores comments; they're there for the humans reading the code (including future you).

```js
// Greet the user. This whole line is a comment.
console.log("Welcome!"); // a comment can also follow code

/* A comment between these markers
   can span several lines. */
console.log("Bye!");
```

Good comments explain **why**, not what. `// prices are stored in cents to avoid rounding errors` helps a reader; `// log welcome` just repeats the code.

## How JavaScript runs your file

JavaScript runs a program **from top to bottom, one statement at a time**. This always prints first, second, third, in that order:

```js
console.log("first");
console.log("second");
console.log("third");
```

JavaScript is **case-sensitive**: `console.log` works, but `Console.log` and `console.Log` are different names that don't exist. It is also strict about punctuation: every `(` needs its `)`, every `{` its `}`, and every string needs a closing quote of the same kind. Spaces and indentation, on the other hand, are free: JavaScript doesn't care how you indent (unlike Python), but people do, so keep it neat.

## Other console tools

`console.log` has some siblings. `console.error("...")` and `console.warn("...")` print messages that browsers show in red and yellow, and Node.js sends to a separate "error" output. You'll meet `console.table` when you have tables of data. In DevQuest they all print to the same output box.

## Common beginner mistakes

- **Forgetting the quotes**: `console.log(Hello)` makes JavaScript look for something *named* `Hello`, which doesn't exist.
- **Wrong capitals**: `Console.log(...)` or `console.Log(...)`.
- **Curly "smart" quotes** copied from a word processor (`“Hello”`) aren't valid JavaScript. Use the plain `"`, `'` or `` ` `` keys.
- **Mismatched quotes**: `"Hello'` starts with one kind and ends with another.
- **A missing parenthesis**: `console.log("Hi"`.

Each of these produces an error message. Reading them is the topic of the next lesson.

=== lesson js-reading-errors | Reading error messages | 60
## Errors are messages, not failures

Every programmer, at every level, sees error messages all day long. An error is not the computer telling you that you're bad at this; it's the computer telling you **exactly what confused it and where**. Learning to read errors calmly is one of the most valuable skills in programming.

## The anatomy of an error

Here is a program with a typo on line 3. Run it and look at the output:

```js
const name = "Ada";
console.log("Hello");
console.log(nme);
```

Notice that `Hello` was printed first. JavaScript ran the program from the top, and stopped at the line it couldn't do. DevQuest shows the error like this:

```
ReferenceError: nme is not defined (line 3)
```

1. **The error type**: `ReferenceError`. It tells you the *category* of problem.
2. **The message**: `nme is not defined`. It tells you *what* went wrong: JavaScript was asked for something called `nme` and nothing has that name (the variable is called `name`).
3. **The line**: line 3. Go there first.

On your own computer, Node.js shows more detail for the same program:

```
/home/ada/hello.js:3
console.log(nme);
            ^

ReferenceError: nme is not defined
    at Object.<anonymous> (/home/ada/hello.js:3:13)
    at Module._compile (node:internal/modules/cjs/loader:1554:14)
    ...

Node.js v22.12.0
```

- The first line names the file and line (`hello.js:3`), then shows that line with a `^` under the spot where things went wrong.
- Then come the error type and message: the most important part.
- The `at ...` lines are the **stack trace**: the chain of code that was running. The first one points to your file with `line:column` (`3:13`). Lines that mention `node:internal` are Node's own machinery; skip them.

In a **browser**, errors appear in red in the developer tools' Console as `Uncaught ReferenceError: nme is not defined`, with a link like `app.js:3` on the right. Click it to jump to the line.

## Syntax errors: nothing runs at all

Before running anything, the engine reads (**parses**) the whole program to understand its grammar. If the grammar is broken, you get a **SyntaxError** and *not a single line runs*, not even the correct ones above the mistake:

```js
console.log("first");
console.log("second";
```

The fix is a missing `)`. The line in the message is where the engine *noticed* the problem; sometimes the real mistake is a line or two earlier (an unclosed bracket on line 2 might only be noticed on line 5). Common syntax messages:

| Message | Usual cause |
|---|---|
| `missing ) after argument list` | a forgotten `)`, or a missing comma between two values |
| `Invalid or unexpected token` | a string with no closing quote, or a strange character such as a curly quote |
| `Unexpected token ')'` | an extra bracket, or brackets that don't pair up |
| `Unexpected identifier 'y'` | two things side by side with no operator or comma between them |
| `Unexpected end of input` | a `{` or `(` that is never closed |
| `Identifier 'x' has already been declared` | the same variable created twice |

## Runtime errors: the program starts, then stops

These happen while the program runs, at the first line that can't be done:

| Error type | What it means | Example |
|---|---|---|
| `ReferenceError` | a name that doesn't exist: a typo, or something not created yet | `console.log(scroe)` |
| `TypeError` | the right name, but the wrong kind of value for what you asked | `console.lg("hi")`: `console.lg is not a function` |
| `RangeError` | a number outside the allowed range | `(3.14).toFixed(200)` |

You'll meet `TypeError` most often. Its three classic messages are worth memorising:

- `x is not a function`: you tried to call something that isn't a function (often a typo after a dot).
- `Cannot read properties of undefined (reading 'length')`: you asked a value for one of its parts, but the value was `undefined` (empty). You'll see why in the next lessons.
- `Assignment to constant variable.`: you tried to change a `const` (next lesson).

## Bugs that don't cause errors

Here JavaScript is very different from stricter languages: many mistakes **don't** raise an error. They quietly produce a strange value instead:

```js
console.log("5" * "abc");          // NaN
console.log(10 / 0);               // Infinity
console.log("Total: " + 4 + 6);    // Total: 46, not 10!
```

`NaN` means "Not a Number": the result of maths that makes no sense. These silent bugs are often harder to find than real errors. When output looks wrong but there is no error, print the values along the way with `console.log` to see where things go off course. Later in the course, **tests** and **TypeScript** catch many of these for you.

## A strategy for fixing errors

1. **Read the error type and message.** Say it out loud in plain words: "it doesn't know any `nme`".
2. **Go to the line.** For syntax errors, also look at the line or two above it.
3. **Make one change, then run again.** Changing five things at once makes it impossible to learn what fixed it.
4. **Fix the first error first.** One mistake can cause others further down.
5. **Search the exact message** (without your own names) if you're stuck. MDN has a page explaining every JavaScript error message.

> 💡 **The console.log trick.** When a result is wrong, add `console.log("price is", price);` lines to see the values as the program runs. It's the oldest debugging technique there is, and professionals use it every day. Remove those lines when you're done.

=== lesson js-variables | Variables: let and const | 70
## Giving values a name

A **variable** is a name that refers to a value, so you can use the value later and change it as the program runs. Think of a labelled box, or better, a **label you stick on a value**.

```js
let score = 0;
const playerName = "Ada";
console.log(playerName, "has", score, "points");
```

- `let` and `const` are **keywords**: words with a special meaning in JavaScript. They **declare** (create) a variable.
- `score` is the variable's name.
- `=` is **assignment**: "make the name on the left refer to the value on the right". It does *not* mean "equals" as in maths.
- `0` is the value it starts with.

When JavaScript sees a variable's name in an expression, it uses the variable's current value.

## let: a variable that can change

A `let` variable can be given a new value later. You only write `let` once, when you create it:

```js
let score = 0;
console.log(score);
score = 10;
console.log(score);
score = score + 5;
console.log(score);
```

`score = score + 5` looks impossible in maths, but in programming it's natural: JavaScript first works out the right-hand side using the *current* value (10 + 5), then makes `score` refer to the result (15).

## const: a name that never changes

A `const` (constant) must get its value straight away, and can never be assigned again:

```js
const daysInWeek = 7;
console.log(daysInWeek * 52);
daysInWeek = 8;
```

Run it: the first `console.log` works, then `TypeError: Assignment to constant variable.`

**Professional rule: use `const` by default, and `let` only when you actually need to reassign.** When a reader sees `const`, they know that name will refer to the same value for the rest of the code, which makes programs much easier to understand. (You'll learn in Module 6 that `const` protects the *name*, not the inside of objects and arrays.)

## Shortcuts for updating a variable

Changing a variable based on its current value is so common that there are shortcuts:

| Shortcut | Means |
|---|---|
| `x += 5` | `x = x + 5` |
| `x -= 2` | `x = x - 2` |
| `x *= 3` | `x = x * 3` |
| `x /= 4` | `x = x / 4` |
| `x++` | `x = x + 1` |
| `x--` | `x = x - 1` |

```js
let lives = 3;
lives -= 1;
lives++;
lives *= 10;
console.log(lives);
```

> 💡 `x++` and `++x` both add 1, but differ in the value of the *expression itself* (old value versus new value). Using them inside bigger expressions is a classic source of confusion, so write `x++;` as a statement of its own and you'll never have to care.

## Tracing a program by hand

Programmers often follow a program line by line on paper, writing down each variable's value. This is called **tracing**, and it's how you predict what code does before you run it.

```js
let a = 5;
let b = a * 2;
a = 1;
b = b + a;
console.log(a, b);
```

| After line | `a` | `b` |
|---|---|---|
| 1 | 5 | (not created yet) |
| 2 | 5 | 10 |
| 3 | 1 | 10 |
| 4 | 1 | 11 |

Changing `a` on line 3 doesn't change `b`: on line 2, `b` got the *value* 10, not a link to the formula `a * 2`.

## Naming rules and style

A name may contain letters, digits, `_` and `$`, but can't start with a digit, can't contain spaces or `-`, and can't be a keyword (`let`, `const`, `if`, `class`, `return`...).

| Name | Valid? |
|---|---|
| `score`, `totalPrice`, `_count`, `$el` | ✅ |
| `2ndPlace` | ❌ starts with a digit |
| `total-price` | ❌ `-` means minus |
| `let` | ❌ a keyword |

JavaScript style is **camelCase**: start lowercase, and capitalise each following word: `totalPrice`, `isLoggedIn`, `maxRetryCount`. Names are case-sensitive, so `score` and `Score` are two different variables. Constants that are fixed, well-known settings are sometimes written in `UPPER_SNAKE_CASE` (`const MAX_PLAYERS = 4;`).

**Choose names that say what the value means.** `const secondsPerDay = 86400;` is self-explanatory; `const x = 86400;` makes every reader stop and think. Clear names are the cheapest documentation there is.

## Declare before use, declare once

```js
console.log(points);
let points = 50;
```

`ReferenceError: Cannot access 'points' before initialization`: the variable exists only from its `let` line onwards. And declaring the same name twice is a syntax error (`Identifier 'points' has already been declared`). To change a variable, just assign without `let`.

A `let` with no value starts out as **`undefined`**, JavaScript's "nothing here yet" value:

```js
let winner;
console.log(winner);
winner = "Grace";
console.log(winner);
```

## What about var?

Older JavaScript code (and old tutorials) use `var` to declare variables. It still works, but it follows looser, older rules: you can declare the same name twice by accident, and it ignores the `{ }` blocks you'll meet in Module 3. Modern code uses `const` and `let` only. Recognise `var` when you read it; don't write it.

## Swapping two values

A classic puzzle: swap what two variables hold. You need a temporary third variable, just as swapping the contents of two cups needs a third cup:

```js
let left = "coffee";
let right = "tea";
const temp = left;
left = right;
right = temp;
console.log(left, right);
```

(JavaScript also has a one-line trick, `[left, right] = [right, left];`, that you'll understand in Module 6.)

=== lesson js-types | Values and types | 75
## Every value has a type

A value's **type** decides what you can do with it: you can multiply numbers, but not sentences; you can make text uppercase, but not numbers. JavaScript has these basic types, called **primitive types**:

| Type | Examples | Used for |
|---|---|---|
| `number` | `42`, `-7`, `3.14` | all numbers, whole or decimal |
| `string` | `"hello"`, `'A'`, `` `Hi ${name}` `` | text |
| `boolean` | `true`, `false` | yes/no answers |
| `undefined` | `undefined` | "no value has been given" |
| `null` | `null` | "deliberately empty" |
| `bigint` | `9007199254740993n` | whole numbers too big for `number` |
| `symbol` | `Symbol("id")` | unique keys (advanced, rarely needed) |

Everything else (arrays, objects, functions, dates...) is an **object**, which you'll meet from Module 5 on. The `typeof` operator tells you a value's type, as a string:

```js
console.log(typeof 42);
console.log(typeof "42");
console.log(typeof true);
console.log(typeof undefined);
console.log(typeof null);
```

The last one says `object`, which is wrong: it's a famous bug from JavaScript's first version in 1995 that can never be fixed without breaking old websites. Just remember that `null` is its own type.

**`undefined` versus `null`**: both mean "no value". `undefined` is what JavaScript gives you when nothing was set (a `let` with no value, a missing piece of data). `null` is what *programmers* write to say "empty on purpose", like an empty seat that's been explicitly marked free.

## Numbers and strings are not the same

`7` is a number; `"7"` is a string that contains the character 7. They look alike when printed, but behave differently. The `+` operator is the trap: with two numbers it **adds**, but if either side is a string it **joins** (concatenates) them as text:

```js
console.log(7 + 7);
console.log("7" + 7);
console.log("7" + "7");
console.log(1 + 2 + "3");
console.log("1" + 2 + 3);
```

JavaScript works left to right: `1 + 2` is 3, then `3 + "3"` is `"33"`. But `"1" + 2` is already the string `"12"`, so adding 3 gives `"123"`.

The other maths operators (`-`, `*`, `/`) only work on numbers, so JavaScript quietly converts strings to numbers for them:

```js
console.log("10" - 3);
console.log("10" * "2");
console.log("ten" * 2);
```

This automatic conversion is called **type coercion**. It sometimes helps and often hides bugs, so professionals convert types **explicitly**, as below.

## Converting between types

| You have | You want | Write | Result |
|---|---|---|---|
| `"42"` | a number | `Number("42")` | `42` |
| `"3.5"` | a number | `Number("3.5")` | `3.5` |
| `"42px"` | the number at the start | `parseInt("42px")` | `42` |
| `"9.99 EUR"` | the decimal at the start | `parseFloat("9.99 EUR")` | `9.99` |
| `42` | a string | `String(42)` | `"42"` |
| anything | true/false | `Boolean(value)` | see below |

```js
console.log(Number("42") + 8);
console.log(Number("  12  "));
console.log(Number("twelve"));
console.log(Number(""));
console.log(parseInt("42px"), parseFloat("9.99 EUR"));
console.log(String(42) + 8);
```

Notice the results that are easy to get wrong: `Number("twelve")` is `NaN` (not an error!), and `Number("")` is `0`. When you convert something a user typed, always ask what happens if they typed nothing, or typed nonsense. You'll learn to check for `NaN` with `Number.isNaN(value)` in the next lesson.

## Truthy and falsy

Every value can be treated as `true` or `false` when JavaScript needs a yes/no answer (you'll use this constantly with `if` in Module 3). Only these values count as false, and are called **falsy**:

`false`, `0`, `-0`, `0n`, `""` (the empty string), `null`, `undefined`, `NaN`

**Everything else is truthy**, including `"0"`, `"false"`, `" "` (a space) and empty arrays `[]`.

```js
console.log(Boolean(0), Boolean(""), Boolean(null), Boolean(NaN));
console.log(Boolean("0"), Boolean(" "), Boolean(-5), Boolean("false"));
```

## Comparing: always use ===

`===` asks "are these the same type **and** the same value?"; `!==` is its opposite. There's also an older `==` that converts types first, with rules so strange that most style guides ban it:

```js
console.log(7 === 7);
console.log(7 === "7");
console.log(7 == "7");
console.log(0 == "");
console.log(null == undefined);
```

**Always use `===` and `!==`.** You'll learn all the comparison operators in Module 3.

## Reading what the user types: prompt()

`prompt("question")` asks the user to type something and gives you their answer **as a string**. In a browser it opens a little dialog box. In DevQuest, type your answers in the **⌨️ Typed input** box that appears under the example (one line per `prompt` call); the output then shows each question followed by what was typed, like a terminal would.

```js
const name = prompt("What's your name?");
const age = Number(prompt("How old are you?"));
console.log(`Hi ${name}! Next year you'll be ${age + 1}.`);
```

Try typing `Ada` and `36` on two lines in the input box, then run it. Then remove the `Number(...)` and run it again to see what goes wrong: `"36" + 1` is `"361"`.

Two facts about `prompt` worth knowing:

- It **always returns a string** (or `null` if the user presses Cancel). Convert numbers with `Number(...)` before doing maths.
- It exists **in browsers only**. Node.js has no `prompt`; command-line programs read input with a module called `readline`, which you'll use in Module 11. Real web pages rarely use `prompt` either: they read input from forms (Module 11 again). It's simply the shortest way to learn about input.

## The arithmetic operators

| Operator | Meaning | Example | Result |
|---|---|---|---|
| `+` | add | `7 + 2` | `9` |
| `-` | subtract | `7 - 2` | `5` |
| `*` | multiply | `7 * 2` | `14` |
| `/` | divide | `7 / 2` | `3.5` |
| `%` | remainder | `7 % 2` | `1` |
| `**` | power | `7 ** 2` | `49` |

JavaScript has **one** number type for whole and decimal numbers alike, so `7 / 2` is simply `3.5`. The usual maths rules decide the order: `**` first, then `*`, `/` and `%`, then `+` and `-`, left to right within each level. Brackets go first of all.

```js
console.log(2 + 3 * 4);
console.log((2 + 3) * 4);
console.log(2 ** 3 ** 2);
console.log(100 / 10 / 2);
```

(`**` is the exception that groups from the right: `2 ** 3 ** 2` is `2 ** 9`.) When in doubt, add brackets: they cost nothing and make your intent clear.

## Whole-number division and remainders

There's no separate "integer division" operator. To divide and drop the decimals, use `Math.floor` (round down) or `Math.trunc` (cut off the decimals):

```js
const minutes = 135;
const hours = Math.floor(minutes / 60);
const rest = minutes % 60;
console.log(`${minutes} minutes is ${hours}h ${rest}min`);
```

`%` gives the **remainder** after dividing, and it's more useful than it looks:

- `n % 2 === 0` tests whether `n` is even.
- `n % 10` is the last digit of `n`.
- `seconds % 60` is what's left after taking out the whole minutes.

⚠️ With negative numbers, `%` keeps the sign of the left side: `-7 % 3` is `-1` (Python would say 2). And `Math.floor(-3.5)` is `-4`, while `Math.trunc(-3.5)` is `-3`.

## The Math object

`Math` holds common maths functions:

```js
console.log(Math.round(4.5), Math.round(4.4));
console.log(Math.floor(4.9), Math.ceil(4.1), Math.trunc(-4.9));
console.log(Math.max(3, 9, 2), Math.min(3, 9, 2));
console.log(Math.abs(-12), Math.sqrt(81), Math.PI);
```

`Math.round` rounds an exact half **up** (towards plus infinity): `Math.round(2.5)` is 3 and `Math.round(-2.5)` is -2. To round to 2 decimal places, multiply, round and divide: `Math.round(x * 100) / 100`.

`Math.random()` gives a random decimal from 0 up to (but not including) 1. To get a whole number from 1 to 6, like a dice:

```js
const roll = Math.floor(Math.random() * 6) + 1;
console.log("You rolled", roll);
```

Run it a few times. `Math.random() * 6` is between 0 and 5.999..., `Math.floor` makes it 0 to 5, and `+ 1` shifts it to 1 to 6.

## Decimals are not exact

```js
console.log(0.1 + 0.2);
console.log(0.1 + 0.2 === 0.3);
```

This surprises everyone once. Computers store numbers in binary, and just as 1/3 can't be written exactly in decimal (0.3333...), 0.1 can't be stored exactly in binary. The tiny errors usually stay hidden, but sometimes they show. This isn't a JavaScript bug: almost every language (Python, Java, C#...) behaves the same, because they all use the same IEEE 754 standard.

What professionals do about it:

- **For display**, format the number: `(0.1 + 0.2).toFixed(2)` gives the string `"0.30"`. Note that `toFixed` returns a **string**.
- **For money**, count whole cents (or pence) instead of decimal euros: `1999` cents rather than `19.99`. Whole numbers are exact.
- **To compare decimals**, check that they're *close*: `Math.abs(a - b) < 1e-9`.

```js
const priceCents = 1999;
const quantity = 3;
const totalCents = priceCents * quantity;
console.log(`Total: ${(totalCents / 100).toFixed(2)} EUR`);
```

## Special number values

Where many languages raise an error, JavaScript returns a special value:

```js
console.log(10 / 0);
console.log(-10 / 0);
console.log("abc" * 3);
console.log(Math.sqrt(-1));
```

`NaN` ("Not a Number") has a strange property: it is not equal to anything, **not even itself**. So `x === NaN` is always false. Test for it with `Number.isNaN(x)`:

```js
const age = Number("forty");
console.log(age === NaN);
console.log(Number.isNaN(age));
```

## How big can numbers get?

Numbers are stored with about 15 to 17 significant digits. Whole numbers are exact up to `Number.MAX_SAFE_INTEGER` (9007199254740991, about 9 quadrillion). Beyond that, use **BigInt** by adding an `n`: `2n ** 64n`. BigInts can't be mixed with ordinary numbers in maths (`1n + 1` is a TypeError), so you'll only reach for them when you really need huge whole numbers.

For readability, you can put `_` between digits: `1_000_000` is one million. Big and tiny numbers can be written in scientific notation: `1e6` is 1000000, `2.5e-3` is 0.0025.

## Updating numbers

The shortcuts from the variables lesson work with every operator:

```js
let balance = 100;
balance += 50;
balance *= 1.1;
balance -= 15;
console.log(balance.toFixed(2));
```

=== lesson js-setup | JavaScript on your own computer | 60
## Two homes for JavaScript

DevQuest runs your JavaScript inside the app, which is perfect for learning. Real projects run in one of two places, and it's worth setting up both:

1. **The browser**, for code that powers web pages.
2. **Node.js**, for code that runs on its own: servers, scripts and tools.

## The browser's developer tools

Every desktop browser has developer tools with a **Console** where you can type JavaScript and see the result immediately. Open it:

- **Chrome, Edge, Firefox**: press `F12`, or `Ctrl+Shift+J` (`Cmd+Option+J` on a Mac), and pick the **Console** tab.
- **Safari**: first tick "Show features for web developers" in Settings → Advanced, then press `Cmd+Option+C`.

Type `2 + 2` and press Enter. Then `console.log("Hi from the console")`. The console shows the value of whatever you type, which makes it a great calculator and experiment pad. It works on *any* page you visit: open it on a website and type `document.title` to see the page's title.

## A page with your own script

A web page is an HTML file; JavaScript is attached with a `<script>` tag. Press **▶ Show page** to run this one; it changes the page's text when the script runs:

```html
<!doctype html>
<html>
  <body>
    <h1 id="title">Waiting for JavaScript...</h1>
    <script>
      document.getElementById("title").textContent = "Hello from JavaScript!";
      console.log("The script ran");
    </script>
  </body>
</html>
```

In a real project the JavaScript lives in its own file, and the page loads it: `<script src="app.js"></script>`. To try it, create a folder with two files, `index.html` and `app.js`, put the script tag in the HTML, and double-click `index.html` to open it in your browser. Open the developer tools to see what `app.js` logs. You'll build real pages in Module 11.

## Installing Node.js

1. Go to **nodejs.org** and download the **LTS** version ("long-term support": the stable one companies use).
2. Run the installer and accept the defaults. It also installs **npm**, the tool for adding other people's code to your project (Module 11).
3. Open a terminal (on Windows: PowerShell or Windows Terminal; on a Mac: Terminal) and check it worked:

```
node --version
npm --version
```

Each should print a version number such as `v22.12.0`. If you get "command not found", close the terminal and open a new one; if it still fails, re-run the installer.

> 💡 Professionals often install Node through a **version manager** such as `nvm` (macOS and Linux), `nvm-windows` or `fnm`, which lets each project use a different Node version. For learning, the installer from nodejs.org is all you need.

## The Node REPL

Type `node` on its own and press Enter. The prompt changes to `>`: you're in the **REPL** (Read, Evaluate, Print, Loop). Type JavaScript and Node prints the result:

```
> 7 * 6
42
> "abc".toUpperCase()
'ABC'
> .exit
```

Type `.exit` (or press `Ctrl+C` twice) to leave. The REPL is perfect for checking a quick idea.

## Running a program file

1. Install a code editor. **Visual Studio Code** (code.visualstudio.com) is free and the most popular choice for JavaScript.
2. Make a folder for your code, open it in VS Code (File → Open Folder), and create a file called `hello.js`.
3. Write `console.log("Hello from Node!");` and save.
4. Open a terminal in that folder (in VS Code: Terminal → New Terminal) and run:

```
node hello.js
```

Your program's output appears in the terminal. Change the file, save, and run the command again (press the up arrow to bring back the last command). If a program runs forever, press `Ctrl+C` to stop it.

## Browser versus Node.js

The language is the same everywhere; what differs is what the environment gives you:

| | Browser | Node.js |
|---|---|---|
| The page (`document`, `window`) | ✅ | ❌ |
| `prompt()`, `alert()` | ✅ | ❌ |
| Files on disk, processes (`fs`, `process`) | ❌ (for safety) | ✅ |
| `console.log`, `Math`, `setTimeout`, `fetch` | ✅ | ✅ |

So `document.title` fails in Node with `ReferenceError: document is not defined`, and `process.version` fails in a browser. DevQuest gives you the shared parts, plus `prompt()` for typed input.

## Strict mode

Old JavaScript silently accepted some mistakes, such as assigning to a variable you never declared (it would quietly create a global variable). Writing `"use strict";` as the first line of a file switches on **strict mode**, which turns those silent mistakes into errors. DevQuest always runs your code in strict mode, and so do JavaScript **modules** and **classes**, which you'll use later. Modern code is effectively always strict.

📚 **Go deeper:** nodejs.org, "Introduction to Node.js" and "How to install Node.js"; MDN, "What are browser developer tools?"; javascript.info, "Developer console" and "The modern mode, use strict".
