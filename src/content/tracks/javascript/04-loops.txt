## Repeating work

Computers are brilliant at doing the same thing many times without getting bored or making mistakes. A **loop** repeats a block of code. The simplest is `while`: "while this condition is true, keep running the block".

```js
let count = 1;
while (count <= 5) {
  console.log("Lap", count);
  count++;
}
console.log("Finished!");
```

Step by step:

1. Check the condition. `1 <= 5` is true, so run the block: print "Lap 1", then add 1.
2. Back to the top: check again. `2 <= 5`: run the block again.
3. ...until `count` is 6. Now `6 <= 5` is false, so skip the block and continue after it.

Each run of the block is called an **iteration**. The variable that changes each time (`count`) is the **loop variable**.

## The three parts of a counting loop

Almost every counting loop has:

1. **Initialise** a variable before the loop: `let count = 1;`
2. **Test** it in the condition: `count <= 5`
3. **Update** it inside the block: `count++;`

Forget the update and the condition never becomes false: an **infinite loop**. The program hangs forever (DevQuest stops it after a few seconds; in a terminal, press `Ctrl+C`; in a browser, the tab freezes until you close it).

```js
let n = 10;
while (n > 0) {
  console.log(n);
  n -= 3;
}
```

Trace it: 10, 7, 4, 1, then `n` becomes -2 and the loop ends. Tracing loops in a table, one row per iteration, is the best way to understand them.

## Accumulators: building up a result

A very common pattern is to **accumulate** a result as you loop: start with a neutral value and update it every iteration.

```js
let total = 0;
let n = 1;
while (n <= 100) {
  total += n;
  n++;
}
console.log("1 + 2 + ... + 100 =", total);
```

`total` starts at 0 (adding 0 changes nothing). To multiply things together, start at 1 instead. To build text, start with `""`.

## Loops that wait for the user

`while` shines when you don't know in advance how many iterations you need. A **sentinel** value (here, the word `done`) tells the loop to stop:

```js
let total = 0;
let line = prompt("Number (or done):");
while (line !== "done" && line !== null) {
  total += Number(line);
  line = prompt("Number (or done):");
}
console.log("Total:", total);
```

Type `5`, `7` and `done` on three lines in the input box, then run it. `prompt` returns `null` when there's no more input (or when someone presses Cancel in a browser), and the loop stops then too, so it can't loop forever.

## break and continue

- `break` leaves the loop immediately.
- `continue` skips the rest of this iteration and jumps back to the condition.

A loop of the form `while (true) { ... break; }` runs "forever" until a `break` fires. It's often the clearest way to write "ask until the answer is valid":

```js
let tries = 0;
while (true) {
  const answer = prompt("What is 6 x 7?");
  tries++;
  if (answer === null) {
    console.log("Giving up.");
    break;
  }
  if (Number(answer) === 42) {
    console.log(`Correct after ${tries} tries!`);
    break;
  }
  console.log("Not quite, try again.");
}
```

Try typing `40`, `41`, `42` on three lines. With `while (true)`, make sure every path eventually reaches a `break`.

`continue` is useful for skipping items you don't care about:

```js
let n = 0;
while (n < 10) {
  n++;
  if (n % 3 !== 0) {
    continue;
  }
  console.log(n, "is a multiple of 3");
}
```

Notice that `n++` comes *before* the `continue`: if the update came after it, `continue` would skip the update and the loop would never end.

## do...while: run at least once

A `do...while` loop checks its condition **after** each iteration, so the block always runs at least once:

```js
let i = 100;
do {
  console.log("This runs once, even though i is not < 5:", i);
  i++;
} while (i < 5);
```

It's rare in practice (`while (true)` with `break` usually reads better), but you'll meet it.

## Don't loop on exact decimals

```js
let x = 0.1;
let steps = 0;
while (x !== 1 && steps < 20) {
  x += 0.1;
  steps++;
}
console.log(x, steps);
```

Because 0.1 isn't stored exactly (Module 1), `x` jumps from 0.9999999999999999 to 1.0999999999999999 and is **never** exactly 1. The `steps < 20` safety limit is the only thing that stops this loop. Count with whole numbers, or test with `<` / `>` rather than `!==`.

=== lesson js-for | for loops | 75
## The counting loop, in one line

Counting loops are so common that JavaScript has a compact form that puts all three parts (initialise, test, update) on one line:

```js
for (let i = 1; i <= 5; i++) {
  console.log("Lap", i);
}
```

Read the header as: "start with `i = 1`; while `i <= 5`, run the block; after each iteration, do `i++`". It does exactly the same as the `while` version from the last lesson, but you can see the whole loop's behaviour at a glance, and you can't forget the update.

The loop variable, declared with `let` in the header, exists only inside the loop.

## Counting patterns

Change the three parts to count however you need:

```js
for (let i = 0; i < 5; i++) {
  console.log("zero-based:", i);
}
for (let i = 10; i >= 0; i -= 5) {
  console.log("down in fives:", i);
}
for (let i = 2; i <= 20; i *= 2) {
  console.log("doubling:", i);
}
```

Programmers usually count **from 0, while `i < n`**: that runs exactly `n` times and matches how positions are numbered in strings (and arrays). So `for (let i = 0; i < 5; i++)` is "do this 5 times".

## Looping over a string with an index

With a `for` loop counting from 0 to `length - 1`, you can visit every character:

```js
const word = "loop";
for (let i = 0; i < word.length; i++) {
  console.log(i, word[i]);
}
```

The test is `i < word.length`, not `<=`: the last index is `length - 1`. Writing `<=` is the famous **off-by-one error**, and here it would visit index 4, which gives `undefined`.

## for...of: when you don't need the index

When you just want each character in turn, `for...of` is shorter and can't go off by one:

```js
for (const ch of "hello") {
  console.log(ch.toUpperCase());
}
```

- `const ch` is a fresh variable for each iteration, holding the next character.
- `for...of` works on anything that can be iterated: strings now, and arrays, maps and sets in Module 6.
- It also handles emoji correctly: `for (const ch of "hi😀")` gives three characters.

Use `for...of` when you need the items, and a counting `for` when you need the positions (or need to count without any string at all).

## Counting things with a loop

Combine a loop with `if` and an accumulator to count matches:

```js
const text = "Programming in JavaScript is fun";
let vowels = 0;
for (const ch of text.toLowerCase()) {
  if ("aeiou".includes(ch)) {
    vowels++;
  }
}
console.log("Vowels:", vowels);
```

`"aeiou".includes(ch)` is a neat trick: "is this character one of these?".

## Building a new string

Strings can't be changed, but you can build a new one character by character:

```js
const message = "attack at dawn";
let result = "";
for (const ch of message) {
  result += ch === " " ? "_" : ch.toUpperCase();
}
console.log(result);
```

And here's how to reverse a string: put each character in **front** of what you have so far.

```js
let reversed = "";
for (const ch of "stressed") {
  reversed = ch + reversed;
}
console.log(reversed);
```

## break and continue work here too

```js
const code = "AB12-XY";
for (let i = 0; i < code.length; i++) {
  if (code[i] === "-") {
    console.log("Dash found at position", i);
    break;
  }
}
```

A loop that stops at the first match is called a **search**. Note that if there's no dash, nothing is printed; the next lesson shows how to report "not found" properly.

## Which loop should I use?

| Situation | Loop |
|---|---|
| Visit each character (or array item) | `for...of` |
| Need the position, or count a fixed number of times | `for (let i = 0; i < n; i++)` |
| Repeat until something happens (input, a condition) | `while` |

You'll also see `for...in` in older code; it loops over an object's property *names* and is covered with objects in Module 6. Don't use it on strings or arrays.

=== lesson js-loop-patterns | Loop patterns and nested loops | 80
## Patterns you'll write a thousand times

Most loops you'll ever write are variations of a handful of patterns. Recognising them means you don't solve each problem from scratch.

## Sum and count

You've met these already: an accumulator that starts at 0.

```js
let sum = 0;
let count = 0;
for (let n = 1; n <= 50; n++) {
  if (n % 7 === 0) {
    sum += n;
    count++;
  }
}
console.log(`${count} multiples of 7, adding up to ${sum}`);
```

## Maximum and minimum

To find the largest value, keep "the best so far" and replace it whenever you see something bigger. Start with the **first** value (or `-Infinity`, which everything beats):

```js
const digits = "3819275";
let max = -Infinity;
let min = Infinity;
for (const ch of digits) {
  const d = Number(ch);
  if (d > max) max = d;
  if (d < min) min = d;
}
console.log("max", max, "min", min);
```

(For a one-statement `if`, you may leave out the braces, as here. Many teams require braces always, to avoid bugs when someone adds a second line later; follow your team's style.)

## Search with a flag

A **search** loop looks for something and stops when it finds it. Use a variable, a **flag**, to remember whether it was found, so you can report "not found" after the loop:

```js
const password = "sunshine";
let hasDigit = false;
for (const ch of password) {
  if ("0123456789".includes(ch)) {
    hasDigit = true;
    break;
  }
}
console.log(hasDigit ? "Contains a digit" : "No digit found");
```

To remember *where* it was found, use a position variable that starts at -1 (like `indexOf` does).

## "All" and "any"

Two variants of the flag pattern answer common questions:

- **Any**: start with `false`; set it to `true` (and `break`) when one item matches.
- **All**: start with `true`; set it to `false` (and `break`) when one item *fails*.

```js
const pin = "4096";
let allDigits = true;
for (const ch of pin) {
  if (!"0123456789".includes(ch)) {
    allDigits = false;
    break;
  }
}
console.log(pin.length === 4 && allDigits ? "Valid PIN" : "Invalid PIN");
```

## Nested loops

A loop inside another loop: for **each** iteration of the outer loop, the inner loop runs **completely**.

```js
for (let row = 1; row <= 3; row++) {
  let line = "";
  for (let col = 1; col <= 4; col++) {
    line += `(${row},${col}) `;
  }
  console.log(line);
}
```

3 rows × 4 columns = 12 inner iterations. Nested loops are how you handle anything two-dimensional: grids, tables, game boards, pixels, comparing every item with every other item.

The inner loop can depend on the outer loop's variable. Here each row is as long as its row number:

```js
for (let row = 1; row <= 5; row++) {
  let line = "";
  for (let i = 1; i <= row; i++) {
    line += "*";
  }
  console.log(line);
}
```

## A full multiplication grid

```js
const size = 5;
let header = "   |";
for (let c = 1; c <= size; c++) header += String(c).padStart(4);
console.log(header);
console.log("-".repeat(header.length));
for (let r = 1; r <= size; r++) {
  let line = String(r).padStart(2) + " |";
  for (let c = 1; c <= size; c++) {
    line += String(r * c).padStart(4);
  }
  console.log(line);
}
```

## break only leaves the inner loop

`break` exits the loop it's directly in. To stop *both* loops when you've found something, use a flag and check it in the outer loop too (or put the loops in a function and `return`, Module 5):

```js
const target = 12;
let found = false;
for (let a = 1; a <= 10 && !found; a++) {
  for (let b = a; b <= 10; b++) {
    if (a * b === target && a + b === 7) {
      console.log(`Found: ${a} x ${b}`);
      found = true;
      break;
    }
  }
}
```

(JavaScript also has *labelled* breaks, `outer: for (...) { ... break outer; }`, but they're rare and many style guides discourage them.)

## How much work is a loop?

A loop over `n` items does about `n` steps. Two nested loops over `n` items each do about `n × n` steps: for 1,000 items that's a million, for 100,000 items ten billion, which takes minutes, not milliseconds. Computer scientists write this as **O(n)** and **O(n²)** ("big O" notation). You don't need the theory yet, but get into the habit of asking "how many times will this run?" before nesting loops over big data. The [Data Structures & Algorithms](#/track/dsa) track covers it properly.

📚 **Go deeper:** *Eloquent JavaScript* (4th ed.), chapter 2, exercises "Looping a triangle", "FizzBuzz" and "Chessboard"; javascript.info, "Loops: while and for" (labels); MDN JavaScript Guide, "Loops and iteration".
