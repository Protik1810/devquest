## Programs that choose

So far every program ran every line, top to bottom. Real programs **choose**: show the "log in" button only to visitors who aren't logged in, charge a child's price for children, warn when the battery is low. The tool for this is the `if` statement, and it works with **booleans**: the values `true` and `false`.

## Comparisons give booleans

| Operator | Means | Example | Result |
|---|---|---|---|
| `===` | is equal to (same type and value) | `5 === 5` | `true` |
| `!==` | is not equal to | `5 !== 3` | `true` |
| `<` | is less than | `3 < 5` | `true` |
| `>` | is greater than | `3 > 5` | `false` |
| `<=` | is less than or equal to | `5 <= 5` | `true` |
| `>=` | is greater than or equal to | `4 >= 5` | `false` |

A comparison is an expression like `2 + 3`: it produces a value, and that value is a boolean you can print or store:

```js
const age = 17;
console.log(age >= 18);
const isAdult = age >= 18;
console.log(typeof isAdult, isAdult);
```

Name boolean variables like yes/no questions: `isAdult`, `hasTicket`, `canEdit`. Then `if (isAdult)` reads like English.

⚠️ Don't confuse `=` (assignment: "make this name refer to that value") with `===` (comparison: "are these equal?"). And remember from Module 1: use `===`, never `==`.

## The if statement

```js
const temperature = 31;
if (temperature > 30) {
  console.log("It's hot! Drink some water.");
}
console.log("Have a nice day.");
```

- The **condition** goes in parentheses after `if`.
- The code in the curly braces `{ }`, called a **block**, runs only when the condition is truthy.
- After the block, the program carries on as normal: the last line always runs.

Change `31` to `20` and run it again: the warning disappears, the goodbye stays.

Indent the code inside a block by two spaces. JavaScript doesn't require it, but every reader and every code formatter expects it, so the shape of the code shows its logic at a glance.

## else: the other path

`else` gives the code to run when the condition is falsy. Exactly one of the two blocks runs, never both, never neither:

```js
const balance = 40;
const price = 55;
if (balance >= price) {
  console.log("Purchase complete.");
} else {
  console.log(`You need ${price - balance} more.`);
}
```

## else if: more than two paths

Chain conditions with `else if`. JavaScript checks them **from top to bottom** and runs only the **first** block whose condition is true; the rest are skipped:

```js
const score = 72;
if (score >= 90) {
  console.log("Grade A");
} else if (score >= 80) {
  console.log("Grade B");
} else if (score >= 70) {
  console.log("Grade C");
} else {
  console.log("Grade F");
}
```

Order matters. With 72, the first two tests fail and `score >= 70` is the first true one. If you put `score >= 70` *first*, a score of 95 would also stop there and get a C. Write the most specific (or highest) test first.

## Conditions use truthiness

An `if` doesn't need a real boolean; any value works, and JavaScript uses its truthiness (Module 1: `false`, `0`, `""`, `null`, `undefined` and `NaN` are falsy, everything else is truthy). That makes checks for "is there anything there?" short:

```js
const username = "";
if (username) {
  console.log(`Welcome back, ${username}!`);
} else {
  console.log("Welcome, guest!");
}
```

Be careful when `0` is a valid value: `if (quantity)` treats a quantity of 0 the same as "no quantity at all". When 0 matters, compare explicitly: `if (quantity !== undefined)` or `if (quantity > 0)`.

## Blocks create a scope

A variable declared with `let` or `const` inside a block exists **only inside that block**:

```js
const hour = 9;
if (hour < 12) {
  const greeting = "Good morning";
  console.log(greeting);
}
console.log(greeting);
```

`greeting is not defined` on the last line. This is a feature: names used for one small job don't leak out and collide with names elsewhere. When you need the value after the `if`, declare the variable *before* it with `let`, and assign it inside:

```js
const hour = 15;
let greeting;
if (hour < 12) {
  greeting = "Good morning";
} else {
  greeting = "Good afternoon";
}
console.log(greeting);
```

## The conditional operator: ? :

For choosing between two **values**, there's a compact expression: `condition ? valueIfTruthy : valueIfFalsy`. (It's often called the *ternary* operator because it has three parts.)

```js
const hour = 15;
const greeting = hour < 12 ? "Good morning" : "Good afternoon";
console.log(greeting);
const items = 1;
console.log(`You have ${items} ${items === 1 ? "item" : "items"}.`);
```

Use it for simple choices of a value, as above; it lets you use `const`. For anything with several steps or more than two cases, use `if`: nested `? :` chains quickly become unreadable.

## switch: comparing one value with many cases

When you compare **one** value against many fixed options, `switch` can be clearer than a long `else if` chain:

```js
const day = "sat";
switch (day) {
  case "sat":
  case "sun":
    console.log("Weekend!");
    break;
  case "fri":
    console.log("Almost weekend.");
    break;
  default:
    console.log("A work day.");
}
```

- `switch` compares the value with each `case` using `===`.
- Execution starts at the first matching case and **continues downwards until a `break`**. Forgetting `break` is the classic switch bug: the next case's code runs too ("fall-through").
- Two cases with nothing between them (`"sat"` and `"sun"`) share code on purpose.
- `default` runs when nothing matched, like a final `else`.

Here's the fall-through bug in action. `day` is 3, so only "Wed" should print:

```js
const day = 3;
switch (day) {
  case 1:
    console.log("Mon");
  case 3:
    console.log("Wed");
  case 4:
    console.log("Thu");
    break;
  default:
    console.log("Other");
}
```

## Guard clauses: handle the special cases first

Deep nesting is hard to read. A common professional habit is to deal with problem cases first, and keep the main path flat:

```js
const input = "";
const amount = Number(input);
if (input.trim() === "") {
  console.log("Please type an amount.");
} else if (Number.isNaN(amount)) {
  console.log("That's not a number.");
} else if (amount <= 0) {
  console.log("The amount must be positive.");
} else {
  console.log(`Paying ${amount.toFixed(2)}...`);
}
```

Each special case is handled and done with; the real work sits at the end, not three levels deep. Inside functions (Module 5) you'll write these as early `return`s.

## Combining conditions

Real decisions depend on several facts at once: "you can drive if you're at least 18 **and** have a licence"; "the shop is closed on Saturday **or** Sunday". JavaScript's **logical operators** combine booleans:

| Operator | Name | True when |
|---|---|---|
| `a && b` | AND | both `a` and `b` are true |
| `a \|\| b` | OR | at least one of them is true |
| `!a` | NOT | `a` is false |

```js
const age = 20;
const hasLicence = false;
console.log(age >= 18 && hasLicence);
console.log(age >= 18 || hasLicence);
console.log(!hasLicence);
```

The truth tables, worth knowing by heart:

| `a` | `b` | `a && b` | `a \|\| b` |
|---|---|---|---|
| true | true | true | true |
| true | false | false | true |
| false | true | false | true |
| false | false | false | false |

## Ranges and precedence

To test whether a number lies in a range, you need **two** comparisons joined with `&&`:

```js
const age = 15;
const isTeen = age >= 13 && age <= 19;
console.log(isTeen);
```

Writing `13 <= age <= 19` is a classic mistake: JavaScript works it out as `(13 <= age) <= 19`, which compares `true` or `false` with 19 and is **always true**. Run `console.log(13 <= 50 <= 19)` to see it.

`!` binds tightest, then `&&`, then `||`. So `a || b && c` means `a || (b && c)`. Add brackets whenever you mix `&&` and `||`, even when not strictly needed: readers shouldn't have to remember precedence tables.

~~~check
? `const ok = x > 0 && x < 10 || x === 100;` For which value of x is `ok` true?
- `0`
- `10`
+ `100`
- `-5`
> `&&` groups first: `(x > 0 && x < 10) || x === 100`. Only 100 makes either side true.
~~~

## Negating: ! and De Morgan's laws

`!` flips a boolean. To negate a whole combination, either wrap it, `!(a && b)`, or use **De Morgan's laws** to push the `!` inside, flipping `&&` and `||`:

- `!(a && b)` is the same as `!a || !b`
- `!(a || b)` is the same as `!a && !b`

"It's not (sunny and warm)" means "it's not sunny, or it's not warm". This comes up constantly when you rewrite conditions to make them read better, for example in guard clauses.

## Short-circuit evaluation

`&&` and `||` stop as soon as they know the answer: `false && anything` is false whatever "anything" is, so JavaScript **doesn't even evaluate** the right side. Likewise for `true || anything`.

This matters, because it lets the left side protect the right side:

```js
const text = "";
if (text.length > 0 && text[0] === "#") {
  console.log("A heading");
} else {
  console.log("Not a heading");
}
```

If the text is empty, `text[0]` is never looked at.

## && and || return a value, not just true/false

Here's a JavaScript speciality: `&&` and `||` don't return `true` or `false`, they return **one of their operands**:

- `a || b` returns `a` if `a` is truthy, otherwise `b`.
- `a && b` returns `a` if `a` is falsy, otherwise `b`.

```js
console.log("Ada" || "Guest");
console.log("" || "Guest");
console.log(0 || 10);
console.log("yes" && "both truthy");
console.log(null && "never reached");
```

That's why you'll often see `||` used to provide a **default value**: `const name = typed || "Guest";`. But it has a trap: `0` and `""` are falsy, so they're replaced by the default even when they're perfectly valid:

```js
const volume = 0;
console.log(volume || 50);
```

The user chose volume 0 (mute), and got 50!

## ?? : the nullish coalescing operator

`a ?? b` returns `b` **only if `a` is `null` or `undefined`** ("nullish"), and keeps every other value, including `0`, `""` and `false`:

```js
const volume = 0;
console.log(volume ?? 50);
const nickname = undefined;
console.log(nickname ?? "anonymous");
```

**Rule of thumb:** for defaults, prefer `??`. Use `||` only when you really mean "replace anything falsy, including empty text and zero".

You can't mix `??` with `&&` or `||` without brackets: `a || b ?? c` is a SyntaxError, precisely because the meaning would be unclear. Write `(a || b) ?? c`.

There are matching assignment shortcuts: `x ??= 5` sets `x` to 5 only if it's nullish; `x ||= 5` only if it's falsy; `x &&= 5` only if it's truthy.

## Booleans instead of if/else

Beginners often write:

```js
const age = 20;
let isAdult;
if (age >= 18) {
  isAdult = true;
} else {
  isAdult = false;
}
console.log(isAdult);
```

But the comparison already *is* the boolean. This says the same in one line:

```js
const age = 20;
const isAdult = age >= 18;
console.log(isAdult);
```

## A worked example: leap years

A year is a leap year if it's divisible by 4, **except** years divisible by 100, **unless** they're also divisible by 400. So 2024 is a leap year, 1900 is not, 2000 is. As one expression:

```js
const year = 1900;
const isLeap = (year % 4 === 0 && year % 100 !== 0) || year % 400 === 0;
console.log(`${year} is ${isLeap ? "" : "not "}a leap year`);
```

Try 2024, 2000 and 2023. Reading complex conditions is easier if you name the parts: `const divisibleBy4 = year % 4 === 0;` and so on.

--- cards
&& (AND) :: True only when both sides are true. Returns the first falsy operand, or the last one.
|| (OR) :: True when at least one side is true. Returns the first truthy operand, or the last one.
! (NOT) :: Flips true and false. !!x converts x to a boolean.
Short-circuit evaluation :: && stops at the first falsy value, || at the first truthy one; the rest isn't evaluated.
?? (nullish coalescing) :: a ?? b gives b only if a is null or undefined. Keeps 0, "" and false. Prefer it for defaults.

::prompt
A parcel service prices shipping by weight (in kg) and destination. Read both with `prompt` and print the price:

- up to 1 kg: $5; over 1 and up to 5 kg: $12; over 5 and up to 20 kg: $25; over 20 kg: print `Too heavy to ship` and nothing else.
- International parcels (destination `intl`) cost double. Any other destination is domestic.
- Express delivery isn't part of this exercise.

Print the price with two decimals:
```
Weight (kg): 3.5
Destination (home/intl): intl
Shipping: $24.00
```
::starter
const weight = Number(prompt("Weight (kg):"));
const destination = prompt("Destination (home/intl):");
// your code here
::solution
const weight = Number(prompt("Weight (kg):"));
const destination = prompt("Destination (home/intl):").trim().toLowerCase();
if (weight > 20) {
  console.log("Too heavy to ship");
} else {
  let price;
  if (weight <= 1) {
    price = 5;
  } else if (weight <= 5) {
    price = 12;
  } else {
    price = 25;
  }
  if (destination === "intl") {
    price *= 2;
  }
  console.log(`Shipping: $${price.toFixed(2)}`);
}

::prompt
Write a password checker. Read a password with `prompt` and print `Strong`, `Medium` or `Weak`:

- **Strong**: at least 12 characters, and contains a digit **and** a non-letter symbol from `!`, `?`, `#`, `@`.
- **Medium**: at least 8 characters (but not strong).
- **Weak**: anything else.

To test for a digit without loops, check each digit with `includes`, or use this ready-made test: `/[0-9]/.test(password)` (it's a *regular expression*, Module 12). Symbols: check `includes` for each of the four.
```
Password: correct#horse7
Strong
```
::starter
const password = prompt("Password:");
const hasDigit = /[0-9]/.test(password);
// work out hasSymbol, then decide
::solution
const password = prompt("Password:");
const hasDigit = /[0-9]/.test(password);
const hasSymbol = password.includes("!") || password.includes("?") || password.includes("#") || password.includes("@");
if (password.length >= 12 && hasDigit && hasSymbol) {
  console.log("Strong");
} else if (password.length >= 8) {
  console.log("Medium");
} else {
  console.log("Weak");
}
