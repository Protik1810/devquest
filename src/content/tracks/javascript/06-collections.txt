## Many values in one place

Programs work with *collections* of things: the songs in a playlist, the items in a basket, the scores in a game. An **array** is an ordered list of values, written in square brackets:

```js
const playlist = ["Intro", "Song for Ada", "Loops", "Outro"];
const scores = [72, 95, 88];
const empty = [];
const mixed = ["text", 42, true, null];
console.log(playlist);
console.log(scores.length, empty.length);
```

An array can hold any values, even different types, but in practice an array usually holds many values *of the same kind*. Arrays are **objects**, so `typeof []` is `"object"`; to check for an array, use `Array.isArray(value)`.

## Reading and changing items

Arrays are indexed like strings, from 0:

```js
const colours = ["red", "green", "blue"];
console.log(colours[0], colours[2], colours.at(-1));
console.log(colours[5]);
colours[1] = "yellow";
console.log(colours);
```

Unlike strings, **arrays can be changed** in place. Notice that `colours` is a `const`, and yet we changed an item. `const` means the *name* always refers to the same array; the array's contents can still change. (The next lessons explain this properly.)

## Adding and removing items

| Method | Does | Returns |
|---|---|---|
| `push(x, ...)` | adds to the **end** | the new length |
| `pop()` | removes from the **end** | the removed item |
| `unshift(x, ...)` | adds to the **start** | the new length |
| `shift()` | removes from the **start** | the removed item |

```js
const queue = ["Ada", "Grace"];
queue.push("Linus");
queue.unshift("Alan");
console.log(queue);
const served = queue.shift();
const lastIn = queue.pop();
console.log(served, lastIn, queue);
```

`push` and `pop` are fast whatever the array's size; `unshift` and `shift` must move every other item along, so they get slow on huge arrays. Using only `push` and `pop` gives you a **stack** (last in, first out, like the call stack); `push` plus `shift` gives a **queue** (first in, first out).

## Looping over an array

All the loops from Module 4 work:

```js
const scores = [72, 95, 88];
for (const score of scores) {
  console.log("Score:", score);
}
for (let i = 0; i < scores.length; i++) {
  console.log(`#${i + 1}: ${scores[i]}`);
}
for (const [i, score] of scores.entries()) {
  console.log(i, score);
}
```

Use `for...of` when you need the items, and `entries()` (which gives `[index, item]` pairs) or a counting loop when you also need the positions. The loop patterns from Module 4 (sum, count, max, search with a flag) all apply directly to arrays.

## Searching

```js
const fruit = ["apple", "banana", "cherry", "banana"];
console.log(fruit.includes("cherry"));
console.log(fruit.indexOf("banana"), fruit.lastIndexOf("banana"), fruit.indexOf("kiwi"));
```

`includes` and `indexOf` compare with `===`, so they work for strings and numbers. Finding *objects* by a property (the user whose id is 7) needs `find`, coming in the next lesson.

## Slicing, splicing, joining

- `slice(start, end)` returns a **new** array with part of the items (just like strings). `slice()` with no arguments copies the whole array.
- `splice(start, count, ...newItems)` **changes** the array: removes `count` items at `start`, optionally inserts new ones there, and returns the removed items.
- `concat(other)` returns a new array with the items of both.
- `join(separator)` makes a string; `split` (Module 2) goes the other way.

```js
const letters = ["a", "b", "c", "d", "e"];
console.log(letters.slice(1, 3), letters);
const removed = letters.splice(1, 2, "X");
console.log(removed, letters);
console.log(letters.concat(["f", "g"]).join("-"));
```

⚠️ Notice the pattern: some methods **mutate** (change) the array they're called on, others return a new one and leave the original alone. Mixing them up is a common source of bugs. `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse` and `fill` mutate; `slice`, `concat`, `join`, `map`, `filter` and most others don't.

## Building arrays

```js
const squares = [];
for (let i = 1; i <= 5; i++) {
  squares.push(i * i);
}
console.log(squares);
console.log(Array.from({ length: 5 }, (_, i) => i * 10));
console.log(new Array(4).fill(0));
console.log(Array.from("hello"));
```

Starting with `[]` and pushing in a loop is the most common way. `Array.from({ length: n }, fn)` builds an array of n items by calling `fn` with each index (the `_` is a conventional name for a parameter you don't use).

## Arrays of arrays

An array can contain arrays, which gives you a grid (a **two-dimensional** array): a game board, a spreadsheet, an image. `grid[row][col]` reads one cell:

```js
const board = [
  ["X", "O", "X"],
  [" ", "X", "O"],
  ["O", " ", "X"],
];
console.log(board[1][2]);
for (const row of board) {
  console.log(row.join(" | "));
}
```

`[[1, 2], [3, [4]]].flat()` flattens one level of nesting; `.flat(Infinity)` flattens all levels.

## Loops you don't have to write

Most loops over arrays do one of a few jobs: transform every item, keep some items, find one item, or combine all items into one value. Arrays have a method for each job. They take a **callback** (Module 5) and call it for each item, so you write only the interesting part:

```js
const prices = [12, 5, 30, 8];
const withTax = prices.map((p) => p * 1.2);
const cheap = prices.filter((p) => p < 10);
const total = prices.reduce((sum, p) => sum + p, 0);
console.log(withTax, cheap, total);
```

These methods are everywhere in professional JavaScript, front end and back end. Learn them well.

## map: transform every item

`map(fn)` returns a **new array of the same length**, where each item is `fn(item)`:

```js
const names = ["ada", "grace", "linus"];
const capitalised = names.map((n) => n[0].toUpperCase() + n.slice(1));
const lengths = names.map((n) => n.length);
console.log(capitalised, lengths, names);
```

The callback also receives the index as a second argument: `names.map((n, i) => `${i + 1}. ${n}`)`.

## filter: keep some items

`filter(predicate)` returns a **new array** with only the items for which the predicate returns a truthy value:

```js
const scores = [45, 82, 67, 91, 30, 75];
const passed = scores.filter((s) => s >= 50);
const evens = scores.filter((s) => s % 2 === 0);
console.log(passed, evens);
```

## find, findIndex, some, every

| Method | Returns |
|---|---|
| `find(pred)` | the **first** item that matches, or `undefined` |
| `findIndex(pred)` | its index, or `-1` |
| `findLast(pred)` / `findLastIndex(pred)` | the same, searching from the end |
| `some(pred)` | `true` if **at least one** item matches |
| `every(pred)` | `true` if **all** items match |

They stop as soon as they know the answer, just like the search and any/all loops from Module 4:

```js
const users = [
  { name: "Ada", age: 36, admin: false },
  { name: "Grace", age: 85, admin: true },
  { name: "Linus", age: 21, admin: false },
];
console.log(users.find((u) => u.admin));
console.log(users.findIndex((u) => u.name === "Linus"));
console.log(users.some((u) => u.age < 18), users.every((u) => u.age >= 18));
```

(These are arrays of **objects**, the most common shape of real data. `u.name` reads the object's `name` property; objects are the next lesson.)

## reduce: combine everything into one value

`reduce(fn, start)` walks through the array carrying an **accumulator**, the sum/count/max pattern from Module 4 in method form. The callback receives the accumulator so far and the current item, and returns the new accumulator:

```js
const cart = [12.5, 4, 30, 8.25];
const total = cart.reduce((sum, price) => sum + price, 0);
const most = cart.reduce((best, price) => (price > best ? price : best), -Infinity);
console.log(total, most);
```

Trace `reduce((sum, price) => sum + price, 0)`: `sum` starts at 0; then 0 + 12.5 = 12.5; 12.5 + 4 = 16.5; and so on. **Always pass the start value**: without it, `reduce` uses the first item as the start, and on an empty array it throws `TypeError: Reduce of empty array with no initial value`.

`reduce` can build any kind of result, including objects. Counting how often each word appears:

```js
const words = ["js", "css", "js", "html", "js", "css"];
const counts = words.reduce((acc, w) => {
  acc[w] = (acc[w] ?? 0) + 1;
  return acc;
}, {});
console.log(counts);
```

If a `reduce` gets hard to read, a plain `for...of` loop is a perfectly professional alternative. Clarity beats cleverness.

## Chaining: data pipelines

Because `map` and `filter` return arrays, you can chain them into a pipeline that reads like a description of the task:

```js
const orders = [
  { item: "Laptop", price: 999, paid: true },
  { item: "Mouse", price: 25, paid: false },
  { item: "Monitor", price: 189, paid: true },
  { item: "Cable", price: 9, paid: true },
];
const paidTotal = orders
  .filter((o) => o.paid)
  .map((o) => o.price)
  .reduce((sum, p) => sum + p, 0);
console.log(paidTotal);
```

"Take the paid orders, get their prices, add them up." Put each step on its own line.

## forEach: just do something with each item

`forEach(fn)` calls `fn` for each item and returns nothing. It's for side effects such as printing; when you're building a value, `map`, `filter` or `reduce` say more about your intent. Note that you can't `break` out of `forEach`; use `for...of` when you might need to stop early.

## Sorting

`sort()` sorts the array **in place** (it mutates!) and, by default, compares items **as strings**:

```js
const nums = [10, 9, 1, 100, 25];
console.log([...nums].sort());
console.log([...nums].sort((a, b) => a - b));
console.log([...nums].sort((a, b) => b - a));
```

`[10, 9, 1, 100, 25].sort()` gives `[1, 10, 100, 25, 9]` because "10" comes before "9" as text: one of JavaScript's most famous surprises. To sort numbers, pass a **comparator** function `(a, b) => ...` that returns a negative number if `a` should come first, positive if `b` should, and 0 if they're equal. `a - b` does exactly that for ascending order.

For text, use `localeCompare`, and for objects, compare a property:

```js
const people = [
  { name: "Linus", age: 21 },
  { name: "ada", age: 36 },
  { name: "Grace", age: 85 },
];
console.log(people.map((p) => p.name).sort());
console.log(people.map((p) => p.name).sort((a, b) => a.localeCompare(b)));
const byAge = [...people].sort((a, b) => b.age - a.age);
console.log(byAge.map((p) => `${p.name} (${p.age})`));
```

`[...people]` makes a copy first (spread syntax, two lessons from now), so the original order is kept. Newer JavaScript (2023+) has non-mutating versions: `toSorted`, `toReversed` and `toSpliced` return new arrays and leave the original alone.

## Mutating or not?

| Returns a new array (original unchanged) | Changes the original |
|---|---|
| `map`, `filter`, `slice`, `concat`, `flat`, `flatMap`, `toSorted`, `toReversed` | `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill` |

Prefer the left column. Code that doesn't change data behind other code's back is far easier to reason about.

::prompt
Write `wordFrequencies(text)` that returns an array of `[word, count]` pairs for the words in `text`, sorted by count (highest first), and alphabetically for equal counts. Words are separated by spaces; ignore case and empty words (from double spaces). Use `split`, `filter`, `reduce` (to count into an object) and `Object.entries(counts)`, which turns an object into an array of `[key, value]` pairs.
::starter
function wordFrequencies(text) {
}
::solution
function wordFrequencies(text) {
  const counts = text
    .toLowerCase()
    .split(" ")
    .filter((w) => w !== "")
    .reduce((acc, w) => {
      acc[w] = (acc[w] ?? 0) + 1;
      return acc;
    }, {});
  return Object.entries(counts).sort((a, b) => b[1] - a[1] || a[0].localeCompare(b[0]));
}
::tests

assert.deepStrictEqual(wordFrequencies("Go go  GO stop"), [["go", 3], ["stop", 1]]);
assert.deepStrictEqual(wordFrequencies(""), []);
assert.deepStrictEqual(wordFrequencies("b a"), [["a", 1], ["b", 1]]);
::hints
- Count with `reduce` into an object: `acc[w] = (acc[w] ?? 0) + 1`.
- `Object.entries(counts)` gives pairs like `["the", 2]`: `pair[0]` is the word, `pair[1]` the count.
- In the comparator, `b[1] - a[1]` sorts by count; when that's 0, `||` falls back to `a[0].localeCompare(b[0])`.

## Grouping data with names

An array is a list of values in order. An **object** groups values by **name**: a user has a name, an email and an age; a product has a title, a price and a stock level. Each named value is a **property** (a key and its value):

```js
const user = {
  name: "Ada Lovelace",
  email: "ada@example.com",
  age: 36,
  isAdmin: false,
};
console.log(user);
console.log(user.name, user.age);
```

Objects are JavaScript's main way of modelling things. Every value that isn't a primitive (arrays, functions, dates, maps...) is some kind of object.

## Reading properties: dot and brackets

Two ways to read a property:

```js
const book = { title: "Eloquent JavaScript", "page count": 472, year: 2024 };
console.log(book.title);
console.log(book["page count"]);
const field = "year";
console.log(book[field]);
console.log(book.author);
```

- **Dot notation** (`book.title`) is the normal way, for keys that are valid names.
- **Bracket notation** (`book["page count"]`) works for any key, including keys with spaces, and keys **stored in a variable** (`book[field]`). That last one is essential: it's how code works with keys it doesn't know in advance.
- A property that doesn't exist reads as `undefined`, without an error. But reading a property **of** `undefined` is an error: `book.author.name` throws `TypeError: Cannot read properties of undefined (reading 'name')`, which is the error from Module 1, finally explained.

## Adding, changing and deleting

Objects are mutable, like arrays:

```js
const player = { name: "Ada", score: 0 };
player.score += 10;
player.level = 2;
player["lives"] = 3;
delete player.level;
console.log(player);
console.log("lives" in player, "level" in player);
```

`"key" in obj` tells you whether a property exists, which is different from its value being `undefined`. `Object.hasOwn(obj, key)` does the same but ignores properties the object inherits (Module 8).

## Nested data

Properties can hold arrays and other objects, so real data is usually a tree:

```js
const order = {
  id: 1042,
  customer: { name: "Grace", city: "Arlington" },
  items: [
    { product: "Keyboard", qty: 1, price: 49 },
    { product: "Mouse pad", qty: 2, price: 8 },
  ],
};
console.log(order.customer.city);
console.log(order.items[1].product);
console.log(order.items.length, "items");
const total = order.items.reduce((sum, it) => sum + it.qty * it.price, 0);
console.log("Total:", total);
```

Read `order.items[1].product` from left to right: the order's items, the one at index 1, its product. An **array of objects** like `items` is the most common data shape there is: rows from a database, results from a web API, the posts in a feed.

## Looping over an object

```js
const prices = { coffee: 3.2, tea: 2.5, juice: 4 };
console.log(Object.keys(prices));
console.log(Object.values(prices));
console.log(Object.entries(prices));
for (const [item, price] of Object.entries(prices)) {
  console.log(`${item}: ${price.toFixed(2)}`);
}
```

`Object.keys`, `Object.values` and `Object.entries` turn an object into arrays, and from there all the array methods work. `Object.fromEntries(pairs)` goes the other way. You may also see `for (const key in obj)`, which loops over the keys; `Object.entries` with `for...of` is usually clearer.

Keys are kept in the order they were added, except that keys that look like whole numbers (`"1"`, `"42"`) come first, in numeric order.

## Objects as lookup tables

An object makes a fast **dictionary**: look up a value by its key directly, instead of searching through a list.

```js
const capitals = { France: "Paris", Japan: "Tokyo", Kenya: "Nairobi" };
const country = "Japan";
console.log(capitals[country] ?? "unknown");

const text = "to be or not to be";
const counts = {};
for (const word of text.split(" ")) {
  counts[word] = (counts[word] ?? 0) + 1;
}
console.log(counts);
```

The counting idiom `counts[key] = (counts[key] ?? 0) + 1` is worth memorising. (For lookup tables whose keys come from users or can be anything, the `Map` coming later in this module is safer.)

## Shorthand syntax

When a property's value comes from a variable with the same name, write it once. Functions stored in objects can drop the `function` keyword. Keys can be computed with `[ ]`:

```js
const name = "Ada";
const age = 36;
const key = "favourite" + "Language";
const person = {
  name,
  age,
  [key]: "JavaScript",
  greet() {
    return `Hi, I'm ${this.name}`;
  },
};
console.log(person);
console.log(person.greet());
```

A function stored in an object is a **method**, just like `toUpperCase` belongs to strings. Inside it, `this` refers to the object the method was called on (`person` here). Methods and `this` get a full lesson in Module 8.

## Arrays or objects?

| Use an array when... | Use an object when... |
|---|---|
| the items are many values of the same kind | the values are different facts about one thing |
| order matters | you look things up by name |
| you'll loop over all of them | each property has its own meaning |

Most real data combines both: an array of objects, or an object whose properties hold arrays.

## Unpacking values: destructuring

**Destructuring** pulls values out of arrays and objects into variables in one step. With arrays, positions decide which variable gets what:

```js
const point = [3, 7];
const [x, y] = point;
console.log(x, y);

const [first, , third = "default", ...others] = ["a", "b"];
console.log(first, third, others);
```

- Leave a gap (`, ,`) to skip an item.
- `= value` gives a **default** for a missing item.
- `...rest` collects the remaining items into an array (it must come last).

It also makes the classic swap from Module 1 a one-liner:

```js
let left = "coffee";
let right = "tea";
[left, right] = [right, left];
console.log(left, right);
```

## Destructuring objects

With objects, **names** decide: each variable takes the property with the same name, in any order:

```js
const user = { name: "Ada", email: "ada@example.com", age: 36 };
const { name, age } = user;
console.log(name, age);

const { email: contact, country = "UK", phone } = user;
console.log(contact, country, phone);
```

- `email: contact` reads the `email` property into a variable called `contact` (rename).
- `country = "UK"` gives a default when the property is missing (or `undefined`).
- A missing property with no default (`phone`) is just `undefined`.

You can destructure nested data, too: `const { customer: { city } } = order;`. Keep it shallow, though: two levels is already hard to read.

## Destructuring parameters: options objects

The most useful place for destructuring is a function's parameter list. Instead of a long row of positional arguments, take **one object** and destructure it, with defaults:

```js
function createUser({ name, role = "member", active = true }) {
  return `${name} (${role}${active ? "" : ", inactive"})`;
}
console.log(createUser({ name: "Ada" }));
console.log(createUser({ name: "Grace", role: "admin" }));
console.log(createUser({ active: false, name: "Linus" }));
```

Calls are self-explanatory (`createUser({ name: "Grace", role: "admin" })` versus `createUser("Grace", "admin", true)`), arguments can come in any order, and optional ones can simply be left out. This is called an **options object**, and you'll see it in every major library.

It works in callbacks too: `users.map(({ name }) => name)`, and `Object.entries(obj)` pairs destructure nicely: `for (const [key, value] of Object.entries(obj))`.

## Spread: unpacking into a new array or object

The three dots also work the other way round. **Spread** (`...`) unpacks an array's items or an object's properties into a new array or object:

```js
const weekdays = ["Mon", "Tue", "Wed", "Thu", "Fri"];
const weekend = ["Sat", "Sun"];
const week = [...weekdays, ...weekend];
console.log(week.length);
const copy = [...weekdays];
copy.push("Extra");
console.log(weekdays.length, copy.length);
console.log(Math.max(...[4, 9, 2]));
```

With objects, later properties override earlier ones, which makes spread perfect for "a copy with some changes":

```js
const defaults = { theme: "light", fontSize: 14, autosave: true };
const userSettings = { fontSize: 18 };
const settings = { ...defaults, ...userSettings };
console.log(settings);
const updated = { ...settings, theme: "dark" };
console.log(updated, settings.theme);
```

And **rest** in object destructuring collects "everything else", a neat way to leave a property out:

```js
const account = { id: 7, name: "Ada", password: "hunter2" };
const { password, ...safe } = account;
console.log(safe);
```

Same three dots, two jobs: on the **left** of `=` or in parameters, they *collect* (rest); in an array, object or call, they *spread*.

## Optional chaining: ?.

Reading deep into data that might be incomplete used to need a chain of checks: `user && user.address && user.address.city`. **Optional chaining** does it in one go: `a?.b` gives `undefined` (instead of throwing) if `a` is `null` or `undefined`:

```js
const user = { name: "Ada", address: null };
console.log(user.address?.city);
console.log(user.profile?.avatar?.url);
console.log(user.address?.city ?? "No city given");
console.log(user.greet?.());
const list = null;
console.log(list?.[0]);
```

- `obj?.prop` and `obj?.[key]` read safely.
- `fn?.()` calls a function only if it exists.
- Combine with `??` for a default.

Don't sprinkle `?.` everywhere, though. If a value should *always* be there, a crash with a clear error is better than a silent `undefined` that causes a confusing bug later. Use `?.` for data that's genuinely optional.

## Two kinds of values

Primitives (numbers, strings, booleans, `null`, `undefined`, bigints and symbols) are **values**: when you assign one to another variable, the variable gets its own copy.

Objects (including arrays and functions) are different. A variable doesn't contain the object itself; it holds a **reference** to it, like an address that says where the object lives in memory. Assigning the variable copies the *reference*, so both names point at the **same** object:

```js
let a = 5;
let b = a;
b += 1;
console.log(a, b);

const list = [1, 2, 3];
const other = list;
other.push(4);
console.log(list, other);
```

Changing `b` didn't affect `a`. But `list` and `other` are two names for one array, so the push shows through both. Two names for one object are called **aliases**, and unexpected aliasing is one of the most common sources of bugs in JavaScript.

## const doesn't freeze objects

This explains the puzzle from the arrays lesson: `const` makes the **name** permanent, so it always points at the same object; it doesn't stop the object from changing.

```js
const team = { name: "Blue", members: ["Ada"] };
team.members.push("Grace");
team.name = "Green";
console.log(team);
```

If you really need an object that can't change, `Object.freeze(obj)` blocks changes to its own properties (in strict mode, attempts throw a TypeError). But it's **shallow**: objects inside a frozen object can still change.

## Equality compares references

`===` on objects asks "are these the **same object**?", not "do they look alike?":

```js
const p1 = { x: 1, y: 2 };
const p2 = { x: 1, y: 2 };
const p3 = p1;
console.log(p1 === p2, p1 === p3);
console.log([1, 2] === [1, 2]);
```

Two separately created objects are never `===`, even with identical contents. To compare **contents**, you compare property by property (a "deep equality" check, which `assert.deepStrictEqual` does for you in tests). The quick trick `JSON.stringify(a) === JSON.stringify(b)` works for simple data, but it's fooled by different property orders and can't handle values JSON doesn't support (the JSON lesson explains which).

This also affects searching: `[{ id: 1 }].includes({ id: 1 })` is `false`, because the object you're searching for is a new one. Search by a property instead: `items.some((it) => it.id === 1)`.

## Functions receive references too

When you pass an object to a function, the parameter is another alias. If the function changes the object, the caller sees the change:

```js
function addBonus(scores) {
  for (let i = 0; i < scores.length; i++) {
    scores[i] += 10;
  }
  return scores;
}
const original = [50, 70];
const boosted = addBonus(original);
console.log(original, boosted, original === boosted);
```

The caller probably didn't expect `original` to change. That hidden side effect is the kind of bug that takes hours to find. Professional style: **don't mutate inputs**; return new data instead:

```js
const addBonus = (scores) => scores.map((s) => s + 10);
const original = [50, 70];
const boosted = addBonus(original);
console.log(original, boosted);
```

(Reassigning a parameter, `scores = []`, only changes where the local name points; the caller's variable is unaffected.)

## Shallow copies

To get an independent copy, create a new object. These all make **shallow** copies, new at the top level only:

| For | Copy with |
|---|---|
| arrays | `[...arr]`, `arr.slice()`, `Array.from(arr)` |
| objects | `{ ...obj }`, `Object.assign({}, obj)` |

Shallow means nested objects are still **shared**:

```js
const original = { name: "Ada", skills: ["maths"] };
const copy = { ...original };
copy.name = "Grace";
copy.skills.push("poetry");
console.log(original);
```

The `name` change stayed in the copy, but `skills` is one array referenced by both objects.

## Deep copies

`structuredClone(value)` makes a **deep** copy: every nested array and object is copied too. It's built into browsers and Node.js 17+:

```js
const original = { name: "Ada", skills: ["maths"], meta: { joined: 1843 } };
const deep = structuredClone(original);
deep.skills.push("poetry");
deep.meta.joined = 2026;
console.log(original);
console.log(deep);
```

It handles dates, maps, sets and even circular references, but not functions or class methods. Older code used `JSON.parse(JSON.stringify(obj))` for the same job, which loses dates, `undefined` values and more.

## Immutable updates

Modern front-end frameworks such as React rely on a habit: **never change existing data; create updated copies**. Then "has anything changed?" is just a quick `===` check. The patterns, all with spread, `map` and `filter`:

```js
const todos = [
  { id: 1, text: "Learn arrays", done: true },
  { id: 2, text: "Learn objects", done: false },
];
const added = [...todos, { id: 3, text: "Learn Map", done: false }];
const toggled = added.map((t) => (t.id === 2 ? { ...t, done: !t.done } : t));
const removed = toggled.filter((t) => t.id !== 1);
console.log(todos.length, removed);
console.log(todos[1].done);
```

Add with spread, change with `map` plus a spread copy of the one item, remove with `filter`. The original `todos` never changed.

## Set: a collection of unique values

A **Set** holds values with **no duplicates**. Adding a value that's already there does nothing:

```js
const tags = new Set();
tags.add("js");
tags.add("css");
tags.add("js");
console.log(tags, tags.size);
console.log(tags.has("css"), tags.has("python"));
tags.delete("css");
console.log([...tags]);
```

The most common use is removing duplicates from an array: make a Set from it, then spread it back into an array.

```js
const visitors = ["ada", "bob", "ada", "cy", "bob", "ada"];
const unique = [...new Set(visitors)];
console.log(unique, unique.length);
```

Sets keep values in the order they were first added, and you can loop over them with `for...of`. The big advantage over an array is speed: `set.has(x)` takes the same tiny time whether the set holds 10 values or 10 million, while `array.includes(x)` has to look through the items one by one.

### Set operations

```js
const frontEnd = new Set(["html", "css", "js"]);
const backEnd = new Set(["js", "python", "sql"]);
const both = [...frontEnd].filter((x) => backEnd.has(x));
const either = new Set([...frontEnd, ...backEnd]);
const onlyFront = [...frontEnd].filter((x) => !backEnd.has(x));
console.log(both, [...either], onlyFront);
```

Since 2024, sets also have methods for this: `a.intersection(b)`, `a.union(b)`, `a.difference(b)`, `a.isSubsetOf(b)` and friends, in current browsers and Node.js 22+. The `filter` versions work everywhere.

## Map: a dictionary done right

A **Map** stores key-value pairs, like an object used as a lookup table, but designed for the job:

```js
const stock = new Map();
stock.set("apples", 12);
stock.set("pears", 0);
stock.set("plums", 7);
console.log(stock.get("apples"), stock.get("kiwis"));
console.log(stock.has("pears"), stock.size);
stock.set("apples", stock.get("apples") - 2);
stock.delete("plums");
console.log(stock);
for (const [fruit, qty] of stock) {
  console.log(`${fruit}: ${qty}`);
}
```

## Map or object?

| | Object | Map |
|---|---|---|
| Keys | strings (and symbols) only | **any value**: numbers, objects, even functions |
| Size | `Object.keys(obj).length` | `map.size` |
| Order | mostly insertion, but number-like keys first | always insertion order |
| Built-in keys | inherits some, such as `toString` | none: only what you put in |
| JSON | `JSON.stringify` works | needs converting first |

Use **objects** for records with fixed, known properties (a user, a product). Use a **Map** for a lookup table that grows and shrinks at runtime, especially when keys come from data or users, or aren't strings.

The "built-in keys" row is a real trap with objects:

```js
const counts = {};
const word = "constructor";
console.log(word in counts, counts[word]);
const safe = new Map();
console.log(safe.has(word), safe.get(word));
```

Objects inherit properties like `constructor` and `toString`, so a word-count program built on `{}` gets confused by those words. A Map starts truly empty.

## Converting

```js
const prices = { tea: 2.5, coffee: 3.2 };
const map = new Map(Object.entries(prices));
map.set("juice", 4);
console.log(map);
console.log(Object.fromEntries(map));
console.log([...map.keys()], [...map.values()]);
```

`new Map(pairs)` takes an array of `[key, value]` pairs, which is exactly what `Object.entries` gives you; `Object.fromEntries(map)` converts back.

## Counting and grouping with a Map

```js
const words = "the cat and the hat and the bat".split(" ");
const counts = new Map();
for (const w of words) {
  counts.set(w, (counts.get(w) ?? 0) + 1);
}
const sorted = [...counts].sort((a, b) => b[1] - a[1]);
console.log(sorted.slice(0, 2));
```

For grouping, modern JavaScript (2024+) has `Object.groupBy(items, fn)` and `Map.groupBy(items, fn)`, which call `fn` on each item and group the items by its result:

```js
const scores = [45, 82, 67, 91, 30];
console.log(Map.groupBy(scores, (s) => (s >= 50 ? "pass" : "fail")));
```

## Memoization with a Map

Remember the slow recursive Fibonacci from Module 5? A Map can remember each result so it's computed only once:

```js
const memo = new Map();
function fib(n) {
  if (n < 2) return n;
  if (memo.has(n)) return memo.get(n);
  const result = fib(n - 1) + fib(n - 2);
  memo.set(n, result);
  return result;
}
console.log(fib(90));
```

`fib(90)` instantly, where the naive version would take longer than you'd live. Trading a little memory for a lot of speed like this is one of the most important ideas in computer science.

## WeakMap and WeakSet

You'll occasionally see `WeakMap` and `WeakSet`. Their keys must be objects, and they don't keep those objects alive: once nothing else refers to an object, it's removed automatically. Libraries use them to attach extra data to objects they don't own, without causing memory leaks. You can safely ignore them for now.

Map :: Key-value pairs with keys of any type: set, get, has, delete, size; iterates as [key, value].

=== lesson js-json | JSON | 75
## Data that travels

Programs constantly exchange data: a web page asks a server for products, an app saves settings to a file, two services send each other messages. They need a common text format, and the most common by far is **JSON** (JavaScript Object Notation). It looks almost exactly like JavaScript objects and arrays:

```json
{
  "name": "Ada Lovelace",
  "born": 1815,
  "languages": ["English", "French"],
  "mathematician": true,
  "spouse": null
}
```

Every language can read and write JSON (Python has its `json` module, for instance), which is why it became the universal language of web APIs.

## JSON's rules

JSON is **stricter** than JavaScript:

- Keys **must** be in **double quotes**: `{"name": "Ada"}`, never `{name: 'Ada'}`.
- Strings use double quotes only.
- Values can be strings, numbers, `true`, `false`, `null`, arrays and objects. No `undefined`, functions, dates, `NaN` or `Infinity`.
- No trailing commas, and no comments.

## JSON.stringify: from values to text

```js
const user = { name: "Ada", born: 1815, languages: ["English", "French"], admin: false };
const text = JSON.stringify(user);
console.log(text);
console.log(typeof text);
console.log(JSON.stringify(user, null, 2));
```

The third argument indents the output, which makes it readable for humans (great for config files and debugging). Watch what happens to values JSON can't represent:

```js
const tricky = {
  when: new Date(Date.UTC(2026, 9, 14)),
  nothing: undefined,
  greet() { return "hi"; },
  notANumber: NaN,
  tags: new Set(["a"]),
};
console.log(JSON.stringify(tricky));
```

- Dates become ISO strings (`"2026-10-14T00:00:00.000Z"`), but they come back as **strings**, not dates.
- Properties holding `undefined` or functions disappear (in arrays they become `null`).
- `NaN` and `Infinity` become `null`.
- Maps and Sets become `{}`: convert them first, e.g. `[...set]` or `Object.fromEntries(map)`.

The second argument can choose which properties to keep: `JSON.stringify(user, ["name", "born"])`.

## JSON.parse: from text to values

```js
const text = '{"title": "Dune", "year": 1965, "tags": ["sci-fi", "classic"]}';
const book = JSON.parse(text);
console.log(book.title, book.tags[1], book.year + 1);
```

`JSON.parse` gives you real JavaScript objects and arrays. If the text isn't valid JSON, it throws a `SyntaxError` that tells you the position of the problem:

```js
const broken = "{name: 'Dune'}";
JSON.parse(broken);
```

Text from outside your program (a file, a server, a user) can always be broken, so real code wraps `JSON.parse` in `try`/`catch` (Module 7) and checks that the data has the shape it expects:

```js
function parseConfig(text) {
  try {
    return JSON.parse(text);
  } catch (error) {
    console.log("Invalid config:", error.message);
    return {};
  }
}
console.log(parseConfig('{"theme": "dark"}'));
console.log(parseConfig("{oops}"));
```

~~~check
? Which is valid JSON?
- `{name: "Ada"}`
- `{'name': 'Ada'}`
+ `{"name": "Ada", "tags": []}`
- `{"name": "Ada",}`
> Keys and strings need double quotes, and trailing commas aren't allowed.
~~~

## Bringing dates back

Because dates turn into strings, parsing gives you strings. The second argument of `JSON.parse`, a **reviver** function, can convert values on the way in:

```js
const saved = JSON.stringify({ event: "Launch", at: new Date(Date.UTC(2026, 0, 1)) });
const restored = JSON.parse(saved, (key, value) => (key === "at" ? new Date(value) : value));
console.log(typeof restored.at, restored.at.getUTCFullYear());
```

## Where you'll use JSON

- **Web APIs**: `fetch` responses are usually JSON, read with `await response.json()` (Module 10).
- **Saving data in the browser**: `localStorage` only stores strings, so apps save with `localStorage.setItem("todos", JSON.stringify(todos))` and load with `JSON.parse(localStorage.getItem("todos") ?? "[]")`. DevQuest saves your progress exactly this way.
- **Configuration files**: `package.json` (Module 11), `tsconfig.json` and countless others.
- **Copying simple data**: `JSON.parse(JSON.stringify(data))` makes a deep copy, with the losses listed above. Prefer `structuredClone`.

📚 **Go deeper:** json.org (the whole format on one page); javascript.info, "JSON methods, toJSON"; MDN, "Working with JSON".

function toJsonSafe(value) {
  if (value instanceof Map) return Object.fromEntries([...value].map(([k, v]) => [k, toJsonSafe(v)]));
  if (value instanceof Set) return [...value].map(toJsonSafe);

}

  const regions = new Map();
  for (const { region, rep, amount } of sales) {
    if (!regions.has(region)) regions.set(region, new Map());
    const reps = regions.get(region);

(This is exactly how state management works in React apps, with a function called a **reducer**.)
::starter

::solution
function update(state, action) {
  switch (action.type) {
    case "add": {
      const id = state.todos.reduce((max, t) => Math.max(max, t.id), 0) + 1;
      return { ...state, todos: [...state.todos, { id, text: action.text, done: false }] };
    }
    case "toggle":
      return { ...state, todos: state.todos.map((t) => (t.id === action.id ? { ...t, done: !t.done } : t)) };
    case "remove":
      return { ...state, todos: state.todos.filter((t) => t.id !== action.id) };
    case "filter":
      return { ...state, filter: action.value };
    default:
      return state;
  }
}
