## A language designed for big software

**Go** (often called *Golang* because of its old website, golang.org) was designed at Google in 2007 by Robert Griesemer, Rob Pike and Ken Thompson (one of the creators of Unix and of C's predecessor B). It was released as open source in 2009, and Go 1.0 arrived in 2012.

Its designers were frustrated by huge C++ code bases that took close to an hour to compile, by complicated type hierarchies, and by how hard it was to use many CPU cores safely. So they made a deliberately **small** language:

- **compiled to native machine code**, very quickly: a large program builds in seconds, into a single executable file with no runtime to install;
- **statically typed**, with type inference (`x := 42`) so it feels light;
- **garbage collected**, so you don't free memory by hand as in C;
- **concurrency built in**: *goroutines* (very cheap threads) and *channels* (pipes between them) are part of the language;
- **few features on purpose**: no classes and no inheritance (structs, methods and interfaces instead), no exceptions (errors are ordinary values), one loop keyword (`for`). Generics arrived only in Go 1.18 (2022), after years of careful design.

```
main.go  --go build-->  one native executable (app.exe / app)  --> runs directly on Windows, Linux or macOS
```

## Where Go is used

- **Cloud infrastructure**: Docker, Kubernetes, Terraform, Prometheus, etcd and most "cloud-native" tools are written in Go.
- **Back ends and APIs**: Google, Uber, Twitch, Dropbox, Cloudflare and many start-ups run Go services; the standard library includes a production-quality HTTP server.
- **Command-line tools**: GitHub's `gh`, Hugo, and countless DevOps tools, because one static binary is easy to distribute.
- **Networking and systems**: proxies, databases (CockroachDB), message queues.

## What working with Go feels like

Go values **simplicity and readability over cleverness**. There's usually one obvious way to write something, all Go code is formatted the same way by `gofmt`, and the standard library covers most everyday needs (HTTP, JSON, files, testing, cryptography). The **Go 1 compatibility promise** means code written for Go 1.0 still compiles today. A new version ships every six months (February and August); this course needs **Go 1.23 or newer**.

=== lesson go-setup | Installing Go and running programs | 55
## Install the toolchain

Download the installer for your system from **go.dev/dl** and run it (on Linux you can also use your package manager, but it may be older; on macOS, `brew install go` works). Then open a new terminal and check:

```
go version
```

You should see something like `go version go1.27.2 windows/amd64`. DevQuest's desktop app finds Go automatically (Settings → Local compilers shows what it found).

For editing, **Visual Studio Code** with the official **Go extension** is the most popular choice (it installs `gopls`, the Go language server, for completion and errors as you type); **GoLand** (JetBrains) is a full IDE.

## Your first project

Go code lives in **modules**: a folder with a `go.mod` file that names the module and the Go version. Create one:

```
mkdir hello
cd hello
go mod init example.com/hello
```

`go.mod` now contains:

```
module example.com/hello

go 1.27
```

The module path is usually where the code will live online (`github.com/yourname/hello`); for a private experiment any name works. Create `main.go`:

```
package main

import "fmt"

func main() {
	fmt.Println("Hello, Go!")
}
```

## The go command

One command does almost everything:

| Command | Does |
|---|---|
| `go run .` | compile and run the program in this folder (nothing is left behind) |
| `go build` | compile it into an executable (`hello.exe` on Windows, `hello` elsewhere) |
| `go fmt ./...` | format all files the standard way (editors do it on save) |
| `go vet ./...` | report suspicious code that compiles but is probably wrong |
| `go test ./...` | run the tests (Module 7) |
| `go get example.com/pkg` | add a dependency to `go.mod` |
| `go mod tidy` | add missing and remove unused dependencies |
| `go doc fmt.Println` | show documentation |

`./...` means "this folder and all folders below it".

**Cross-compiling** is famously easy: `GOOS=linux GOARCH=arm64 go build` (in a Unix shell; in PowerShell set `$env:GOOS` and `$env:GOARCH` first) builds a Linux ARM executable from any computer.

## Formatting is not optional

Go has one official style, applied by `gofmt`: **tabs** for indentation, braces on the same line, aligned comments. Nobody argues about style in Go code reviews, because the tool decides. Opening braces must stay on the same line: Go automatically inserts semicolons at line ends, so a `{` on the next line is a syntax error.

```go
package main

import "fmt"

func main() {
	name := "gopher"
	for i := 1; i <= 3; i++ {
		fmt.Println(i, "hello,", name)
	}
}
```

=== lesson go-basics | Hello, Go: the structure of a program | 65
## Packages, imports and main

Every Go file starts by saying which **package** it belongs to. A program's entry point is the function **`main`** in package **`main`**:

```go
package main // this file belongs to the executable program

import (
	"fmt"     // formatted printing
	"strings" // string helpers
)

// main is where the program starts
func main() {
	greeting := strings.ToUpper("hello")
	fmt.Println(greeting, "from Go")
}
```

- `import` lists the packages the file uses, from the **standard library** (`fmt`, `strings`, `os`, `math`, …) or from other modules.
- You call a package's functions with its name: `strings.ToUpper`. Only names starting with a **capital letter** are visible outside their package (*exported*): `fmt.Println` is exported, a function `helper` wouldn't be.
- `//` starts a comment to the end of the line; `/* ... */` spans lines.
- There are no semicolons at line ends: the compiler adds them.

## Variables

Go has several ways to declare a variable; all of them give it a fixed **type**:

```go
package main

import "fmt"

func main() {
	var city string = "Lisbon" // full form
	var year = 2026            // type inferred: int
	temperature := 21.5        // short form, inside functions: float64
	var visits int             // no value: the zero value, 0

	var (
		active  bool   // false
		nickname string // "" (empty string)
	)

	city = "Porto"  // assign a new value of the same type
	visits++        // add 1

	fmt.Println(city, year, temperature, visits, active, nickname == "")
	a, b := 1, 2
	a, b = b, a // swap in one statement
	fmt.Println(a, b)
}
```

- `:=` declares **and** assigns, and only works inside functions; `=` assigns to an existing variable.
- Every type has a **zero value**: `0` for numbers, `false` for `bool`, `""` for strings, `nil` for pointers, slices, maps and some others. A Go variable is never "uninitialised".
- The compiler **refuses unused variables and unused imports**. It feels strict at first, but it keeps programs clean. Assign to the blank identifier `_` to ignore a value on purpose.

## Constants

```go
package main

import "fmt"

const appName = "Tracker"
const maxUsers = 100

const (
	Small = iota // 0
	Medium       // 1
	Large        // 2
)

func main() {
	fmt.Println(appName, maxUsers, Small, Medium, Large)
	const ratio = 1.0 / 3 // untyped constant: exact until used
	fmt.Printf("%.4f\n", ratio)
}
```

Constants are computed by the compiler. **`iota`** counts up inside a `const` group, Go's simple way to make enumerations.

## Printing with fmt

| Function | Does |
|---|---|
| `fmt.Println(a, b)` | values separated by spaces, then a line break |
| `fmt.Print(a, b)` | no line break (spaces only between non-strings) |
| `fmt.Printf(format, args...)` | formatted: `%d` integer, `%s` string, `%f` float (`%.2f` two decimals), `%t` bool, `%v` any value, `%q` quoted, `%T` the type, `%5d` width 5, `%-8s` left-aligned |
| `fmt.Sprintf(...)` | like Printf but returns the string |

```go
package main

import "fmt"

func main() {
	item, qty, price := "coffee", 3, 2.5
	fmt.Printf("%-8s x%d = %6.2f\n", item, qty, float64(qty)*price)
	fmt.Printf("%v %T | %q\n", qty, price, item)
	line := fmt.Sprintf("%s costs %.2f", item, price)
	fmt.Println(line)
}
```

Note `float64(qty)`: Go never converts between numeric types automatically; you write the conversion.

=== lesson go-errors | Reading compiler errors and panics | 55
## Compile errors

Go's compiler is fast and strict. It reports problems with the **file, line and column**, then a message:

```
main.go:6:2: "os" imported and not used
main.go:10:2: declared and not used: total
main.go:11:18: cannot use "5" (untyped string constant) as int value in variable declaration
main.go:12:6: undefined: fmt.Printn
```

Read them like this: `main.go:11:18` is line 11, column 18. Fix the **first** error first; later ones are often consequences of it. This example doesn't compile on purpose; press ▶ Run and read the messages:

```go
// error
package main

import (
	"fmt"
	"os"
)

func main() {
	total := 0
	var count int = "5"
	fmt.Printn(count)
}
```

The most common messages for beginners:

| Message | Meaning |
|---|---|
| `declared and not used: x` | delete the variable, use it, or assign it to `_` |
| `"os" imported and not used` | remove the import (editors do it for you) |
| `undefined: x` | a typo, a missing import, or a lowercase (unexported) name from another package |
| `cannot use x (variable of type float64) as int value` | convert explicitly: `int(x)` |
| `missing return` | a function with a result type must return on every path |
| `syntax error: unexpected newline` | often a `{` on the next line, or a missing comma in a multi-line list |

## Runtime panics

Some mistakes can only be found while the program runs: indexing past the end of a slice, dividing an integer by zero, using a `nil` map or pointer. Go then **panics**: it stops the program and prints the reason and a **stack trace**, the list of function calls that led there, most recent first:

```go
// error
package main

import "fmt"

func main() {
	scores := []int{90, 75, 82}
	fmt.Println("average of the first four:", average(scores, 4))
}

func average(values []int, n int) int {
	sum := 0
	for i := 0; i < n; i++ {
		sum += values[i]
	}
	return sum / n
}
```

```
panic: runtime error: index out of range [3] with length 3

goroutine 1 [running]:
main.average(...)
	main.go:14
main.main()
	main.go:8 +0xc6
```

Read it bottom-up to see the path (`main` called `average`), and top-down to find **where** it broke: line 14 of `main.go`, inside `average`. The message says exactly what happened: index 3 in a slice of length 3.

Expected problems (a missing file, invalid input) are not panics in Go: functions **return an `error` value**, which you check. That's Module 3's topic.

## A debugging habit

1. Read the whole message; note the file and line.
2. Print values just before the failing line (`fmt.Println("i =", i)`) or use the debugger in VS Code (Delve).
3. Change one thing at a time, and run again.
