=== lesson py-loops | while loops | 85
Computers are brilliant at repetition: they'll do the same thing a million times without a single mistake or complaint. A **loop** runs a block of code over and over. Python has two kinds; this lesson covers `while`, which repeats **as long as a condition is true**.

## Anatomy of a while loop

```python
count = 1
while count <= 5:
    print("Lap", count)
    count += 1
print("Finished!")
```

Python checks the condition. If it's true, it runs the indented **body**, then goes back up and checks the condition again. When the condition is false, it skips to the first line after the loop. Each pass through the body is called an **iteration**.

Tracing it:

| count | `count <= 5`? | prints |
|---|---|---|
| 1 | True | Lap 1 |
| 2 | True | Lap 2 |
| ... | ... | ... |
| 5 | True | Lap 5 |
| 6 | False | (the loop ends) Finished! |

Every `while` loop needs three things:

1. **initialise** the variable the condition depends on (`count = 1`);
2. a **condition** that will eventually become false (`count <= 5`);
3. an **update** inside the body that moves towards that (`count += 1`).

Forget the update and the condition never changes: an **infinite loop**. In DevQuest a run stops itself after a few seconds ("Timed out... Is there an infinite loop?"); in a terminal, press **Ctrl+C** to stop a runaway program.

## Accumulating a result

A very common pattern: a variable created **before** the loop, updated **in** it, and used **after** it.

```python
total = 0
n = 1
while n <= 100:
    total += n
    n += 1
print(total)    # 5050
```

## Reading input until a sentinel

Loops shine when you don't know in advance how many times to repeat, for example reading numbers until the user types `done`. A special value that means "stop" is called a **sentinel**:

```python
total = 0
entry = input("Number (or done): ")
while entry != "done":
    total += int(entry)
    entry = input("Number (or done): ")
print("Total:", total)
```

## while True and break

`break` leaves the loop immediately, whatever the condition. Combined with `while True` (a loop that would run forever), it lets you test in the middle of the body, so the `input` line isn't written twice:

```python
total = 0
while True:
    entry = input("Number (or done): ")
    if entry == "done":
        break
    total += int(entry)
print("Total:", total)
```

This "loop and a half" is a very common shape for programs that talk to a user.

## continue

`continue` skips the rest of the current iteration and jumps straight back to the condition:

```python
n = 0
while n < 10:
    n += 1
    if n % 3 == 0:
        continue           # skip multiples of 3
    print(n, end=" ")
# 1 2 4 5 7 8 10
```

Careful: if the update came *after* the `continue`, it would be skipped too, and the loop would never end.

## Validating input with a loop

Keep asking until the answer is usable:

```python
age = input("Age: ")
while not age.isdigit():
    print("Please type a whole number.")
    age = input("Age: ")
age = int(age)
```

## while ... else

A loop can have an `else` block. It runs when the loop ends **normally** (its condition became false), but **not** when it's left with `break`. That's perfect for searches:

```python
target = 91
d = 2
while d * d <= target:
    if target % d == 0:
        print(target, "is divisible by", d)
        break
    d += 1
else:
    print(target, "is prime")
# 91 is divisible by 7
```

## Common loop bugs

- **Off by one**: `<` where `<=` was needed, so the loop runs one time too few (or too many). Trace the first and last iterations.
- **No update**, or an update hidden inside an `if` that doesn't always run: infinite loop.
- **Resetting the accumulator inside the loop** (`total = 0` in the body), so it starts over every time.

=== lesson py-for | for loops, range, enumerate and zip | 90
A `while` loop repeats while a condition holds. A `for` loop does something simpler and more common: it goes through a **sequence of items, one at a time**.

```python
for letter in "Hi!":
    print(letter)
```

prints `H`, `i` and `!` on separate lines. Each time round, the **loop variable** (`letter`) refers to the next item, and the body runs once per item. There's no counter to update and no condition to get wrong, so `for` loops can't accidentally run forever.

## Looping over a list

You've seen lists come out of `split()`. A **list** is an ordered collection written in square brackets (Module 6 covers them in depth):

```python
scores = [72, 95, 88]
for score in scores:
    print("Score:", score)
```

## range(): looping over numbers

`range` produces a sequence of whole numbers. Like slicing, it goes **up to but not including** the stop value:

| Call | Numbers |
|---|---|
| `range(5)` | 0, 1, 2, 3, 4 |
| `range(2, 6)` | 2, 3, 4, 5 |
| `range(0, 20, 5)` | 0, 5, 10, 15 |
| `range(10, 0, -1)` | 10, 9, ... , 1 |

```python
for i in range(1, 4):
    print(i, "squared is", i ** 2)
```

To just repeat something N times, loop over `range(N)`. By convention, a loop variable you don't use is named `_`:

```python
for _ in range(3):
    print("Hip hip hooray!")
```

`range` doesn't build a list in memory; it produces numbers as needed. To see them, convert it: `list(range(5))` is `[0, 1, 2, 3, 4]`.

## Accumulating with for

The accumulator pattern from `while` works the same way:

```python
prices = [3.5, 12.0, 7.25]
total = 0
for price in prices:
    total += price
print(total)    # 22.75
```

Python has built-ins for the common cases: `sum(prices)`, `max(prices)`, `min(prices)`, `len(prices)`. Use them in real code, but learn the pattern: you'll need it for everything the built-ins don't cover.

## enumerate: the position and the item

When you need to know *where* you are, `enumerate` gives you pairs of (position, item):

```python
names = ["Ada", "Alan", "Grace"]
for i, name in enumerate(names, start=1):
    print(f"{i}. {name}")
# 1. Ada
# 2. Alan
# 3. Grace
```

`for i, name in ...` unpacks each pair into two variables, like `a, b = 1, 2`. Without `start=1`, counting begins at 0. Prefer `enumerate` to `for i in range(len(names))`, which works but is harder to read.

## zip: walking two sequences side by side

```python
names = ["Ada", "Alan", "Grace"]
years = [1815, 1912, 1906]
for name, year in zip(names, years):
    print(name, "was born in", year)
```

`zip` pairs up the first items, then the second items, and so on. It stops when the **shortest** sequence runs out.

## break, continue and else work in for loops too

```python
for n in [3, 7, 12, 5]:
    if n % 2 == 0:
        print("First even number:", n)
        break
else:
    print("No even numbers")
```

## Don't change a list while looping over it

Adding or removing items of the list you're looping over makes the loop skip or repeat items. Build a new list instead (Module 6 shows how).

## for or while?

- Use `for` when you're going through **known items** or a **known number of times**: every letter, every line of a file, 10 times.
- Use `while` when you repeat **until something happens**: the user types `done`, a value gets small enough, the game ends.

## A small gotcha

After a `for` loop ends, the loop variable still holds the **last** item. And if the sequence was empty, the variable is never created at all.

=== lesson py-nested-loops | Loop patterns and nested loops | 90
Most loops you'll ever write are one of a handful of **patterns**. Recognise them, and new problems become variations on things you already know.

## The core patterns

**Count** the items that match:

```python
count = 0
for word in words:
    if len(word) > 5:
        count += 1
```

**Sum or average**: the accumulator from the last lessons.

**Find the biggest (or smallest) yourself**, remembering where it was:

```python
temps = [18, 24, 21, 31, 27]
best = temps[0]
best_day = 1
for day, t in enumerate(temps, start=1):
    if t > best:
        best = t
        best_day = day
print(f"Hottest: {best} on day {best_day}")
```

Start with the first item, not with 0: if all values were negative, 0 would wrongly "win".

**Search with an early exit**: stop as soon as you've found it, using `break` (and `else` for "not found"), or a **flag** variable:

```python
found = False
for name in names:
    if name.startswith("Z"):
        found = True
        break
```

**Filter into a new list**, using the list method `append()` to add an item at the end:

```python
long_words = []
for word in words:
    if len(word) > 5:
        long_words.append(word)
```

**Build a string** piece by piece:

```python
no_vowels = ""
for ch in text:
    if ch.lower() not in "aeiou":
        no_vowels += ch
```

**Compare each item with the previous one**, keeping a "running" state, for example the longest streak:

```python
results = "WWLWWWLW"
streak = best = 0
for r in results:
    if r == "W":
        streak += 1
        best = max(best, streak)
    else:
        streak = 0
print("Longest winning streak:", best)    # 3
```

## Nested loops

A loop inside a loop: for **each** iteration of the outer loop, the inner loop runs **all the way through**.

```python
for row in range(1, 4):
    for col in range(1, 4):
        print(row * col, end="\t")
    print()        # end the row
```

```
1	2	3
2	4	6
3	6	9
```

Trace it as a table of `row` and `col`: (1,1), (1,2), (1,3), then (2,1), (2,2)... The inner variable changes fastest, like the minutes on a clock while the hour hand moves slowly.

Nested loops are how you handle **grids** (rows and columns), **all pairs** of items, and **text patterns**:

```python
for i in range(1, 5):
    print("*" * i)
```

```
*
**
***
****
```

Two things to know:

- `break` only leaves the **innermost** loop it's in.
- The work multiplies: an outer loop of 1,000 with an inner loop of 1,000 runs the body **a million** times. That's why nested loops over big data can be slow, a topic you'll study as "Big-O" in the algorithms track.

Print all the prime numbers up to `n` on one line. A prime is a number above 1 that's only divisible by 1 and itself. Use a nested loop: for each candidate, try dividing it by smaller numbers (a `for`/`else` is perfect here).

::solution

    for d in range(2, candidate):
        if candidate % d == 0:
            break
    else:
        primes += " " + str(candidate)

- The inner loop's `else` runs only when nothing divided it, so that's where you record a prime.
