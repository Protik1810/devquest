=== lesson py-lists | Lists | 90
A **list** holds many values in order, under one name: a shopping list, the scores of every player, the lines of a file. Lists are the workhorse of Python.

```python
fruits = ["apple", "banana", "cherry"]
scores = [72, 95, 88, 95]
mixed = ["Ada", 36, True, 3.5]     # any types can mix
empty = []
```

## Indexing and slicing: just like strings

```python
fruits[0]        # 'apple'
fruits[-1]       # 'cherry'
fruits[1:]       # ['banana', 'cherry']
len(fruits)      # 3
"banana" in fruits    # True
```

Going past the end raises `IndexError: list index out of range`.

## Lists can change

Unlike strings, lists are **mutable**: you can change them in place.

```python
fruits[0] = "apricot"          # replace an item
fruits.append("date")          # add to the end
fruits.insert(1, "blueberry")  # insert before index 1
fruits.extend(["fig", "grape"])  # add several items at the end
print(fruits)
# ['apricot', 'blueberry', 'banana', 'cherry', 'date', 'fig', 'grape']
```

Removing items:

| Code | What it does |
|---|---|
| `fruits.remove("banana")` | removes the first item equal to `"banana"` (`ValueError` if there isn't one) |
| `fruits.pop()` | removes **and returns** the last item |
| `fruits.pop(0)` | removes and returns the item at index 0 |
| `del fruits[1]` | deletes the item at index 1 (also works with slices: `del fruits[:2]`) |
| `fruits.clear()` | empties the list |

Finding things: `fruits.index("cherry")` gives the position (or `ValueError`), and `scores.count(95)` counts matching items.

## Sorting

```python
scores = [72, 95, 88, 61]
scores.sort()                    # sorts the list IN PLACE: [61, 72, 88, 95]
scores.sort(reverse=True)        # [95, 88, 72, 61]
ordered = sorted(scores)         # returns a NEW sorted list; scores is unchanged
scores.reverse()                 # reverses in place
```

**Careful:** `sort()` changes the list and returns `None`. Writing `scores = scores.sort()` throws your list away and leaves `scores` set to `None`. Use `sorted()` when you want a new list.

Strings sort alphabetically, with capitals before lowercase letters. `sorted(words, key=str.lower)` sorts ignoring case; the `key` is a function applied to each item to decide the order (more in the comprehensions lesson).

## Built-ins that work on lists

```python
nums = [4, 9, 1, 7]
sum(nums), min(nums), max(nums), len(nums)    # 21 1 9 4
sorted(nums), list(reversed(nums))
```

## Building lists

```python
squares = []
for n in range(1, 6):
    squares.append(n * n)          # [1, 4, 9, 16, 25]

list("abc")                        # ['a', 'b', 'c']
list(range(3))                     # [0, 1, 2]
"a b c".split()                    # ['a', 'b', 'c']
[0] * 4                            # [0, 0, 0, 0]
[1, 2] + [3]                       # [1, 2, 3]
```

## Lists inside lists

A list can contain other lists, for example a grid of rows:

```python
board = [
    ["X", "O", "X"],
    [" ", "X", "O"],
    ["O", " ", "X"],
]
board[1][2]     # 'O': row 1, then column 2
```

## Common mistakes

- `x = x.sort()` (sets `x` to `None`). Use `x.sort()` alone, or `x = sorted(x)`.
- Removing items from a list **while looping over it**: the loop skips items. Loop over a copy (`for x in items[:]`) or build a new list.
- Confusing `append` and `extend`: `a.append([1, 2])` adds **one** item (a list); `a.extend([1, 2])` adds two items.

=== lesson py-list-copies | References, copies and nested lists | 90
This lesson explains one of the most important ideas in Python, and the source of many confusing bugs: **variables are references to objects**.

## Names point at objects

When you write `a = [1, 2, 3]`, Python creates a list **object** in memory, and the name `a` refers to it, like a label tied to a box. Assigning to another name does **not** copy the list; it ties a second label to the **same** box:

```python
a = [1, 2, 3]
b = a            # b refers to the same list as a
b.append(4)
print(a)         # [1, 2, 3, 4]   ← a "changed" too!
```

Two names for one object is called **aliasing**. With strings and numbers it never causes surprises, because they're immutable: nothing can change them in place. With mutable objects like lists, a change through one name is visible through all of them.

## is versus ==

- `a == b` asks: do they have **equal values**?
- `a is b` asks: are they the **same object**?

```python
a = [1, 2, 3]
b = a
c = [1, 2, 3]
print(a == c, a is c)    # True False  (equal values, different lists)
print(a == b, a is b)    # True True   (the same list)
```

`id(x)` shows an object's identity number; `a is b` is the same as `id(a) == id(b)`. Use `is` mainly for `None`: `if result is None:`.

## Making a real copy

```python
a = [1, 2, 3]
b = a.copy()     # or list(a), or a[:]
b.append(4)
print(a)         # [1, 2, 3]   unchanged
print(b)         # [1, 2, 3, 4]
```

## Shallow and deep copies

`copy()` makes a **shallow** copy: a new outer list, but the items inside are the same objects. For a list of lists, the inner lists are still shared:

```python
grid = [[1, 2], [3, 4]]
shallow = grid.copy()
shallow[0].append(99)
print(grid)          # [[1, 2, 99], [3, 4]]   the inner list is shared
```

For a fully independent copy at every level, use a **deep copy**:

```python
import copy
deep = copy.deepcopy(grid)
```

## Functions receive references too

Passing a list to a function passes a reference, so the function can change the caller's list:

```python
def add_bonus(scores):
    for i in range(len(scores)):
        scores[i] += 5

marks = [70, 80]
add_bonus(marks)
print(marks)     # [75, 85]
```

Sometimes that's what you want (and the function's docstring should say so). Usually it's safer for a function to **return a new list** and leave its input alone, so callers aren't surprised.

Reassigning the parameter is different: `scores = [0, 0]` inside the function just points the local name at a new list, and the caller's list is unaffected.

## The [[0] * 3] * 3 trap

Multiplying a list copies **references**, so this "grid" has three references to one row:

```python
grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)      # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]   all rows changed!
```

Build each row separately instead:

```python
grid = []
for _ in range(3):
    grid.append([0] * 3)       # a brand-new row each time
```

(`[0] * 3` itself is fine: numbers are immutable, so sharing them can't cause trouble.)

## Working with grids (matrices)

A list of lists is the usual way to store a table or a matrix. Use two indexes, row first, and nested loops to visit every cell:

```python
matrix = [[1, 2, 3],
          [4, 5, 6]]
for row in matrix:
    for value in row:
        print(value, end=" ")
    print()
rows = len(matrix)         # 2
cols = len(matrix[0])      # 3
```

=== lesson py-list-comprehensions | List comprehensions and sorting | 95
Building a list with a loop and `append` is so common that Python has a compact expression for it: the **list comprehension**.

```python
squares = []
for n in range(1, 6):
    squares.append(n * n)

squares = [n * n for n in range(1, 6)]      # the same, in one line
```

Read it as "**n squared, for each n in range(1, 6)**". The general shape is:

```
[expression for item in iterable]
```

## Filtering with if

Add a condition at the end to keep only some items:

```python
evens = [n for n in range(20) if n % 2 == 0]
long_words = [w for w in words if len(w) > 5]
```

## Transforming with if/else

To **change** items depending on a condition (rather than drop them), put a conditional expression in the expression part:

```python
labels = ["even" if n % 2 == 0 else "odd" for n in range(4)]
# ['even', 'odd', 'even', 'odd']
```

Remember the difference: an `if` at the **end** filters; an `if ... else` at the **start** chooses a value.

## Nested comprehensions

Two `for`s read in the same order as nested loops:

```python
matrix = [[1, 2], [3, 4], [5, 6]]
flat = [x for row in matrix for x in row]          # [1, 2, 3, 4, 5, 6]
grid = [[0] * 3 for _ in range(2)]                 # [[0, 0, 0], [0, 0, 0]], separate rows
table = [[r * c for c in range(1, 4)] for r in range(1, 4)]
```

The middle example is the safe way to build a grid from the last lesson.

## Feeding functions directly

Without the square brackets, the same syntax inside a function call is a **generator expression**: it produces the values one at a time without building a list first.

```python
total = sum(n * n for n in range(1, 101))
any_negative = any(x < 0 for x in data)     # True if at least one is
all_passed = all(s >= 50 for s in scores)   # True if every one is
```

## When not to use one

Comprehensions are for building a collection from another one. If the logic needs several steps, `print`s or `try`, a normal loop is clearer. Readability beats cleverness.

## Sorting with a key

`sorted()` and `list.sort()` accept a `key`: a **function** called on each item to get the value to sort by. You pass the function itself, without calling it:

```python
words = ["banana", "Kiwi", "apple", "fig"]
sorted(words)                    # ['Kiwi', 'apple', 'banana', 'fig']   capitals first
sorted(words, key=str.lower)     # ['apple', 'banana', 'fig', 'Kiwi']
sorted(words, key=len)           # ['fig', 'Kiwi', 'apple', 'banana']
sorted(words, key=len, reverse=True)
```

You can write your own key function:

```python
def last_letter(word):
    return word[-1]

sorted(words, key=last_letter)
```

Python's sort is **stable**: items with equal keys keep their original order. That gives a neat trick for sorting by two things: sort by the *secondary* key first, then by the *primary* key:

```python
by_name = sorted(words)              # alphabetical first...
by_length = sorted(by_name, key=len) # ...then by length; equal lengths stay alphabetical
```

Module 12 shows a shorter way with `lambda`.

=== lesson py-tuples-sets | Tuples and sets | 90
Lists aren't the only collections. Two more are used constantly: **tuples** for fixed groups of values, and **sets** for collections of unique items.

## Tuples: fixed, ordered groups

A tuple is like a list that can't be changed. It's written with parentheses (or just commas):

```python
point = (3, 4)
rgb = (255, 128, 0)
person = ("Ada", 1815, "London")
point[0]           # 3     indexing and slicing work
len(rgb)           # 3
point[0] = 10      # TypeError: 'tuple' object does not support item assignment
```

Use a tuple for a **record**: a fixed number of related values whose positions have meanings (x and y; name, year, city). Use a list for a varying number of **similar** things.

A tuple with one item needs a comma: `(5,)` is a tuple, but `(5)` is just the number 5 in parentheses. `()` is the empty tuple.

## Packing and unpacking

You've been using tuples already: `a, b = 1, 2` **packs** `1, 2` into a tuple and **unpacks** it into two names. It works with any sequence of the right length:

```python
name, year, city = person
x, y = point
first, *rest = [1, 2, 3, 4]     # first = 1, rest = [2, 3, 4]
for name, score in [("Ada", 95), ("Alan", 88)]:
    print(name, score)
```

Functions that `return a, b` are returning a tuple, which is why `low, high = min_max(nums)` works.

Because tuples are immutable, they can be used where Python needs values that never change, such as dictionary keys (next lesson): `distances[("London", "Paris")] = 344`.

## Sets: unique items, no order

A **set** holds each value at most once, in no particular order:

```python
colours = {"red", "green", "blue", "red"}
print(colours)            # {'green', 'red', 'blue'}  (order may vary; duplicates gone)
len(colours)              # 3
"red" in colours          # True, and very fast even for millions of items
empty = set()             # NOT {}  (that's an empty dictionary)
```

Changing a set:

```python
colours.add("yellow")
colours.remove("green")      # KeyError if it isn't there
colours.discard("purple")    # no error if it isn't there
```

Sets can't be indexed (`colours[0]` is a `TypeError`); there's no "first" item. Loop over them, or convert: `sorted(colours)` gives a sorted list.

## Removing duplicates

```python
emails = ["a@x.com", "b@x.com", "a@x.com"]
unique = set(emails)               # {'a@x.com', 'b@x.com'}
has_duplicates = len(set(emails)) != len(emails)
```

`set()` loses the original order. To keep the order of first appearance, remember what you've seen:

```python
seen = set()
unique_in_order = []
for e in emails:
    if e not in seen:
        seen.add(e)
        unique_in_order.append(e)
```

## Set operations

Sets support the operations from maths, with operators:

```python
a = {"Ada", "Alan", "Grace"}
b = {"Grace", "Linus"}
a | b      # union: in either          {'Ada', 'Alan', 'Grace', 'Linus'}
a & b      # intersection: in both     {'Grace'}
a - b      # difference: in a, not b   {'Ada', 'Alan'}
a ^ b      # symmetric difference: in exactly one   {'Ada', 'Alan', 'Linus'}
a <= b     # is a a subset of b?        False
```

These make questions like "which customers bought both products?" one-liners.

## Why is `in` so fast for sets?

A list check `x in items` looks at the items one by one, so it gets slower as the list grows. A set stores items by their **hash** (a number computed from the value), so it can jump straight to where `x` would be. That's also why set items (and dictionary keys) must be **hashable**: immutable values like numbers, strings and tuples. A list can't go in a set.

Set comprehensions work too: `{w.lower() for w in words}`. And `frozenset` is an immutable set, usable as a dictionary key.

=== lesson py-dicts | Dictionaries | 95
A **dictionary** (`dict`) stores **key → value** pairs. Instead of finding things by position, you find them by a meaningful key, like looking up a word in a real dictionary.

```python
ages = {"Ada": 36, "Alan": 41, "Grace": 85}
print(ages["Alan"])      # 41
```

Keys are usually strings or numbers (any hashable value); values can be anything, including lists and other dictionaries.

## Reading values safely

```python
ages["Linus"]                # KeyError: 'Linus'
ages.get("Linus")            # None   (no error)
ages.get("Linus", 0)         # 0      (your own default)
"Ada" in ages                # True   (in checks the KEYS)
36 in ages                   # False  (36 is a value, not a key)
```

## Adding, changing and removing

```python
ages["Linus"] = 54           # adds a new key
ages["Ada"] = 37             # replaces the value of an existing key
del ages["Alan"]             # removes a key (KeyError if missing)
grace = ages.pop("Grace")    # removes and returns the value
ages.update({"Tim": 69, "Ada": 38})   # adds or replaces several at once
```

A key can appear only once: assigning to an existing key overwrites its value.

## Looping over a dictionary

```python
for name in ages:                  # keys
    print(name)
for age in ages.values():          # values
    print(age)
for name, age in ages.items():     # (key, value) pairs
    print(f"{name} is {age}")
```

Since Python 3.7, dictionaries remember the **order in which keys were added**.

## The counting pattern

Counting things is the classic dictionary job:

```python
counts = {}
for word in "the cat and the hat".split():
    counts[word] = counts.get(word, 0) + 1
print(counts)    # {'the': 2, 'cat': 1, 'and': 1, 'hat': 1}
```

`counts.get(word, 0)` reads the current count, or 0 the first time.

## The grouping pattern

A dictionary of lists groups items by some property:

```python
groups = {}
for word in ["apple", "avocado", "banana", "blueberry", "cherry"]:
    first = word[0]
    if first not in groups:
        groups[first] = []
    groups[first].append(word)
# {'a': ['apple', 'avocado'], 'b': ['banana', 'blueberry'], 'c': ['cherry']}
```

(`groups.setdefault(first, []).append(word)` does the same in one line.)

## Dictionary comprehensions

```python
squares = {n: n * n for n in range(1, 5)}      # {1: 1, 2: 4, 3: 9, 4: 16}
lengths = {w: len(w) for w in ["hi", "hello"]}
```

## Nested dictionaries

Real data is often dictionaries inside dictionaries (and lists), exactly the shape of the **JSON** data that web APIs send:

```python
inventory = {
    "apple":  {"price": 0.5, "qty": 120},
    "banana": {"price": 0.25, "qty": 0},
}
inventory["apple"]["qty"]          # 120
for name, item in inventory.items():
    if item["qty"] == 0:
        print(name, "is out of stock")
```

## Sorting a dictionary's items

A dictionary isn't sorted itself, but you can sort its items. Each item is a `(key, value)` tuple, so to sort by value write a small key function:

```python
def by_score(pair):
    return pair[1]

scores = {"Ada": 95, "Alan": 88, "Grace": 99}
ranking = sorted(scores.items(), key=by_score, reverse=True)
# [('Grace', 99), ('Ada', 95), ('Alan', 88)]
```

## Choosing a data structure

| Need | Use |
|---|---|
| items in order, changing over time | `list` |
| a fixed record of a few values | `tuple` |
| unique items, fast "is it in there?" | `set` |
| look up values by a key | `dict` |

=== lesson py-collections-module | The collections module | 90
Python's standard library includes the `collections` module: specialised containers that make common jobs shorter and faster. Import what you need:

```python
from collections import Counter, defaultdict, namedtuple, deque
```

## Counter: counting made easy

```python
from collections import Counter

votes = ["red", "blue", "red", "green", "red", "blue"]
tally = Counter(votes)
print(tally)                    # Counter({'red': 3, 'blue': 2, 'green': 1})
tally["red"]                    # 3
tally["purple"]                 # 0   (no KeyError for missing items)
tally.most_common(2)            # [('red', 3), ('blue', 2)]
Counter("mississippi")          # counts letters
```

A `Counter` is a dictionary with superpowers: counters can be added (`c1 + c2`), updated with more items (`tally.update(["red"])`), and asked for the top items.

## defaultdict: no more "if key not in"

A `defaultdict` creates a value automatically the first time a missing key is used. You give it a function that makes the default:

```python
from collections import defaultdict

groups = defaultdict(list)        # missing keys start as []
for word in ["apple", "avocado", "banana"]:
    groups[word[0]].append(word)
# defaultdict(<class 'list'>, {'a': ['apple', 'avocado'], 'b': ['banana']})

totals = defaultdict(int)         # missing keys start as 0
for item, amount in [("tea", 3), ("cake", 5), ("tea", 2)]:
    totals[item] += amount
```

Pass the function itself: `list`, not `list()`. Convert back with `dict(groups)` if you need a plain dictionary.

## namedtuple: tuples with field names

```python
from collections import namedtuple

Point = namedtuple("Point", ["x", "y"])
p = Point(3, 4)
p.x, p.y          # 3 4   (much clearer than p[0], p[1])
x, y = p          # still unpacks like a tuple
p._replace(x=10)  # a new Point(x=10, y=4)
```

Great for small, fixed records. (Module 9's **dataclasses** are the more flexible modern option.)

## deque: a fast double-ended queue

A list is fast at the end but slow at the **front**: `items.pop(0)` and `items.insert(0, x)` shift every other item. A `deque` ("deck") is fast at both ends:

```python
from collections import deque

queue = deque(["Ada", "Alan"])
queue.append("Grace")        # join at the back
first = queue.popleft()      # serve from the front: 'Ada'
queue.appendleft("VIP")      # jump the queue

recent = deque(maxlen=3)     # keeps only the last 3 items
for page in ["home", "about", "blog", "contact"]:
    recent.append(page)
print(list(recent))          # ['about', 'blog', 'contact']
```

Use a deque for queues (first in, first out), "the last N things", and breadth-first search (algorithms track).

## Choosing well

| Task | Tool |
|---|---|
| count how often things occur | `Counter` |
| group or total by key | `defaultdict(list)` / `defaultdict(int)` |
| a small record with named fields | `namedtuple` (or a dataclass) |
| a queue, or the last N items | `deque` |

Picking the right data structure is one of the most valuable skills in programming: good structures make the code simple, and the code obviously correct.

**Anagrams** are words with the same letters in a different order (`listen`, `silent`). Write `group_anagrams(words)` that groups them with a `defaultdict(list)` keyed by each word's sorted letters. Return the groups as a list of lists, each group in its original word order, and the groups in the order their first word appeared.
::starter
from collections import defaultdict

def group_anagrams(words):
    pass
::solution
from collections import defaultdict

def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        key = "".join(sorted(w))
        groups[key].append(w)
    return list(groups.values())
::tests
assert group_anagrams(["listen", "google", "silent", "enlist", "gogole", "cat"]) == [["listen", "silent", "enlist"], ["google", "gogole"], ["cat"]]
assert group_anagrams([]) == []
assert group_anagrams(["ab", "ba", "ab"]) == [["ab", "ba", "ab"]]
::hints
- `sorted("listen")` is a list of letters; `"".join(...)` turns it into the key `"eilnst"`.
- Dictionaries keep insertion order, so `list(groups.values())` is already in first-appearance order.

::solution
from collections import deque, namedtuple
import math

Point = namedtuple("Point", ["x", "y"])

def last_lines(lines, n):
    return list(deque(lines, maxlen=n))


def distance(p, q):
    return math.sqrt((q.x - p.x) ** 2 + (q.y - p.y) ** 2)

::prompt
Write `merge_stock(a, b)` that merges two inventory dictionaries (product → quantity) into a **new** dictionary, adding quantities for products that appear in both. Leave both inputs unchanged.
::starter
def merge_stock(a, b):
    pass
::solution
def merge_stock(a, b):
    merged = dict(a)
    for product, qty in b.items():
        merged[product] = merged.get(product, 0) + qty
    return merged
::tests
x = {"apple": 3, "pear": 2}
y = {"pear": 5, "fig": 1}
assert merge_stock(x, y) == {"apple": 3, "pear": 7, "fig": 1}
assert x == {"apple": 3, "pear": 2} and y == {"pear": 5, "fig": 1}, "inputs must not change"
assert merge_stock({}, {}) == {}
assert merge_stock({"a": 1}, {}) == {"a": 1}
::hints
- Start from a copy: `dict(a)` or `a.copy()`.
- Add each of `b`'s quantities with the `.get(product, 0)` pattern.

::prompt
Write `matrix_summary(matrix)` for a non-empty rectangular list of lists of numbers. Return a dictionary with:

- `"rows"`: a list of each row's sum;
- `"cols"`: a list of each column's sum;
- `"total"`: the sum of everything;
- `"max"`: the largest value.
::starter
def matrix_summary(matrix):
    pass
::solution
def matrix_summary(matrix):
    rows = [sum(row) for row in matrix]
    cols = [sum(row[c] for row in matrix) for c in range(len(matrix[0]))]
    return {"rows": rows, "cols": cols, "total": sum(rows), "max": max(max(row) for row in matrix)}
::tests
m = [[1, 2, 3], [4, 5, 6]]
assert matrix_summary(m) == {"rows": [6, 15], "cols": [5, 7, 9], "total": 21, "max": 6}
assert matrix_summary([[7]]) == {"rows": [7], "cols": [7], "total": 7, "max": 7}
assert matrix_summary([[-1, -2], [-3, -4]])["max"] == -1
::hints
- Row sums: `[sum(row) for row in matrix]`.
- Column `c`'s sum adds `row[c]` from every row.
- The overall maximum is the largest of the rows' maximums.

::prompt
`records` is a list of `(name, score)` tuples. Write `top_students(records, n)` that returns the **names** of the `n` best students: highest score first, and students with equal scores in alphabetical order.
::starter
def top_students(records, n):
    pass
::solution
def score_of(record):
    return record[1]


def top_students(records, n):
    by_name = sorted(records)
    ranked = sorted(by_name, key=score_of, reverse=True)
    return [name for name, score in ranked[:n]]
::tests
data = [("Ada", 91), ("Linus", 78), ("Grace", 97), ("Alan", 91), ("Tim", 85)]
assert top_students(data, 3) == ["Grace", "Ada", "Alan"]
assert top_students(data, 1) == ["Grace"]
assert top_students(data, 10) == ["Grace", "Ada", "Alan", "Tim", "Linus"]
assert top_students([], 2) == []
::hints
- Sort by name first (`sorted(records)` sorts tuples by their first item).
- Then sort that by score with a key function returning `record[1]`, `reverse=True`. Stability keeps equal scores alphabetical.
- Finally take the first `n` and keep just the names.
