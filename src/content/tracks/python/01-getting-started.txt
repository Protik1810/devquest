## What is a program?

A **program** is a list of instructions for a computer, written precisely enough that there is no room for guessing. A recipe can say "add a pinch of salt"; a computer needs "add 0.5 grams of salt". Learning to program is mostly learning to describe what you want *that* precisely, and then letting the machine repeat it a million times without getting bored.

**Python** is a programming language designed to be easy to read. It runs website backends (Instagram, Spotify), data science and AI, scientific research, and countless scripts that automate boring tasks. The program that reads your Python code and carries it out is the **Python interpreter**. In DevQuest the interpreter runs inside the app (it is the real CPython, compiled to WebAssembly), so there is nothing to install.

## print(): making the computer say something

```python
print("Hello, World!")
```

- `print` is a **function**: a named action Python already knows how to do.
- The parentheses **call** the function. What goes inside them is the **argument**: here, what to print.
- `"Hello, World!"` is a **string**: a piece of text. The quotes mark where the text starts and ends; they are not printed.

Single quotes work too. That's handy when the text itself contains a quote:

```python
print('She said "hi"')
print("It's raining")
```

## Several values in one print

Give `print` several arguments separated by commas, and it prints them **separated by one space**:

```python
print("I am", 12, "years old")    # I am 12 years old
```

Numbers don't need quotes. `12` is a number; `"12"` is text that happens to contain digits. You'll see why that difference matters in a few lessons.

`print` also has two optional settings, called **keyword arguments**:

| Setting | Default | What it controls |
|---|---|---|
| `sep=` | `" "` (one space) | what goes **between** the values |
| `end=` | `"\n"` (a new line) | what goes **after** the last value |

```python
print("2026", "10", "14", sep="-")   # 2026-10-14
print("Loading", end="...")
print("done")                        # Loading...done
print()                              # just an empty line
```

`\n` is how you write "start a new line" inside a string. Because `end` is normally `"\n"`, each `print` starts a fresh line; change `end` and the next print continues on the same line.

## Comments

Everything after a `#` on a line is a **comment**. Python ignores it; it's there for the humans reading the code (including future you).

```python
# Greet the user. This whole line is a comment.
print("Welcome!")  # a comment can also follow code
```

Good comments explain **why**, not what. `# prices are stored in cents to avoid rounding errors` helps a reader; `# print welcome` just repeats the code.

## How Python runs your file

Python runs a program **from top to bottom, one line at a time**. Each line is normally one **statement** (one instruction), so this always prints first, second, third, in that order:

```python
print("first")
print("second")
print("third")
```

Python is **case-sensitive**: `print` works, but `Print` and `PRINT` are different names that Python doesn't know. It is also strict about punctuation: every `(` needs its `)`, and every string needs a closing quote of the same kind.

## Common beginner mistakes

- **Forgetting the quotes**: `print(Hello)` makes Python look for something *named* `Hello`, which doesn't exist.
- **Curly "smart" quotes** copied from a word processor (`“Hello”`) aren't valid Python. Use the plain `"` or `'` keys.
- **Mismatched quotes**: `"Hello'` starts with one kind and ends with the other.
- **A missing parenthesis**: `print("Hi"`.

Each of these produces an error message. Reading them is the topic of the next lesson.

> 💡 **How to study code**: type the examples yourself instead of pasting them. Change something, *predict* what will happen, then run it. Being wrong about a prediction is the fastest way to learn.

=== lesson py-reading-errors | Reading error messages | 60
Everybody's code breaks, constantly, including professionals'. What separates a beginner from an experienced developer isn't fewer errors; it's that the experienced one **reads** the error message, because it says *what* went wrong and *where*.

## Two kinds of errors

1. **Syntax errors.** The code isn't valid Python, like a sentence with missing punctuation. Python checks the whole file before running it, so with a syntax error **nothing runs at all**.
2. **Runtime errors**, also called **exceptions**. The code is valid, but something goes wrong while it runs, such as dividing by zero. Everything *before* the failing line has already happened; the program stops at that line.

## Anatomy of a traceback

When a program crashes, Python prints a **traceback**:

```
Traceback (most recent call last):
  File "main.py", line 3, in <module>
    print("Total: " + 5)
          ~~~~~~~~~~^~~
TypeError: can only concatenate str (not "int") to str
```

Read it **from the bottom up**:

1. **The last line** names the error **type** (`TypeError`) and gives a **message** explaining it. Start here.
2. **The line above** shows the code that failed, with `^` and `~` marks under the exact part that caused it.
3. **`File "main.py", line 3`** says where. In DevQuest your program's file is called `<exec>`.

~~~check

+ None: Python checks the whole file first and refuses to run any of it
- Only line 1
- Lines 1–4 run, then it stops
> Syntax errors are found before anything runs. Runtime errors, by contrast, stop the program at the failing line, after the earlier lines have run.
~~~

## The errors you'll meet most

| Error | Usual cause | Example |
|---|---|---|
| `SyntaxError` | a missing `)` or quote, a misspelled keyword, a stray character | `print("hi"` |
| `IndentationError` | spaces at the start of a line where none belong (or missing where needed) | ` print("hi")` |
| `NameError` | a name Python doesn't know: a typo, a variable used before it's created, or text without quotes | `pritn("hi")`, `print(hello)` |
| `TypeError` | an operation on the wrong kind of value | `"Age: " + 30` |
| `ValueError` | the right type of value, but an unusable one | `int("ten")` |
| `ZeroDivisionError` | dividing by zero | `10 / 0` |

Modern Python often suggests the fix for you:

```
NameError: name 'pritn' is not defined. Did you mean: 'print'?
```

## A debugging routine that works

1. Read the **last line**. What type of error? What does the message say?
2. Go to the **line number**. Look at that line *and the line above it*: a missing `)` on line 2 is often only noticed on line 3.
3. Make a guess about the cause, change **one thing**, and run again.
4. Still stuck? Explain the code out loud, line by line, as if to a rubber duck. You'll often *hear* the mistake as you describe what the line is supposed to do. (Programmers really do call this **rubber duck debugging**.)

> 💡 If you get several errors, they're rarely several problems. Fix the **first** one and run again; the rest often disappear with it.

DevQuest's checks work the same way: when you submit and a check fails, you see what was expected and what your program produced. Compare them calmly, line by line.

=== lesson py-vars | Variables & assignment | 70
## Giving values a name

Programs need to remember things: a score, a user's name, a price. A **variable** is a **name** that refers to a **value**.

```python
score = 0
player = "Ada"
print(player, "has", score, "points")    # Ada has 0 points
```

Picture a variable as a **name tag** stuck onto a value. `score = 0` means "put the tag `score` on the value 0". Afterwards, writing `score` gives you whatever value that tag is currently on.

## = means "assign", not "equals"

In maths, `x = x + 1` is nonsense. In Python it's an **instruction** carried out in two steps:

1. Work out the **right-hand side** first, using the *current* values (`x + 1`).
2. Then make the name on the **left** refer to the result.

```python
x = 5
x = x + 1     # right side: 5 + 1 is 6; then x refers to 6
print(x)      # 6
```

Updating a variable based on its own value is so common that it has a shortcut: `x += 1` means `x = x + 1`. The same works for other operators: `-=`, `*=`, `/=`.

Assignment takes the value at that moment; it doesn't create a permanent link. Changing `x` later does **not** change `y`:

```python
x = 10
y = x       # y refers to 10
x = 20      # x now refers to 20; y still refers to 10
print(y)    # 10
```

## Tracing: be the computer

The single most useful skill for a beginner is **tracing**: walking through the code line by line and writing down every variable's value after each line.

```python
a = 3
b = a * 2
a = a + b
b = b - 1
```

| After line | a | b |
|---|---|---|
| 1 | 3 | (doesn't exist yet) |
| 2 | 3 | 6 |
| 3 | 9 | 6 |
| 4 | 9 | 5 |

Whenever code surprises you, trace it on paper. Most "mysterious" bugs turn out to be a variable holding a different value than you assumed.

## Naming rules, and good names

- Use letters, digits and underscores only, and **don't start with a digit**: `player2` is fine, `2player` is not.
- Names are **case-sensitive**: `Score` and `score` are two different variables.
- You can't use a **keyword** (a word reserved by Python), such as `if`, `for`, `class`, `True` or `None`.
- Python's style guide (**PEP 8**) recommends lowercase words joined by underscores, called **snake_case**: `total_price`, `user_name`.
- Values meant never to change (**constants**) are written in CAPITALS: `MAX_LIVES = 3`. Python doesn't enforce this; it's a signal to other programmers.
- Choose names that say what the value *means*. `seconds_per_day = 86400` explains itself; `x = 86400` doesn't.

## Handy assignment forms

```python
a, b = 1, 2       # assign two names at once
a, b = b, a       # swap: now a is 2 and b is 1
x = y = 0         # both names refer to 0
```

The swap works because Python evaluates the *whole* right side (`b, a`) before assigning anything. In many other languages you'd need a temporary variable: `temp = a`, `a = b`, `b = temp`.

## Variables don't have types; values do

The same name can refer to a number now and some text later. Python is **dynamically typed**:

```python
thing = 42
thing = "forty-two"   # allowed, though usually confusing
print(type(thing))    # <class 'str'>
```

`type()` tells you what type a value is. The next lesson covers types properly.

## Common mistakes

- Using a variable before giving it a value: `NameError`.
- Writing it backwards, `5 = x`: the name must be on the left (`SyntaxError`).
- Expecting `y = x` to keep `y` "linked" to `x` forever.

=== lesson py-types | Types, conversions & input() | 75
## Every value has a type

A value's **type** decides what it is and what you can do with it. These are the basic ones:

| Type | What it is | Examples |
|---|---|---|
| `int` | an integer (whole number) | `0`, `42`, `-7`, `1_000_000` |
| `float` | a number with a fractional part | `3.14`, `-0.5`, `2.0`, `1e6` |
| `str` | a string (text) | `"hi"`, `'42'`, `""` (the empty string) |
| `bool` | a truth value | `True`, `False` |
| `NoneType` | "no value here" | `None` |

```python
print(type(42))      # <class 'int'>
print(type(4.2))     # <class 'float'>
print(type("42"))    # <class 'str'>
print(type(True))    # <class 'bool'>
```

Underscores inside numbers are only there to help you read them: `1_000_000` is one million. `2.0` is a float even though it's a whole number, and `1e6` means 1 × 10⁶ (also a float).

## Same digits, different meaning

```python
print(5 + 3)        # 8      numbers add
print("5" + "3")    # 53     strings join end to end ("concatenation")
print("5" * 3)      # 555    a string repeated 3 times
```

This difference causes a huge share of beginner bugs, so always ask yourself: *is this a number or text?*

## Converting between types

Use the type's name like a function:

```python
int("42")       # 42
float("3.5")    # 3.5
str(99)         # '99'
int(3.99)       # 3    (drops the fraction; it does NOT round)
float(7)        # 7.0
```

A conversion that makes no sense raises a `ValueError`:

```python
int("ten")      # ValueError: invalid literal for int() with base 10: 'ten'
int("3.5")      # ValueError too; use float("3.5") instead
```

## True, False and "truthiness"

`bool()` turns any value into `True` or `False`. These values are **falsy** (count as False): `0`, `0.0`, `""` (empty string), `None`, and empty collections you'll meet later. Nearly everything else is **truthy**:

```python
print(bool(0), bool(""), bool(None))    # False False False
print(bool(7), bool("0"), bool(" "))    # True True True
```

Note that `"0"` and `" "` are truthy: they're non-empty strings. This becomes important with `if` statements in Module 3.

## None

`None` means "nothing" or "no value yet". It isn't 0 and it isn't an empty string; it's its own thing. You'll see it when a function has nothing to return.

## Reading what the user types: input()

`input()` pauses the program, waits for the user to type a line and press Enter, and **returns that line as a string**:

```python
name = input("What is your name? ")
print("Nice to meet you,", name)
```

The text inside `input(...)` is the **prompt** shown to the user. The space at the end of it stops the answer touching the question.

Because `input()` always returns a **string**, convert it before doing maths with it:

```python
age = input("Age? ")         # the user types 30, and age is "30", a string
print(age + 1)               # TypeError: can only concatenate str (not "int") to str

age = int(input("Age? "))    # now age is 30, an int
print(age + 1)               # 31
```

Read `int(input("Age? "))` from the inside out: show the prompt and get the text, then convert that text to an int.

> ⌨️ **In DevQuest**, exercises that use `input()` type their lines in for you; they're shown above the editor. The output shows each prompt followed by what was typed, just like a terminal does.

## Common mistakes

- Forgetting to convert `input()` before arithmetic (a `TypeError`).

=== lesson py-math | Numbers & arithmetic | 75
## The arithmetic operators

| Operator | Meaning | Example | Result |
|---|---|---|---|
| `+` `-` `*` | add, subtract, multiply | `7 * 3` | `21` |
| `/` | division (always gives a float) | `7 / 2` and `6 / 3` | `3.5` and `2.0` |
| `//` | floor division (divide, then round down) | `7 // 2` | `3` |
| `%` | modulo: the remainder after dividing | `7 % 2` | `1` |
| `**` | to the power of | `2 ** 10` | `1024` |

`//` and `%` work as a pair: `//` tells you how many times something fits, `%` what's left over. They solve many everyday problems:

- **Even or odd?** `n % 2` is `0` for even numbers and `1` for odd ones.
- **Last digit:** `1234 % 10` is `4`. **Remove the last digit:** `1234 // 10` is `123`.
- **Splitting units:** 135 minutes is `135 // 60` = 2 hours and `135 % 60` = 15 minutes.
- **Wrapping around**, like a clock: 5 hours after 10 o'clock is `(10 + 5) % 12` = 3 o'clock.
- `divmod(135, 60)` gives both at once: `(2, 15)`.

## Order of operations

Python follows the usual maths rules: parentheses first, then `**`, then `*`, `/`, `//` and `%` (left to right), then `+` and `-` (left to right).

```python
print(2 + 3 * 4)      # 14
print((2 + 3) * 4)    # 20
print(2 ** 3 ** 2)    # 512, because ** groups from the right: 3 ** 2 first
print(-2 ** 2)        # -4, because the power happens before the minus sign
```

When in doubt, add parentheses. They cost nothing and make your intent obvious to the reader.

~~~check
? What is `100 // 7` and `100 % 7`?
- `14.28` and `2`
+ `14` and `2`
- `14` and `14`
- `15` and `5`
> 7 fits into 100 fourteen times (98), with 2 left over.
~~~

## Negative numbers with // and %

`//` always rounds **down** (towards minus infinity), not towards zero, and the result of `%` takes the sign of the number you divide by:

```python
print(-7 // 2)    # -4, not -3
print(-7 % 2)     # 1
```

## Integers are exact; floats are approximations

Python's integers are exact and can be as large as you like: `2 ** 100` is no problem. Floats are stored in binary with about 15–17 significant digits, so most decimal fractions are stored *approximately*:

```python
print(0.1 + 0.2)           # 0.30000000000000004
print(0.1 + 0.2 == 0.3)    # False
```

This isn't a Python bug. Almost every computer stores fractions this way (the IEEE 754 standard), just as 1/3 can't be written exactly in decimal. What it means for you:

- Don't compare floats with `==`. Use `math.isclose(a, b)`.
- For money, count **whole cents** with integers, or use the `decimal` module.
- Mixing an int and a float gives a float: `3 + 2.0` is `5.0`.

## Rounding

```python
round(3.14159, 2)    # 3.14
round(3.5)           # 4
round(2.5)           # 2    (!)
```

`round()` uses **banker's rounding**: a value exactly halfway goes to the nearest **even** number. Over many values, that avoids always nudging totals upward.

## Built-in helpers and the math module

```python
abs(-5)          # 5
min(3, 9, 1)     # 1
max(3, 9, 1)     # 9

import math
math.sqrt(16)    # 4.0
math.floor(3.7)  # 3   (round down)
math.ceil(3.2)   # 4   (round up)
math.pi          # 3.141592653589793
```

`import math` loads Python's maths **module**: a library of extra tools that ships with Python. Module 11 covers modules properly.

## A peek at other number systems

Computers store numbers in **binary** (base 2). Python can write and read other bases:

```python
bin(10)          # '0b1010'
hex(255)         # '0xff'
int("ff", 16)    # 255
0b1010           # 10, written directly in binary
```

**Bitwise operators** work on those binary digits: `&` (and), `|` (or), `^` (exclusive or), `~` (not), and `<<`, `>>` (shift left and right). For example, `6 & 3` is `2` because `110 & 011` = `010`. You'll rarely need them at first, but they appear in certification exams (such as PCEP) and in low-level code.
