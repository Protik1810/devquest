=== lesson py-modules | Modules, packages and the standard library | 100
## Why split code into modules?

A real program can have thousands of lines. Keeping them all in one file would be like writing a book as one endless paragraph. A **module** is simply a `.py` file whose functions, classes and variables other files can **import**. Modules let you organise code by topic, reuse it across projects, and work on one part without wading through the rest.

Python also comes with a huge **standard library**, hundreds of modules for maths, files, dates, JSON, web requests, compression, testing and more. That's what people mean by Python having "batteries included".

## Importing

```python
import math                       # the whole module; use its contents with a dot
print(math.sqrt(16))

from math import sqrt, pi         # specific names, used without the prefix
print(sqrt(16), pi)

import statistics as stats        # a shorter alias
print(stats.mean([2, 4, 9]))

from collections import Counter as Tally   # an alias for one name
```

Prefer `import module` or importing specific names. Avoid `from module import *`: it dumps every name into your file, so readers can't tell where anything came from, and names can silently clash.

## Randomness you can test

Random numbers make programs unpredictable, and tests need predictability. Two techniques:

- `random.seed(42)` makes the sequence repeat exactly on every run (on the same Python version).
- Better: use your own generator object, `rng = random.Random(42)`, and **pass it in** to the functions that need randomness (dependency injection again). Tests pass a seeded generator; the real program passes an unseeded one.

```python
import random

def roll(n, rng):
    return [rng.randint(1, 6) for _ in range(n)]

roll(3, random.Random(1)) == roll(3, random.Random(1))    # True: same seed, same rolls
```

## Writing your own module

Any `.py` file is a module. If `geometry.py` contains

```python
PI = 3.14159

def circle_area(r):
    return PI * r * r
```

then another file in the same folder can do `import geometry` and call `geometry.circle_area(2)`. The first `import` runs the module's code once and caches the module in `sys.modules`; later imports reuse it.

## if __name__ == "__main__":

Every module has a `__name__` variable. When a file is **run directly** (`python geometry.py`), its `__name__` is `"__main__"`; when it's **imported**, `__name__` is the module's name (`"geometry"`). So this idiom runs code only when the file is the main program:

```python
def main():
    print(circle_area(2))

if __name__ == "__main__":
    main()          # runs for  python geometry.py,  but not on  import geometry
```

It lets one file be both a reusable module and a runnable script, and it stops imports from accidentally running a program's main code. DevQuest runs your code as `__main__`, just like `python file.py`.

## Packages: folders of modules

A **package** is a folder of modules, usually with an `__init__.py` file:

```
shop/
    __init__.py
    cart.py
    payments/
        __init__.py
        card.py
```

You import with dots: `from shop.cart import Cart`, `import shop.payments.card`. `__init__.py` runs when the package is first imported and can expose the package's main names.

## Public names, private names and __all__

A module's names are all importable, but conventions say what's public:

- Names starting with an underscore (`_helper`) are **internal** to the module. `from module import *` skips them, and readers know not to rely on them.
- A module can list its public names explicitly: `__all__ = ["parse", "Report"]`. Then `from module import *` imports exactly those, and tools and documentation treat them as the module's API.

Inside a package, modules can import each other with **relative imports**: `from .cart import Cart` (same package) or `from ..utils import slugify` (the parent package). Relative imports only work inside packages, not in a script run directly.

Python also caches the compiled form of imported modules in `__pycache__` folders (`.pyc` files), so the next import starts faster. You can safely delete them, and they belong in `.gitignore`.

The `platform` module describes the machine a program runs on: `platform.system()` (for example `'Windows'`, `'Linux'`, `'Darwin'` for macOS), `platform.python_version()`, `platform.machine()`.

## Where does Python find modules?

`import x` searches the folders listed in `sys.path`: the folder of the script you're running first, then the standard library, then **site-packages**, where installed third-party packages live. One consequence catches many beginners: **don't name your own file after a module you use**. A file called `random.py` in your folder hides the real `random` module, and `random.randint` suddenly "doesn't exist".

## Third-party packages

Beyond the standard library, the **Python Package Index** (PyPI, pypi.org) hosts over half a million packages: `requests` for HTTP, `pandas` for data, `pytest` for testing, `fastapi` and `django` for web apps. You install them with `pip`, ideally inside a **virtual environment**; Module 12 shows the professional setup.

=== lesson py-files | Files and paths | 100
Programs need to **persist** data beyond a single run: settings, notes, reports, logs. The simplest way is files.

> 💾 In DevQuest, your programs have a private, temporary disk: files you create exist only while the app is open. The code is exactly what you'd write on your own computer.

## Opening, reading and writing

```python
with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("first line\n")
    f.write("second line\n")

with open("notes.txt", encoding="utf-8") as f:     # "r" (read) is the default mode
    text = f.read()
print(text)
```

- `open()` returns a **file object**; `with` closes it automatically when the block ends, even if an exception happens (it's a context manager, Module 10). Always use `with`.
- `write()` doesn't add a newline; include `"\n"` yourself. `print(..., file=f)` is an alternative that adds it.
- **Always pass `encoding="utf-8"`.** Without it, Python uses the operating system's default, which differs between Windows and other systems, and text with accents or emoji can break.

## File modes

| Mode | Meaning |
|---|---|
| `"r"` | read (the default); `FileNotFoundError` if it doesn't exist |
| `"w"` | write: creates the file, or **erases** an existing one |
| `"a"` | append: add to the end, creating it if needed |
| `"x"` | create: fails with `FileExistsError` if it already exists |
| `"b"` | added to the others for **binary** data: `"rb"`, `"wb"` |

Beware: opening with `"w"` instantly empties the file, before you've written anything.

## Reading in different ways

```python
with open("notes.txt", encoding="utf-8") as f:
    for line in f:                    # best for big files: one line at a time
        print(line.rstrip("\n"))      # each line still ends with "\n"

with open("notes.txt", encoding="utf-8") as f:
    lines = f.read().splitlines()     # all lines, newlines removed
```

`f.readline()` reads a single line and `f.readlines()` a list of lines (with their `\n`). Looping over the file is memory-friendly: a 10 GB log file can be processed line by line.

## pathlib: paths as objects

The modern way to work with paths is `pathlib.Path`:

```python
from pathlib import Path

folder = Path("reports")
folder.mkdir(exist_ok=True)                   # create the folder (no error if it exists)
path = folder / "2026" / "october.txt"        # the / operator joins path parts
path.parent.mkdir(parents=True, exist_ok=True)
path.write_text("Sales: 42\n", encoding="utf-8")
print(path.read_text(encoding="utf-8"))
print(path.name, path.stem, path.suffix)      # october.txt october .txt
print(path.exists(), path.is_file())          # True True
for p in folder.rglob("*.txt"):               # every .txt file in all subfolders
    print(p)
```

`Path` objects work on Windows, macOS and Linux alike, handling `\` versus `/` for you. `open(path)` accepts them too.

## Errors you should expect

Files fail in the real world: the file doesn't exist (`FileNotFoundError`), you're not allowed to read it (`PermissionError`), the disk is full. These are all `OSError`s. Handle the ones you can do something about:

```python
try:
    text = Path("config.txt").read_text(encoding="utf-8")
except FileNotFoundError:
    text = ""            # no config yet: use defaults
```

## Text and bytes

Files on disk hold **bytes**. Text mode decodes them to `str` using an encoding (UTF-8); binary mode (`"rb"`) gives raw `bytes`, for images, zip files and other non-text data. You can convert yourself:

```python
data = "héllo".encode("utf-8")     # b'h\xc3\xa9llo'  (é takes two bytes in UTF-8)
text = data.decode("utf-8")        # 'héllo'
```

A `UnicodeDecodeError` means the bytes weren't in the encoding you claimed.

## Other useful tools

- `os.listdir(folder)`, `os.remove(path)`, `os.rename(a, b)`, or the `Path` methods `iterdir()`, `unlink()`, `rename()`.
- `shutil.copy(src, dst)` copies a file; `shutil.rmtree(folder)` deletes a folder tree (carefully!).
- `tempfile.TemporaryDirectory()` gives a scratch folder that's deleted afterwards, perfect for tests.

from pathlib import Path


def files_by_extension(folder):
    groups = {}
    for p in Path(folder).iterdir():
        if p.is_file():
            ext = p.suffix.lower().lstrip(".")
            groups.setdefault(ext, []).append(p.name)
    return {ext: sorted(names) for ext, names in groups.items()}

=== lesson py-json-csv | JSON and CSV | 100
Two text formats carry most of the world's everyday data: **JSON**, used by almost every web API and many config files, and **CSV**, the universal format of spreadsheets. Python's standard library handles both.

## JSON: data as text

JSON (JavaScript Object Notation) looks almost exactly like Python dictionaries and lists:

```json
{"name": "Ada", "languages": ["Python", "C"], "active": true, "manager": null}
```

The `json` module converts between JSON text and Python objects:

```python
import json

user = {"name": "Ada", "languages": ["Python", "C"], "active": True, "manager": None}
text = json.dumps(user)                  # Python → JSON text ("dump to string")
back = json.loads(text)                  # JSON text → Python ("load from string")
pretty = json.dumps(user, indent=2, sort_keys=True)   # human-friendly

with open("user.json", "w", encoding="utf-8") as f:
    json.dump(user, f, indent=2)         # straight to a file
with open("user.json", encoding="utf-8") as f:
    user = json.load(f)
```

How types map:

| JSON | Python |
|---|---|
| object `{}` | `dict` (keys are always strings) |
| array `[]` | `list` (tuples become lists) |
| string | `str` |
| number | `int` or `float` |
| `true` / `false` | `True` / `False` |
| `null` | `None` |

Two surprises: JSON object keys are **always strings** (`{1: "a"}` comes back as `{"1": "a"}`), and sets, dates and your own objects **can't** be converted automatically (`TypeError: Object of type ... is not JSON serializable`). Convert them to plain data first, for example with a `to_dict()` method or `dataclasses.asdict()`.

Invalid JSON raises `json.JSONDecodeError`, a subclass of `ValueError`, which tells you the line and column of the problem.

- `{"tags": "ab"}`

## CSV: rows and columns

A CSV (comma-separated values) file is a table in plain text:

```
name,department,salary
Ada,Engineering,72000
"Hopper, Grace",Navy,65000
```

Values containing commas are wrapped in quotes, which is why you should **never** parse CSV with `line.split(",")`: use the `csv` module, which handles quoting, escaping and line endings correctly.

```python
import csv

with open("staff.csv", newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):          # each row is a dict keyed by the header
        print(row["name"], int(row["salary"]))
```

- Open CSV files with `newline=""` so the module controls line endings.
- Everything comes back as **strings**: convert numbers yourself.
- `csv.reader` gives lists instead of dicts; `csv.writer` / `csv.DictWriter` write files:

```python
rows = [{"name": "Ada", "score": 95}, {"name": "Alan", "score": 88}]
with open("scores.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["name", "score"])
    writer.writeheader()
    writer.writerows(rows)
```

## Files in memory: io.StringIO

`io.StringIO` is a file-like object that lives in memory. Anything that reads or writes files works with it, which is handy for tests and for CSV/JSON text you already have as a string:

```python
import csv, io

text = "name,score\nAda,95\nAlan,88\n"
rows = list(csv.DictReader(io.StringIO(text)))
```

That's duck typing at work: `csv` only needs something with the methods of a file.

=== lesson py-binary-formats | Bytes, binary files and other data formats | 100
Not all data is text. Images, audio, zip files and network packets are **binary**: raw bytes with no characters. This lesson covers working with bytes, and three more data formats you'll meet: pickle, INI configuration files and XML.

## bytes and bytearray

A `bytes` object is an immutable sequence of numbers from 0 to 255:

```python
data = b"Hi!"                 # a bytes literal: ASCII characters only
data[0]                       # 72: indexing gives an int, not a character
list(data)                    # [72, 105, 33]
data.hex()                    # '486921'
bytes.fromhex("48 69")        # b'Hi'
"héllo".encode("utf-8")       # b'h\xc3\xa9llo'  (text → bytes)
b'h\xc3\xa9llo'.decode()      # 'héllo'          (bytes → text)
```

`bytearray` is the **mutable** version, useful as a buffer you fill in place: `buf = bytearray(4)` then `buf[0] = 255`.

## Binary files

Open files in binary mode with `"rb"` / `"wb"`; you read and write `bytes`, with no encoding involved. Large files are read in **chunks**:

```python
import hashlib

def sha256_of(path):
    digest = hashlib.sha256()
    with open(path, "rb") as f:
        while chunk := f.read(65536):       # 64 KB at a time
            digest.update(chunk)
    return digest.hexdigest()
```

That's how download sites let you check a file's integrity.

## Recognising files by their first bytes

Most file formats begin with a fixed **signature** (a "magic number"): PNG images start with `b"\x89PNG"`, PDFs with `b"%PDF"`, ZIP files (and .docx, .xlsx, .jar) with `b"PK\x03\x04"`, JPEGs with `b"\xff\xd8\xff"`. Checking the signature is more reliable than trusting a file's name.

## Packing binary records with struct

`struct` converts between Python numbers and fixed-size binary layouts, as used by file formats and network protocols:

```python
import struct
record = struct.pack("<Hh", 7, -125)       # little-endian: unsigned short, signed short
record                                     # b'\x07\x00\x83\xff'  (4 bytes)
struct.unpack("<Hh", record)               # (7, -125)
struct.calcsize("<Hh")                     # 4
```

Format letters: `b`/`B` 1-byte signed/unsigned, `h`/`H` 2-byte, `i`/`I` 4-byte, `q`/`Q` 8-byte, `f`/`d` floats; `<` means little-endian (most PCs), `>` big-endian (network order).

## base64: bytes as safe text

To put binary data where only text fits (JSON, emails, URLs), encode it as **base64**: `base64.b64encode(b"\x00\xff")` gives `b'AP8='`; `b64decode` reverses it. It's an encoding, **not** encryption: anyone can decode it.

## pickle: Python objects as bytes, with a warning

`pickle` can save almost any Python object, including your own classes:

```python
import pickle
blob = pickle.dumps({"scores": [1, 2, 3]})
pickle.loads(blob)                          # {'scores': [1, 2, 3]}
```

⚠️ **Never unpickle data you don't trust.** A crafted pickle can run any code when loaded. Use pickle only for your own program's private caches; use JSON to exchange data.

## INI configuration files: configparser

Many tools keep settings in INI files:

```
[server]
host = example.com
port = 8080
debug = yes
```

```python
import configparser
config = configparser.ConfigParser()
config.read_string(text)                    # or config.read("settings.ini")
config["server"]["host"]                    # 'example.com'
config.getint("server", "port")             # 8080
config.getboolean("server", "debug")        # True ("yes", "on", "1", "true" all count)
config.get("server", "timeout", fallback="30")
```

## XML: ElementTree

XML is a tree of nested **elements** with tags, attributes and text, still common in older APIs, office documents and RSS feeds:

```python
import xml.etree.ElementTree as ET

xml = '<library><book year="1949"><title>1984</title><author>Orwell</author></book></library>'
root = ET.fromstring(xml)
for book in root.findall("book"):
    print(book.find("title").text, book.get("year"))     # 1984 1949
```

For XML from untrusted sources, use the `defusedxml` package, which blocks some nasty attacks.

=== lesson py-sqlite | Databases with sqlite3 | 105
When data grows beyond a few files, or many parts of a program need to search and update it safely, you want a **database**. Python includes **SQLite**, a complete SQL database stored in a single file (or in memory), used in phones, browsers and countless apps. This lesson connects Python to it. (The **SQL** track teaches the SQL language itself in depth.)

## Connecting and creating tables

```python
import sqlite3

conn = sqlite3.connect("shop.db")     # a file, created if needed; ":memory:" for a temporary database
conn.execute("""
    CREATE TABLE IF NOT EXISTS products (
        id INTEGER PRIMARY KEY,
        name TEXT NOT NULL,
        price_cents INTEGER NOT NULL
    )
""")
```

`conn.execute(sql)` runs one statement. `INTEGER PRIMARY KEY` gives each row a unique id automatically.

## Inserting: always use placeholders

```python
conn.execute("INSERT INTO products (name, price_cents) VALUES (?, ?)", ("Mug", 899))
conn.executemany("INSERT INTO products (name, price_cents) VALUES (?, ?)", [("Pen", 150), ("Pad", 300)])
conn.commit()                          # make the changes permanent
```

The `?` **placeholders** are filled in safely by sqlite3 from the tuple. Never build SQL with f-strings or `+`:

```python
name = "x' OR '1'='1"
conn.execute(f"SELECT * FROM users WHERE name = '{name}'")   # ☠️ SQL injection: matches every user
conn.execute("SELECT * FROM users WHERE name = ?", (name,))   # ✅ treated as plain text
```

**SQL injection** (inserting SQL through data) is one of the most common and damaging security bugs in history. Placeholders make it impossible.

## Querying

```python
cur = conn.execute("SELECT name, price_cents FROM products WHERE price_cents < ? ORDER BY name", (500,))
cur.fetchall()           # [('Pad', 300), ('Pen', 150)]
conn.execute("SELECT COUNT(*) FROM products").fetchone()      # (3,)
for name, price in conn.execute("SELECT name, price_cents FROM products"):
    print(name, price)
```

Rows come back as tuples. Set `conn.row_factory = sqlite3.Row` to read columns by name: `row["name"]`.

## Transactions: all or nothing

A **transaction** groups changes so they all happen or none do. Using the connection as a context manager commits if the block succeeds and **rolls back** if it raises:

```python
with conn:
    conn.execute("UPDATE accounts SET balance = balance - ? WHERE id = ?", (50, 1))
    conn.execute("UPDATE accounts SET balance = balance + ? WHERE id = ?", (50, 2))
# both updates, or (on an error) neither
```

Note that `with conn:` doesn't close the connection; call `conn.close()` when you're done (or use `contextlib.closing`).

## Beyond sqlite3

Bigger applications often use **PostgreSQL** or **MySQL** servers (the PostgreSQL and MySQL tracks cover them) with the same ideas: connect, parameterised queries, transactions. Many projects use an **ORM** such as SQLAlchemy or Django's ORM, which maps tables to Python classes, plus **migrations** to evolve the schema over time. Learn plain SQL first: ORMs are much easier once you know what they generate.

+ `conn.execute("DELETE FROM notes WHERE id = ?", (note_id,))`
- `conn.execute("DELETE FROM notes WHERE id = '%s'" % note_id)`
> Only placeholders keep data separate from the SQL. Note the one-item tuple `(note_id,)`.

=== lesson py-http | HTTP and web APIs | 105
Most programs today talk to other programs over the web: weather services, payment providers, maps, AI models, your own backend. They do it through **web APIs** that speak **HTTP**. This lesson explains the protocol and how to write robust API clients in Python.

> 🔒 DevQuest's sandbox has no network access (so code you run can't reach the internet), so the exercises use a **fake server**. That's also exactly how professionals test API clients.

## Requests and responses

A **client** sends a **request** to a **server**, which sends back a **response**:

```
GET /v1/weather?city=Oslo HTTP/1.1          ← method, path and query
Host: api.example.com                        ← headers
Accept: application/json

HTTP/1.1 200 OK                              ← status code
Content-Type: application/json

{"city": "Oslo", "temp": 4.5}                ← body
```

**Methods** say what to do, and map onto the CRUD operations of a database:

| Method | Meaning | CRUD |
|---|---|---|
| `GET` | read a resource | Read |
| `POST` | create a new resource | Create |
| `PUT` / `PATCH` | replace / partly update a resource | Update |
| `DELETE` | remove a resource | Delete |

**Status codes** say how it went: `2xx` success (200 OK, 201 Created, 204 No Content), `3xx` redirect, `4xx` **your** mistake (400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict, 429 Too Many Requests), `5xx` the **server's** problem (500 Internal Server Error, 502/503/504 gateway or availability trouble).

## URLs, built safely

```python
from urllib.parse import urlencode, urljoin, urlparse

urljoin("https://api.example.com/v1/", "users")             # 'https://api.example.com/v1/users'
"?" + urlencode({"q": "ada lovelace", "page": 2})          # '?q=ada+lovelace&page=2'
urlparse("https://example.com:8080/a/b?x=1").port          # 8080
```

Let `urlencode` escape values; building query strings by hand breaks on spaces, `&` and non-English characters.

## Making requests

The standard library has `urllib.request`, but almost everyone uses the friendlier **requests** package (`pip install requests`):

```python
import requests

response = requests.get(
    "https://api.example.com/v1/weather",
    params={"city": "Oslo"},
    headers={"Authorization": f"Bearer {api_key}"},
    timeout=5,                       # ALWAYS set a timeout
)
response.raise_for_status()          # raise for 4xx/5xx
data = response.json()               # parse the JSON body
requests.post(url, json={"name": "Ada"}, timeout=5)      # send JSON
```

## Writing a robust client

Networks fail. A good API client:

- sets a **timeout** on every request (otherwise a dead server hangs your program forever);
- **retries** temporary failures (429, 502, 503, 504, connection errors) a few times, waiting longer each time (**exponential backoff**), but never retries 4xx mistakes like 404;
- translates failures into **domain exceptions** (`CityNotFound`, `ApiUnavailable`), so callers don't depend on HTTP details;
- keeps API keys in environment variables, never in code;
- respects **rate limits** and handles **pagination** (results split over several pages).

And it receives its HTTP layer (the "transport") as a dependency, so tests can pass a fake that returns canned responses. That's dependency injection once more, and it's exactly what the exercises do.

~~~check

- Yes, three times
+ No: 4xx means the request itself was wrong, so it will keep failing
- Only with a longer timeout
- Yes, forever
> Retry temporary server-side problems (5xx, 429), not client errors.
~~~

=== lesson py-regex | Regular expressions | 105
A **regular expression** (regex) is a tiny language for describing **patterns** in text: "three digits, a dash, four digits", "a word starting with #", "a date like 2026-10-14". Python's `re` module searches, extracts, validates and replaces text using them.

```python
import re

text = "Call 555-1234 or 555-9876 today"
re.findall(r"\d{3}-\d{4}", text)       # ['555-1234', '555-9876']
```

Always write patterns as **raw strings** (`r"..."`): regexes use lots of backslashes, and raw strings stop Python from interpreting them first.

## The building blocks

| Pattern | Matches |
|---|---|
| `abc` | the literal text abc |
| `.` | any character except a newline |
| `\d` / `\D` | a digit / a non-digit |
| `\w` / `\W` | a "word" character (letter, digit, underscore) / anything else |
| `\s` / `\S` | whitespace / non-whitespace |
| `[aeiou]` | one of these characters |
| `[a-z0-9]` | a range of characters |
| `[^0-9]` | anything **except** these |
| `^` / `$` | start / end of the text (or of each line with `re.MULTILINE`) |
| `\b` | a word boundary |
| `\.` | a literal dot (backslash escapes special characters) |

**Quantifiers** say how many times:

| Quantifier | Means |
|---|---|
| `*` | 0 or more |
| `+` | 1 or more |
| `?` | 0 or 1 (optional) |
| `{3}` | exactly 3 |
| `{2,4}` | 2 to 4 |

So `\d{3}-\d{4}` means three digits, a dash, four digits. `colou?r` matches `color` and `colour`. `#\w+` matches a hashtag.

## The main functions

```python
re.search(r"\d+", "order 66 shipped")      # first match anywhere, or None
re.fullmatch(r"\d{4}", "2026")             # the WHOLE text must match: for validation
re.findall(r"#(\w+)", "#python #regex")    # all matches → ['python', 'regex']
re.sub(r"\s+", " ", "too    many   spaces")   # replace → 'too many spaces'
re.split(r"[,;]\s*", "a, b;c")             # split on a pattern → ['a', 'b', 'c']
```

`search` and `fullmatch` return a **match object** (or `None`), so check before using it:

```python
m = re.search(r"(\d{4})-(\d{2})-(\d{2})", "Due: 2026-10-14!")
if m:
    print(m.group())       # '2026-10-14'   the whole match
    print(m.group(1))      # '2026'         the first group
    print(m.groups())      # ('2026', '10', '14')
```

`re.match` checks only at the **start** of the text, a common source of confusion; prefer `search` or `fullmatch`.

~~~check

- `"a123"`
+ `"B704"`
- `"B70"`
- `"B7045"`
> One capital letter followed by exactly three digits, and nothing else.
~~~

## Groups

Parentheses create **groups**: they capture parts of a match, and let quantifiers apply to several characters. When a pattern has groups, `findall` returns the groups instead of whole matches. **Named groups** make complex patterns readable:

```python
line = "2026-10-14 09:30:12 [ERROR] Disk full"
m = re.fullmatch(r"(?P<date>\S+) (?P<time>\S+) \[(?P<level>\w+)\] (?P<message>.*)", line)
m.group("level")         # 'ERROR'
m.groupdict()            # {'date': '2026-10-14', 'time': '09:30:12', 'level': 'ERROR', 'message': 'Disk full'}
```

`(?:...)` groups **without** capturing, when you only need the grouping.

## Greedy and lazy

Quantifiers are **greedy**: they match as much as possible. `<.+>` on `<b>bold</b>` matches the **whole** string. Adding `?` makes them **lazy** (as little as possible): `<.+?>` matches `<b>` and then `</b>`.

## Flags and compiling

```python
re.search(r"python", "I love PYTHON", re.IGNORECASE)    # case-insensitive
re.findall(r"^\w+", text, re.MULTILINE)               # ^ matches at every line start
pattern = re.compile(r"\d{3}-\d{4}")                  # reuse a pattern many times
pattern.findall(text)
```

## When not to use a regex

Regexes are powerful but hard to read. For simple jobs, string methods are clearer (`text.startswith("#")`, `"@" in email`). For structured formats like HTML, JSON or CSV, use a real parser. Fully validating email addresses with a regex is famously impractical; check for something reasonable and send a confirmation email instead.

Tools like regex101.com explain a pattern piece by piece and let you test it, which is very useful while learning.

=== lesson py-datetime | Dates and times | 100
Dates look simple until you calculate with them: months have different lengths, leap years exist, and clocks change. The `datetime` module does the hard parts correctly.

## The main types

```python
from datetime import date, time, datetime, timedelta

d = date(2026, 10, 14)                 # a calendar date
t = time(18, 5)                        # a time of day
dt = datetime(2026, 10, 14, 18, 5)     # both together
date.today()                           # today's date
datetime.now()                         # now, to the microsecond
d.year, d.month, d.day                 # 2026 10 14
d.weekday()                            # 2: Monday is 0, Sunday is 6
```

## Durations: timedelta

Subtracting dates gives a `timedelta`; adding a `timedelta` to a date gives a new date:

```python
launch = date(2026, 12, 25)
until = launch - date(2026, 10, 14)
until.days                              # 72
date(2026, 1, 31) + timedelta(days=1)   # date(2026, 2, 1): month lengths handled for you
datetime(2026, 10, 14, 23, 0) + timedelta(hours=3)    # 2026-10-15 02:00
timedelta(hours=1, minutes=30).total_seconds()        # 5400.0
```

Dates and datetimes compare with `<`, `>` and `==`, so they sort correctly too.

## Text to dates and back: strptime and strftime

```python
dt = datetime.strptime("14/10/2026 18:05", "%d/%m/%Y %H:%M")    # parse ("string parse time")
dt.strftime("%A %d %B %Y, %H:%M")                               # format: 'Wednesday 14 October 2026, 18:05'
```

| Code | Meaning | Example |
|---|---|---|
| `%Y` | 4-digit year | 2026 |
| `%m` / `%d` | month / day, zero-padded | 10 / 04 |
| `%H` / `%M` / `%S` | hour (24h) / minute / second | 18 / 05 / 00 |
| `%A` / `%a` | weekday name / short | Wednesday / Wed |
| `%B` / `%b` | month name / short | October / Oct |

## ISO 8601: the format to use for data

For files, APIs and databases, use the international standard **ISO 8601**: `2026-10-14` and `2026-10-14T18:05:00`. It's unambiguous (is `04/05` April 5th or May 4th?) and sorts correctly even as text.

```python
d.isoformat()                          # '2026-10-14'
datetime.fromisoformat("2026-10-14T18:05:00")
```

## Time zones

A `datetime` without time-zone information is **naive**; one with it is **aware**. Store and compute in **UTC**, and convert to local time only for display:

```python
from datetime import timezone
now_utc = datetime.now(timezone.utc)
paris = timezone(timedelta(hours=2))       # a fixed offset
now_utc.astimezone(paris)
```

Real time zones (with daylight-saving rules) come from `zoneinfo.ZoneInfo("Europe/Paris")`, which needs the time-zone database installed. Mixing naive and aware datetimes in calculations raises a `TypeError`, which is Python protecting you from a subtle bug.

## Measuring how long code takes

```python
import time
start = time.perf_counter()
...                                       # the work to measure
elapsed = time.perf_counter() - start     # seconds, very precise
```

Use `perf_counter` (not the wall clock) for timing, since the system clock can jump.

import re
from collections import Counter

LINE = re.compile(r"(?P<date>\d{4}-\d{2}-\d{2}) (?P<time>\d{2}:\d{2}:\d{2}) \[(?P<level>[A-Z]+)\] (?P<message>.*)")


def summarise(log_text):
    levels = Counter()
    hours = Counter()
    first_error = None
    for line in log_text.splitlines():
        m = LINE.fullmatch(line.strip())
        if not m:
            continue
        levels[m["level"]] += 1
        hours[m["time"][:2]] += 1
        if m["level"] == "ERROR" and first_error is None:
            first_error = m["time"]
    busiest = None
    if hours:
        top = max(hours.values())
        busiest = min(h for h, n in hours.items() if n == top)
    return {"levels": dict(levels), "first_error": first_error, "busiest_hour": busiest}
