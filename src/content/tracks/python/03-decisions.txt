=== module Module 3 · Making decisions

=== lesson py-if | if, elif and else | 85
So far, every line of every program has run, in order. Real programs **decide**: if the password is right, log in, otherwise show an error; if the cart is empty, hide the checkout button. This lesson teaches your programs to choose.

## Comparisons give True or False

A **comparison** asks a yes/no question and produces a **boolean** (`True` or `False`):

| Operator | Meaning | Example | Result |
|---|---|---|---|
| `==` | equal to | `3 == 3` | `True` |
| `!=` | not equal to | `3 != 4` | `True` |
| `<` and `>` | less than, greater than | `2 > 5` | `False` |
| `<=` and `>=` | at most, at least | `5 <= 5` | `True` |

- `=` **assigns** a value; `==` **compares** two values. Mixing them up is a classic slip.
- Strings compare too: `"cat" == "Cat"` is `False` (case matters), and `"apple" < "banana"` is `True`.
- You can chain comparisons like in maths: `0 <= age < 18` means `0 <= age and age < 18`.
- Different types are never equal: `5 == "5"` is `False`, and `5 < "5"` is a `TypeError`.

## The if statement

```python
temperature = 31
if temperature > 30:
    print("It's hot!")
    print("Drink some water.")
print("Have a nice day.")
```

The parts:

1. the keyword `if`;
2. a **condition**, any expression that is true or false;
3. a **colon** `:`;
4. an **indented block**: the lines that run only when the condition is true.

The block ends where the indentation ends, so `Have a nice day.` prints whatever the temperature is.

In Python, **indentation is part of the syntax**. Many other languages mark blocks with `{ }`; Python uses the indentation itself. The standard is **4 spaces** per level (editors insert them when you press Tab). Get it wrong and Python tells you:

```
IndentationError: expected an indented block after 'if' statement on line 2
```

## else: otherwise

```python
age = 15
if age >= 18:
    print("You can vote.")
else:
    print("Not yet: in", 18 - age, "years.")
```

With `if`/`else`, **exactly one** of the two blocks runs.

## elif: choosing between many options

`elif` ("else if") adds more conditions:

```python
score = 72
if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
else:
    grade = "F"
print(grade)    # C
```

Python checks the conditions **from top to bottom** and runs the **first** branch whose condition is true. Then it skips the rest of the chain. Trace it for 72: `72 >= 90`? No. `72 >= 80`? No. `72 >= 70`? Yes: grade C, and the `else` is skipped.

That's why **order matters**. If the `score >= 70` test came first, a score of 95 would get a C, because it would match that branch first.

## A chain of elifs is not the same as several ifs

```python
score = 95
if score >= 90:
    print("A")
if score >= 80:      # a separate if: it's checked too
    print("B")
```

This prints **both** A and B: each `if` is an independent question. Use `elif` when the options are mutually exclusive.

## Nesting

A block can contain another `if`, indented one more level:

```python
if logged_in:
    if is_admin:
        print("Admin panel")
    else:
        print("Your dashboard")
else:
    print("Please log in")
```

Deep nesting gets hard to read; the next lesson's `and`/`or` often flattens it.

## pass: an empty block

A block can't be empty. When you need a placeholder (say, a branch you'll write later), use `pass`, a statement that does nothing.

## Testing decisions: think about boundaries

When you test code that decides, try **one value per branch**, plus the **boundaries** between them. For the grade example, test 95, 90, 89, 80, 79, 70, 69. Most decision bugs are at a boundary: `>` written where `>=` was meant.

## Common mistakes

- Forgetting the colon: `SyntaxError: expected ':'`.
- Writing `if x = 5:`. Python replies `SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?`
- Indenting inconsistently, or not indenting the block at all.
- Ordering an `elif` chain so that a broad condition catches values meant for a later branch.

=== lesson py-logic | Logic: and, or, not, and match | 85
## Combining conditions

Real decisions often depend on several facts at once. Three **logical operators** combine booleans:

| A | B | `A and B` | `A or B` |
|---|---|---|---|
| True | True | True | True |
| True | False | False | True |
| False | True | False | True |
| False | False | False | False |

- `and` is true only when **both** sides are true.
- `or` is true when **at least one** side is true.
- `not` flips a value: `not True` is `False`.

```python
age = 15
has_ticket = True
if age >= 13 and age <= 19:
    print("teenager")
if day == "Sat" or day == "Sun":
    print("weekend")
if not has_ticket:
    print("Please buy a ticket")
```

## A trap: comparing to several values

```python
day = "Mon"
if day == "Sat" or "Sun":      # BUG: always true!
    print("weekend")
```

This reads naturally in English but means `(day == "Sat") or ("Sun")`. The right side is just the string `"Sun"`, which is **truthy**, so the whole condition is always true. Write the comparison twice, or use membership:

```python
if day == "Sat" or day == "Sun":
if day in ("Sat", "Sun"):          # neater
```

## Precedence

`not` binds tightest, then `and`, then `or`. So `a or b and c` means `a or (b and c)`. Parentheses make your intent clear; use them whenever you mix `and` and `or`.

## Short-circuit evaluation

Python stops evaluating as soon as the answer is known:

- `A and B`: if A is false, B is never evaluated.
- `A or B`: if A is true, B is never evaluated.

This is often used to guard against errors:

```python
if count > 0 and total / count > 10:    # no ZeroDivisionError when count is 0
    print("big average")
```

`and` and `or` actually return one of their operands (not necessarily `True`/`False`), which gives a handy idiom for defaults:

```python
name = input("Name: ") or "Guest"    # an empty answer is falsy, so "Guest" is used
```

## Truthiness in conditions

Any value can be a condition; Python uses its truthiness (Module 1). So `if name:` means "if `name` isn't empty", and `if not items:` means "if the collection is empty". It's shorter and very common in Python code.

## Conditional expressions

For a choice between two values, there's a one-line form:

```python
label = "even" if n % 2 == 0 else "odd"
print("Welcome back!" if returning else "Welcome!")
```

Read it as: *value-if-true* `if` *condition* `else` *value-if-false*. Keep it for short, simple choices.

## Checking against None

To test whether something is `None`, use `is`: `if result is None:`. (`is` checks whether two names refer to the very same object; Module 8 explains the difference from `==`.)

## Validating input

`int(input())` crashes if the user types letters. You can check first:

```python
text = input("Age: ")
if text.isdigit():
    age = int(text)
    print("Next year you'll be", age + 1)
else:
    print("Please type a whole number.")
```

Checking data before using it is called **defensive programming**. (Module 7 shows the other approach: trying it and handling the error with `try`/`except`.)

## match: choosing by value (Python 3.10+)

When you compare one value against many options, `match` can read more clearly than a long `elif` chain:

```python
command = input("> ").strip().lower()
match command:
    case "start":
        print("Starting")
    case "stop" | "quit":          # | means "or" in a pattern
        print("Stopping")
    case "":
        print("Type a command")
    case _:                        # _ matches anything else
        print("Unknown command:", command)
```

The first matching `case` runs. `case _:` plays the role of `else`. A case can also have a **guard**: `case n if n < 0:`. `match` can do much more (taking apart lists and objects), which you'll meet later; for now, think of it as a tidy multi-way choice.

## Simplifying conditions: De Morgan's laws

Two rules for negations: `not (a and b)` is the same as `(not a) or (not b)`, and `not (a or b)` is the same as `(not a) and (not b)`. They help turn a confusing `not (...)` into something readable.

::prompt
Decide a game of rock, paper, scissors. Read two moves (prompts `Player 1: ` and `Player 2: `, any case). Print `Draw`, `Player 1 wins` or `Player 2 wins`. Rock beats scissors, scissors beat paper, paper beats rock. If either move isn't one of the three, print `Invalid move`.
::starter
p1 = input("Player 1: ").strip().lower()
p2 = input("Player 2: ").strip().lower()
::solution
p1 = input("Player 1: ").strip().lower()
p2 = input("Player 2: ").strip().lower()
moves = ("rock", "paper", "scissors")
if p1 not in moves or p2 not in moves:
    print("Invalid move")
elif p1 == p2:
    print("Draw")
elif (p1 == "rock" and p2 == "scissors") or (p1 == "scissors" and p2 == "paper") or (p1 == "paper" and p2 == "rock"):
    print("Player 1 wins")
else:
    print("Player 2 wins")
