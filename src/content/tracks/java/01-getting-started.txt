=== lesson java-why | What Java is | 50
## Write once, run anywhere

Java was created at Sun Microsystems by James Gosling's team and released in 1995. Its big idea was **portability**: you compile a Java program once, into **bytecode**, and that bytecode runs on any computer that has a **Java Virtual Machine** (JVM), whether it runs Windows, Linux or macOS, on a laptop, a server or (originally) a set-top box.

```
Main.java  --javac (compiler)-->  Main.class (bytecode)  --java (JVM)-->  runs on any OS
```

Thirty years later, Java is one of the most used programming languages in the world:

- **Enterprise back ends**: banks, insurers, airlines, retailers and governments run huge systems on Java, often with the **Spring** framework.
- **Android**: Android apps were written in Java for a decade (Kotlin, which runs on the same JVM, is now preferred, and the Kotlin course builds on this one).
- **Big data and infrastructure**: Hadoop, Kafka, Elasticsearch, Cassandra and Spark are written in Java or other JVM languages.
- **Tools and games**: IntelliJ IDEA, Minecraft (Java Edition) and countless desktop and server tools.

Learning Java also teaches you the ideas behind C#, Kotlin, Scala and a large part of C++: it's the classic language for **object-oriented programming**, and most textbooks on software design use it.

## What makes Java Java

- **Statically typed**: every variable has a type, checked by the compiler before the program runs (like TypeScript, and unlike Python and JavaScript). Many mistakes are caught early.
- **Object-oriented**: code is organised into **classes**; nearly everything is an object.
- **Garbage collected**: you create objects and the JVM frees the memory when they're no longer used (unlike C and C++).
- **Compiled and fast**: the JVM's **JIT compiler** turns frequently used bytecode into optimised machine code while the program runs, so long-running Java programs are very fast.
- **A huge standard library and ecosystem**: collections, networking, concurrency, dates, files, plus hundreds of thousands of open-source libraries on Maven Central.
- **Backward compatible**: code written for Java 1.4 in 2002 generally still compiles and runs today.

## Versions

Java has a new version every six months; every two years one is a **Long-Term Support** (LTS) release that companies use for years: **8** (2014, still found in older systems), **11**, **17**, **21** (2023) and **25** (2025). This course uses **Java 21** and points out modern features (records, switch expressions, pattern matching, virtual threads) that older code bases don't have.

Java is open source (**OpenJDK**). You install a **JDK** (Java Development Kit: compiler, JVM and tools) from a distributor: Eclipse Temurin (Adoptium), Microsoft, Amazon Corretto, Oracle and others all build the same OpenJDK code.

=== lesson java-setup | Installing Java and running programs | 55
## Install a JDK

1. Download a **JDK 21** (or newer LTS) from **adoptium.net** (Eclipse Temurin) or **learn.microsoft.com/java/openjdk**, choosing your operating system. On Linux: `sudo apt install openjdk-21-jdk`; on macOS with Homebrew: `brew install openjdk@21`.
2. Check it in a terminal:

```
java -version
javac -version
```

Both should print 21 or later. If the command isn't found, the installer didn't add Java to your `PATH`: reopen the terminal, or set `JAVA_HOME` to the JDK folder and add its `bin` folder to `PATH`.

DevQuest's desktop app finds the JDK automatically (see **Languages** in the sidebar). Once it shows Java as available, **▶ Run** works in every Java lesson.

## Compile, then run

Save this as `Main.java` (the file name must match the public class name, including capitals):

```java
public class Main {
    public static void main(String[] args) {
        int apples = 5;
        int pears = 3;
        System.out.println("Fruit: " + (apples + pears));
    }
}
```

Then, in the folder containing it:

```
javac Main.java      # compiles: creates Main.class (bytecode)
java Main            # runs the class Main on the JVM
```

Since Java 11 you can skip the separate step for a single file: `java Main.java` compiles it in memory and runs it. That's what DevQuest does. Larger programs (several files, libraries) use a build tool, **Maven** or **Gradle** (Module 6).

## One file, several classes

In a real project, each public class has its own file. In DevQuest, an exercise is a single file, so the convention is:

- `public class Main` comes **first**, with the `main` method;
- other classes go **below** it, without `public`.

```java
public class Main {
    public static void main(String[] args) {
        Greeter greeter = new Greeter();
        System.out.println(greeter.greet("Ada"));
    }
}

class Greeter {
    String greet(String name) {
        return "Hello, " + name + "!";
    }
}
```

## Editors and IDEs

Java is usually written in an **IDE** (integrated development environment), which compiles as you type, completes code and refactors safely:

- **IntelliJ IDEA** (Community Edition is free): the most popular Java IDE;
- **VS Code** with the "Extension Pack for Java";
- **Eclipse**, long the standard, still widely used in companies.

## JShell: Java's REPL

`jshell` (in the JDK) lets you type Java expressions and see results immediately, without a class or `main`. It's great for experimenting:

```
$ jshell
jshell> 7 / 2
$1 ==> 3
jshell> "Java".toUpperCase()
$2 ==> "JAVA"
jshell> /exit
```

=== lesson java-basics | Hello, Java: the structure of a program | 65
## Taking the first program apart

```java
public class Main {
    public static void main(String[] args) {
        // This line prints a greeting
        System.out.println("Hello, Java!");
    }
}
```

| Part | Meaning |
|---|---|
| `public class Main { ... }` | declares a **class** named `Main`. All Java code lives inside classes. |
| `public static void main(String[] args)` | the **entry point**: the JVM starts here. `public`: callable from outside; `static`: belongs to the class, no object needed; `void`: returns nothing; `String[] args`: the command-line arguments. |
| `{ }` | **braces** group code into blocks (Python uses indentation; Java uses braces, and indents for readability). |
| `System.out.println(...)` | prints a value and a line break. `System.out.print` prints without the line break. |
| `;` | ends each **statement**. Forgetting one is the most common beginner error. |
| `// ...` | a comment, ignored by the compiler (`/* ... */` spans lines; `/** ... */` is a Javadoc comment). |

Java is **case-sensitive**: `System` and `system` are different names, and `Main` isn't `main`.

## Values and variables

A **variable** stores a value, and in Java every variable has a **type** that never changes:

```java
public class Main {
    public static void main(String[] args) {
        String name = "Duke";
        int year = 1995;
        double version = 21.0;
        boolean fun = true;

        System.out.println(name + " was born in " + year);
        System.out.println("Version " + version + ", fun: " + fun);

        year = year + 31;
        System.out.println("Now it's " + year);
    }
}
```

- `String` (text), `int` (whole numbers), `double` (decimal numbers) and `boolean` (`true`/`false`) are the everyday types; the next module covers all of them.
- A variable is declared once, with its type (`int year = 1995;`), then assigned new values without the type (`year = ...`).
- `+` joins strings, and turns numbers into text when one side is a string.

Since Java 10, **`var`** lets the compiler infer the type of a local variable from its value: `var count = 3;` is still an `int`, forever. It saves typing when the type is obvious.

## printf and formatted text

`System.out.printf` formats values with placeholders, like C and Python's `%` formatting:

```java
public class Main {
    public static void main(String[] args) {
        String item = "Coffee";
        int quantity = 3;
        double price = 2.5;
        System.out.printf("%s x%d = %.2f%n", item, quantity, quantity * price);
        System.out.println(String.format("%-8s|%5d|", item, quantity));
    }
}
```

`%s` is a string, `%d` an integer, `%.2f` a decimal with 2 places, `%n` a line break; widths like `%5d` (right-aligned) and `%-8s` (left-aligned) line up columns. `String.format` (or `"...".formatted(...)`) returns the text instead of printing it.

=== lesson java-errors | Reading compiler errors and exceptions | 55
## Two kinds of errors

Java reports problems at two moments:

1. **Compile errors**: `javac` refuses to compile a program that breaks the language's rules or types. Nothing runs.
2. **Exceptions**: a compiled program hits a problem while running (dividing by zero, an invalid index) and stops with a **stack trace**.

Static typing moves many mistakes from the second kind to the first, which is good: compile errors appear immediately, on the exact line, before any user sees them.

## Compile errors

```java
// error: a misspelt method name
public class Main {
    public static void main(String[] args) {
        System.out.printn("Hello");
    }
}
```

The compiler answers:

```
Main.java:4: error: cannot find symbol
        System.out.printn("Hello");
                  ^
  symbol:   method printn(String)
  location: variable out of type PrintStream
1 error
```

Read it as: **file and line** (`Main.java:4`), **what's wrong** (`cannot find symbol`), the line with a `^` under the problem, and details. The common ones:

| Message | Usual cause |
|---|---|
| `';' expected` | a missing semicolon (reported on the line where the compiler noticed, often the next line) |
| `cannot find symbol` | a typo, wrong capitalisation, a missing variable or import |
| `incompatible types: String cannot be converted to int` | a value of the wrong type |
| `missing return statement` | a method that should return a value doesn't on every path |
| `variable x might not have been initialized` | using a local variable before giving it a value |
| `class Main is public, should be declared in a file named Main.java` | the file name doesn't match |
| `reached end of file while parsing` | a missing closing brace `}` |

```java
// error: assigning text to an int variable
public class Main {
    public static void main(String[] args) {
        int age = "thirty";
        System.out.println(age);
    }
}
```

When several errors appear, **fix the first one first**: later errors are often consequences of it.

## Exceptions and stack traces

```java
// error: this program compiles, then fails while running
public class Main {
    public static void main(String[] args) {
        int[] scores = {90, 85, 77};
        System.out.println("First: " + scores[0]);
        System.out.println("Fourth: " + scores[3]);
    }
}
```

```
First: 90
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
	at Main.main(Main.java:6)
```

The first line names the **exception class** and a message; the lines starting with `at` are the **stack trace**: the chain of method calls that led there, innermost first, each with its file and line. In a big application, look for the first `at` line in **your** code. Common runtime exceptions:

| Exception | Means |
|---|---|
| `NullPointerException` | using a variable that holds `null` (no object) |
| `ArrayIndexOutOfBoundsException` | an index outside an array |
| `ArithmeticException: / by zero` | integer division by zero |
| `NumberFormatException` | `Integer.parseInt("abc")` |
| `ClassCastException` | converting an object to a type it isn't |

Module 5 shows how to catch and handle exceptions.
