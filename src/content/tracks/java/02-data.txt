## Eight primitive types

Java has eight **primitive types**, the building blocks of every value. They're stored directly (not as objects) and have fixed sizes on every platform:

| Type | Size | Range / values | Example |
|---|---|---|---|
| `byte` | 8 bits | -128 to 127 | `byte b = 100;` |
| `short` | 16 bits | -32,768 to 32,767 | `short s = 2000;` |
| `int` | 32 bits | about ±2.1 billion | `int count = 42;` |
| `long` | 64 bits | about ±9.2 × 10¹⁸ | `long views = 8_000_000_000L;` |
| `float` | 32 bits | ~7 significant digits | `float f = 1.5f;` |
| `double` | 64 bits | ~15 significant digits | `double pi = 3.14159;` |
| `char` | 16 bits | one UTF-16 character | `char grade = 'A';` |
| `boolean` | (1 bit of information) | `true`, `false` | `boolean done = false;` |

In practice you'll use `int`, `long`, `double`, `boolean` and `char` almost all the time. Everything else (`String`, arrays, your own classes) is a **reference type**: the variable holds a reference to an object (Module 4).

```java
public class Main {
    public static void main(String[] args) {
        int population = 8_100_000;          // underscores make big numbers readable
        long worldPopulation = 8_100_000_000L; // too big for int: needs long and an L suffix
        double temperature = -3.5;
        char initial = 'J';                   // single quotes for one char
        boolean isWinter = temperature < 5;

        System.out.println(population + " " + worldPopulation);
        System.out.println(temperature + " " + initial + " " + isWinter);
        System.out.println("int max: " + Integer.MAX_VALUE + ", long max: " + Long.MAX_VALUE);
    }
}
```

## Literals

- Integer literals are `int` by default; add `L` for `long` (`10_000_000_000L`). Hexadecimal `0xFF`, binary `0b1010`.
- Decimal literals are `double` by default; add `f` for `float` (`1.5f`).
- `char` literals use **single** quotes (`'A'`, `'\n'`); `String` literals use **double** quotes.

## Conversions: widening and casting

Java converts automatically when no information can be lost (**widening**: `int` → `long` → `double`):

```java
public class Main {
    public static void main(String[] args) {
        int apples = 7;
        double asDouble = apples;           // widening: automatic
        double average = 7.9;
        int truncated = (int) average;      // narrowing: needs an explicit cast, drops the fraction
        long big = 3_000_000_000L;
        int overflowed = (int) big;         // keeps the low 32 bits: a surprising number
        char letter = 'A';
        int code = letter;                  // a char is a number (its UTF-16 code)

        System.out.println(asDouble + " " + truncated + " " + overflowed + " " + code + " " + (char) (code + 2));
        System.out.println(Math.round(7.9) + " " + (int) Math.round(7.5));
    }
}
```

A **cast** `(int) value` forces a narrowing conversion and is your way of saying "I know information may be lost". Casting a `double` to `int` **truncates** towards zero; use `Math.round` to round. Casting a value that doesn't fit wraps around silently, so check ranges first.

## Constants with final

`final` makes a variable unchangeable after its first assignment. Constants are conventionally written in `UPPER_SNAKE_CASE`:

```java
public class Main {
    static final double VAT_RATE = 0.20;

    public static void main(String[] args) {
        final int maxUsers = 100;
        double net = 50.0;
        System.out.println("Gross: " + net * (1 + VAT_RATE) + ", limit: " + maxUsers);
    }
}
```

Assigning to a `final` variable again is a compile error, which documents and enforces your intent.

## Naming

Java's conventions: `camelCase` for variables and methods (`totalPrice`), `PascalCase` for classes (`OrderService`), `UPPER_SNAKE_CASE` for constants. Names can't start with a digit or be keywords (`class`, `int`, `new`...).

## Arithmetic

```java
public class Main {
    public static void main(String[] args) {
        System.out.println(17 + 5);       // 22
        System.out.println(17 - 5);       // 12
        System.out.println(17 * 5);       // 85
        System.out.println(17 / 5);       // 3   integer division: the fraction is dropped
        System.out.println(17 % 5);       // 2   remainder (modulo)
        System.out.println(17 / 5.0);     // 3.4 one double operand makes it floating-point
        System.out.println(-17 / 5);      // -3  truncates towards zero
        System.out.println(-17 % 5);      // -2  the remainder has the sign of the left side
    }
}
```

**Integer division** is the classic Java surprise (also in C, C# and SQL): `7 / 2` is `3`. When you want a fraction, make one side a `double` (`7 / 2.0`, or `(double) a / b`). The **modulo** `%` is useful for "every n-th" and "is it even?" (`n % 2 == 0`).

## Overflow

Integer arithmetic **wraps around** silently when the result doesn't fit:

```java
public class Main {
    public static void main(String[] args) {
        int max = Integer.MAX_VALUE;
        System.out.println(max + 1);                  // wraps to the most negative int
        long safe = (long) max + 1;
        System.out.println(safe);
        System.out.println(Math.addExact(5, 7));      // throws ArithmeticException on overflow instead
        System.out.println(0.1 + 0.2);                // floating-point is approximate
    }
}
```

Use `long` when values can grow large, `Math.addExact`/`multiplyExact` when overflow must be detected, and `BigDecimal` for money (Module 5).

## Assignment, compound and increment operators

```java
public class Main {
    public static void main(String[] args) {
        int score = 10;
        score += 5;      // score = score + 5  → 15
        score *= 2;      // → 30
        score -= 4;      // → 26
        score /= 3;      // → 8
        score %= 5;      // → 3
        int a = score++; // a gets 3, then score becomes 4 (postfix)
        int b = ++score; // score becomes 5, then b gets 5 (prefix)
        System.out.println(score + " " + a + " " + b);
    }
}
```

Prefer `count++` on its own line; mixing `++` into larger expressions makes code hard to read.

## Comparison and logical operators

| Operator | Meaning |
|---|---|
| `==`, `!=` | equal, not equal (for primitives; for objects, see below) |
| `<`, `<=`, `>`, `>=` | comparisons |
| `&&` | and, **short-circuit**: the right side runs only if the left is true |
| `\|\|` | or, short-circuit: the right side runs only if the left is false |
| `!` | not |
| `? :` | conditional (ternary) expression: `cond ? a : b` |

```java
public class Main {
    public static void main(String[] args) {
        int age = 20;
        boolean hasTicket = true;
        boolean canEnter = age >= 18 && hasTicket;
        String label = canEnter ? "welcome" : "sorry";
        String text = null;
        boolean empty = text == null || text.isEmpty();   // safe thanks to short-circuiting
        System.out.println(canEnter + " " + label + " " + empty);
    }
}
```

**`==` on objects compares references** (is it the same object?), not contents. For strings and other objects use `equals` (next lesson): `"a" == new String("a")` is `false`.

## Bitwise operators

`&`, `|`, `^` (xor), `~` (not), `<<`, `>>` and `>>>` work on the bits of integers. They're used for flags, hashing, graphics and low-level protocols:

```java
public class Main {
    public static void main(String[] args) {
        int READ = 0b100, WRITE = 0b010, EXECUTE = 0b001;
        int permissions = READ | WRITE;
        System.out.println(Integer.toBinaryString(permissions));
        System.out.println((permissions & WRITE) != 0);
        System.out.println((permissions & EXECUTE) != 0);
        System.out.println(1 << 10);
    }
}
```

## Precedence

`*`, `/`, `%` bind tighter than `+`, `-`; comparisons come next, then `&&`, then `||`, then the ternary and assignments. When in doubt, add parentheses: `(a + b) / 2`, `(x > 0) && (y > 0)`.

## String basics

`String` is the type for text. Strings are **objects**, but Java gives them special syntax (literals in double quotes and `+` for joining):

```java
public class Main {
    public static void main(String[] args) {
        String language = "Java";
        System.out.println(language.length());              // 4
        System.out.println(language.toUpperCase());         // JAVA
        System.out.println(language.charAt(0));             // J
        System.out.println(language.indexOf("va"));         // 2
        System.out.println(language.substring(1, 3));       // av (from 1, up to but not including 3)
        System.out.println(language.contains("av"));        // true
        System.out.println(language.replace("a", "4"));     // J4v4
        System.out.println("  padded  ".strip() + "|");     // padded|
        System.out.println(String.join(", ", "a", "b", "c"));
        System.out.println("a,b,,c".split(",").length);     // 4
        System.out.println("ha".repeat(3));                 // hahaha
    }
}
```

Indexes start at **0**; `substring(start, end)` excludes `end`. Other useful methods: `startsWith`, `endsWith`, `isEmpty`, `isBlank`, `lastIndexOf`, `toLowerCase`, `trim`, `chars()`.

## Strings are immutable

No `String` method changes the string: they all return a **new** string.

```java
public class Main {
    public static void main(String[] args) {
        String name = "ada";
        name.toUpperCase();                  // result thrown away!
        System.out.println(name);            // still "ada"
        name = name.toUpperCase();           // keep the result
        System.out.println(name);
    }
}
```

Immutability makes strings safe to share between parts of a program (and threads), and lets Java reuse identical literals.

## Comparing strings: equals, never ==

```java
public class Main {
    public static void main(String[] args) {
        String a = "hello";
        String b = new String("hello");
        System.out.println(a == b);                       // false: different objects
        System.out.println(a.equals(b));                  // true: same characters
        System.out.println("HELLO".equalsIgnoreCase(a));  // true
        System.out.println("apple".compareTo("banana"));  // negative: "apple" sorts first
    }
}
```

`==` compares **references**. It sometimes appears to work for strings (identical literals are shared), which makes the bug especially sneaky. Always use `equals` (or `equalsIgnoreCase`), and `compareTo` for alphabetical order. A safe pattern when one side may be `null`: `"admin".equals(role)`.

## Building strings efficiently: StringBuilder

Because strings are immutable, `s += x` in a loop creates a new string every time. For building text piece by piece, use a **`StringBuilder`**:

```java
public class Main {
    public static void main(String[] args) {
        StringBuilder sb = new StringBuilder();
        for (int i = 1; i <= 5; i++) {
            sb.append(i);
            if (i < 5) sb.append(" -> ");
        }
        System.out.println(sb.toString());
        System.out.println(new StringBuilder("stressed").reverse());
    }
}
```

## Text blocks and formatting

**Text blocks** (Java 15+) write multi-line strings between triple quotes, without `\n` escapes:

```java
public class Main {
    public static void main(String[] args) {
        String json = """
            {
              "name": "%s",
              "level": %d
            }
            """.formatted("Ada", 3);
        System.out.print(json);
    }
}
```

The common indentation is removed automatically. `formatted(...)` (like `String.format`) fills `%s`/`%d` placeholders.

Escape sequences in normal strings: `\n` (new line), `\t` (tab), `\"` (quote), `\\` (backslash), `é` (a Unicode character).

## Characters

A `char` is a single UTF-16 code unit. The `Character` class helps classify them:

```java
public class Main {
    public static void main(String[] args) {
        String text = "R2-D2 lands!";
        int letters = 0, digits = 0;
        for (char c : text.toCharArray()) {
            if (Character.isLetter(c)) letters++;
            else if (Character.isDigit(c)) digits++;
        }
        System.out.println(letters + " letters, " + digits + " digits");
    }
}
```

public class Main {
    static boolean isPalindrome(String text) {
        StringBuilder cleaned = new StringBuilder();
        for (char c : text.toCharArray()) {
            if (Character.isLetterOrDigit(c)) cleaned.append(Character.toLowerCase(c));
        }
        String forward = cleaned.toString();
        return forward.equals(cleaned.reverse().toString());
    }

    public static void main(String[] args) {
        String[] phrases = {"A man, a plan, a canal: Panama", "Java", "Was it a car or a cat I saw?"};
        for (String p : phrases) {
            System.out.println(p + " -> " + isPalindrome(p));

=== lesson java-input | Reading input: Scanner | 55
## Reading what the user types

Programs read keyboard input from **standard input**, `System.in`. The easiest way is a **`Scanner`**, from the `java.util` package (so it needs an `import` at the top of the file):

```java
// stdin: Ada | 36
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        System.out.print("What's your name? ");
        String name = in.nextLine();
        System.out.print("How old are you? ");
        int age = in.nextInt();
        System.out.println();
        System.out.println("Hi " + name + ", next year you'll be " + (age + 1) + ".");
    }
}
```

In DevQuest, the input lines go in the box under the example (one line per read) before you press **▶ Run**; this example fills in `Ada` and `36` for you (from its `// stdin:` comment), and you can change them. As in a real terminal capture, what you type isn't repeated in the output, which is why the example prints an empty line before its answer.

| Method | Reads |
|---|---|
| `nextLine()` | the rest of the current line, as a `String` |
| `next()` | the next word (up to whitespace) |
| `nextInt()`, `nextDouble()`, `nextLong()`, `nextBoolean()` | the next token, converted |
| `hasNextInt()`, `hasNextLine()`, `hasNext()` | whether such input is available (without reading it) |

## The nextInt / nextLine trap

`nextInt()` reads the number but **not** the line break after it. A `nextLine()` right after returns the empty rest of that line:

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner("42\nAda\n");   // a Scanner can also read from a string, handy for tests
        int age = in.nextInt();
        String name = in.nextLine();             // reads "" (the rest of the "42" line)
        System.out.println("[" + name + "]");
        name = in.nextLine();                    // now reads "Ada"
        System.out.println("[" + name + "]");
    }
}
```

Two simple fixes: call `in.nextLine()` once after `nextInt()` to skip the line break, or read every line with `nextLine()` and convert it yourself with `Integer.parseInt(line.strip())`. The second approach is more robust, and is how most programs read line-based input.

## Parsing and validating

`Integer.parseInt`, `Double.parseDouble` and `Long.parseLong` convert text to numbers, and throw `NumberFormatException` for invalid text. `hasNextInt()` lets you check before reading:

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner("12 seven 30 4.5 8");
        int sum = 0;
        while (in.hasNext()) {
            if (in.hasNextInt()) sum += in.nextInt();
            else System.out.println("skipping " + in.next());
        }
        System.out.println("sum = " + sum);
    }
}
```

## Reading until the end of input

`while (in.hasNextLine())` processes every line until the input ends, which is how command-line tools read files piped into them (`java Main < data.txt`).

import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int count = 0;
        int sum = 0;
        int max = Integer.MIN_VALUE;
        while (in.hasNextLine()) {
            String line = in.nextLine().strip();
            if (line.isEmpty()) continue;
            try {
                int n = Integer.parseInt(line);
                count++;
                sum += n;
                max = Math.max(max, n);
            } catch (NumberFormatException e) {
                System.out.println("ignored: " + line);
            }
        }
        if (count == 0) System.out.println("no numbers");
        else System.out.println("count=" + count + " sum=" + sum + " max=" + max);
    }
}

import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        String line = in.nextLine().strip();
        String[] words = line.split("\\s+");
        String longest = "";
        for (String w : words) {
            if (w.length() > longest.length()) longest = w;
        }
        System.out.println("Words: " + words.length);
        System.out.println("Longest: " + longest);
        StringBuilder report = new StringBuilder();
        String lower = line.toLowerCase();
        for (char v : "aeiou".toCharArray()) {
            int count = 0;
            for (char c : lower.toCharArray()) {
                if (c == v) count++;
            }
            if (count > 0) {
                if (report.length() > 0) report.append(' ');
                report.append(v).append('=').append(count);
            }
        }
        System.out.println(report);
    }
}
