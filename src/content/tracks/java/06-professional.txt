=== lesson java-packages | Packages, modules and JARs | 60
## Packages: organising classes

Real projects have hundreds of classes, organised into **packages**: namespaces that mirror folders. The first line of a file declares its package, and the file lives in the matching folder:

```
src/main/java/
└── com/acme/shop/
    ├── Main.java                 package com.acme.shop;
    ├── model/
    │   ├── Product.java          package com.acme.shop.model;
    │   └── Order.java
    └── service/
        └── OrderService.java     package com.acme.shop.service;
```

```
package com.acme.shop.service;

import com.acme.shop.model.Order;
import com.acme.shop.model.Product;
import java.util.List;

public class OrderService {
    public Order place(List<Product> products) { ... }
}
```

- Package names are lower case and start with a reversed domain you control (`com.acme`), which keeps names globally unique.
- **`import`** lets you use a class by its short name; without it you'd write `java.util.List` in full. `java.lang` (`String`, `Math`, `System`...) is imported automatically. `import java.util.*;` imports a whole package (style guides usually prefer explicit imports).
- The **fully qualified name** of a class includes its package: `com.acme.shop.model.Order`.

## Access across packages

Packages are also an encapsulation boundary. With no modifier, a class or member is **package-private**: visible only inside its package. Make public only what other packages need: the API, not the helpers.

## JAR files

Compiled classes are distributed as **JAR files** (Java ARchives, ZIP files of `.class` files plus metadata):

```
javac -d out $(find src -name "*.java")
jar --create --file shop.jar --main-class com.acme.shop.Main -C out .
java -jar shop.jar
```

Libraries are JARs on the **classpath**; a runnable application JAR names its main class in its manifest. In practice, build tools (next lesson) do all of this, and frameworks like Spring Boot package everything, dependencies included, into one runnable "fat" JAR.

## Modules (Java 9+)

The **Java Platform Module System** (JPMS) adds a level above packages: a **module** declares, in `module-info.java`, which packages it exports and which modules it needs:

```
module com.acme.shop {
    requires java.sql;
    exports com.acme.shop.api;      // only this package is visible to other modules
}
```

Modules give strong encapsulation (non-exported packages are invisible even if their classes are public) and let `jlink` build a small custom runtime. The JDK itself is modularised (`java.base`, `java.sql`, `java.net.http`...). Many applications still run on the classpath without their own `module-info.java`, but you'll meet modules in libraries and when building lean container images.

=== lesson java-build | Build tools: Maven and Gradle | 55
## Why build tools

A real project needs more than `javac`: downloading libraries (and *their* libraries), compiling hundreds of files, running tests, packaging JARs, generating documentation, publishing releases. **Build tools** automate all of it from a declarative description of the project. The two standards:

- **Maven** (2004): XML configuration (`pom.xml`), strict conventions, very widespread in enterprises.
- **Gradle** (2012): configuration as code (Kotlin or Groovy, `build.gradle.kts`), faster incremental builds, standard for Android.

Both use the same **standard layout** and the same central repository of libraries, **Maven Central**:

```
my-app/
├── pom.xml (or build.gradle.kts)
└── src/
    ├── main/java/        application code
    ├── main/resources/   configuration files, templates
    ├── test/java/        tests
    └── test/resources/
```

## Maven

```
<project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>
  <groupId>com.acme</groupId>
  <artifactId>shop</artifactId>
  <version>1.0.0</version>

  <properties>
    <maven.compiler.release>21</maven.compiler.release>
  </properties>

  <dependencies>
    <dependency>
      <groupId>com.google.code.gson</groupId>
      <artifactId>gson</artifactId>
      <version>2.11.0</version>
    </dependency>
    <dependency>
      <groupId>org.junit.jupiter</groupId>
      <artifactId>junit-jupiter</artifactId>
      <version>5.11.0</version>
      <scope>test</scope>
    </dependency>
  </dependencies>
</project>
```

A library is identified by **coordinates**: `groupId:artifactId:version`. Maven downloads it and everything it depends on (**transitive dependencies**). The `test` scope keeps JUnit out of the production JAR.

Maven's lifecycle runs phases in order; each command runs all phases before it:

```
mvn compile     # compile src/main/java
mvn test        # ...and run the tests
mvn package     # ...and build target/shop-1.0.0.jar
mvn install     # ...and copy it to your local repository (~/.m2)
mvn clean       # delete target/
```

## Gradle

The same project in Gradle's Kotlin DSL:

```
plugins {
    application
}

java {
    toolchain { languageVersion = JavaLanguageVersion.of(21) }
}

repositories { mavenCentral() }

dependencies {
    implementation("com.google.code.gson:gson:2.11.0")
    testImplementation("org.junit.jupiter:junit-jupiter:5.11.0")
}

application { mainClass = "com.acme.shop.Main" }
```

```
./gradlew build     # compile, test and package
./gradlew run       # run the application
./gradlew test
```

The `gradlew` script (the **Gradle wrapper**, committed to the repository) downloads the right Gradle version, so every developer and CI server builds the same way; Maven has an equivalent `mvnw`.

## Dependency hygiene

- Pin versions, and update them regularly (tools like Dependabot or Renovate open the pull requests).
- Fewer dependencies means a smaller attack surface: check a library is maintained before adding it.
- Scan for known vulnerabilities (OWASP Dependency-Check, GitHub's alerts): the Log4Shell vulnerability (2021) in a popular logging library affected a huge part of the Java world.
- `mvn dependency:tree` / `./gradlew dependencies` show where a library comes from.

=== lesson java-testing | Testing with JUnit | 65
## Automated tests

A test is code that checks other code: it calls a method with known inputs and **asserts** the result. A good test suite runs in seconds, after every change, and catches regressions long before users do. Java's standard test framework is **JUnit 5** (Jupiter):

```
import static org.junit.jupiter.api.Assertions.*;

import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.CsvSource;

class PriceCalculatorTest {
    private PriceCalculator calc;

    @BeforeEach
    void setUp() {
        calc = new PriceCalculator(0.20);      // a fresh object for every test
    }

    @Test
    void addsVat() {
        assertEquals(120.0, calc.gross(100.0), 0.001);
    }

    @Test
    void rejectsNegativePrices() {
        var e = assertThrows(IllegalArgumentException.class, () -> calc.gross(-1));
        assertEquals("price must not be negative", e.getMessage());
    }

    @ParameterizedTest
    @CsvSource({"0, 0", "10, 12", "99.99, 119.988"})
    void grossForManyPrices(double net, double expected) {
        assertEquals(expected, calc.gross(net), 0.001);
    }
}
```

- Test classes live in `src/test/java`, usually one per class under test, named `...Test`.
- `@Test` marks a test method; `@BeforeEach` runs before every test (fresh state, so tests don't affect each other); `@AfterEach`, `@BeforeAll` and `@AfterAll` also exist.
- Assertions: `assertEquals(expected, actual)` (with a tolerance for doubles), `assertTrue`, `assertNull`, `assertThrows`, `assertAll`. **AssertJ** offers more readable fluent assertions: `assertThat(list).hasSize(3).contains("a")`.
- `@ParameterizedTest` runs one test with many inputs.
- `mvn test` or `./gradlew test` runs everything; IDEs run single tests with one click.

## What and how to test

- Test **behaviour**, through the public API, not private details: tests then survive refactoring.
- Name tests after the behaviour (`rejectsNegativePrices`), and keep the **Arrange, Act, Assert** shape.
- Cover the edges: empty input, zero, negative numbers, maximum values, `null`, duplicates.
- Each test should fail for one reason, and never depend on another test's leftovers.
- Replace slow or external dependencies (databases, clocks, payment APIs) with **test doubles**: hand-written fakes behind an interface, or a mocking library like **Mockito** (`when(repo.find(1)).thenReturn(...)`).
- **Test-driven development** (TDD): write a failing test, make it pass with the simplest code, refactor. It keeps designs small and testable.

## Testing without a framework

DevQuest runs single files without JUnit on the classpath, so the exercises use a few lines of home-made assertions. The ideas are identical:

```java
public class Main {
    static int passed = 0, failed = 0;

    static void check(String name, Object expected, Object actual) {
        if (java.util.Objects.equals(expected, actual)) passed++;
        else {
            failed++;
            System.out.println("FAIL " + name + ": expected " + expected + " but got " + actual);
        }
    }

    static String slugify(String title) {
        return title.strip().toLowerCase().replaceAll("[^a-z0-9]+", "-").replaceAll("(^-|-$)", "");
    }

    public static void main(String[] args) {
        check("simple", "hello-world", slugify("Hello World"));
        check("punctuation", "java-21-is-here", slugify("Java 21 is here!"));
        check("extra spaces", "a-b", slugify("  a   b  "));
        check("empty", "", slugify(""));
        System.out.println(passed + " passed, " + failed + " failed");
    }
}
```

    static int passed = 0, failed = 0;

    static void check(String name, boolean expected, boolean actual) {
        if (expected == actual) passed++;
        else {
            failed++;
            System.out.println("FAIL " + name);
        }

    static boolean isValidIsbn10(String isbn) {
        String digits = isbn.replace("-", "");
        if (digits.length() != 10) return false;
        int sum = 0;
        for (int i = 0; i < 10; i++) {
            char c = digits.charAt(i);
            int value;
            if (Character.isDigit(c)) value = c - '0';
            else if (c == 'X' && i == 9) value = 10;
            else return false;
            sum += value * (10 - i);
        }
        return sum % 11 == 0;
    }

        check("valid", true, isValidIsbn10("0-306-40615-2"));
        check("valid with X", true, isValidIsbn10("0-8044-2957-X"));
        check("no hyphens", true, isValidIsbn10("0306406152"));
        check("wrong check digit", false, isValidIsbn10("0-306-40615-3"));

=== lesson java-io | Files and I/O | 65
## java.nio.file: Path and Files

Modern Java reads and writes files with **`Path`** (a location) and the static helpers in **`Files`** (`java.nio.file`, Java 7+):

```java
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;

public class Main {
    public static void main(String[] args) throws IOException {
        Path dir = Files.createTempDirectory("devquest");
        Path notes = dir.resolve("notes.txt");

        Files.writeString(notes, "first line\n");
        Files.writeString(notes, "second line\n", java.nio.file.StandardOpenOption.APPEND);
        Files.write(dir.resolve("todo.txt"), List.of("buy milk", "learn Java"));

        System.out.println(Files.readString(notes).strip());
        List<String> todo = Files.readAllLines(dir.resolve("todo.txt"));
        System.out.println(todo.size() + " tasks: " + todo);
        System.out.println(Files.exists(notes) + " " + Files.size(notes) + " bytes");
        System.out.println(notes.getFileName() + " in " + notes.getParent().getFileName().toString().startsWith("devquest"));
    }
}
```

| Method | Does |
|---|---|
| `Files.readString(path)` / `writeString` | whole file as one string |
| `Files.readAllLines` / `write(path, lines)` | list of lines |
| `Files.lines(path)` | a lazy `Stream<String>` (for big files; close it with try-with-resources) |
| `Files.newBufferedReader` / `newBufferedWriter` | line-by-line streaming |
| `Files.exists`, `isDirectory`, `size`, `createDirectories`, `copy`, `move`, `delete`, `list`, `walk` | file system operations |

`Path.of("data", "orders.csv")` builds paths portably (no `\` versus `/` worries); `resolve` appends a part. File operations throw the checked `IOException`, which you must catch or declare (here `main` declares it). Text uses **UTF-8** by default since Java 18.

## Processing a file as a stream

```java
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;
import java.util.stream.Stream;

public class Main {
    public static void main(String[] args) throws IOException {
        Path csv = Files.createTempFile("sales", ".csv");
        Files.write(csv, List.of("region,amount", "north,120", "south,300", "north,80"));

        try (Stream<String> lines = Files.lines(csv)) {
            int northTotal = lines.skip(1)                       // skip the header
                .map(line -> line.split(","))
                .filter(parts -> parts[0].equals("north"))
                .mapToInt(parts -> Integer.parseInt(parts[1]))
                .sum();
            System.out.println("north: " + northTotal);
        }
        Files.delete(csv);
    }
}
```

Real CSV has quoted fields with commas inside, so production code uses a library (Apache Commons CSV, OpenCSV, Jackson) instead of `split`.

## Streams of bytes and characters

Under `Files` lies the older `java.io` package: **byte streams** (`InputStream`/`OutputStream`) for binary data and **character streams** (`Reader`/`Writer`) for text, combined like building blocks (`new BufferedReader(new InputStreamReader(socket.getInputStream(), UTF_8))`). You'll meet them with network sockets, HTTP bodies and libraries. Always wrap them in try-with-resources.

## Serialization

Turning objects into bytes or text to store or send them is **serialization**. Java's built-in `Serializable` mechanism is considered legacy and a security risk; modern code uses **JSON** with Jackson or Gson (`objectMapper.writeValueAsString(order)`), or formats like Protocol Buffers.

=== lesson java-concurrency | Concurrency and virtual threads | 85
## Doing several things at once

A **thread** is an independent path of execution inside a program. Servers handle many requests at once with threads; desktop apps keep the interface responsive while working in the background. Java has had threads since version 1.0, and Java 21 added **virtual threads**, which make them cheap enough to use by the million.

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> System.out.println("hello from " + Thread.currentThread().getName()), "worker-1");
        worker.start();          // runs the lambda concurrently
        worker.join();           // wait for it to finish
        System.out.println("main is done");
    }
}
```

`start()` begins the thread (calling `run()` directly would just run it in the current thread); `join()` waits for it.

## Executors: don't manage threads by hand

In real code, submit **tasks** to an **ExecutorService**, which manages threads for you, and get results back as **Futures**:

```java
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

public class Main {
    static long slowSquare(int n) throws InterruptedException {
        Thread.sleep(100);           // pretend this calls a slow service
        return (long) n * n;
    }

    public static void main(String[] args) throws Exception {
        long start = System.nanoTime();
        try (ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor()) {
            List<Future<Long>> futures = new ArrayList<>();
            for (int i = 1; i <= 50; i++) {
                int n = i;
                futures.add(pool.submit(() -> slowSquare(n)));
            }
            long sum = 0;
            for (Future<Long> f : futures) sum += f.get();   // get() waits for each result
            System.out.println("sum of squares: " + sum);
        }
        long ms = (System.nanoTime() - start) / 1_000_000;
        System.out.println(ms < 2000 ? "finished in well under the 5 s a single thread would need" : "slow");
    }
}
```

Fifty tasks that each wait 100 ms finish in about 100 ms, because they wait **concurrently**. `Executors.newVirtualThreadPerTaskExecutor()` (Java 21) runs each task on its own **virtual thread**: a lightweight thread managed by the JVM, ideal for I/O-heavy work (HTTP calls, database queries). For CPU-heavy work, a fixed pool sized to the processor cores (`Executors.newFixedThreadPool(n)`) is better. The executor is `AutoCloseable` (Java 19+): closing it waits for all tasks.

## Race conditions

Threads share memory, and that's where bugs start. `count++` is really three steps (read, add, write), so two threads can interleave them and lose updates:

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.atomic.AtomicInteger;

public class Main {
    static int unsafeCount = 0;
    static final AtomicInteger safeCount = new AtomicInteger();
    static int lockedCount = 0;
    static final Object lock = new Object();

    public static void main(String[] args) {
        try (ExecutorService pool = Executors.newFixedThreadPool(4)) {
            for (int t = 0; t < 4; t++) {
                pool.submit(() -> {
                    for (int i = 0; i < 100_000; i++) {
                        unsafeCount++;                      // race condition
                        safeCount.incrementAndGet();        // atomic
                        synchronized (lock) { lockedCount++; }  // one thread at a time
                    }
                });
            }
        }
        System.out.println("atomic: " + safeCount.get() + ", synchronized: " + lockedCount);
        System.out.println("unsafe lost updates: " + (unsafeCount < 400_000 ? "probably" : "not this time"));
    }
}
```

Tools for safe sharing, from simplest to most delicate:

1. **Don't share mutable state**: give each task its own data and combine results at the end (as with the futures above), or use immutable objects.
2. **Concurrent collections**: `ConcurrentHashMap`, `CopyOnWriteArrayList`, `BlockingQueue` (for producer-consumer pipelines).
3. **Atomic variables**: `AtomicInteger`, `AtomicLong`, `LongAdder`.
4. **Locks**: `synchronized` blocks and methods, or `ReentrantLock`; keep critical sections short, and always acquire several locks in the same order to avoid **deadlocks**.

## CompletableFuture: composing asynchronous work

`CompletableFuture` chains asynchronous steps, much like JavaScript promises:

```java
import java.util.concurrent.CompletableFuture;

public class Main {
    public static void main(String[] args) {
        CompletableFuture<String> user = CompletableFuture.supplyAsync(() -> "ada");
        CompletableFuture<Integer> orders = CompletableFuture.supplyAsync(() -> 3);
        String summary = user
            .thenCombine(orders, (name, count) -> name + " has " + count + " orders")
            .thenApply(String::toUpperCase)
            .exceptionally(e -> "unavailable")
            .join();
        System.out.println(summary);
    }
}
```

With virtual threads, much code that used to need `CompletableFuture` chains can again be written in plain, blocking, sequential style, one virtual thread per request, which is easier to read and debug.

=== lesson java-modern | Modern Java: pattern matching and design | 75
## Pattern matching

Java 16 to 21 added **pattern matching**, which tests the shape of a value and extracts its parts in one step. With sealed types and records, it gives Java a clean way to model data, close to functional languages:

```java
public class Main {
    sealed interface Shape permits Circle, Rectangle, Triangle {}
    record Circle(double radius) implements Shape {}
    record Rectangle(double width, double height) implements Shape {}
    record Triangle(double base, double height) implements Shape {}

    static double area(Shape shape) {
        return switch (shape) {
            case Circle c -> Math.PI * c.radius() * c.radius();
            case Rectangle(double w, double h) -> w * h;               // record pattern: deconstruct
            case Triangle(double b, double h) when b <= 0 -> 0;          // guard
            case Triangle(double b, double h) -> b * h / 2;
        };
    }

    public static void main(String[] args) {
        Shape[] shapes = {new Circle(1), new Rectangle(2, 3), new Triangle(4, 5), new Triangle(-1, 2)};
        for (Shape s : shapes) System.out.printf("%s -> %.2f%n", s, area(s));
    }
}
```

- `case Circle c` is a **type pattern**: it matches circles and binds `c`.
- `case Rectangle(double w, double h)` is a **record pattern**: it deconstructs the record into its components (patterns can nest).
- `when` adds a **guard** condition.
- Because `Shape` is **sealed**, the compiler knows the switch covers every case: no `default`, and adding a new shape makes every incomplete switch a compile error. This is the same exhaustiveness check TypeScript gives discriminated unions.

Pattern matching also works with `instanceof` (`if (obj instanceof String s && !s.isEmpty())`) and for `null` (`case null ->`).

## Data-oriented programming

Combining records (data), sealed interfaces (closed sets of alternatives) and pattern-matching switches (behaviour) is called **data-oriented programming**. It complements classic OOP: use polymorphic methods when the set of operations is fixed and new types are added often; use sealed hierarchies and switches when the set of types is fixed and new operations are added often (like an interpreter's expression types, or a payment workflow's states).

## Design patterns in Java

The classic design patterns (*Design Patterns*, 1994, written with C++ and Smalltalk; Java made them famous) appear throughout Java code and frameworks:


            case Mul(Expr l, Expr r) -> eval(l) * eval(r);
            case Neg(Expr inner) -> -eval(inner);

=== lesson java-jvm | Inside the JVM | 60
## What happens when a Java program runs

1. **Class loading**: the JVM finds `.class` files (in JARs, on the classpath or module path) and loads them lazily, the first time a class is used. **Class loaders** form a hierarchy (bootstrap, platform, application), which is also how application servers isolate applications.
2. **Verification**: the bytecode is checked for safety (no invalid jumps, type errors or stack overflows).
3. **Execution**: the bytecode is first **interpreted**. The JVM profiles which methods are "hot", and the **JIT compiler** (C1 quickly, then C2 with aggressive optimisations: inlining, escape analysis, loop unrolling) compiles them to native machine code. This is why Java programs get faster after a **warm-up** period, and why micro-benchmarks need a harness like **JMH**.

You can look at bytecode with `javap -c Main.class`: a stack-based instruction set (`iload`, `iadd`, `invokevirtual`...).

## Memory: stack and heap

- Each thread has a **stack** of frames, one per method call, holding local variables and partial results. Primitives in local variables live there. Deep recursion overflows it (`StackOverflowError`).
- **Objects** live on the **heap**, shared by all threads. Local variables hold references to them.

```java
public class Main {
    public static void main(String[] args) {
        Runtime rt = Runtime.getRuntime();
        System.out.println("processors: " + (rt.availableProcessors() > 0));
        System.out.println("max heap set: " + (rt.maxMemory() > 0));
        long before = rt.totalMemory() - rt.freeMemory();
        int[][] big = new int[1000][1000];      // about 4 MB on the heap
        long after = rt.totalMemory() - rt.freeMemory();
        System.out.println("allocated something: " + (after > before || big.length == 1000));
    }
}
```

## Garbage collection

The **garbage collector** frees objects that are no longer reachable from any live reference (local variables, static fields, other live objects). Most objects die young, so the heap is split into generations, and young objects are collected cheaply and often. Modern collectors:

- **G1** (default): balances throughput and pause times, for most applications;
- **ZGC** and **Shenandoah**: pauses of a millisecond or less even with huge heaps, for latency-sensitive services;
- **Parallel**: maximum throughput for batch jobs.

GC doesn't make memory leaks impossible: objects kept reachable by mistake (a static map that only grows, listeners never removed, caches without limits) are never freed and eventually cause `OutOfMemoryError`.

## Tuning and observing

```
java -Xms512m -Xmx2g -XX:+UseZGC -jar app.jar     # initial and maximum heap, collector
jcmd <pid> GC.heap_info                           # inspect a running JVM
jstack <pid>                                      # thread dump (find deadlocks, stuck threads)
jfr / JDK Mission Control                         # low-overhead profiling and event recording
```

In containers, modern JVMs respect the container's CPU and memory limits. For fast start-up (serverless, CLIs), **GraalVM Native Image** compiles Java ahead of time into a native executable that starts in milliseconds, at the cost of some flexibility.

The JVM runs many languages besides Java: **Kotlin**, **Scala**, **Groovy** and **Clojure** all compile to bytecode and share the same libraries, tools and runtime.

## Java on the network

Networking has been part of Java since 1995 (sockets in `java.net`), and most Java code today runs as **web services**: programs that receive HTTP requests and send responses, and that call other services over HTTP.

- **Sockets** (`Socket`, `ServerSocket`) are the low level: a two-way stream of bytes between two programs over TCP. Protocols such as HTTP are built on top of them.
- The **HTTP client** (`java.net.http.HttpClient`, Java 11+) calls web APIs, with HTTP/2, timeouts and asynchronous requests.
- The JDK includes a small **HTTP server** (`com.sun.net.httpserver`), enough for tools, tests and learning. Production services use a framework: **Spring Boot** (with an embedded Tomcat or Netty server), Quarkus, Micronaut or Javalin. The classic standard underneath is the **Servlet** API (Jakarta EE), which Spring MVC is built on.

This example starts a server on a free local port, then calls it with the client, all inside one program, so it runs without internet access:

```java
import com.sun.net.httpserver.HttpServer;
import java.net.InetSocketAddress;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.nio.charset.StandardCharsets;

public class Main {
    public static void main(String[] args) throws Exception {
        HttpServer server = HttpServer.create(new InetSocketAddress("127.0.0.1", 0), 0);   // port 0: any free port
        server.createContext("/hello", exchange -> {
            String query = exchange.getRequestURI().getQuery();
            String name = query != null && query.startsWith("name=") ? query.substring(5) : "world";
            byte[] body = ("{\"greeting\": \"Hello, " + name + "!\"}").getBytes(StandardCharsets.UTF_8);
            exchange.getResponseHeaders().set("Content-Type", "application/json");
            exchange.sendResponseHeaders(200, body.length);
            exchange.getResponseBody().write(body);
            exchange.close();
        });
        server.start();
        int port = server.getAddress().getPort();

        HttpClient client = HttpClient.newHttpClient();
        HttpRequest request = HttpRequest.newBuilder(URI.create("http://127.0.0.1:" + port + "/hello?name=Ada")).GET().build();
        HttpResponse<String> response = client.send(request, HttpResponse.BodyHandlers.ofString());
        System.out.println(response.statusCode() + " " + response.headers().firstValue("Content-Type").orElse("?"));
        System.out.println(response.body());

        HttpResponse<String> missing = client.send(HttpRequest.newBuilder(URI.create("http://127.0.0.1:" + port + "/nope")).build(), HttpResponse.BodyHandlers.ofString());
        System.out.println(missing.statusCode());
        server.stop(0);
    }
}
```

The pieces of an HTTP exchange, from either side:

| Part | Request (client) | Response (server) |
|---|---|---|
| start | method + path: `GET /hello?name=Ada` | status code: `200`, `404`, `500`... |
| headers | `Accept`, `Authorization`, `Content-Type` | `Content-Type`, `Cache-Control`, `Location` |
| body | JSON for `POST`/`PUT` | the resource, usually JSON |

The **client** builds an immutable `HttpRequest` (a builder: method, URI, headers, body, timeout), sends it with `send` (blocking: ideal with virtual threads) or `sendAsync` (returns a `CompletableFuture`), and reads the body with a `BodyHandler` (`ofString`, `ofFile`, `ofLines`...). Always set a **timeout** on real network calls (`.timeout(Duration.ofSeconds(5))`), because remote services can hang.

import com.sun.net.httpserver.HttpExchange;
import com.sun.net.httpserver.HttpServer;
import java.io.IOException;
import java.net.InetSocketAddress;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.nio.charset.StandardCharsets;
import java.util.HashMap;
import java.util.Map;

public class Main {
    static Map<String, String> params(String query) {
        Map<String, String> map = new HashMap<>();
        if (query == null) return map;
        for (String pair : query.split("&")) {
            String[] kv = pair.split("=", 2);
            if (kv.length == 2) map.put(kv[0], kv[1]);
        }
        return map;
    }

    static void send(HttpExchange exchange, int status, String text) throws IOException {
        byte[] body = text.getBytes(StandardCharsets.UTF_8);
        exchange.sendResponseHeaders(status, body.length);
        exchange.getResponseBody().write(body);
        exchange.close();
    }

    static void handleAdd(HttpExchange exchange) throws IOException {
        Map<String, String> p = params(exchange.getRequestURI().getQuery());
        try {
            long a = Long.parseLong(p.get("a"));
            long b = Long.parseLong(p.get("b"));
            send(exchange, 200, String.valueOf(a + b));
        } catch (NumberFormatException e) {
            send(exchange, 400, "bad request");
        }
    }

    public static void main(String[] args) throws Exception {
        HttpServer server = HttpServer.create(new InetSocketAddress("127.0.0.1", 0), 0);
        server.createContext("/add", Main::handleAdd);
        server.start();
        String base = "http://127.0.0.1:" + server.getAddress().getPort();
        HttpClient client = HttpClient.newHttpClient();
        for (String path : new String[] {"/add?a=2&b=40", "/add?a=2&b=x", "/add?a=-10&b=3"}) {
            HttpResponse<String> r = client.send(HttpRequest.newBuilder(URI.create(base + path)).build(), HttpResponse.BodyHandlers.ofString());
            System.out.println(r.statusCode() + " " + r.body());
        }
        server.stop(0);
    }
}

import java.util.Comparator;
import java.util.List;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class Main {
    public static void main(String[] args) throws Exception {
        List<String> documents = List.of(
            "The quick brown fox jumps over the lazy dog.",
            "The fox sleeps. The dog barks!",
            "A fox, the end; the END?");

        Map<String, Integer> counts = new ConcurrentHashMap<>();
        try (ExecutorService pool = Executors.newFixedThreadPool(3)) {
            for (String doc : documents) {
                pool.submit(() -> {
                    for (String word : doc.toLowerCase().split("[^a-z]+")) {
                        if (!word.isEmpty()) counts.merge(word, 1, Integer::sum);
                    }
                });
            }
        }
        counts.entrySet().stream()
            .sorted(Comparator.comparing((Map.Entry<String, Integer> e) -> -e.getValue()).thenComparing(Map.Entry::getKey))
            .limit(3)
            .forEach(e -> System.out.println(e.getKey() + ": " + e.getValue()));
        System.out.println("total: " + counts.values().stream().mapToInt(Integer::intValue).sum());
    }
}
::expected
the: 6
fox: 3
dog: 2
total: 21
::hints
- `ConcurrentHashMap.merge(word, 1, Integer::sum)` is atomic, so tasks can update it safely.
- Closing the executor (try-with-resources) waits until every task is done.
- Sort entries by count descending, then by key, and `limit(3)`.
