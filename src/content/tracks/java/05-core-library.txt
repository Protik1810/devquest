## Handling errors with try and catch

When something goes wrong at run time, Java **throws** an exception object. If nothing **catches** it, the program stops with a stack trace. `try`/`catch` handles it:

```java
public class Main {
    public static void main(String[] args) {
        String[] inputs = {"42", "x7", "-3"};
        for (String input : inputs) {
            try {
                int n = Integer.parseInt(input);
                System.out.println("square root of " + n + " = " + safeSqrt(n));
            } catch (NumberFormatException e) {
                System.out.println("not a number: " + input);
            } catch (IllegalArgumentException e) {
                System.out.println("invalid: " + e.getMessage());
            } finally {
                System.out.println("-- done with " + input);
            }
        }
    }

    static double safeSqrt(int n) {
        if (n < 0) throw new IllegalArgumentException("negative input " + n);
        return Math.sqrt(n);
    }
}
```

- The `try` block runs until an exception is thrown; then the first `catch` whose type matches runs.
- Order matters: more specific types first (`NumberFormatException` is a subclass of `IllegalArgumentException`, so it must come before it).
- **`finally`** always runs, exception or not, which suits clean-up.
- `throw new SomeException("message")` raises your own; `e.getMessage()` reads the message.
- One `catch` can handle several unrelated types: `catch (IOException | SQLException e)`.

## The exception hierarchy: checked and unchecked

```
Throwable
├── Error                      (JVM problems: OutOfMemoryError, StackOverflowError) — don't catch
└── Exception
    ├── RuntimeException       (unchecked: bugs and bad arguments)
    │   ├── NullPointerException, IllegalArgumentException, IllegalStateException,
    │   │   IndexOutOfBoundsException, ArithmeticException, ClassCastException...
    └── IOException, SQLException, ...   (checked)
```

Java is unusual in having **checked exceptions**: for anything that isn't a `RuntimeException` (like `IOException`), the compiler forces you to either catch it or **declare** it with `throws`:

```java
import java.io.IOException;

public class Main {
    static String readConfig(String name) throws IOException {
        if (name.isBlank()) throw new IOException("no file name given");
        return "debug=true";
    }

    public static void main(String[] args) {
        try {
            System.out.println(readConfig("app.properties"));
            System.out.println(readConfig(""));
        } catch (IOException e) {
            System.out.println("Could not read config: " + e.getMessage());
        }
    }
}
```

The idea: checked exceptions are for problems a caller can reasonably handle (a missing file, a network failure); unchecked ones signal bugs or invalid arguments. In practice, modern APIs and frameworks lean towards unchecked exceptions, and it's common to wrap a checked exception in an unchecked one when a layer can't do anything useful with it: `throw new UncheckedIOException(e)`.

## Custom exceptions

Define your own exception type when callers need to recognise a specific failure:

```java
public class Main {
    public static void main(String[] args) {
        Wallet w = new Wallet(30);
        try {
            w.pay(50);
        } catch (InsufficientFundsException e) {
            System.out.println(e.getMessage() + " (short by " + e.getShortBy() + ")");
        }
    }
}

class InsufficientFundsException extends RuntimeException {
    private final double shortBy;

    InsufficientFundsException(double shortBy) {
        super("Insufficient funds");
        this.shortBy = shortBy;
    }

    double getShortBy() { return shortBy; }
}

class Wallet {
    private double balance;
    Wallet(double balance) { this.balance = balance; }

    void pay(double amount) {
        if (amount > balance) throw new InsufficientFundsException(amount - balance);
        balance -= amount;
    }
}
```

When you catch an exception and throw another, pass the original as the **cause** (`new ServiceException("...", e)`), so the stack trace keeps the whole story.

## try-with-resources

Files, network connections and database connections must be **closed** even when errors happen. `try (...)` closes anything that implements `AutoCloseable`, automatically and in reverse order:

```java
public class Main {
    public static void main(String[] args) {
        try (Resource db = new Resource("database"); Resource file = new Resource("log file")) {
            System.out.println("working with both");
            throw new IllegalStateException("something failed");
        } catch (IllegalStateException e) {
            System.out.println("caught: " + e.getMessage());
        }
    }
}

class Resource implements AutoCloseable {
    private final String name;
    Resource(String name) {
        this.name = name;
        System.out.println("open " + name);
    }

    @Override
    public void close() {
        System.out.println("close " + name);
    }
}
```

Always prefer try-with-resources over closing in `finally` by hand.

## Good practice

- **Don't swallow exceptions**: an empty `catch {}` hides bugs. At least log them.
- Catch exceptions where you can **do something** about them (retry, use a default, show a message); otherwise let them propagate.
- **Fail fast**: validate arguments at the start of a method (`Objects.requireNonNull(name)`, `throw new IllegalArgumentException(...)`).
- Don't use exceptions for normal control flow (like ending a loop).

## The Collections Framework

Arrays have a fixed size. The **Collections Framework** (`java.util`) provides growable, well-tested data structures behind a few interfaces:

| Interface | Holds | Main implementations |
|---|---|---|
| `List<E>` | an ordered sequence, duplicates allowed | `ArrayList`, `LinkedList` |
| `Set<E>` | unique elements | `HashSet` (fast, unordered), `LinkedHashSet` (insertion order), `TreeSet` (sorted) |
| `Map<K, V>` | key → value pairs, unique keys | `HashMap`, `LinkedHashMap`, `TreeMap` |
| `Queue<E>` / `Deque<E>` | elements processed in order | `ArrayDeque`, `PriorityQueue` |

The `<E>` is a **type parameter** (generics, next lesson): `List<String>` holds only strings, checked by the compiler. Declare variables with the **interface** type and choose the implementation on the right: `List<String> names = new ArrayList<>();`.

Collections hold **objects**, so primitives are stored as their wrapper classes: `List<Integer>`, not `List<int>`. Java converts automatically (**autoboxing**).

## Lists

```java
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<String> tasks = new ArrayList<>();
        tasks.add("write tests");
        tasks.add("fix bug");
        tasks.add(0, "coffee");                 // insert at index 0
        System.out.println(tasks + " size " + tasks.size());
        System.out.println(tasks.get(1) + " " + tasks.contains("fix bug") + " " + tasks.indexOf("fix bug"));
        tasks.set(2, "fix two bugs");
        tasks.remove("coffee");
        Collections.sort(tasks);
        System.out.println(tasks);
        for (String t : tasks) System.out.println("- " + t);

        List<Integer> fixed = List.of(3, 1, 2);    // immutable list
        System.out.println(fixed);
    }
}
```

`List.of(...)`, `Set.of(...)` and `Map.of(...)` create **immutable** collections (adding throws `UnsupportedOperationException`): ideal for constants and return values.

Removing elements while looping with for-each throws `ConcurrentModificationException`; use `list.removeIf(x -> ...)` instead.

## Sets

```java
import java.util.HashSet;
import java.util.List;
import java.util.Set;
import java.util.TreeSet;

public class Main {
    public static void main(String[] args) {
        List<String> visits = List.of("home", "about", "home", "blog", "about", "home");
        Set<String> unique = new HashSet<>(visits);
        Set<String> sorted = new TreeSet<>(visits);
        System.out.println(unique.size() + " unique pages, sorted: " + sorted);
        System.out.println(unique.add("contact") + " " + unique.add("home"));   // add reports whether it was new

        Set<String> a = new TreeSet<>(Set.of("java", "sql", "git"));
        Set<String> b = Set.of("git", "docker");
        a.retainAll(b);                        // intersection
        System.out.println(a);
    }
}
```

Sets answer "have I seen this?" in constant time, which is far faster than searching a list. A `HashSet` relies on the elements' `equals` and `hashCode` (Module 4).

## Maps

```java
import java.util.HashMap;
import java.util.Map;
import java.util.TreeMap;

public class Main {
    public static void main(String[] args) {
        String text = "the cat and the hat and the bat";
        Map<String, Integer> counts = new TreeMap<>();
        for (String word : text.split(" ")) {
            counts.merge(word, 1, Integer::sum);       // add 1, starting from 1 for new words
        }
        System.out.println(counts);

        Map<String, String> capitals = new HashMap<>();
        capitals.put("France", "Paris");
        capitals.put("Japan", "Tokyo");
        System.out.println(capitals.get("Japan") + " " + capitals.get("Peru"));
        System.out.println(capitals.getOrDefault("Peru", "unknown"));
        System.out.println(capitals.containsKey("France"));

        for (Map.Entry<String, Integer> e : counts.entrySet()) {
            if (e.getValue() > 1) System.out.println(e.getKey() + " x" + e.getValue());
        }
    }
}
```

- `get` returns `null` for a missing key; `getOrDefault` gives a fallback.
- `merge`, `computeIfAbsent` and `putIfAbsent` update maps in one step: `groups.computeIfAbsent(key, k -> new ArrayList<>()).add(item)` builds a map of lists.
- `HashMap` has no order, `LinkedHashMap` keeps insertion order, `TreeMap` sorts by key.

## Queues and stacks

```java
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.PriorityQueue;

public class Main {
    public static void main(String[] args) {
        Deque<String> stack = new ArrayDeque<>();
        stack.push("a"); stack.push("b"); stack.push("c");
        System.out.println(stack.pop() + stack.pop());       // last in, first out

        Deque<String> queue = new ArrayDeque<>();
        queue.offer("first"); queue.offer("second");
        System.out.println(queue.poll());                     // first in, first out

        PriorityQueue<Integer> pq = new PriorityQueue<>(java.util.List.of(5, 1, 4, 2));
        System.out.println(pq.poll() + " " + pq.poll());      // smallest first
    }
}
```

`ArrayDeque` replaces the old `Stack` class. `PriorityQueue` always hands out the smallest element (or the largest, with a reversed comparator), which powers schedulers and algorithms like Dijkstra's.

## Choosing a collection

- Need order and index access? **`ArrayList`** (the default choice).
- Need fast "contains" or uniqueness? **`HashSet`**.
- Need lookups by key? **`HashMap`**.
- Need sorted keys or ranges? **`TreeMap`** / **`TreeSet`**.
- Need FIFO/LIFO? **`ArrayDeque`**; priorities? **`PriorityQueue`**.

import java.util.LinkedHashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;
import java.util.TreeMap;

public class Main {
    public static void main(String[] args) {
        List<String> orders = List.of("ada:book", "bob:pen", "ada:lamp", "cy:lamp", "ada:book", "cy:book", "ada:pen");
        Map<String, Set<String>> byCustomer = new TreeMap<>();
        Map<String, Integer> productCounts = new TreeMap<>();
        for (String order : orders) {
            String[] parts = order.split(":");
            byCustomer.computeIfAbsent(parts[0], k -> new LinkedHashSet<>()).add(parts[1]);
            productCounts.merge(parts[1], 1, Integer::sum);

            System.out.println(e.getKey() + ": " + e.getValue());

        String best = null;
        for (Map.Entry<String, Integer> e : productCounts.entrySet()) {
            if (best == null || e.getValue() > productCounts.get(best)) best = e.getKey();
        }
        System.out.println("Most ordered: " + best);
    }
}

import java.util.ArrayDeque;
import java.util.Deque;

public class Main {
    static boolean balanced(String s) {
        Deque<Character> stack = new ArrayDeque<>();
        for (char c : s.toCharArray()) {
            switch (c) {
                case '(', '[', '{' -> stack.push(c);
                case ')', ']', '}' -> {
                    if (stack.isEmpty()) return false;
                    char open = stack.pop();
                    if ((c == ')' && open != '(') || (c == ']' && open != '[') || (c == '}' && open != '{')) return false;
                }
                default -> { }
            }
        }
        return stack.isEmpty();
    }

    public static void main(String[] args) {
        for (String s : new String[] {"(a[b]{c})", "(]", "((())", "{[()()]}", ""}) {
            System.out.println(s + " -> " + balanced(s));
        }
    }
}

=== lesson java-generics | Generics | 75
## Type parameters

The Collections Framework is written once and works for every element type, thanks to **generics**. You can write your own generic classes and methods:

```java
public class Main {
    public static void main(String[] args) {
        Box<String> text = new Box<>("hello");
        Box<Integer> number = new Box<>(42);
        String s = text.get();          // no cast needed
        int n = number.get() + 1;
        System.out.println(s + " " + n);
        Pair<String, Double> price = new Pair<>("coffee", 2.5);
        System.out.println(price);
    }
}

class Box<T> {
    private final T value;
    Box(T value) { this.value = value; }
    T get() { return value; }
}

record Pair<A, B>(A first, B second) {}
```

`T` is a **type parameter**, replaced by a real type at each use (`Box<String>`). The compiler checks types at compile time, so a `Box<String>` can never contain an `Integer`, and reading from it needs no cast. Before generics (Java 5), collections held `Object` and every read needed a risky cast.

## Generic methods

```java
import java.util.List;

public class Main {
    static <T> T firstOrDefault(List<T> list, T fallback) {
        return list.isEmpty() ? fallback : list.get(0);
    }

    static <T extends Comparable<T>> T max(List<T> list) {
        T best = list.get(0);
        for (T item : list) {
            if (item.compareTo(best) > 0) best = item;
        }
        return best;
    }

    public static void main(String[] args) {
        System.out.println(firstOrDefault(List.of("a", "b"), "none"));
        System.out.println(firstOrDefault(List.<String>of(), "none"));
        System.out.println(max(List.of(3, 9, 4)) + " " + max(List.of("pear", "apple", "zucchini")));
    }
}
```

The `<T>` before the return type declares the method's type parameter; the compiler **infers** it from the arguments. **`<T extends Comparable<T>>`** is a **bounded** type parameter: `T` can be any type that can be compared, so `compareTo` is allowed inside.

## Wildcards

How do you write a method that sums any list of numbers, `List<Integer>` or `List<Double>`? `List<Number>` doesn't work, because a `List<Integer>` **isn't** a `List<Number>` (otherwise you could add a `Double` to a list of integers). **Wildcards** solve it:

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    static double sum(List<? extends Number> numbers) {     // read from it: a producer
        double total = 0;
        for (Number n : numbers) total += n.doubleValue();
        return total;
    }

    static void addDefaults(List<? super Integer> target) { // write into it: a consumer
        target.add(0);
        target.add(1);
    }

    public static void main(String[] args) {
        System.out.println(sum(List.of(1, 2, 3)) + " " + sum(List.of(1.5, 2.5)));
        List<Number> numbers = new ArrayList<>();
        addDefaults(numbers);
        System.out.println(numbers);
    }
}
```

The rule is **PECS**: *Producer Extends, Consumer Super*. Use `? extends T` when you only read `T`s from a structure, `? super T` when you only put `T`s into it. (`List<?>` means "a list of something": you can only read `Object`s.)

## Type erasure

Generics exist only at compile time: the compiler checks them, then **erases** them, so at run time a `List<String>` is just a `List`. Consequences: you can't write `new T()`, `T[]` creation or `instanceof List<String>`, and primitives can't be type arguments (`List<int>`). Usually you don't notice; when you do, pass a `Class<T>` or a factory (`Supplier<T>`) explicitly.

        return items.subList(Math.max(0, items.size() - n), items.size());
    }

        Stats<Integer> ns = new Stats<>();
        for (int n : numbers) ns.add(n);
        Stats<String> ws = new Stats<>();
        for (String w : List.of("kiwi", "pear", "apple")) ws.add(w);
        System.out.println("numbers: " + ns);
        System.out.println("words: " + ws);
        System.out.println("last 2: " + lastN(numbers, 2));
        System.out.println("last 9: " + lastN(numbers, 9));
    }
}

class Stats<T extends Comparable<T>> {
    private T min;
    private T max;
    private int count;

    void add(T item) {
        if (count == 0 || item.compareTo(min) < 0) min = item;
        if (count == 0 || item.compareTo(max) > 0) max = item;
        count++;
    }

    @Override
    public String toString() {
        return "min=" + min + " max=" + max + " count=" + count;
    }

## Functions as values: lambdas

A **lambda** is a short anonymous function: `(a, b) -> a + b`. It implements a **functional interface** (one abstract method, Module 4). The standard ones live in `java.util.function`:

| Interface | Shape | Example |
|---|---|---|
| `Function<T, R>` | T → R | `s -> s.length()` |
| `Predicate<T>` | T → boolean | `n -> n % 2 == 0` |
| `Consumer<T>` | T → nothing | `s -> System.out.println(s)` |
| `Supplier<T>` | nothing → T | `() -> new ArrayList<>()` |
| `BiFunction<T, U, R>` | (T, U) → R | `(a, b) -> a * b` |
| `UnaryOperator<T>`, `BinaryOperator<T>` | T → T, (T, T) → T | `x -> x * 2` |

```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;
import java.util.function.Function;
import java.util.function.Predicate;

public class Main {
    public static void main(String[] args) {
        Predicate<String> isLong = s -> s.length() > 4;
        Function<String, String> shout = s -> s.toUpperCase() + "!";
        System.out.println(isLong.test("Java") + " " + shout.apply("hi"));

        List<String> names = new ArrayList<>(List.of("Grace", "Ada", "Linus", "Barbara"));
        names.sort(Comparator.comparing(String::length).thenComparing(Comparator.naturalOrder()));
        System.out.println(names);
        names.removeIf(n -> n.startsWith("L"));
        names.forEach(n -> System.out.print(n + " "));
        System.out.println();
    }
}
```

A **method reference** (`String::length`, `System.out::println`, `Integer::sum`) is shorthand for a lambda that just calls one method. `Comparator.comparing(...)` builds comparators from a key, chainable with `thenComparing` and `reversed()`.

Lambdas can use local variables from the enclosing method only if they're **effectively final** (never reassigned).

## Streams: pipelines over collections

A **stream** processes a sequence of elements through a pipeline of operations, in a declarative style similar to SQL or JavaScript's array methods:

```java
import java.util.List;

public class Main {
    record Order(String customer, String product, int quantity, double price) {
        double total() { return quantity * price; }
    }

    public static void main(String[] args) {
        List<Order> orders = List.of(
            new Order("ada", "book", 2, 12.5),
            new Order("bob", "pen", 10, 1.2),
            new Order("ada", "lamp", 1, 35.0),
            new Order("cy", "book", 1, 12.5));

        List<String> bigOrders = orders.stream()
            .filter(o -> o.total() > 20)              // keep some
            .map(o -> o.customer() + ":" + o.product())  // transform each
            .toList();                                 // collect the result
        System.out.println(bigOrders);

        double revenue = orders.stream().mapToDouble(Order::total).sum();
        long bookOrders = orders.stream().filter(o -> o.product().equals("book")).count();
        System.out.println(revenue + " " + bookOrders);
    }
}
```

A pipeline has three parts:

1. a **source**: `list.stream()`, `Arrays.stream(array)`, `Stream.of(...)`, `IntStream.range(0, 10)`;
2. **intermediate operations**, which return a new stream and are **lazy** (nothing runs yet): `filter`, `map`, `flatMap`, `sorted`, `distinct`, `limit`, `skip`, `peek`;
3. a **terminal operation**, which runs the pipeline and produces a result: `toList`, `collect`, `forEach`, `count`, `sum`, `min`, `max`, `reduce`, `anyMatch`, `allMatch`, `findFirst`.

Streams don't modify their source, and can be used only once.

## Collectors: grouping and summarising

`collect(Collectors...)` builds maps, joined strings and statistics, like SQL's `GROUP BY`:

```java
import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import java.util.stream.Collectors;

public class Main {
    record Sale(String region, String product, double amount) {}

    public static void main(String[] args) {
        List<Sale> sales = List.of(
            new Sale("north", "tea", 120), new Sale("south", "coffee", 300),
            new Sale("north", "coffee", 80), new Sale("south", "tea", 50), new Sale("north", "tea", 30));

        Map<String, Double> byRegion = sales.stream()
            .collect(Collectors.groupingBy(Sale::region, TreeMap::new, Collectors.summingDouble(Sale::amount)));
        System.out.println(byRegion);

        Map<String, Long> countByProduct = sales.stream()
            .collect(Collectors.groupingBy(Sale::product, TreeMap::new, Collectors.counting()));
        System.out.println(countByProduct);

        String products = sales.stream().map(Sale::product).distinct().sorted().collect(Collectors.joining(", ", "[", "]"));
        System.out.println(products);

        var stats = sales.stream().mapToDouble(Sale::amount).summaryStatistics();
        System.out.printf("min %.0f max %.0f avg %.1f%n", stats.getMin(), stats.getMax(), stats.getAverage());
    }
}
```

## Streams or loops?

Streams make data transformations short and readable, especially filter-map-group pipelines. Plain loops are clearer when there's complex control flow, early exits with side effects, or performance-critical code with primitive arrays. Use whichever reads better; don't force every loop into a stream. (`parallelStream()` can use several cores for big CPU-heavy workloads, but rarely helps for small collections.)

## Optional: a value that may be absent

Returning `null` for "nothing found" invites `NullPointerException`s. **`Optional<T>`** makes absence explicit in the type:

```java
import java.util.List;
import java.util.Optional;

public class Main {
    static Optional<String> findEmail(String user) {
        return switch (user) {
            case "ada" -> Optional.of("ada@example.com");
            default -> Optional.empty();
        };
    }

    public static void main(String[] args) {
        System.out.println(findEmail("ada").orElse("no email"));
        System.out.println(findEmail("bob").orElse("no email"));
        System.out.println(findEmail("ada").map(String::toUpperCase).orElse("-"));
        findEmail("ada").ifPresent(e -> System.out.println("sending to " + e));
        System.out.println(findEmail("bob").isPresent());
        Optional<Integer> firstEven = List.of(3, 5, 8, 10).stream().filter(n -> n % 2 == 0).findFirst();
        System.out.println(firstEven.orElseThrow());
    }
}
```

Use `Optional` as a **return type** for "maybe a value"; read it with `orElse`, `orElseGet`, `orElseThrow`, `map`, `ifPresent`. Don't use it for fields or parameters, and never call `get()` without checking.

## Wrapper classes and autoboxing

Each primitive has a wrapper class: `Integer`, `Long`, `Double`, `Boolean`, `Character`... They're needed for collections and generics, and hold useful static methods (`Integer.parseInt`, `Integer.MAX_VALUE`, `Character.isDigit`). Java converts automatically (**autoboxing** / **unboxing**), with two traps:

```java
import java.util.HashMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        Integer a = 127, b = 127, c = 1000, d = 1000;
        System.out.println((a == b) + " " + (c == d) + " " + c.equals(d));

        Map<String, Integer> stock = new HashMap<>();
        Integer pens = stock.get("pens");          // null: no such key
        System.out.println(pens);
        // int p = stock.get("pens");              // would throw NullPointerException while unboxing
    }
}
```

1. `==` on wrappers compares **references**: it happens to work for small values (Java caches -128 to 127) and fails for others. Use `equals`, or unbox first.
2. Unboxing `null` throws `NullPointerException`.

## Math and exact decimals

`Math` has `abs`, `pow`, `sqrt`, `max`, `min`, `round`, `floor`, `ceil`, `hypot`, `random`, and the overflow-checking `addExact`/`multiplyExact`. For **money**, `double` is wrong (0.1 + 0.2 ≠ 0.3); use **`BigDecimal`**:

```java
import java.math.BigDecimal;
import java.math.RoundingMode;

public class Main {
    public static void main(String[] args) {
        System.out.println(0.1 + 0.2);
        BigDecimal price = new BigDecimal("19.99");
        BigDecimal quantity = new BigDecimal("3");
        BigDecimal subtotal = price.multiply(quantity);
        BigDecimal vat = subtotal.multiply(new BigDecimal("0.20")).setScale(2, RoundingMode.HALF_UP);
        System.out.println(subtotal + " + " + vat + " = " + subtotal.add(vat));
        System.out.println(new BigDecimal("10").divide(new BigDecimal("3"), 4, RoundingMode.HALF_EVEN));
    }
}
```

Create `BigDecimal`s from **strings** (`new BigDecimal("0.1")`, not `new BigDecimal(0.1)`), compare with `compareTo` (not `equals`, which also compares the scale: `2.0` vs `2.00`), and always specify the rounding when dividing.

## Dates and times: java.time

The `java.time` package (Java 8+) replaced the old, error-prone `Date` and `Calendar` classes. Its types are immutable:

| Type | Represents |
|---|---|
| `LocalDate` | a date without time: 2026-03-15 |
| `LocalTime` | a time of day: 14:30 |
| `LocalDateTime` | date and time, no time zone |
| `ZonedDateTime` | date and time in a zone (Europe/Paris) |
| `Instant` | a moment on the global timeline (UTC), for timestamps |
| `Duration` / `Period` | a time-based / date-based amount |

```java
import java.time.DayOfWeek;
import java.time.Duration;
import java.time.LocalDate;
import java.time.LocalDateTime;
import java.time.Period;
import java.time.ZoneId;
import java.time.format.DateTimeFormatter;
import java.time.temporal.ChronoUnit;

public class Main {
    public static void main(String[] args) {
        LocalDate release = LocalDate.of(2026, 3, 15);
        LocalDate deadline = release.plusWeeks(6);
        System.out.println(deadline + " " + deadline.getDayOfWeek());
        System.out.println(ChronoUnit.DAYS.between(release, deadline) + " days");
        System.out.println(Period.between(LocalDate.of(1990, 6, 1), release));
        System.out.println(release.isLeapYear() + " " + release.with(DayOfWeek.MONDAY));

        LocalDateTime meeting = LocalDateTime.of(2026, 3, 15, 16, 0);
        System.out.println(meeting.atZone(ZoneId.of("Europe/London")).withZoneSameInstant(ZoneId.of("Asia/Tokyo")).toLocalDateTime());
        System.out.println(Duration.ofMinutes(135));
        System.out.println(meeting.format(DateTimeFormatter.ofPattern("dd MMM yyyy, HH:mm")));
        System.out.println(LocalDate.parse("2026-12-25").getDayOfYear());
    }
}
```

Store timestamps as `Instant` (UTC), convert to a `ZonedDateTime` only to show them to people. `LocalDate.now()` and `Instant.now()` read the clock; in testable code, pass a `Clock` instead of calling `now()` directly.

import java.time.LocalDateTime;
import java.time.format.DateTimeParseException;
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.TreeMap;
import java.util.stream.Collectors;

public class Main {
    record LogEntry(LocalDateTime time, String level, String message) {}

    static Optional<LogEntry> parse(String line) {
        String[] parts = line.split(" ", 3);
        if (parts.length < 3) return Optional.empty();
        try {
            return Optional.of(new LogEntry(LocalDateTime.parse(parts[0]), parts[1], parts[2]));
        } catch (DateTimeParseException e) {
            return Optional.empty();
        }
    }

    public static void main(String[] args) {
        List<String> lines = List.of(
            "2026-03-15T09:58:00 INFO service started",
            "2026-03-15T10:02:11 ERROR payment timeout",
            "garbage line",
            "2026-03-15T10:15:40 WARN slow query",
            "2026-03-15T10:47:03 ERROR payment timeout",
            "2026-13-40T10:00:00 ERROR bad date",
            "2026-03-15T11:05:59 ERROR disk full",
            "2026-03-15T11:30:00 INFO backup done");

        List<LogEntry> entries = new ArrayList<>();
        int malformed = 0;
        for (String line : lines) {
            Optional<LogEntry> e = parse(line);
            if (e.isPresent()) entries.add(e.get());
            else malformed++;
        }
        System.out.println("Malformed lines: " + malformed);
        System.out.println("Levels: " + entries.stream().collect(Collectors.groupingBy(LogEntry::level, TreeMap::new, Collectors.counting())));
        List<LogEntry> errors = entries.stream().filter(e -> e.level().equals("ERROR")).toList();
        LogEntry first = errors.stream().min(Comparator.comparing(LogEntry::time)).orElseThrow();
        System.out.println("First error: " + first.time().toLocalTime() + " " + first.message());
        System.out.println("Errors per hour: " + errors.stream().collect(Collectors.groupingBy(e -> e.time().getHour(), TreeMap::new, Collectors.counting())));
        Map<String, Long> byMessage = errors.stream().collect(Collectors.groupingBy(LogEntry::message, TreeMap::new, Collectors.counting()));
        Map.Entry<String, Long> top = byMessage.entrySet().stream()
            .max(Comparator.comparing((Map.Entry<String, Long> e) -> e.getValue()).thenComparing(Map.Entry::getKey, Comparator.reverseOrder()))
            .orElseThrow();
        System.out.println("Most common error: " + top.getKey() + " (" + top.getValue() + ")");
    }
}

First error: 10:02:11 payment timeout
Errors per hour: {10=2, 11=1}
Most common error: payment timeout (2)
::hints
- `line.split(" ", 3)` splits into at most 3 parts, so the message keeps its spaces.
- `LocalDateTime.parse` throws `DateTimeParseException` for invalid dates: return `Optional.empty()` then.
- `Collectors.groupingBy(key, TreeMap::new, Collectors.counting())` gives sorted counts.
