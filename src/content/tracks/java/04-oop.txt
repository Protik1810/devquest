## Bundling data with behaviour

So far, `Main` held static methods and local variables. Real programs model **things**: accounts, orders, players. A **class** describes a kind of thing: the data each one holds (**fields**) and what it can do (**methods**). An **object** is one instance of a class, created with **`new`**.

```java
public class Main {
    public static void main(String[] args) {
        BankAccount alice = new BankAccount("Alice", 100);
        BankAccount bob = new BankAccount("Bob", 20);
        alice.deposit(50);
        bob.withdraw(30);
        System.out.println(alice.describe());
        System.out.println(bob.describe());
    }
}

class BankAccount {
    String owner;
    double balance;

    BankAccount(String owner, double opening) {
        this.owner = owner;
        this.balance = opening;
    }

    void deposit(double amount) {
        balance += amount;
    }

    boolean withdraw(double amount) {
        if (amount > balance) return false;
        balance -= amount;
        return true;
    }

    String describe() {
        return owner + ": " + balance;
    }
}
```

- **Fields** (`owner`, `balance`) are variables that belong to each object: Alice's balance and Bob's are separate.
- The **constructor** (`BankAccount(...)`, same name as the class, no return type) initialises a new object. `new BankAccount("Alice", 100)` allocates the object and runs it.
- **Instance methods** (no `static`) work on a particular object: `alice.deposit(50)` changes Alice's balance. Inside, fields can be used directly, or as `this.balance`.
- **`this`** refers to the current object; it's needed when a parameter has the same name as a field (`this.owner = owner`).

Bob's withdrawal of 30 fails (he has 20), and the method reports it by returning `false`, which the example ignores. Real code would check it.

## References and null

A variable of a class type holds a **reference** to an object, not the object itself:

```java
public class Main {
    public static void main(String[] args) {
        Point a = new Point(1, 2);
        Point b = a;            // same object, two references
        b.x = 10;
        System.out.println(a.x);
        Point c = null;         // refers to no object
        System.out.println(c == null);
    }
}

class Point {
    int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }
}
```

`null` means "no object". Calling a method or reading a field through a `null` reference throws `NullPointerException`, the most common Java exception. Objects that nothing refers to any more are freed by the **garbage collector**.

## Default values and multiple constructors

Fields get default values (`0`, `false`, `null`) if not initialised. A class can have several constructors (overloading), and one can call another with `this(...)`:

```java
public class Main {
    public static void main(String[] args) {
        System.out.println(new Pizza("Margherita").describe());
        System.out.println(new Pizza("Diavola", 30, true).describe());
    }
}

class Pizza {
    String name;
    int diameterCm;
    boolean extraCheese;

    Pizza(String name) {
        this(name, 26, false);        // delegate to the full constructor
    }

    Pizza(String name, int diameterCm, boolean extraCheese) {
        this.name = name;
        this.diameterCm = diameterCm;
        this.extraCheese = extraCheese;
    }

    String describe() {
        return name + " " + diameterCm + "cm" + (extraCheese ? " + cheese" : "");
    }
}
```

If you write no constructor, Java provides an empty default one; as soon as you write any, it doesn't.

## toString

Every class can override **`toString()`**, which Java calls whenever an object is printed or joined to a string:

```java
public class Main {
    public static void main(String[] args) {
        Temperature t = new Temperature(21.5);
        System.out.println(t);
        System.out.println("Now: " + t);
    }
}

class Temperature {
    double celsius;
    Temperature(double celsius) { this.celsius = celsius; }

    @Override
    public String toString() {
        return celsius + "°C";
    }
}
```

`@Override` asks the compiler to check that this method really overrides one from a parent class (all classes inherit from `Object`, which has a default `toString`). Lesson 3 explains inheritance.

## Protect your data: private fields

In the last lesson, any code could write `alice.balance = -1_000_000`. **Encapsulation** hides an object's fields and exposes only methods that keep its data valid:

```java
public class Main {
    public static void main(String[] args) {
        Account acc = new Account("Ada", 100);
        acc.deposit(25);
        try {
            acc.withdraw(500);
        } catch (IllegalArgumentException e) {
            System.out.println("Refused: " + e.getMessage());
        }
        System.out.println(acc.getOwner() + " has " + acc.getBalance());
    }
}

class Account {
    private final String owner;
    private double balance;

    Account(String owner, double opening) {
        if (opening < 0) throw new IllegalArgumentException("opening balance can't be negative");
        this.owner = owner;
        this.balance = opening;
    }

    public String getOwner() { return owner; }
    public double getBalance() { return balance; }

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("deposit must be positive");
        balance += amount;
    }

    public void withdraw(double amount) {
        if (amount > balance) throw new IllegalArgumentException("insufficient funds");
        balance -= amount;
    }
}
```

The class now guarantees an **invariant**: the balance is never negative, whatever other code does. Invalid requests are rejected by **throwing an exception** (Module 5 covers `try`/`catch`).

## Access modifiers

| Modifier | Visible from |
|---|---|
| `private` | the class itself only |
| (none: package-private) | classes in the same package |
| `protected` | the same package, and subclasses |
| `public` | everywhere |

The rule of thumb: **fields `private`**, and methods as restricted as possible. **Getters** (`getBalance()`) expose values; **setters** (`setName(...)`) should exist only when a field really may change, and should validate. Not every field needs a getter and setter: expose behaviour (`deposit`), not data.

## static members

`static` fields and methods belong to the **class**, shared by all objects:

```java
public class Main {
    public static void main(String[] args) {
        Ticket a = new Ticket();
        Ticket b = new Ticket();
        Ticket c = new Ticket();
        System.out.println(a.getNumber() + " " + b.getNumber() + " " + c.getNumber());
        System.out.println("Issued: " + Ticket.issued());
    }
}

class Ticket {
    private static int nextNumber = 1;    // one counter for the whole class
    private final int number;             // one per ticket

    Ticket() {
        number = nextNumber++;
    }

    int getNumber() { return number; }
    static int issued() { return nextNumber - 1; }
}
```

Static methods can't use instance fields (there's no `this`). Typical static members: constants (`Math.PI`), factory methods (`List.of(...)`), utility methods (`Math.max`), and counters like this one.

## Immutable objects

An **immutable** object can't change after construction: all fields `private final`, no setters, and "changing" methods return a **new** object (like `String`). Immutable objects are simple to reason about, safe to share and to use as map keys, and thread-safe:

```java
public class Main {
    public static void main(String[] args) {
        Money price = new Money(1999, "EUR");
        Money doubled = price.times(2);
        System.out.println(price + " -> " + doubled);
    }
}

final class Money {
    private final long cents;
    private final String currency;

    Money(long cents, String currency) {
        this.cents = cents;
        this.currency = currency;
    }

    Money times(int factor) {
        return new Money(cents * factor, currency);
    }

    @Override
    public String toString() {
        return String.format("%d.%02d %s", cents / 100, cents % 100, currency);
    }
}
```

`final class` also prevents subclasses from breaking the guarantees. Java's **records** (lesson 5) make such classes one line long.

## extends: building on a class

A class can **extend** another, inheriting its fields and methods and adding or changing behaviour. The parent is the **superclass**, the child the **subclass**:

```java
public class Main {
    public static void main(String[] args) {
        Employee e = new Employee("Ada", 4000);
        Manager m = new Manager("Grace", 6000, 1500);
        System.out.println(e.describe());
        System.out.println(m.describe());
        System.out.println(m.getName() + " earns " + m.monthlyPay());
    }
}

class Employee {
    private final String name;
    protected final double salary;

    Employee(String name, double salary) {
        this.name = name;
        this.salary = salary;
    }

    String getName() { return name; }
    double monthlyPay() { return salary; }
    String describe() { return name + " (" + getClass().getSimpleName() + "): " + monthlyPay(); }
}

class Manager extends Employee {
    private final double bonus;

    Manager(String name, double salary, double bonus) {
        super(name, salary);        // must come first: initialise the Employee part
        this.bonus = bonus;
    }

    @Override
    double monthlyPay() {
        return super.monthlyPay() + bonus;   // reuse the parent's version
    }
}
```

- `super(...)` calls the parent's constructor (it must be the first statement).
- **Overriding** replaces an inherited method; `super.method()` calls the parent's version. Always write **`@Override`**: the compiler then catches typos and signature mismatches.
- `protected` members are visible to subclasses.
- Java has **single inheritance**: a class extends exactly one class (`Object` if none is given). It can implement many interfaces (next lesson).

## Polymorphism

A variable of a superclass type can refer to any subclass object, and calls go to the **object's actual class** (dynamic dispatch):

```java
public class Main {
    public static void main(String[] args) {
        Shape[] shapes = {new Circle(1), new Rectangle(2, 3), new Circle(0.5)};
        double total = 0;
        for (Shape s : shapes) {
            System.out.printf("%s: %.2f%n", s.name(), s.area());
            total += s.area();
        }
        System.out.printf("Total: %.2f%n", total);
    }
}

abstract class Shape {
    abstract double area();
    String name() { return getClass().getSimpleName(); }
}

class Circle extends Shape {
    private final double r;
    Circle(double r) { this.r = r; }
    @Override double area() { return Math.PI * r * r; }
}

class Rectangle extends Shape {
    private final double w, h;
    Rectangle(double w, double h) { this.w = w; this.h = h; }
    @Override double area() { return w * h; }
}
```

The loop doesn't know or care which shapes it has: adding a `Triangle` requires no change to it. That's the **open/closed principle** in action, the main payoff of polymorphism.

An **abstract class** can't be instantiated (`new Shape()` is an error) and can declare **abstract methods** with no body, which every concrete subclass must implement.

## The Object class: equals and hashCode

Every class inherits from `java.lang.Object`: `toString()`, `equals(Object)`, `hashCode()`, `getClass()`. By default, `equals` compares **references** (same object). For value-like classes, override `equals` **and** `hashCode` together, so that equal objects work correctly in sets and maps (Module 5):

```java
import java.util.Objects;

public class Main {
    public static void main(String[] args) {
        Isbn a = new Isbn("978-0134685991");
        Isbn b = new Isbn("978-0134685991");
        System.out.println(a == b);           // false: two objects
        System.out.println(a.equals(b));      // true: same value
        System.out.println(a.hashCode() == b.hashCode());
    }
}

final class Isbn {
    private final String code;
    Isbn(String code) { this.code = code; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Isbn other)) return false;
        return code.equals(other.code);
    }

    @Override
    public int hashCode() {
        return Objects.hash(code);
    }
}
```

(`o instanceof Isbn other` tests the type and, if it matches, gives you `other` already cast: **pattern matching**, Java 16+.) Records (lesson 5) generate `equals`, `hashCode` and `toString` for you.

## Casting objects

Upcasting (subclass to superclass) is automatic. Downcasting needs a check, or it throws `ClassCastException`; pattern matching makes it safe and short: `if (shape instanceof Circle c) { ... c ... }`.

## Prefer composition to inheritance

Inheritance creates a tight coupling: a subclass depends on its parent's internals, and deep hierarchies become rigid. Use `extends` for a genuine "is a" relationship (a `Manager` **is an** `Employee`); otherwise build objects from other objects (**composition**: a `Car` **has an** `Engine`). *Effective Java* (item 18) and most modern design advice say: favour composition over inheritance, and mark classes `final` unless designed for extension.

    private final int den;

    Fraction(int num, int den) {
        if (den == 0) throw new ArithmeticException("denominator is zero");
        int sign = den < 0 ? -1 : 1;
        int g = gcd(Math.abs(num), Math.abs(den));
        this.num = sign * num / g;
        this.den = Math.abs(den) / g;
    }

    private static int gcd(int a, int b) {
        return b == 0 ? Math.max(a, 1) : gcd(b, a % b);
    }

    Fraction plus(Fraction other) {
        return new Fraction(num * other.den + other.num * den, den * other.den);
    }

    @Override
    public boolean equals(Object o) {
        return o instanceof Fraction f && num == f.num && den == f.den;
    }

    @Override
    public int hashCode() {
        return Objects.hash(num, den);
    }

    @Override
    public String toString() {
        return den == 1 ? String.valueOf(num) : num + "/" + den;
    }
}
::expected
1/2 equals 2/4: true
1/2 == 2/4: false
1/2 + 1/3 = 5/6
3/-6 = -1/2
4/2 = 2
same hash: true
::hints
- Reduce in the constructor by the greatest common divisor, and move a negative sign from the denominator to the numerator.
- Because fractions are always reduced, `equals` can compare the two fields directly.
- `Objects.hash(num, den)` gives a hash code consistent with `equals`.

@Override :: Ask the compiler to check that a method really overrides one.

=== lesson java-interfaces | Interfaces and abstract design | 75
## Contracts: interfaces

An **interface** declares what a type can do, without saying how. Classes **implement** it:

```java
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<PaymentMethod> methods = List.of(new Card("4242"), new PayPal("ada@example.com"), new GiftCard(20));
        for (PaymentMethod m : methods) {
            System.out.println(m.describe() + " -> " + (m.pay(25) ? "paid" : "declined"));
        }
    }
}

interface PaymentMethod {
    boolean pay(double amount);
    String describe();
}

class Card implements PaymentMethod {
    private final String last4;
    Card(String last4) { this.last4 = last4; }
    public boolean pay(double amount) { return true; }
    public String describe() { return "Card ending " + last4; }
}

class PayPal implements PaymentMethod {
    private final String email;
    PayPal(String email) { this.email = email; }
    public boolean pay(double amount) { return amount <= 1000; }
    public String describe() { return "PayPal " + email; }
}

class GiftCard implements PaymentMethod {
    private double balance;
    GiftCard(double balance) { this.balance = balance; }
    public boolean pay(double amount) {
        if (amount > balance) return false;
        balance -= amount;
        return true;
    }
    public String describe() { return "Gift card (" + balance + " left)"; }
}
```

- Interface methods are implicitly `public` and `abstract`, so implementations must be `public`.
- A class can implement **many** interfaces (`class Duck implements Flyer, Swimmer`), unlike `extends`.
- Code that depends on the **interface** (`PaymentMethod`) works with every implementation, including future ones, and can be tested with fakes. "Program to an interface, not an implementation" is one of the oldest design rules.

The standard library is built on interfaces: `List`, `Map`, `Comparable`, `Runnable`, `AutoCloseable`...

## default and static methods

Since Java 8, interfaces can include **default methods** (with a body, inherited by implementations) and **static methods**:

```java
public class Main {
    public static void main(String[] args) {
        Greeter english = name -> "Hello, " + name;
        System.out.println(english.greet("Ada"));
        System.out.println(english.greetAll("Ada", "Grace"));
        System.out.println(Greeter.polite().greet("Linus"));
    }
}

interface Greeter {
    String greet(String name);

    default String greetAll(String... names) {
        StringBuilder sb = new StringBuilder();
        for (String n : names) sb.append(greet(n)).append(". ");
        return sb.toString().strip();
    }

    static Greeter polite() {
        return name -> "Good morning, " + name;
    }
}
```

`Greeter` has exactly one abstract method, so it's a **functional interface**, and a **lambda** (`name -> "Hello, " + name`) can implement it. Module 5 makes heavy use of this.

## Comparable: a standard interface

Implementing `Comparable<T>` gives a class a **natural order**, used by `Arrays.sort`, `Collections.sort` and sorted collections:

```java
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        Version[] versions = {new Version(1, 10), new Version(1, 2), new Version(0, 9)};
        Arrays.sort(versions);
        System.out.println(Arrays.toString(versions));
    }
}

class Version implements Comparable<Version> {
    final int major, minor;
    Version(int major, int minor) { this.major = major; this.minor = minor; }

    @Override
    public int compareTo(Version other) {
        if (major != other.major) return Integer.compare(major, other.major);
        return Integer.compare(minor, other.minor);
    }

    @Override
    public String toString() { return major + "." + minor; }
}
```

`compareTo` returns a negative number, zero or a positive number. Use `Integer.compare`, not subtraction (`a - b` can overflow).

## Interfaces or abstract classes?

| | Interface | Abstract class |
|---|---|---|
| implement/extend several | yes | no (one superclass) |
| fields with state | no (only constants) | yes |
| constructors | no | yes |
| best for | capabilities and contracts ("can be paid with", "is comparable") | sharing implementation between closely related classes |

Start with an interface; add an abstract class (often implementing that interface) when several implementations share real code.

## Sealed hierarchies (Java 17+)

A **sealed** interface or class lists exactly which types may implement it. The compiler then knows every possibility, which makes `switch` over it exhaustive without a `default` (Module 6):

```java
public class Main {
    public static void main(String[] args) {
        Shape[] shapes = {new Circle(1), new Square(2)};
        for (Shape s : shapes) {
            double area = switch (s) {
                case Circle c -> Math.PI * c.radius() * c.radius();
                case Square q -> q.side() * q.side();
            };
            System.out.printf("%.2f%n", area);
        }
    }
}

sealed interface Shape permits Circle, Square {}
record Circle(double radius) implements Shape {}
record Square(double side) implements Shape {}
```

=== lesson java-records-enums | Records and enums | 70
## Records: data classes in one line

Many classes just carry data: a point, a money amount, an API response. Writing their constructor, getters, `equals`, `hashCode` and `toString` by hand is long and error-prone. A **record** (Java 16+) declares them all at once:

```java
public class Main {
    public static void main(String[] args) {
        Point a = new Point(3, 4);
        Point b = new Point(3, 4);
        System.out.println(a);                  // Point[x=3, y=4]
        System.out.println(a.x() + " " + a.y());
        System.out.println(a.equals(b) + " " + (a == b));
        System.out.println(a.distanceToOrigin());
        System.out.println(a.withX(10));
    }
}

record Point(int x, int y) {
    double distanceToOrigin() {
        return Math.sqrt(x * x + y * y);
    }

    Point withX(int newX) {
        return new Point(newX, y);
    }
}
```

A record:

- has `private final` fields and an accessor per component (`x()`, not `getX()`);
- is **immutable** and `final`;
- gets `equals`, `hashCode` and `toString` based on its components;
- can have extra methods, static members and a **compact constructor** for validation:

```java
public class Main {
    public static void main(String[] args) {
        System.out.println(new Email("Ada@Example.com"));
        try {
            new Email("nope");
        } catch (IllegalArgumentException e) {
            System.out.println("Rejected: " + e.getMessage());
        }
    }
}

record Email(String address) {
    Email {
        if (!address.contains("@")) throw new IllegalArgumentException("not an email: " + address);
        address = address.toLowerCase();
    }
}
```

Use records for **values** and data transfer objects; use classes for things with identity and changing state (an account, a game character).

## Enums: a fixed set of constants

An **enum** defines a type with a fixed set of named values:

```java
public class Main {
    public static void main(String[] args) {
        Status s = Status.SHIPPED;
        System.out.println(s + " " + s.ordinal() + " " + s.name());
        for (Status status : Status.values()) {
            System.out.print(status + " ");
        }
        System.out.println();
        System.out.println(Status.valueOf("PAID").next());
        String message = switch (s) {
            case PENDING -> "Waiting for payment";
            case PAID -> "Being prepared";
            case SHIPPED -> "On its way";
            case DELIVERED -> "Delivered";
        };
        System.out.println(message);
    }
}

enum Status {
    PENDING, PAID, SHIPPED, DELIVERED;

    Status next() {
        return this == DELIVERED ? this : values()[ordinal() + 1];
    }
}
```

- Enum values are **singletons** and can be compared with `==`.
- `values()`, `valueOf(String)`, `name()` and `ordinal()` come for free.
- A `switch` over an enum that covers every constant needs no `default`: add a constant and the compiler flags every incomplete switch expression.

Enums are full classes: they can have fields, constructors and methods, even per-constant behaviour:

```java
public class Main {
    public static void main(String[] args) {
        for (Planet p : Planet.values()) {
            System.out.printf("%-7s %5.2f%n", p, p.surfaceGravity());
        }
    }
}

enum Planet {
    MERCURY(3.303e23, 2.4397e6),
    EARTH(5.976e24, 6.37814e6),
    JUPITER(1.9e27, 7.1492e7);

    private static final double G = 6.67300E-11;
    private final double mass;
    private final double radius;

    Planet(double mass, double radius) {
        this.mass = mass;
        this.radius = radius;
    }

    double surfaceGravity() {
        return G * mass / (radius * radius);
    }
}
```

Use enums instead of string or int constants for anything with a known set of values: statuses, roles, directions, units. The compiler then catches typos. `EnumMap` and `EnumSet` (Module 5) are fast collections keyed by enums.

class Garage {
    private final int capacity;
    private final ArrayList<Vehicle> parked = new ArrayList<>();

    Garage(int capacity) {
        this.capacity = capacity;
    }

    private Vehicle find(String plate) {
        for (Vehicle v : parked) {
            if (v.plate().equals(plate)) return v;
        }
        return null;
    }

    boolean park(Vehicle v) {
        if (parked.size() >= capacity || find(v.plate()) != null) return false;
        parked.add(v);
        return true;
    }

    double leave(String plate, int hours) {
        Vehicle v = find(plate);
        if (v == null) return -1;
        parked.remove(v);
        return v.type().hourlyRate * Math.min(hours, 8);
    }

    int free() {
        return capacity - parked.size();
    }
}
