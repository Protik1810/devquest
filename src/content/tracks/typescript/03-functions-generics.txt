## Parameters and return types

You've annotated parameters and return values since Module 1. The rest of a function's signature follows the same JavaScript features you already know:

```ts
function greet(name: string, greeting = "Hello", punctuation?: string): string {
  return `${greeting}, ${name}${punctuation ?? "!"}`;
}

function sum(...numbers: number[]): number {
  return numbers.reduce((a, b) => a + b, 0);
}

console.log(greet("Ada"), greet("Grace", "Hi", "."), sum(1, 2, 3));
```

- A **default value** (`greeting = "Hello"`) makes a parameter optional and gives it a type by inference.
- `punctuation?: string` is an **optional parameter**: inside the function, it's `string | undefined`. Optional parameters must come after required ones.
- A **rest parameter** (`...numbers: number[]`) collects the remaining arguments into an array.

Destructured parameters are annotated as a whole object, after the pattern:

```ts
function createUser({ name, admin = false }: { name: string; admin?: boolean }): string {
  return `${name}${admin ? " (admin)" : ""}`;
}
console.log(createUser({ name: "Ada", admin: true }), createUser({ name: "Bob" }));
```

(Writing `{ name: string }` inside the pattern doesn't work: in a destructuring pattern, `name: string` means "rename `name` to a variable called `string`".)

## Function types

Functions are values, so they have types too. A **function type** looks like an arrow function with types instead of a body:

```ts
type BinaryOp = (a: number, b: number) => number;

const add: BinaryOp = (a, b) => a + b;
const multiply: BinaryOp = (a, b) => a * b;

function applyAll(ops: BinaryOp[], x: number, y: number): number[] {
  return ops.map((op) => op(x, y));
}

console.log(applyAll([add, multiply, Math.pow], 2, 5));
```

Notice that `(a, b) => a + b` needs no annotations: TypeScript knows from `BinaryOp` what `a` and `b` are. This is **contextual typing**: a function written where a function type is expected gets its parameter types from that context. It's why `[1, 2].map((n) => n * 2)` knows `n` is a number.

Callbacks follow the same rule: a parameter's type describes the function it accepts.

```ts
function retry(times: number, task: (attempt: number) => boolean): boolean {
  for (let attempt = 1; attempt <= times; attempt++) {
    if (task(attempt)) return true;
  }
  return false;
}

console.log(retry(3, (attempt) => attempt === 2));
```

A function that takes **fewer** parameters is accepted where more are offered (that's why you can pass `(item) => ...` to `map`, which offers three arguments). JavaScript ignores extra arguments, and TypeScript follows JavaScript.

## void callbacks

A callback type returning `void` means "I'll ignore what you return", not "you must return nothing". So `numbers.forEach((n) => list.push(n))` is fine, even though `push` returns a number:

```ts
const seen: string[] = [];
["a", "b"].forEach((letter) => seen.push(letter));
console.log(seen);
```

## this in functions

In the rare cases where a plain function uses `this` (DOM event handlers written with `function`, some library APIs), you can declare its type with a fake first parameter called `this`. It's erased from the output:

```ts
function describeButton(this: { label: string }, suffix: string): string {
  return `${this.label}${suffix}`;
}
console.log(describeButton.call({ label: "Save" }, "!"));
```

Calling `describeButton("!")` directly is then a compile error, because `this` wouldn't be set. In class-based code and arrow functions you won't need this.

## Return type annotations: when they help

TypeScript infers return types, so annotations are optional. Write them anyway when:

- the function is **exported** or part of an API: the type is documentation, and a change in the body can't silently change it;
- the function has **several return paths**: the annotation makes each one check against your intent, and errors appear in the function rather than at distant callers;
- the function is **recursive**: TypeScript sometimes can't infer it.

```ts
function factorial(n: number): number {
  return n <= 1 ? 1 : n * factorial(n - 1);
}
console.log(factorial(10));
```

=== lesson ts-overloads | Overloads and call signatures | 70
## One function, several shapes

Some JavaScript functions behave differently depending on their arguments. `document.createElement("canvas")` returns an `HTMLCanvasElement`, while `createElement("img")` returns an `HTMLImageElement`. A single signature can't say "the return type depends on the argument" precisely, so TypeScript has **overloads**: several signatures for one implementation.

```ts
function parseDate(timestamp: number): Date;
function parseDate(year: number, month: number, day: number): Date;
function parseDate(a: number, month?: number, day?: number): Date {
  return month === undefined ? new Date(a) : new Date(Date.UTC(a, month - 1, day ?? 1));
}

console.log(parseDate(0).toISOString(), parseDate(2026, 3, 14).toISOString());
```

- The first two lines are the **overload signatures**: the only ways callers may call the function.
- The last one is the **implementation signature**, which must be compatible with all overloads, and **isn't visible to callers**: `parseDate(2026, 3)` is an error, because no overload takes two arguments, even though the implementation could.

TypeScript picks the first overload that matches a call, so list the most specific ones first.

## Return types that depend on arguments

Overloads let the return type follow the input:

```ts
function toArray(value: string): string[];
function toArray(value: number): number[];
function toArray(value: string | number): (string | number)[] {
  return [value];
}

const words = toArray("hi");
const digits = toArray(7);
console.log(words[0].toUpperCase(), digits[0].toFixed(1));
```

`words` is a `string[]` and `digits` a `number[]`. A single signature taking `string | number` and returning `(string | number)[]` would lose that information.

## Prefer unions (or generics) when they suffice

Overloads are verbose, and the implementation isn't checked against each overload very closely. Use them only when the return type really depends on which call shape is used. If one signature with a union parameter describes the function precisely, prefer that:

```ts
function lengthOf(value: string | unknown[]): number {
  return value.length;
}
console.log(lengthOf("abc"), lengthOf([1, 2]));
```

The next lesson, generics, replaces many overloads with a single signature (`toArray<T>(value: T): T[]` would cover both cases above, and every other type too).

## Call signatures and function objects

JavaScript functions can have properties (think of `jQuery.ajax`, or a function with a `.displayName`). An object type with a **call signature** describes them:

```ts
type Counter = {
  (): number;
  count: number;
  reset(): void;
};

function makeCounter(): Counter {
  const counter = () => ++counter.count;
  counter.count = 0;
  counter.reset = () => {
    counter.count = 0;
  };
  return counter;
}

const next = makeCounter();
next();
next();
console.log(next.count, next());
```

`(): number` is the call signature ("can be called with no arguments, returns a number"). TypeScript understands properties assigned to a function declared with `const` right after it, so this pattern type-checks without any casts. Overloads can be written as several call signatures in such a type, too.

There's also the **construct signature**, `new (...args) => T`, for values that can be called with `new` (that is, classes). You'll meet it in Module 4.

## Overloads in the standard library

You'll see overloads constantly when hovering over built-in functions. `addEventListener` has one per event name (so `"click"` gives a `MouseEvent` and `"keydown"` a `KeyboardEvent`), and `Array.prototype.reduce` has several (with and without an initial value). The editor shows them as "+2 overloads"; press the arrows in the hover to read each one.

=== lesson ts-generics | Generics | 100
## The problem: functions that work for any type

Write a function that returns the first element of an array. With what you know so far, you have two poor options:

- `first(list: number[]): number` works only for numbers;
- `first(list: unknown[]): unknown` works for everything, but loses the type: `first(["a"])` gives `unknown`, so `.toUpperCase()` is an error.

**Generics** solve this with a **type parameter**: a placeholder for a type, chosen at each call.

```ts
function first<T>(list: readonly T[]): T | undefined {
  return list[0];
}

const word = first(["apple", "banana"]);
const num = first([3, 1, 2]);
console.log(word?.toUpperCase(), num?.toFixed(1));
```

`<T>` declares the type parameter. At each call, TypeScript **infers** `T` from the arguments: `string` for the first call, `number` for the second, so `word` is `string | undefined`. You can also pass it explicitly, `first<string>([])`, which is useful when there's nothing to infer from.

Think of a type parameter as a function parameter at the type level: `first` is one function for every `T`. You've been using generic types all along: `Array<T>`, `Map<K, V>`, `Promise<T>`, `Record<K, V>`, `ReadonlyArray<T>`.

## Several type parameters

```ts
function mapValues<K extends string, A, B>(obj: Record<K, A>, fn: (value: A) => B): Record<K, B> {
  const out = {} as Record<K, B>;
  for (const key of Object.keys(obj) as K[]) out[key] = fn(obj[key]);
  return out;
}

const lengths = mapValues({ ada: "Lovelace", alan: "Turing" }, (name) => name.length);
console.log(lengths);
```

`K`, `A` and `B` are inferred from the object and the callback. (The two `as` casts are a well-known limitation: `{}` doesn't yet have the keys, and `Object.keys` always returns `string[]` because objects may have extra keys at run time. Containing such casts inside small, well-tested helpers is reasonable.)

Naming: single capitals (`T`, `U`, `K` for keys, `V` for values, `E` for elements or errors) are conventional for short functions; descriptive names (`TItem`, `TResponse`) help in longer ones.

## Constraints: `extends`

Sometimes the type parameter must have certain features. A **constraint** says so:

```ts
function longest<T extends { length: number }>(a: T, b: T): T {
  return b.length > a.length ? b : a;
}

console.log(longest("cat", "horse"), longest([1, 2], [1, 2, 3]));
```

`T extends { length: number }` means "any type, as long as it has a numeric `length`". Inside, `a.length` is allowed; `longest(10, 20)` is a compile error. Note that the function returns `T`, not `{ length: number }`: callers get back exactly the type they passed in (`string`, `number[]`). That's the difference between a generic with a constraint and a plain parameter of the constraint type.

## keyof and indexed access with generics

A classic generic: get a property of an object by name, with full type safety:

```ts
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const book = { title: "Dune", year: 1965, inStock: true };
const year = getProperty(book, "year");
console.log(year + 1, getProperty(book, "title"));
```

`keyof T` is the union of `T`'s property names (`"title" | "year" | "inStock"`), and `T[K]` is the type of property `K` (an **indexed access type**). So `year` is a `number`, and `getProperty(book, "author")` is a compile error. Module 5 explores `keyof` and indexed access types further.

## Generic types and interfaces

Types can have type parameters too:

```ts
interface ApiResponse<T> {
  status: number;
  data: T;
  receivedAt: string;
}

type Pair<A, B = A> = [A, B];

const reply: ApiResponse<string[]> = { status: 200, data: ["a", "b"], receivedAt: "2026-01-01" };
const point: Pair<number> = [1, 2];
const labelled: Pair<string, number> = ["x", 10];
console.log(reply.data.length, point, labelled);
```

`B = A` gives a **default** for a type parameter.

## Generic classes

```ts
class Stack<T> {
  private items: T[] = [];

  push(item: T): void {
    this.items.push(item);
  }

  pop(): T | undefined {
    return this.items.pop();
  }

  get size(): number {
    return this.items.length;
  }
}

const history = new Stack<string>();
history.push("home");
history.push("settings");
console.log(history.pop(), history.size);
```

`history.push(42)` is a compile error. (Class syntax and `private` are Module 4's topic.)

## When not to use generics

A type parameter used only once is pointless: `function log<T>(value: T): void` is just `function log(value: unknown): void`. A generic should **connect** things: an input to an output, or one parameter to another. A good test: if you can't say what relationship the type parameter expresses, you don't need it. And don't use a generic return type to "cast" values that aren't checked: `function parse<T>(json: string): T` is a lie dressed up as a generic (it's `as T` hidden in a signature). Module 6 shows how to validate instead.

function groupBy<T, K extends string>(items: readonly T[], keyOf: (item: T) => K): Partial<Record<K, T[]>> {
  const groups: Partial<Record<K, T[]>> = {};
  for (const item of items) {
    const key = keyOf(item);
    (groups[key] ??= []).push(item);
  }
  return groups;
}

function chunk<T>(items: readonly T[], size: number): T[][] {
  if (size < 1) throw new RangeError("size must be at least 1");
  const out: T[][] = [];
  for (let i = 0; i < items.length; i += size) out.push(items.slice(i, i + size));
  return out;
}

function zip<A, B>(as: readonly A[], bs: readonly B[]): [A, B][] {
  const length = Math.min(as.length, bs.length);
  return Array.from({ length }, (_, i): [A, B] => [as[i], bs[i]]);
}

function pluck<T, K extends keyof T>(items: readonly T[], key: K): T[K][] {
  return items.map((item) => item[key]);
}

Write a generic `class TypedCache<K, V>` with a time-to-live, built on a `Map`:

::starter

}
::solution
class TypedCache<K, V> {
  private entries = new Map<K, { value: V; expires: number }>();

  constructor(
    private readonly ttlMs: number,
    private readonly now: () => number = Date.now,
  ) {}

  set(key: K, value: V): this {
    this.entries.set(key, { value, expires: this.now() + this.ttlMs });
    return this;
  }

  get(key: K): V | undefined {
    const entry = this.entries.get(key);
    if (entry === undefined) return undefined;
    if (entry.expires <= this.now()) {
      this.entries.delete(key);
      return undefined;
    }
    return entry.value;
  }

  getOrCreate(key: K, create: (key: K) => V): V {
    const cached = this.get(key);
    if (cached !== undefined) return cached;
    const value = create(key);
    this.set(key, value);
    return value;
  }

  get size(): number {
    const time = this.now();
    let count = 0;
    for (const entry of this.entries.values()) if (entry.expires > time) count++;
    return count;
  }
}

**Typed event emitter.** Write a generic `class Emitter<Events extends Record<string, unknown>>` where each key of `Events` is an event name and its value the type of the payload:

- `on<E extends keyof Events>(event: E, listener: (payload: Events[E]) => void): () => void` registers a listener and returns an "unsubscribe" function;
- `once<E extends keyof Events>(event: E, listener: (payload: Events[E]) => void): void` listens to one event only;
- `emit<E extends keyof Events>(event: E, payload: Events[E]): number` calls the listeners in order and returns how many were called;
- `listenerCount(event: keyof Events): number`.

The hidden checks make sure a wrong payload type or an unknown event name is a compile error.
::starter

}
::solution
class Emitter<Events extends Record<string, unknown>> {
  private listeners = new Map<keyof Events, ((payload: never) => void)[]>();

  on<E extends keyof Events>(event: E, listener: (payload: Events[E]) => void): () => void {
    const list = this.listeners.get(event) ?? [];
    list.push(listener);
    this.listeners.set(event, list);
    return () => {
      const current = this.listeners.get(event) ?? [];
      this.listeners.set(event, current.filter((l) => l !== listener));
    };
  }

  once<E extends keyof Events>(event: E, listener: (payload: Events[E]) => void): void {
    const off = this.on(event, (payload) => {
      off();
      listener(payload);
    });
  }

  emit<E extends keyof Events>(event: E, payload: Events[E]): number {
    const list = [...(this.listeners.get(event) ?? [])] as ((payload: Events[E]) => void)[];
    for (const listener of list) listener(payload);
    return list.length;
  }

  listenerCount(event: keyof Events): number {
    return this.listeners.get(event)?.length ?? 0;
  }
}
