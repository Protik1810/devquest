=== lesson c-why | What C is | 50
## The language under everything

**C** was created by Dennis Ritchie at Bell Labs between 1969 and 1973, to rewrite the **Unix** operating system in something more portable than assembly language. Brian Kernighan and Ritchie's book *The C Programming Language* (1978) made it famous, and it was standardised in 1989 (**C89**), then revised as C99, C11, C17 and **C23**.

Half a century later, C is still everywhere:

- **operating systems**: the Linux, Windows and macOS kernels are mostly C;
- **embedded systems**: microcontrollers in cars, routers, washing machines and medical devices;
- **infrastructure**: databases (SQLite, PostgreSQL, Redis), web servers (nginx), Git, curl;
- **other languages' engines**: CPython, the Ruby and PHP interpreters, Lua, and the system libraries every language calls.

## What makes C C

- **Compiled to machine code**, with almost no runtime: a C program can run on a bare chip with no operating system.
- **Close to the hardware**: you see memory directly through **pointers**, choose exact integer sizes, and decide when memory is allocated and freed.
- **Small**: about 30 keywords and a modest standard library. There are no classes, no exceptions, no garbage collector, no strings as objects.
- **Trusting**: the compiler assumes you know what you're doing. Reading past the end of an array or using freed memory isn't stopped: it's **undefined behaviour**, and the program may crash, print garbage, or seem to work. Much of learning C is learning the rules that keep you safe.

```
main.c  --compiler (gcc / clang / cl)-->  main.o  --linker-->  main.exe / main  --> runs directly
```

C's syntax (braces, `for`, `printf`-style formatting, `++`, `&&`) was copied by C++, Java, C#, JavaScript, Go and many more, so it will look familiar if you've taken those courses. What's new is what happens underneath: after this course you'll understand what those languages do for you.

## Installing a compiler

C needs a **compiler**. The three big ones:

| Compiler | Where | Install |
|---|---|---|
| **GCC** | Linux (standard), Windows (MinGW-w64, MSYS2) | `sudo apt install build-essential`; on Windows, MSYS2's `pacman -S mingw-w64-ucrt-x86_64-gcc` |
| **Clang** | macOS (standard), Linux, Windows | `xcode-select --install` on macOS; LLVM installers on Windows |
| **MSVC** (`cl`) | Windows | Visual Studio Build Tools with "Desktop development with C++" |

Check it works in a terminal: `gcc --version` or `clang --version`. DevQuest's desktop app finds GCC, Clang or MSVC automatically (Settings → Local compilers).

## Compiling by hand

```
gcc -std=c17 -Wall -Wextra -g -o hello hello.c
./hello
```

| Flag | Meaning |
|---|---|
| `-std=c17` | which C standard to use (`c11`, `c17`, `c2x`/`c23`) |
| `-Wall -Wextra` | turn on most warnings: **always use them** |
| `-Werror` | treat warnings as errors (common in professional builds) |
| `-g` | include debugging information |
| `-O2` | optimise (for release builds) |
| `-o hello` | name of the output file |
| `-fsanitize=address,undefined` | add run-time checks for memory errors and undefined behaviour (GCC/Clang on Linux and macOS): invaluable while learning |

## The four stages

What `gcc hello.c` does, step by step (you can stop after each one):

1. **Preprocessing** (`gcc -E`): handles lines starting with `#`: pastes the contents of `#include`d headers, expands macros.
2. **Compiling** (`gcc -S`): turns C into assembly language for your processor.
3. **Assembling** (`gcc -c`): turns assembly into machine code in an **object file** (`hello.o`).
4. **Linking**: joins your object files with the libraries they use (the C standard library, `libm` for math) into an executable. "undefined reference to `foo`" is a **linker** error: something was declared but never defined.

Bigger programs are split into several `.c` files compiled separately and linked together, usually driven by **make** or **CMake** (Module 6).

## Tools you'll meet

- **Debuggers**: `gdb` (GCC), `lldb` (Clang), the Visual Studio debugger; VS Code drives any of them.
- **Sanitizers** and **Valgrind**: find memory errors at run time.
- **clang-format** formats code; **clang-tidy** and **cppcheck** find bugs statically.

## Exit status

`main` returns an `int` to the operating system: **0 means success**, anything else failure (`EXIT_SUCCESS` and `EXIT_FAILURE` from `<stdlib.h>` say it explicitly). Shell scripts and build tools check it:

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int files_found = 3;
    printf("found %d files\n", files_found);
    return files_found > 0 ? EXIT_SUCCESS : EXIT_FAILURE;
}
```

=== lesson c-basics | Hello, C: the structure of a program | 65
## Anatomy of a program

```c
#include <stdio.h>   /* the standard input/output declarations: printf, scanf... */

/* A function that adds two ints and returns an int */
int add(int a, int b) {
    return a + b;
}

int main(void) {           // execution starts here
    int sum = add(2, 3);   // declare a variable and initialise it
    printf("2 + 3 = %d\n", sum);
    return 0;              // 0: success
}
```

- **`#include <stdio.h>`** is a preprocessor directive: it pastes the declarations of the standard I/O functions into your file. Without it, the compiler doesn't know `printf`.
- Every program has exactly one **`main`** function. `int main(void)` takes no arguments; `int main(int argc, char *argv[])` receives command-line arguments.
- Statements end with **`;`** and blocks are in **`{ }`**. Indentation is for humans only.
- Comments: `/* ... */` (can span lines) and `// ...` (since C99).
- A function must be **declared before it's used**: defining `add` above `main` does that (Module 3 shows prototypes).

## Variables

A variable has a **type**, fixed forever, and must be declared before use:

```c
#include <stdio.h>

int main(void) {
    int age = 36;            // whole number
    double height = 1.68;    // decimal number
    char initial = 'A';      // one character, in single quotes
    const int max_users = 100;  // const: can't be changed

    age = age + 1;
    printf("%c is %d years old and %.2f m tall (limit %d)\n", initial, age, height, max_users);

    int a = 7, b = 2;        // several in one declaration
    printf("%d / %d = %d, remainder %d\n", a, b, a / b, a % b);
    return 0;
}
```

**Always initialise variables.** A local variable declared without a value (`int count;`) holds **garbage**: whatever bytes were in that memory. Reading it is undefined behaviour, and `-Wall` warns about it.

## printf

`printf` takes a **format string** with **conversion specifiers**, then the values to put in them, in order:

| Specifier | For |
|---|---|
| `%d` | `int` |
| `%ld`, `%lld` | `long`, `long long` |
| `%u` | `unsigned int` |
| `%zu` | `size_t` (sizes, from `sizeof`) |
| `%f`, `%.2f` | `double` (2 decimals) |
| `%e`, `%g` | scientific / shortest form |
| `%c` | a character |
| `%s` | a string |
| `%p` | a pointer (address) |
| `%x` | hexadecimal |
| `%%` | a literal `%` |

Width and alignment: `%5d` (right-aligned in 5), `%-10s` (left-aligned in 10), `%05d` (padded with zeros). **The specifier must match the type**: printing a `double` with `%d` is undefined behaviour, and the compiler warns you (that's why DevQuest always shows warnings).

```c
#include <stdio.h>

int main(void) {
    printf("|%5d|%-5d|%05d|\n", 42, 42, 42);
    printf("|%8.3f|%-8s|%c|\n", 3.14159, "pi", 'x');
    printf("%d%% done, hex %x, sci %e\n", 75, 255, 123456.0);
    return 0;
}
```

=== lesson c-errors | Errors, warnings and crashes | 60
## Three kinds of problems

1. **Compile errors**: the code isn't valid C; there's no program to run.
2. **Warnings**: the code is valid, but probably wrong. **In C, take every warning seriously**: many of them are real bugs.
3. **Run-time problems**: crashes (a **segmentation fault**), wrong results, or undefined behaviour that seems to work today and breaks tomorrow.

## Reading compiler messages

GCC and Clang print `file:line:column: error:` (or `warning:`), the message, and the line with a caret `^` under the problem. Fix the **first** error first: later ones are often consequences. This example doesn't compile; run it and read the messages:

```c
// error
#include <stdio.h>

int main(void) {
    int total = 0
    for (int i = 1; i <= 3; i++) {
        total += i;
    }
    printf("%d\n", totl);
    return 0;
}
```

Common messages: `expected ';'` (a missing semicolon, often reported on the **next** line), `use of undeclared identifier` / `'x' undeclared` (a typo or missing declaration), `implicit declaration of function` (a missing `#include` or prototype), `incompatible types`.

## Warnings are bugs waiting to happen

This program compiles and runs, but it's full of mistakes. Run it, read the warnings, and notice that the `if` never prints:

```c
// warning
#include <stdio.h>

int main(void) {
    int count;
    double average = 7.5;
    unsigned int items = 3;
    int unused = 0;
    if (items > -1) {
        printf("items is bigger than -1\n");
    }
    printf("count = %d, average = %d\n", count, average);
    return 0;
}
```

- `count` is **uninitialised**: it prints garbage.
- `%d` for a `double` is **undefined behaviour**: the printed value is nonsense.
- `items > -1` compares unsigned with signed: `-1` is converted to a huge unsigned number, so the condition is **false**, the opposite of what it says. GCC warns about it with `-Wextra` (`-Wsign-compare`); Clang compiles it silently, which shows that warnings catch many bugs, not all of them.
- `unused` is harmless, but often a sign of unfinished code.

Professional C projects compile with `-Wall -Wextra -Werror`, so a warning stops the build.

## Crashes

A **segmentation fault** (Windows: access violation, exit code `0xC0000005`) means the program touched memory it doesn't own. The usual causes: using a `NULL` pointer, an index outside an array, using memory after `free`, or infinite recursion (a **stack overflow**):

```c
// error
#include <stdio.h>

int depth(int n) {
    return depth(n + 1) + 1; // no base case: recursion never stops
}

int main(void) {
    printf("starting\n");
    fflush(stdout);
    printf("%d\n", depth(0));
    return 0;
}
```

C prints no stack trace by itself. To find where it crashed, run the program in a **debugger** (`gdb ./prog`, then `run` and `backtrace`), or compile with `-g -fsanitize=address` to get a detailed report (on Linux and macOS).

## Undefined behaviour

The scariest bugs don't crash. Reading one element past an array's end might return a neighbouring variable's value; signed integer overflow might be "optimised" into an infinite loop. Because the result is **undefined**, the program can behave differently with another compiler, another flag or another day. The defence: warnings, sanitizers, careful code, and tests.
