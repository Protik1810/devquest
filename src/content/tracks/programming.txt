=== lesson fd-thinking | Thinking like a programmer | 45
Programming is mostly **problem solving**; typing the code is the last step. A reliable process:

1. **Understand** the problem. What goes in, what comes out? Work 2-3 examples by hand, including edge cases (empty input, one item, negatives).
2. **Decompose** it into smaller steps that you already know how to do.
3. Write the steps as **pseudocode**: plain language, structured like code.
4. **Translate** the pseudocode into real code, one step at a time.
5. **Test** with your examples, then improve.

Example: *"the average of the even numbers in a list"*:

```
set total to 0 and count to 0
for each number in the list:
    if the number is even:
        add it to total, add 1 to count
if count is 0: the answer is 0
otherwise: the answer is total / count
```

An **algorithm** is exactly that: a finite, precise sequence of steps that solves a problem. The same algorithm can be written in any language. Good habits: name things clearly (`total`, not `t`), solve the simple case first, and check the edge cases you listed in step 1.
--- exercise code python
::prompt
Turn the pseudocode above into a function **`average_of_evens(nums)`** that returns the average of the even numbers in `nums`, or `0` when there are none.
::starter
def average_of_evens(nums):
    # follow the pseudocode step by step
    pass
::solution
def average_of_evens(nums):
    total = 0
    count = 0
    for n in nums:
        if n % 2 == 0:
            total += n
            count += 1
    if count == 0:
        return 0
    return total / count
::tests
assert average_of_evens([1, 2, 3, 4]) == 3, average_of_evens([1, 2, 3, 4])
assert average_of_evens([1, 3, 5]) == 0, 'no even numbers should give 0'
assert average_of_evens([]) == 0, 'an empty list should give 0'
assert average_of_evens([-4, 10, 7]) == 3
assert average_of_evens([6]) == 6
::hints
- An even number has no remainder when divided by 2: `n % 2 == 0`.
- Keep two variables, `total` and `count`, and update both inside the `if`.
- Check `count == 0` before dividing.
--- cards
Algorithm :: A finite, precise sequence of steps that solves a problem, independent of any programming language.
Decomposition :: Breaking a problem into smaller sub-problems you already know how to solve.

=== lesson fd-types | Values, types & conversions | 50
Every value has a **type** that decides what you can do with it:

| Type | Examples | Notes |
|---|---|---|
| `int` | `42`, `-7` | whole numbers, exact |
| `float` | `3.14`, `0.1` | **approximate** binary fractions |
| `str` | `'hi'`, `"42"` | text: `"42"` is not the number 42 |
| `bool` | `True`, `False` | results of comparisons |
| `None` | `None` | "no value" |

**Conversions** are explicit: `int("42")`, `float("3.5")`, `str(7)`, `round(2.675, 2)`.

**Floats are approximate.** `0.1 + 0.2 == 0.3` is **False**, because 0.1 has no exact binary representation (just like 1/3 has no exact decimal one). For money, work in **whole cents** (integers) or use `decimal.Decimal`.

**Division:** `7 / 2` is `3.5`, `7 // 2` is `3` (floor division) and `7 % 2` is `1` (the remainder). Together, `//` and `%` split things fairly: 1000 cents between 3 people is `1000 // 3 = 333` each, plus `1000 % 3 = 1` cent left over.
--- exercise code python
::prompt

2. **`split_bill(total_cents, people)`** returns a list with each person's share in cents. The shares must **add up exactly** to the total, and the first people pay the leftover cents (`split_bill(1000, 3)` → `[334, 333, 333]`).

    extra = total_cents % people
    return [base + 1 if i < extra else base for i in range(people)]

--- cards
Float precision :: Floats are binary approximations: 0.1 + 0.2 != 0.3. Use integer cents or Decimal for money.
// and % :: Floor division and remainder: 1000 // 3 == 333 and 1000 % 3 == 1.

=== lesson fd-binary | Number systems: binary & hex | 55
Computers store everything as **bits** (0 or 1). Eight bits make a **byte** (256 values: 0 to 255).

**Positional notation** works the same in every base: each position is worth *base* times the one to its right.

| Base | Digits | 13 is written | Prefix in code |
|---|---|---|---|
| 10 (decimal) | 0-9 | `13` | |
| 2 (binary) | 0-1 | `1101` (8+4+1) | `0b1101` |
| 16 (hexadecimal) | 0-9, a-f | `d` | `0xd` |

Hex is popular because **one hex digit = 4 bits**, so a byte is exactly two hex digits (`0xff` = 255). That's why colours look like `#ff8800` and memory addresses look like `0x7ffe…`.

**Converting to binary** by hand: divide by 2 repeatedly and read the remainders backwards (13 → 1, 0, 1, 1 → `1101`).

**Negative numbers** use **two's complement**: in *n* bits, `-x` is stored as `2**n - x`. In 8 bits, -1 is `11111111` (255) and -128 is `10000000`. The top bit acts as the sign, and addition just works for both signs.
--- exercise code python

3. **`twos_complement(n, bits)`**: the bit pattern of `n` (possibly negative) as an unsigned number in `bits` bits (`twos_complement(-1, 8)` → `255`, `twos_complement(5, 8)` → `5`).

::solution
def to_binary(n):
    if n == 0:
        return "0"
    digits = ""
    while n > 0:
        digits = str(n % 2) + digits
        n //= 2
    return digits


def from_hex(text):
    value = 0
    for ch in text.lower():
        value = value * 16 + "0123456789abcdef".index(ch)
    return value


def twos_complement(n, bits):
    return n % (2 ** bits)
::tests

assert twos_complement(5, 8) == 5

- Binary: repeat `n % 2` (next digit) and `n //= 2`, building the string from the right.
- Hex: for each character, `value = value * 16 + digit_value`; `"0123456789abcdef".index(ch)` gives the digit value.
- Two's complement in n bits is just `n % 2**bits` in Python.
--- cards
Byte :: 8 bits: 256 values (0-255), written as two hex digits (00-ff).
Two's complement :: Stores -x in n bits as 2**n - x; -1 in 8 bits is 11111111.

=== lesson fd-text | Text & encodings: ASCII, Unicode, UTF-8 | 50
Text is numbers too. Each character has a **code point**: `ord('A')` is 65 and `chr(9731)` is ☃.

- **ASCII** (1963) covers 128 characters: English letters, digits and punctuation, in 7 bits.
- **Unicode** gives every character in every script (plus emoji) a code point, with over 150,000 assigned: `U+00E9` é, `U+4E2D` 中, `U+1F600` 😀.
- **UTF-8** is how most files and web pages *store* Unicode as bytes. It uses a variable length: **1 byte** for ASCII (so ASCII files are valid UTF-8), **2 bytes** up to U+07FF (é, ß, Cyrillic), **3 bytes** up to U+FFFF (most CJK) and **4 bytes** beyond (emoji).

```python
"héllo".encode("utf-8")      # b'h\xc3\xa9llo': 6 bytes for 5 characters
b'h\xc3\xa9llo'.decode("utf-8")
```

**Mojibake** (garbled text like `Ã©`) happens when bytes written in one encoding are read as another. Rule: **decode at the input, work with `str`, encode at the output**, and use UTF-8 everywhere.

`len("😀")` is 1 character, but it's 4 bytes in UTF-8, so string length isn't byte size.

2. **`char_stats(text)`**: a dict counting `"letters"`, `"digits"`, `"spaces"` and `"other"` characters (use `str` methods like `.isalpha()`).
::starter

::solution
def utf8_size(text):
    total = 0
    for ch in text:
        cp = ord(ch)
        if cp < 0x80:
            total += 1
        elif cp < 0x800:
            total += 2
        elif cp < 0x10000:
            total += 3
        else:
            total += 4
    return total


def char_stats(text):
    stats = {"letters": 0, "digits": 0, "spaces": 0, "other": 0}
    for ch in text:
        if ch.isalpha():
            stats["letters"] += 1
        elif ch.isdigit():
            stats["digits"] += 1
        elif ch.isspace():
            stats["spaces"] += 1
        else:
            stats["other"] += 1
    return stats
::tests
for sample in ["hello", "héllo", "中文", "hi 😀", "", "naïve café — ok"]:
    assert utf8_size(sample) == len(sample.encode("utf-8")), f"utf8_size({sample!r}) gave {utf8_size(sample)}, expected {len(sample.encode('utf-8'))}"
assert char_stats("R2-D2 says hi!") == {"letters": 8, "digits": 2, "spaces": 2, "other": 2}, char_stats("R2-D2 says hi!")
assert char_stats("") == {"letters": 0, "digits": 0, "spaces": 0, "other": 0}
assert char_stats("é1 ") == {"letters": 1, "digits": 1, "spaces": 1, "other": 0}
::hints
- `ord(ch)` gives the code point; compare it with `0x80`, `0x800` and `0x10000`.
- Start the dict with all four keys at 0 so every key exists even for empty text.
--- cards
Unicode vs UTF-8 :: Unicode assigns code points to characters; UTF-8 encodes those code points as 1-4 bytes.
Mojibake :: Garbled text from decoding bytes with the wrong encoding (e.g. UTF-8 read as Latin-1: Ã©).

=== lesson fd-logic | Boolean logic & conditions | 45
Conditions are **boolean expressions**: they're `True` or `False`.

| a | b | `a and b` | `a or b` | `a != b` (xor) |
|---|---|---|---|---|
| F | F | F | F | F |
| F | T | F | T | T |
| T | F | F | T | T |
| T | T | T | T | F |

**De Morgan's laws** help simplify and negate conditions:
- `not (a and b)` == `(not a) or (not b)`
- `not (a or b)` == `(not a) and (not b)`

**Short-circuiting:** `and` stops at the first false value and `or` at the first true one, so `user and user.is_admin` never crashes when `user` is `None`.

**Truthiness:** `0`, `""`, `[]`, `{}` and `None` count as false in conditions; almost everything else is true.

Readable conditions beat clever ones: give complex conditions names (`is_adult = age >= 18`) and avoid deep nesting with early returns.

--- cards
De Morgan :: not (a and b) == (not a) or (not b); not (a or b) == (not a) and (not b).
Short-circuit evaluation :: and/or stop as soon as the result is known, so `x and x.attr` is safe when x is None.

=== lesson fd-loops | Loop patterns you'll use forever | 55
Most loops are one of a few **patterns**. Recognise them and code gets easy:

| Pattern | Idea | Sketch |
|---|---|---|
| **Accumulator** | build up a result | `total += x` |
| **Counter** | count matches | `if cond: count += 1` |
| **Search** | stop at the first match | `if found: return i` |
| **Tracker** | remember the best so far | `if x > best: best = x` |
| **Filter / map** | keep or transform items | `[f(x) for x in xs if cond]` |
| **Nested** | every pair / grid cell | `for row in grid: for cell in row:` |

```python
best = None
for x in nums:
    if best is None or x > best:   # "is None" handles the first item
        best = x
```

Off-by-one errors are the most common loop bug: decide whether a range is *inclusive* or *exclusive*, and test with empty and one-item inputs. Prefer `for x in items` over index loops unless you really need the index (then use `enumerate`).
--- exercise code python
::prompt
Write **`summarize(nums)`** that returns a dict with:
- `"smallest"` and `"largest"` (or `None` for an empty list), using the **tracker** pattern, not `min()`/`max()`,
- `"positives"`: how many numbers are greater than 0 (**counter**),
- `"first_negative"`: the **index** of the first negative number, or `-1` (**search**),
- `"running"`: the list of running totals (**accumulator**), e.g. `[1, 2, 3]` → `[1, 3, 6]`.
::starter
def summarize(nums):
    pass
::solution
def summarize(nums):
    smallest = largest = None
    positives = 0
    first_negative = -1
    running = []
    total = 0
    for i, n in enumerate(nums):
        if smallest is None or n < smallest:
            smallest = n
        if largest is None or n > largest:
            largest = n
        if n > 0:
            positives += 1
        if n < 0 and first_negative == -1:
            first_negative = i
        total += n
        running.append(total)
    return {"smallest": smallest, "largest": largest, "positives": positives, "first_negative": first_negative, "running": running}
::tests
r = summarize([3, -1, 4, -5, 9, 0])
assert r == {"smallest": -5, "largest": 9, "positives": 3, "first_negative": 1, "running": [3, 2, 6, 1, 10, 10]}, r
assert summarize([]) == {"smallest": None, "largest": None, "positives": 0, "first_negative": -1, "running": []}, summarize([])
assert summarize([7])["running"] == [7]
assert summarize([-2, -8])["largest"] == -2
::hints
- Start `smallest` and `largest` at `None` and set them on the first item.
- `enumerate(nums)` gives you `(index, value)` pairs.
- Only record the first negative: check `first_negative == -1` before setting it.
--- cards
Tracker pattern :: Keep the best value seen so far (starting from None) and update it when a better one appears.
Off-by-one error :: A loop that runs one time too many or too few; test empty and single-item inputs.

=== lesson fd-functions | Functions, scope & clean code | 50
A **function** packages steps under a name, with **parameters** in and a **return value** out:

```python
def to_fahrenheit(celsius):
    """Convert °C to °F."""          # docstring: what it does
    return celsius * 9 / 5 + 32
```

**`return` vs `print`.** `print` shows text to a human; `return` hands a value back to the code that called the function, so it can be stored, tested and reused. Functions that compute should *return*; let one place at the edge of the program do the printing.

**Scope.** Variables created inside a function are **local** and disappear when it returns. Avoid changing global variables from functions; pass values in and return results instead.

**Pure functions** (output depends only on input, no side effects) are the easiest to test and reuse. **Single responsibility:** each function does one thing. If its name needs "and", split it.

**Default and keyword arguments:** `def greet(name, greeting="Hello")` can be called as `greet("Ada", greeting="Hi")`. Never use a mutable default like `def f(items=[])`, because that list is shared between calls.

=== lesson fd-errors | Errors, exceptions & defensive code | 55
Errors are information. A Python **traceback** reads bottom-up: the **last line** says *what* went wrong (`ZeroDivisionError: division by zero`), and the lines above show *where* (file, line, function), from the outermost call down to the line that failed.

Three kinds of errors:
- **Syntax errors**: the code isn't valid Python, and nothing runs.
- **Runtime exceptions**: valid code meets bad data (`KeyError`, `TypeError`, `ValueError`, `IndexError`).
- **Logic errors**: no crash, just a wrong answer. Only tests catch these.

**Handling exceptions:**

```python
try:
    age = int(text)
except ValueError:
    print("Please enter a number")
else:
    print("ok")        # runs only if no exception
finally:
    print("always runs, e.g. close files")
```

Catch **specific** exceptions you can handle, never a bare `except:` that hides bugs. **Raise** your own errors with a clear message when input breaks your rules: `raise ValueError("age must be between 0 and 150")`. Validating at the boundary (user input, files, network) and failing loudly is called **defensive programming**.

Defensive programming :: Validate input at boundaries and fail loudly with clear errors instead of continuing with bad data.

=== lesson fd-formats | Data formats: JSON & CSV | 55
Programs exchange data as text in standard formats.

**JSON** (JavaScript Object Notation) is the language of web APIs: objects `{}`, arrays `[]`, strings (double quotes only), numbers, `true`/`false`/`null`.

```python
import json
data = json.loads('{"name": "Ada", "skills": ["math"]}')   # text → Python dict
text = json.dumps(data, indent=2)                          # Python → text
```

**CSV** (comma-separated values) is the language of spreadsheets: one record per line, the first line usually holds the headers. Never split on commas yourself, because values can contain quoted commas (`"London, UK"`). Use the `csv` module:

```python
import csv, io
rows = list(csv.DictReader(io.StringIO(text)))   # [{'name': 'Ada', 'age': '36'}, ...]
```

Everything read from CSV is a **string**, so convert numbers yourself. Other formats you'll meet: **YAML** (config files), **XML** (older APIs and documents), **TOML** (`pyproject.toml`) and binary formats like **Protocol Buffers** and **Parquet** for speed.
--- exercise code python

::starter

::solution

=== lesson fd-regex | Regular expressions | 60
A **regular expression** (regex) is a small pattern language for finding and validating text. It's supported by almost every language, editor and command-line tool (`grep`).

| Pattern | Matches |
|---|---|
| `\d` `\w` `\s` | a digit, a word character (letter/digit/_), whitespace |
| `.` | any character except newline |
| `[aeiou]` `[^0-9]` | one of these / not one of these |
| `*` `+` `?` `{2,4}` | 0+, 1+, 0 or 1, 2 to 4 repetitions |
| `^` `$` | start and end of the string |
| `( … )` | a group you can extract |
| `\b` | a word boundary |

```python
import re
re.findall(r"\d+", "3 cats, 12 dogs")            # ['3', '12']
re.fullmatch(r"\d{4}-\d{2}-\d{2}", "2026-03-01")  # matches the whole string, or None
re.sub(r"\s+", " ", "a   lot    of space")         # 'a lot of space'
```

Always write patterns as **raw strings** (`r"..."`) so backslashes reach the regex engine. Regex is great for *shapes* of text; don't use it to parse HTML or to fully validate emails. Combine it with real checks (is the month 1-12?).

import re


def find_emails(text):
    return re.findall(r"[\w.%+-]+@[\w-]+(?:\.[\w-]+)*\.[A-Za-z]{2,}", text)


def is_date(text):
    m = re.fullmatch(r"(\d{4})-(\d{2})-(\d{2})", text)
    if not m:
        return False
    month, day = int(m.group(2)), int(m.group(3))
    return 1 <= month <= 12 and 1 <= day <= 31


def mask_digits(text):
    return re.sub(r"\d{8,}", lambda m: "*" * (len(m.group()) - 4) + m.group()[-4:], text)

=== lesson fd-files | Files, paths & the filesystem | 50
Files outlive your program. The essentials:

```python
with open("notes.txt", "w", encoding="utf-8") as f:   # 'w' overwrites, 'a' appends, 'r' reads
    f.write("first line\n")

with open("notes.txt", encoding="utf-8") as f:
    for line in f:                                      # one line at a time: memory-friendly
        print(line.rstrip("\n"))
```

- **`with`** closes the file automatically, even if an error happens.
- Always pass **`encoding="utf-8"`**; the default differs between operating systems.
- **Paths:** absolute (`/home/ada/data.csv`, `C:\Users\Ada\data.csv`) vs relative (to the *current working directory*, which isn't always your script's folder). Use `pathlib` to join paths portably: `Path("data") / "scores.csv"`.
- **Text vs binary:** images and zips are opened with `"rb"`/`"wb"` and give `bytes`.

Write files safely: write to a temporary file, then rename it over the old one, so a crash mid-write never leaves a half-written file (that's how DevQuest saves your progress). This exercise runs in Python's in-memory filesystem, so it's safe to experiment.

from pathlib import Path


def save_scores(path, scores):
    with open(path, "w", encoding="utf-8") as f:
        for name in sorted(scores):
            f.write(f"{name},{scores[name]}\n")


def load_scores(path):
    if not Path(path).exists():
        return {}
    scores = {}
    with open(path, encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if not line:
                continue
            name, score = line.split(",")
            scores[name] = int(score)
    return scores


def add_score(path, name, points):
    scores = load_scores(path)
    scores[name] = scores.get(name, 0) + points
    save_scores(path, scores)

=== lesson fd-speed | How fast is my code? | 60
Two programs can give the same answer at wildly different speeds. **Big-O** describes how the work grows with the input size *n*:

| Big-O | Name | 1,000 items | 1,000,000 items |
|---|---|---|---|
| O(1) | constant | 1 step | 1 step |
| O(log n) | logarithmic | ~10 | ~20 |
| O(n) | linear | 1,000 | 1,000,000 |
| O(n log n) | sorting | ~10,000 | ~20,000,000 |
| O(n²) | quadratic | 1,000,000 | 1,000,000,000,000 😱 |

The classic trap is a **loop inside a loop** over the same data:

```python
def has_duplicates_slow(items):          # O(n²): compares every pair
    for i in range(len(items)):
        for j in range(i + 1, len(items)):
            if items[i] == items[j]:
                return True
    return False
```

**Data structures matter.** `x in some_list` checks items one by one (O(n)), but `x in some_set` or `x in some_dict` is O(1) on average, thanks to hashing. Swapping a list for a set often turns O(n²) into O(n).

Measure, don't guess: `time.perf_counter()` before and after, and test with *large* inputs, because small inputs hide slow algorithms. This exercise's tests use 100,000 numbers, so an O(n²) solution runs out of time.
--- exercise code python
::prompt
Write two **O(n)** functions (a loop inside a loop will time out on the big test):

2. **`pair_with_sum(nums, target)`**: return a tuple `(a, b)` of two numbers from the list (different positions) that add up to `target`, with `a` appearing **before** `b`; return `None` if there's none.

::solution
def has_duplicates(items):
    seen = set()
    for x in items:
        if x in seen:
            return True
        seen.add(x)
    return False


def pair_with_sum(nums, target):
    seen = set()
    for b in nums:
        a = target - b
        if a in seen:
            return (a, b)
        seen.add(b)
    return None
::tests

assert has_duplicates([3, 1, 4]) is False
assert has_duplicates([]) is False
assert pair_with_sum([2, 7, 11, 15], 9) == (2, 7)
assert pair_with_sum([3, 3], 6) == (3, 3)

::hints
- Keep a `set` of values you've already seen; checking membership in a set is O(1).
- For the pair: for each `b`, the partner you need is `target - b`; check whether you've seen it.
- Add the current number to the set *after* checking, so a number can't pair with itself.
--- cards
Big-O :: How an algorithm's work grows with input size n: O(1), O(log n), O(n), O(n log n), O(n²)…
list vs set membership :: `x in list` is O(n); `x in set` is O(1) on average thanks to hashing.

=== lesson fd-testing | Testing your own code | 55
You can't see a bug you never test for. **Automated tests** are small programs that check your code and can be re-run in a second after every change.

**A good test** has three parts (**Arrange, Act, Assert**):

```python
def test_discount():
    price = 100                     # arrange
    result = apply_discount(price, 0.2)   # act
    assert result == 80             # assert
```

**What to test:**
- the normal case, from the examples in the task;
- **edge cases**: empty input, zero, one item, the largest/smallest allowed value, duplicates;
- **invalid input**: does it raise the error you promised?
- **boundaries**: if the rule is "over 18", test 17, 18 and 19.

**Test-driven development (TDD):** write a failing test first, make it pass with the simplest code, then refactor, in a red → green → refactor loop. Tools like `pytest` (Python), Jest/Vitest (JavaScript) and JUnit (Java) run hundreds of tests and report which ones fail.

A test suite is a **safety net**: you can refactor fearlessly because the tests tell you the moment behaviour changes.

def grade(score):
    if isinstance(score, bool) or not isinstance(score, int):
        raise TypeError("score must be an int")
    if score < 0 or score > 100:
        raise ValueError("score must be between 0 and 100")
    if score >= 90:
        return "A"
    if score >= 80:
        return "B"
    if score >= 70:
        return "C"
    if score >= 60:
        return "D"
    return "F"
