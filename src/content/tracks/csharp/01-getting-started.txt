=== lesson cs-why | What C# and .NET are | 50
## A modern language on a big platform

**C#** (pronounced "C sharp") was created at Microsoft by Anders Hejlsberg (who also designed Turbo Pascal, Delphi and later TypeScript) and released in 2002 together with the **.NET** platform. It began as Microsoft's answer to Java and has since grown into one of the most feature-rich mainstream languages, with a new version every year.

```
Program.cs  --C# compiler (Roslyn)-->  app.dll (IL bytecode)  --.NET runtime (CLR, JIT)-->  runs on Windows, Linux, macOS
```

Like Java, C# compiles to an intermediate language (**IL**) that the **CLR** (Common Language Runtime) turns into machine code with a JIT compiler, and memory is managed by a **garbage collector**. Since 2016, .NET is **open source and cross-platform**: the same program runs on Windows, Linux and macOS, in containers and in the cloud.

Where C# is used:

- **Back ends and cloud services**: ASP.NET Core is one of the fastest web frameworks, used by Microsoft, Stack Overflow and countless companies, especially with Azure.
- **Games**: **Unity**, the most popular game engine, is scripted in C# (Hollow Knight, Cities: Skylines, Pokémon Go, Among Us...). Godot supports it too.
- **Desktop applications**: Windows apps with WPF, WinForms and WinUI; cross-platform ones with .NET MAUI and Avalonia.
- **Enterprise software**, finance, healthcare and government systems.

## What makes C# C#

- **Statically and strongly typed**, with type inference (`var`).
- **Object-oriented** with classes, interfaces and inheritance, plus **value types** (`struct`), properties and events built into the language.
- **Functional features**: lambdas, **LINQ** (queries over any data), pattern matching, records, immutability.
- **Asynchronous programming** with `async`/`await` (C# introduced it in 2012; JavaScript, Python and others copied it).
- **Safety and performance**: nullable reference types catch null errors at compile time, while `Span<T>` and structs allow low-level, allocation-free code when needed.

If you know Java, C# will feel familiar (same syntax family, same ideas); this course points out the differences.

## Versions

.NET has a release every November; even-numbered ones are **Long-Term Support** (LTS): .NET 8 (2023) and **.NET 10** (2025). Each .NET version comes with a C# version: this course uses **C# 14 on .NET 10**. The old Windows-only ".NET Framework" (up to 4.8) still runs many legacy applications.

=== lesson cs-setup | Installing .NET and running programs | 55
## Install the .NET SDK

1. Download the **.NET SDK** (version 10 or later) from **dotnet.microsoft.com/download**, or on Linux use your package manager (`sudo apt install dotnet-sdk-10.0` on Ubuntu) or Microsoft's `dotnet-install` script. On macOS: `brew install --cask dotnet-sdk`.
2. Check it:

```
dotnet --version
dotnet --list-sdks
```

DevQuest's desktop app finds the SDK automatically (see **Languages** in the sidebar).

## Projects and the dotnet CLI

C# code normally lives in a **project**: a folder with a `.csproj` file describing how to build it. The `dotnet` command does everything:

```
dotnet new console -o Hello     # create a console app in the folder Hello
cd Hello
dotnet run                      # build and run
dotnet build                    # build only (creates bin/Debug/net10.0/Hello.dll)
dotnet add package Humanizer    # add a library from NuGet
dotnet test                     # run tests
dotnet publish -c Release       # package for deployment
```

A new console project contains two files:

```
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>
</Project>
```

and `Program.cs`. Since .NET 10 you can also run a single file directly, without a project: `dotnet run app.cs`.

## Top-level statements

Classic C# programs, like Java's, needed a class and a `Main` method:

```csharp
namespace Hello;

class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine("Hello the classic way");
    }
}
```

Since C# 9, a file can contain **top-level statements** instead: the compiler generates the class and `Main` for you, so a program can start with its first line of real code. One file per program may do this, and the statements must come **before** any type declarations in that file:

```csharp
string name = "Ada";
Console.WriteLine(Greeter.Greet(name));

class Greeter
{
    public static string Greet(string name) => $"Hello, {name}!";
}
```

That's the convention in DevQuest: statements first, then your classes below them.

## Implicit usings

`using System;` at the top of a file lets you write `Console` instead of `System.Console`. With `<ImplicitUsings>enable</ImplicitUsings>` (the default), the common namespaces (`System`, `System.Collections.Generic`, `System.IO`, `System.Linq`, `System.Threading.Tasks`...) are imported automatically, so short programs need no `using` lines.

## Editors and IDEs

- **Visual Studio** (Windows; the free Community edition): the classic, full-featured C# IDE;
- **JetBrains Rider** (all platforms, free for non-commercial use);
- **VS Code** with the **C# Dev Kit** extension.

For quick experiments, `dotnet run` on a single file, or online tools like SharpLab (which also shows the compiled IL).

=== lesson cs-basics | Hello, C#: the structure of a program | 65
## Statements, variables and types

```csharp
// A line comment
string name = "Ada";
int year = 1843;
double version = 14.0;
bool fun = true;

Console.WriteLine(name + " wrote the first program in " + year);
Console.WriteLine($"C# {version}, fun: {fun}");

year = year + 183;
Console.WriteLine($"Now it's {year}");
```

- Every statement ends with `;`, and blocks are grouped with braces `{ }`. C# is **case-sensitive** (`Console`, not `console`).
- A variable has a **type** that never changes: `string`, `int`, `double`, `bool` are the everyday ones. Declare once with the type, then assign without it.
- **`var`** lets the compiler infer the type from the value: `var count = 3;` is an `int` forever.
- Comments: `//` for a line, `/* ... */` for a block, `///` for XML documentation comments.

## String interpolation

The **`$`** prefix makes a string **interpolated**: expressions in braces are evaluated and inserted. Format specifiers follow a colon:

```csharp
string item = "Coffee";
int quantity = 3;
decimal price = 2.5m;

Console.WriteLine($"{item} x{quantity} = {quantity * price}");
Console.WriteLine($"Total: {quantity * price:F2}");
Console.WriteLine($"|{item,-8}|{quantity,5}|");
Console.WriteLine($"{0.256:P1} of {1234567:N0} users");
```

| Format | Example | Result |
|---|---|---|
| `F2` | `{7.5:F2}` | `7.50` |
| `N0` | `{1234567:N0}` | `1,234,567` |
| `P1` | `{0.256:P1}` | `25.6 %` (culture-dependent) |
| `,5` / `,-8` | `{x,5}` | right-/left-aligned in a width |
| `D3` | `{7:D3}` | `007` |

Number formatting normally depends on the computer's **culture**: a German PC writes `2,50` where an American one writes `2.50`. DevQuest runs programs with the **invariant culture** (English-style numbers), so everyone gets the same output; in your own programs, pass `CultureInfo.InvariantCulture` when text must be machine-readable (files, APIs), and the user's culture when it's shown to people.

`Console.Write` prints without a line break; `Console.WriteLine()` with no argument prints an empty line.

## Methods

A program grows by splitting it into **methods**. With top-level statements, you can declare local functions right in the file:

```csharp
double CircleArea(double radius) => Math.PI * radius * radius;

void PrintLine(string text)
{
    Console.WriteLine(new string('=', text.Length));
    Console.WriteLine(text);
    Console.WriteLine(new string('=', text.Length));
}

PrintLine($"Area: {CircleArea(2):F2}");
```

`=>` is an **expression body**: a one-expression method without braces and `return`. Module 3 covers methods in depth.

=== lesson cs-errors | Reading compiler errors and exceptions | 55
## Compile errors

The C# compiler (Roslyn) checks the whole program before it runs. Errors have a **code**, a **position** and a message:

```csharp
// error: assigning text to an int
int age = "thirty";
Console.WriteLine(age);
```

```
Program.cs(2,11): error CS0029: Cannot implicitly convert type 'string' to 'int'
```

`Program.cs(2,11)` is the file, **line** 2 and **column** 11. The **error code** (`CS0029`) can be searched: Microsoft documents every one. Common ones:

| Code | Message | Usual cause |
|---|---|---|
| CS1002 | `; expected` | a missing semicolon |
| CS0103 | `The name 'x' does not exist in the current context` | a typo, or a variable used outside its scope |
| CS0029 | `Cannot implicitly convert type 'A' to 'B'` | a value of the wrong type |
| CS0161 | `not all code paths return a value` | a method without a `return` on some path |
| CS0165 | `Use of unassigned local variable 'x'` | reading a variable before giving it a value |
| CS1061 | `'T' does not contain a definition for 'X'` | a misspelt method or property |
| CS0117 | `'Console' does not contain a definition for 'Writeline'` | wrong capitalisation |

```csharp
// error: a misspelt method (C# is case-sensitive)
Console.Writeline("Hello");
```

Fix the **first** error first: later ones are often consequences. **Warnings** (codes like `CS8600`) don't stop the build but deserve attention; many teams treat them as errors.

## Exceptions

Problems that only appear at run time throw an **exception**. Unhandled, it ends the program with a message and a **stack trace**:

```csharp
// error: compiles, then fails while running
int[] scores = { 90, 85, 77 };
Console.WriteLine($"First: {scores[0]}");
Console.WriteLine($"Fourth: {scores[3]}");
```

```
First: 90
Unhandled exception. System.IndexOutOfRangeException: Index was outside the bounds of the array.
   at Program.<Main>$(String[] args) in Program.cs:line 4
```

(`<Main>$` is the method the compiler generated for the top-level statements.) Common exceptions:

| Exception | Means |
|---|---|
| `NullReferenceException` | using a variable that holds `null` |
| `IndexOutOfRangeException` / `ArgumentOutOfRangeException` | an index outside an array / list |
| `DivideByZeroException` | integer division by zero |
| `FormatException` | `int.Parse("abc")` |
| `InvalidCastException` | converting an object to a type it isn't |
| `KeyNotFoundException` | a missing dictionary key |

Module 5 shows how to catch and handle them.
