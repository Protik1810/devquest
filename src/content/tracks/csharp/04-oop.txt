## A class with fields, a constructor and methods

```csharp
var alice = new BankAccount("Alice", 100);
var bob = new BankAccount("Bob", 20);
alice.Deposit(50);
Console.WriteLine(bob.Withdraw(30));      // False: not enough money
Console.WriteLine(alice);
Console.WriteLine(bob.Balance);

class BankAccount
{
    private decimal _balance;               // a field: private by convention, _camelCase

    public BankAccount(string owner, decimal opening)
    {
        Owner = owner;
        _balance = opening;
    }

    public string Owner { get; }            // a read-only auto-property
    public decimal Balance => _balance;     // a computed, read-only property

    public void Deposit(decimal amount) => _balance += amount;

    public bool Withdraw(decimal amount)
    {
        if (amount > _balance) return false;
        _balance -= amount;
        return true;
    }

    public override string ToString() => $"{Owner}: {_balance}";
}
```

- A **constructor** has the class's name and no return type; `new` creates an object and runs it.
- `this` refers to the current object (needed only when names clash).
- `override ToString()` controls how the object prints (every class inherits from `object`).

## Properties

**Properties** are C#'s answer to Java's getters and setters: they look like fields from outside, but run code:

```csharp
var t = new Thermostat();
t.Target = 30;                       // the setter clamps it
Console.WriteLine(t.Target);
t.Target = 18.5;
Console.WriteLine($"{t.Target} {t.IsHeating}");
Console.WriteLine(t.Name);

class Thermostat
{
    private double _target = 20;
    public double Current { get; set; } = 19;        // auto-property with an initial value

    public double Target
    {
        get => _target;
        set => _target = Math.Clamp(value, 5, 28);   // value is the assigned value
    }

    public bool IsHeating => Current < Target;       // computed, read-only
    public string Name { get; init; } = "Living room"; // settable only during initialisation
}
```

| Form | Meaning |
|---|---|
| `public int X { get; set; }` | auto-property: the compiler creates the hidden field |
| `public int X { get; }` | read-only: set only in the constructor |
| `public int X { get; init; }` | settable in an object initialiser, then read-only |
| `public int X { get; private set; }` | readable by all, settable only inside the class |
| `public int X => expr;` | computed, read-only |

## Object initialisers

```csharp
var p = new Product { Name = "Lamp", Price = 35m, Tags = { "home", "light" } };
Console.WriteLine($"{p.Name} {p.Price} [{string.Join(", ", p.Tags)}]");

class Product
{
    public required string Name { get; init; }      // must be set by every creator (C# 11)
    public decimal Price { get; init; }
    public List<string> Tags { get; } = new();
}
```

An **object initialiser** `{ Name = ..., Price = ... }` sets properties right after construction. **`required`** members must be set there, or the code doesn't compile: a clean alternative to long constructors.

## Primary constructors

C# 12 lets a class declare its constructor parameters in its header; they're in scope throughout the class:

```csharp
var g = new Greeter("Hello");
Console.WriteLine(g.Greet("Ada"));

class Greeter(string greeting)
{
    public string Greet(string name) => $"{greeting}, {name}!";
}
```

## Classes are reference types

Variables of a class type hold **references**; assigning shares the object, and `null` means "no object" (using it throws `NullReferenceException`). Objects nothing refers to are freed by the garbage collector.

=== lesson cs-encapsulation | Encapsulation, static and immutability | 65
## Access modifiers

| Modifier | Visible from |
|---|---|
| `private` | the type itself (the **default** for members) |
| `protected` | the type and derived classes |
| `internal` | the same **assembly** (project) (the default for top-level types) |
| `protected internal` / `private protected` | combinations of the above |
| `public` | everywhere |

Keep fields `private`, expose behaviour through methods and properties, and validate in one place:

```csharp
var acc = new Account("Ada", 100);
acc.Deposit(25);
try
{
    acc.Withdraw(500);
}
catch (InvalidOperationException e)
{
    Console.WriteLine($"Refused: {e.Message}");
}
Console.WriteLine($"{acc.Owner} has {acc.Balance}");

class Account
{
    public Account(string owner, decimal opening)
    {
        ArgumentException.ThrowIfNullOrWhiteSpace(owner);
        ArgumentOutOfRangeException.ThrowIfNegative(opening);
        Owner = owner;
        Balance = opening;
    }

    public string Owner { get; }
    public decimal Balance { get; private set; }

    public void Deposit(decimal amount)
    {
        ArgumentOutOfRangeException.ThrowIfNegativeOrZero(amount);
        Balance += amount;
    }

    public void Withdraw(decimal amount)
    {
        if (amount > Balance) throw new InvalidOperationException("insufficient funds");
        Balance -= amount;
    }
}
```

The `ThrowIf...` helpers (.NET 7+) make argument validation one line each.

## static members and static classes

`static` fields, properties and methods belong to the type, shared by all instances. A **static class** can't be instantiated and holds only static members: the place for utility functions (`Math`, `Console`, `File`):

```csharp
var a = new Ticket();
var b = new Ticket();
var c = new Ticket();
Console.WriteLine($"{a.Number} {b.Number} {c.Number} issued: {Ticket.Issued}");
Console.WriteLine(TextUtils.Shout("hello"));

class Ticket
{
    private static int s_next = 1;
    public static int Issued => s_next - 1;
    public int Number { get; } = s_next++;
}

static class TextUtils
{
    public static string Shout(string s) => s.ToUpper() + "!";
}
```

## readonly, const and immutability

- `const`: a compile-time constant (numbers, strings).
- `readonly` field: assigned only in its declaration or the constructor.
- Immutable classes: only get-only or `init` properties, no setters, and methods that return **new** objects (like `string` and `DateTime`).

```csharp
var price = new Money(19.99m, "EUR");
var doubled = price.Times(2);
Console.WriteLine($"{price} -> {doubled}");

sealed class Money(decimal amount, string currency)
{
    public decimal Amount { get; } = amount;
    public string Currency { get; } = currency;
    public Money Times(int factor) => new(Amount * factor, Currency);
    public override string ToString() => $"{Amount:F2} {Currency}";
}
```

(`new(...)` with the type omitted is a **target-typed new**: the type comes from the context.) `sealed` prevents inheritance. **Records** (lesson 5) make such types one line long.

=== lesson cs-inheritance | Inheritance and polymorphism | 75
## Base and derived classes

```csharp
Employee[] staff = { new Employee("Ada", 4000), new Manager("Grace", 6000, 1500) };
foreach (Employee e in staff) Console.WriteLine(e.Describe());

class Employee(string name, decimal salary)
{
    public string Name { get; } = name;
    protected decimal Salary { get; } = salary;

    public virtual decimal MonthlyPay() => Salary;
    public string Describe() => $"{Name} ({GetType().Name}): {MonthlyPay()}";
}

class Manager(string name, decimal salary, decimal bonus) : Employee(name, salary)
{
    public override decimal MonthlyPay() => base.MonthlyPay() + bonus;
}
```

- `class Manager : Employee` derives from `Employee` (single inheritance, like Java); the base constructor is called with the arguments after the colon (`: Employee(name, salary)`, or `: base(...)` in a classic constructor).
- C# methods are **not virtual by default** (unlike Java): a method must be marked **`virtual`** to be overridable, and the override must say **`override`**. `base.Method()` calls the base version.
- `sealed override` stops further overriding; a `sealed class` can't be derived from.

## Abstract classes and polymorphism

```csharp
Shape[] shapes = { new Circle(1), new Rectangle(2, 3), new Circle(0.5) };
foreach (Shape s in shapes) Console.WriteLine($"{s.Name}: {s.Area():F2}");
Console.WriteLine($"Total: {shapes.Sum(s => s.Area()):F2}");

abstract class Shape
{
    public abstract double Area();
    public string Name => GetType().Name;
}

class Circle(double radius) : Shape
{
    public override double Area() => Math.PI * radius * radius;
}

class Rectangle(double width, double height) : Shape
{
    public override double Area() => width * height;
}
```

A call through a base-type reference runs the **actual object's** override (dynamic dispatch). Abstract classes can't be instantiated, and their abstract members must be overridden.

## Equality: Equals, GetHashCode and ==

For classes, `Equals` and `==` compare **references** by default. To give a class value semantics, override `Equals` and `GetHashCode` together (and usually `==`/`!=` too, lesson 6), or use a **record**, which does it for you (lesson 5):

```csharp
var a = new Isbn("978-0134685991");
var b = new Isbn("978-0134685991");
Console.WriteLine($"{a == b} {a.Equals(b)} {a.GetHashCode() == b.GetHashCode()}");

sealed class Isbn(string code)
{
    public string Code { get; } = code;
    public override bool Equals(object? obj) => obj is Isbn other && other.Code == Code;
    public override int GetHashCode() => Code.GetHashCode();
}
```

(`a == b` is still `False`: overriding `Equals` doesn't change `==` for classes.)

## Type tests and casts

`is` tests a type and binds a variable; `as` converts or gives `null`; a cast `(Circle)shape` throws `InvalidCastException` if wrong:

```csharp
object[] things = { new Circle(2), "text", 42 };
foreach (object t in things)
{
    string kind = t switch
    {
        Circle c => $"circle with area {c.Area():F1}",
        string s => $"string of length {s.Length}",
        int n when n > 40 => "a big int",
        _ => "something else",
    };
    Console.WriteLine(kind);
}

class Circle(double r)
{
    public double Area() => Math.PI * r * r;
}
```

Prefer **composition** ("has a") to inheritance ("is a") unless the relationship is genuinely "is a": deep hierarchies are rigid. Many style guides recommend `sealed` by default.

=== lesson cs-interfaces | Interfaces | 65
## Contracts

```csharp
IPaymentMethod[] methods = { new Card("4242"), new PayPal("ada@example.com"), new GiftCard(20) };
foreach (var m in methods) Console.WriteLine($"{m.Describe()} -> {(m.Pay(25) ? "paid" : "declined")}");

interface IPaymentMethod
{
    bool Pay(decimal amount);
    string Describe();
}

class Card(string last4) : IPaymentMethod
{
    public bool Pay(decimal amount) => true;
    public string Describe() => $"Card ending {last4}";
}

class PayPal(string email) : IPaymentMethod
{
    public bool Pay(decimal amount) => amount <= 1000;
    public string Describe() => $"PayPal {email}";
}

class GiftCard(decimal balance) : IPaymentMethod
{
    private decimal _balance = balance;
    public bool Pay(decimal amount)
    {
        if (amount > _balance) return false;
        _balance -= amount;
        return true;
    }
    public string Describe() => $"Gift card ({_balance} left)";
}
```

- Interface names start with **`I`** by convention (`IComparable`, `IDisposable`, `IEnumerable<T>`).
- A class can implement many interfaces (and extend one class): `class Duck : Animal, IFlyer, ISwimmer`.
- Interfaces can contain properties and events, **default implementations** (C# 8) and static members.

## Standard interfaces worth knowing

| Interface | Gives |
|---|---|
| `IComparable<T>` | a natural order: `CompareTo`, used by `Sort` and `OrderBy` |
| `IEquatable<T>` | typed equality (`Equals(T)`) |
| `IEnumerable<T>` | "can be iterated with foreach" (and LINQ) |
| `IDisposable` | a `Dispose()` method to release resources, used by `using` (Module 5) |
| `IComparer<T>`, `IEqualityComparer<T>` | external comparison strategies |

```csharp
var versions = new List<Version>{ new(1, 10), new(1, 2), new(0, 9) };
versions.Sort();
Console.WriteLine(string.Join(", ", versions));

class Version(int major, int minor) : IComparable<Version>
{
    public int Major { get; } = major;
    public int Minor { get; } = minor;

    public int CompareTo(Version? other)
    {
        if (other is null) return 1;
        int byMajor = Major.CompareTo(other.Major);
        return byMajor != 0 ? byMajor : Minor.CompareTo(other.Minor);
    }

    public override string ToString() => $"{Major}.{Minor}";
}
```

## Explicit interface implementation

When two interfaces have a member with the same name, or a member shouldn't clutter the class's public API, implement it **explicitly**; it's then only reachable through the interface:

```csharp
var file = new LogFile();
((IAuditable)file).Audit();

interface IAuditable { void Audit(); }

class LogFile : IAuditable
{
    void IAuditable.Audit() => Console.WriteLine("audited");
}
```

## Interfaces and dependency injection

Code that depends on interfaces (`ILogger`, `IOrderRepository`, `IClock`) can be given any implementation: a real database in production, an in-memory fake in tests. ASP.NET Core's built-in **dependency injection** container is built around this: classes declare the interfaces they need in their constructors, and the framework supplies implementations.

=== lesson cs-structs-records | Structs, records and enums | 75
## Records: value-like types in one line

```csharp
var a = new Point(3, 4);
var b = new Point(3, 4);
Console.WriteLine(a);                       // Point { X = 3, Y = 4 }
Console.WriteLine($"{a == b} {a.Equals(b)} {ReferenceEquals(a, b)}");
var moved = a with { X = 10 };              // a copy with one property changed
Console.WriteLine($"{moved} {a.DistanceToOrigin()}");
var (x, y) = a;                             // deconstruction
Console.WriteLine($"{x},{y}");

record Point(int X, int Y)
{
    public double DistanceToOrigin() => Math.Sqrt(X * X + Y * Y);
}
```

A **record** generates init-only properties, a constructor, value-based `Equals`, `GetHashCode`, `==`/`!=`, a readable `ToString`, deconstruction and **`with` expressions** (non-destructive mutation). Records can have extra members and validation:

```csharp
Console.WriteLine(new Email("Ada@Example.com"));
try { new Email("nope"); }
catch (ArgumentException e) { Console.WriteLine($"Rejected: {e.Message}"); }

record Email
{
    public string Address { get; }
    public Email(string address)
    {
        if (!address.Contains('@')) throw new ArgumentException($"not an email: {address}");
        Address = address.ToLowerInvariant();
    }
}
```

## Structs: value types

A **struct** is a value type: variables hold the data itself, and assignment **copies** it. Structs suit small, immutable values (coordinates, money amounts, colours); .NET's `int`, `double`, `DateTime`, `TimeSpan` and `Guid` are all structs.

```csharp
var p1 = new Vector2(1, 2);
var p2 = p1;                // a full copy
p2 = p2 with { X = 99 };
Console.WriteLine($"{p1} {p2} {p1 + new Vector2(0.5, 0.5)}");

readonly record struct Vector2(double X, double Y)
{
    public static Vector2 operator +(Vector2 a, Vector2 b) => new(a.X + b.X, a.Y + b.Y);
    public double Length => Math.Sqrt(X * X + Y * Y);
}
```

`readonly record struct` (C# 10) combines both ideas: an immutable value type with record features. Rules of thumb: use a `class` for things with identity and changing state; a `record` (class) for immutable data; a `struct` only for small values that are created in large numbers, where avoiding heap allocations matters.

## Operator overloading

Types can define how operators work on them. It suits mathematical and value types:

```csharp
var a = new Money(10.50m, "EUR");
var b = new Money(4.25m, "EUR");
Console.WriteLine(a + b);
Console.WriteLine(a * 3);
Console.WriteLine(a > b);
Console.WriteLine(a == new Money(10.50m, "EUR"));

readonly record struct Money(decimal Amount, string Currency)
{
    public static Money operator +(Money x, Money y)
    {
        if (x.Currency != y.Currency) throw new InvalidOperationException("currency mismatch");
        return new Money(x.Amount + y.Amount, x.Currency);
    }

    public static Money operator *(Money x, int factor) => x with { Amount = x.Amount * factor };
    public static bool operator >(Money x, Money y) => x.Amount > y.Amount;
    public static bool operator <(Money x, Money y) => x.Amount < y.Amount;

    public override string ToString() => $"{Amount:F2} {Currency}";
}
```

Operators are `public static` methods named `operator +`. Some come in pairs (`<` with `>`, `==` with `!=`). Overload operators only when their meaning is obvious; a method with a clear name is better otherwise.

**Conversion operators** define casts: `public static implicit operator decimal(Money m) => m.Amount;` lets a `Money` be used where a `decimal` is expected (`explicit` requires a cast).

## Indexers

An **indexer** lets objects be used with `[ ]`, like arrays and dictionaries:

```csharp
var board = new Board(3);
board[1, 1] = 'X';
board[0, 2] = 'O';
Console.WriteLine(board);
Console.WriteLine(board["b2"]);

class Board(int size)
{
    private readonly char[,] _cells = InitCells(size);

    private static char[,] InitCells(int size)
    {
        var cells = new char[size, size];
        for (int r = 0; r < size; r++) for (int c = 0; c < size; c++) cells[r, c] = '.';
        return cells;
    }

    public char this[int row, int col]
    {
        get => _cells[row, col];
        set => _cells[row, col] = value;
    }

    public char this[string square] => this[square[1] - '1', square[0] - 'a'];   // "b2" → row 1, col 1

    public override string ToString()
    {
        var lines = new List<string>();
        for (int r = 0; r < size; r++)
        {
            var row = new char[size];
            for (int c = 0; c < size; c++) row[c] = _cells[r, c];
            lines.Add(new string(row));
        }
        return string.Join("\n", lines);
    }
}
```

## Extension methods

An **extension method** adds a method to an existing type, even one you don't own (`string`, `int`, `IEnumerable<T>`), without inheritance. It's a static method in a static class whose first parameter is marked `this`:

```csharp
Console.WriteLine("hello world".ToTitleCase());
Console.WriteLine(7.IsBetween(1, 10));
Console.WriteLine("racecar".IsPalindrome());

static class StringExtensions
{
    public static string ToTitleCase(this string s) =>
        string.Join(" ", s.Split(' ').Select(w => w.Length == 0 ? w : char.ToUpper(w[0]) + w[1..]));

    public static bool IsPalindrome(this string s) => s.SequenceEqual(s.Reverse());

    public static bool IsBetween(this int n, int low, int high) => n >= low && n <= high;
}
```

The whole of **LINQ** (Module 5) is a set of extension methods on `IEnumerable<T>`. C# 14 extends this idea with **extension blocks**, which can also add extension properties.

readonly record struct Fraction
{
    public int Numerator { get; }
    public int Denominator { get; }

    public Fraction(int numerator, int denominator)
    {
        if (denominator == 0) throw new DivideByZeroException();
        int sign = denominator < 0 ? -1 : 1;
        int g = Gcd(Math.Abs(numerator), Math.Abs(denominator));
        Numerator = sign * numerator / g;
        Denominator = Math.Abs(denominator) / g;
    }

    private static int Gcd(int a, int b) => b == 0 ? Math.Max(a, 1) : Gcd(b, a % b);

    public static Fraction operator +(Fraction x, Fraction y) =>
        new(x.Numerator * y.Denominator + y.Numerator * x.Denominator, x.Denominator * y.Denominator);

    public static Fraction operator *(Fraction x, Fraction y) =>
        new(x.Numerator * y.Numerator, x.Denominator * y.Denominator);

    public override string ToString() => Denominator == 1 ? $"{Numerator}" : $"{Numerator}/{Denominator}";
}

{
    public static Fraction Over(this int numerator, int denominator) => new(numerator, denominator);
