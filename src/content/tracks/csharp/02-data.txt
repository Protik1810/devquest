=== lesson cs-types | Value types and variables | 65
## Built-in types

C# has a rich set of built-in types. The numeric ones:

| Type | Size | Range / precision | Literal |
|---|---|---|---|
| `int` | 32 bits | about ±2.1 billion | `42` |
| `long` | 64 bits | about ±9.2 × 10¹⁸ | `42L` |
| `byte` / `short` | 8 / 16 bits | 0–255 / ±32,767 | |
| `uint`, `ulong` | 32 / 64 bits | unsigned (no negatives) | `42u` |
| `double` | 64 bits | ~15 digits, approximate | `3.14` |
| `float` | 32 bits | ~7 digits, approximate | `3.14f` |
| `decimal` | 128 bits | 28 digits, **exact decimal** | `19.99m` |

Plus `bool` (`true`/`false`), `char` (one UTF-16 character, `'A'`) and `string` (text, `"hello"`).

**`decimal`** is C#'s great gift for business code: it represents decimal fractions exactly, so it's the type for **money** (Java needs the `BigDecimal` class for this). `double` is for measurements and science, where tiny rounding errors don't matter.

```csharp
double d = 0.1 + 0.2;
decimal m = 0.1m + 0.2m;
Console.WriteLine($"{d == 0.3} {m == 0.3m}");
Console.WriteLine($"{d:R} {m}");

long worldPopulation = 8_100_000_000L;    // underscores for readability
Console.WriteLine($"{int.MaxValue} {long.MaxValue} {worldPopulation}");
```

## Value types and reference types

This distinction runs through all of C#:

- **Value types** (`int`, `double`, `decimal`, `bool`, `char`, enums and every `struct`) hold their data directly. Assigning **copies** the value.
- **Reference types** (`string`, arrays, every `class`) hold a reference to an object on the heap. Assigning copies the **reference**, so two variables can share one object.

```csharp
int a = 5;
int b = a;          // copy of the value
b = 99;
Console.WriteLine(a);            // still 5

int[] first = { 1, 2, 3 };
int[] second = first;            // copy of the reference: same array
second[0] = 99;
Console.WriteLine(first[0]);     // 99
```

(`string` is a reference type but **immutable**, so it behaves like a value in practice.) Module 4 shows how to write your own value types with `struct`.

## Conversions

Widening conversions (no information lost) are **implicit**; narrowing ones need an explicit **cast**:

```csharp
int apples = 7;
double asDouble = apples;               // implicit
double average = 7.9;
int truncated = (int)average;           // explicit: drops the fraction → 7
int rounded = (int)Math.Round(average); // 8
decimal price = (decimal)19.99;         // double to decimal needs a cast
long big = 3_000_000_000L;
int wrapped = unchecked((int)big);      // wraps silently
Console.WriteLine($"{asDouble} {truncated} {rounded} {price} {wrapped}");

try
{
    int safe = checked((int)big);       // checked: throws instead of wrapping
}
catch (OverflowException e)
{
    Console.WriteLine("checked: " + e.GetType().Name);
}
```

Converting **text** to numbers uses `int.Parse("42")` or, safer, `int.TryParse` (lesson 4). `Convert.ToInt32(...)` and `ToString()` convert between many types.

## Constants and var

```csharp
const double VatRate = 0.20;            // compile-time constant
var net = 50m;                          // decimal, inferred from the literal
Console.WriteLine($"Gross: {net * (1 + (decimal)VatRate)}");
```

`const` values are fixed at compile time; for values computed at run time that must not change, use `readonly` fields (Module 4). Naming conventions: `camelCase` for locals and parameters, `PascalCase` for methods, properties, types **and constants** (unlike Java's `UPPER_SNAKE_CASE`).

=== lesson cs-operators | Operators and expressions | 55
## Arithmetic and integer division

```csharp
Console.WriteLine(17 / 5);       // 3   integer division
Console.WriteLine(17 % 5);       // 2   remainder
Console.WriteLine(17 / 5.0);     // 3.4
Console.WriteLine(-17 / 5);      // -3  truncates towards zero
Console.WriteLine(17m / 5);      // 3.4 decimal division
Console.WriteLine(Math.Pow(2, 10) + " " + Math.Sqrt(2).ToString("F3"));
```

Integer division drops the fraction, exactly as in Java and C. When you need the fraction, make one operand `double` or `decimal`.

## Assignment, increment and compound operators

`+=`, `-=`, `*=`, `/=`, `%=`, `++` and `--` work as in Java and JavaScript. C# adds the **null-coalescing** operators (Module 5): `a ?? b` ("a, or b if a is null") and `a ??= b`.

## Comparison, logic and the conditional operator

```csharp
int age = 20;
bool hasTicket = true;
bool canEnter = age >= 18 && hasTicket;        // short-circuit and
string label = canEnter ? "welcome" : "sorry";
string? text = null;
bool empty = text == null || text.Length == 0; // safe thanks to short-circuiting
Console.WriteLine($"{canEnter} {label} {empty} {string.IsNullOrEmpty(text)}");
```

Unlike Java, `==` on **strings** compares their **contents** in C# (the `string` type overloads the operator), so `"a" == "a"` is reliable. For other classes, `==` compares references unless the class overloads it (Module 4).

## Pattern-based comparisons

C# lets you test values against **patterns** with `is`, which reads almost like English:

```csharp
int score = 72;
Console.WriteLine(score is >= 0 and <= 100);
Console.WriteLine(score is < 50 or > 90);
char c = 'k';
Console.WriteLine(c is >= 'a' and <= 'z');
object value = 42;
if (value is int n && n > 40) Console.WriteLine($"an int above 40: {n}");
```

`and`, `or` and `not` combine patterns; `is int n` tests a type and gives you the converted value. Module 3 uses patterns in `switch` expressions.

## Bitwise operators

`&`, `|`, `^`, `~`, `<<`, `>>` (and `>>>` since C# 11) work on integer bits; `[Flags]` enums (Module 4) use them for sets of options.

```csharp
int read = 0b100, write = 0b010, execute = 0b001;
int permissions = read | write;
Console.WriteLine(Convert.ToString(permissions, 2));
Console.WriteLine((permissions & write) != 0);
Console.WriteLine(1 << 10);
```

=== lesson cs-strings | Strings and text | 65
## String essentials

```csharp
string language = "CSharp";
Console.WriteLine(language.Length);              // 6
Console.WriteLine(language.ToUpper());           // CSHARP
Console.WriteLine(language[0]);                  // C (a char)
Console.WriteLine(language.IndexOf("Sh"));       // 1
Console.WriteLine(language.Substring(1, 3));     // Sha (start, length!)
Console.WriteLine(language[1..4]);               // Sha (range: start up to end)
Console.WriteLine(language[^2..]);               // rp (^2 = 2 from the end)
Console.WriteLine(language.Contains("arp"));     // True
Console.WriteLine(language.Replace("Sharp", "#"));
Console.WriteLine("  padded  ".Trim() + "|");
Console.WriteLine(string.Join(", ", new[] { "a", "b", "c" }));
Console.WriteLine("a,b,,c".Split(',').Length);   // 4
Console.WriteLine(new string('-', 10));
```

Watch out: C#'s `Substring(start, length)` takes a **length**, unlike Java's `substring(start, end)`. **Ranges** (`s[1..4]`, `s[^2..]`) avoid the confusion: `..` is end-exclusive, `^n` counts from the end.

Strings are **immutable**: methods return new strings. `==` compares contents; `string.Equals(a, b, StringComparison.OrdinalIgnoreCase)` ignores case; `string.Compare` and `CompareTo` give alphabetical order. Use `string.IsNullOrWhiteSpace(s)` to test for "nothing useful".

## Building strings: StringBuilder

```csharp
using System.Text;

var sb = new StringBuilder();
for (int i = 1; i <= 5; i++)
{
    sb.Append(i);
    if (i < 5) sb.Append(" -> ");
}
Console.WriteLine(sb.ToString());
Console.WriteLine(string.Concat(Enumerable.Repeat("ab", 3)));
```

`+=` in a loop creates a new string each time; `StringBuilder` appends in place. (`StringBuilder` lives in `System.Text`, which isn't among the implicit usings, hence the `using` line.)

## Verbatim and raw strings

```csharp
string path = @"C:\Users\ada\notes.txt";       // verbatim: backslashes are literal
string json = """
    {
      "name": "Ada",
      "tags": ["math", "poetry"]
    }
    """;                                          // raw string literal (C# 11): no escaping at all
Console.WriteLine(path);
Console.WriteLine(json);
string name = "Grace";
Console.WriteLine($$"""{"user": "{{name}}"}""");  // raw + interpolation: {{ }} marks the holes
```

Escape sequences in normal strings: `\n`, `\t`, `\"`, `\\`, `\u00e9`.

## Characters

```csharp
int letters = 0, digits = 0;
foreach (char c in "R2-D2 lands!")
{
    if (char.IsLetter(c)) letters++;
    else if (char.IsDigit(c)) digits++;
}
Console.WriteLine($"{letters} letters, {digits} digits");
Console.WriteLine((int)'A' + " " + (char)('A' + 2));
```

=== lesson cs-input | Reading input and parsing | 55
## Console.ReadLine

`Console.ReadLine()` reads one line of what the user types (without the line break). It returns `null` when the input has ended:

```csharp
// stdin: Ada | 36
Console.Write("What's your name? ");
string name = Console.ReadLine() ?? "";
Console.Write("How old are you? ");
int age = int.Parse(Console.ReadLine() ?? "0");
Console.WriteLine();
Console.WriteLine($"Hi {name}, next year you'll be {age + 1}.");
```

In DevQuest, the typed lines go in the box under the example; this one fills in `Ada` and `36` (from its `// stdin:` comment). As in a real terminal capture, what you type isn't repeated in the output.

`?? ""` replaces a `null` (end of input) with an empty string: the **null-coalescing operator**, which Module 5 explains with nullable types.

## Parse versus TryParse

`int.Parse`, `double.Parse` and `decimal.Parse` throw a `FormatException` for invalid text. **`TryParse`** returns `true` or `false` instead, and puts the number in an **`out`** variable, which makes validation easy:

```csharp
string[] inputs = { "42", "x7", " 15 ", "3.5" };
foreach (string input in inputs)
{
    if (int.TryParse(input, out int n))
        Console.WriteLine($"{input.Trim()} -> {n * 2}");
    else
        Console.WriteLine($"'{input}' is not a whole number");
}
```

(`int.TryParse` accepts surrounding spaces.) Prefer `TryParse` for anything a user typed; it's faster and clearer than catching exceptions.

## Reading until the input ends

```csharp
// stdin: 7 | 2 | 9
int sum = 0;
string? line;
while ((line = Console.ReadLine()) != null)
{
    if (int.TryParse(line, out int value)) sum += value;
}
Console.WriteLine($"sum = {sum}");
```

That's the standard loop of command-line tools that process piped input (`dotnet run < data.txt`).
