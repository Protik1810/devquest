## Waiting without blocking

Most of a real program's time is spent **waiting**: for a web server, a database, a file. If a thread just sits there blocked, a desktop app freezes and a web server runs out of threads. C#'s answer, copied since by JavaScript, Python, Rust and Kotlin, is **async/await**:

- an `async` method returns a **`Task`** (no result) or a **`Task<T>`** (a result of type `T`): a promise of work that finishes later;
- **`await`** pauses the method *without blocking the thread* until the task completes, then continues with its result;
- while it's paused, the thread is free to do other work.

```csharp
using System.Diagnostics;

var watch = Stopwatch.StartNew();
string a = await DownloadAsync("page-a", 300);
string b = await DownloadAsync("page-b", 200);
Console.WriteLine($"one after another: {a}, {b} in about {watch.ElapsedMilliseconds / 100 * 100} ms");

watch.Restart();
Task<string> first = DownloadAsync("page-a", 300);     // both start now
Task<string> second = DownloadAsync("page-b", 200);
string[] both = await Task.WhenAll(first, second);
Console.WriteLine($"at the same time: {string.Join(", ", both)} in about {watch.ElapsedMilliseconds / 100 * 100} ms");

static async Task<string> DownloadAsync(string name, int ms)
{
    await Task.Delay(ms);          // stands in for a network call
    return $"{name} ({ms} ms)";
}
```

Calling an async method **starts** it and hands you the task; `await` is where you wait for it. Start independent work first, then await it together with **`Task.WhenAll`**, which returns the results in the order of the tasks. **`Task.WhenAny`** completes when the first task does, which is useful for timeouts and for taking the fastest answer.

In a program with top-level statements you can `await` directly; otherwise `Main` can be declared `static async Task Main()`.

## Exceptions and cancellation

An exception thrown inside an async method is stored in its task and **rethrown at the `await`**, so ordinary `try`/`catch` works. Long operations should accept a **`CancellationToken`**, so the caller can stop them:

```csharp
using var cts = new CancellationTokenSource(TimeSpan.FromMilliseconds(350));
try
{
    await SlowWorkAsync(cts.Token);
}
catch (OperationCanceledException)
{
    Console.WriteLine("cancelled: took too long");
}

try
{
    await FailingAsync();
}
catch (InvalidOperationException e)
{
    Console.WriteLine($"caught at the await: {e.Message}");
}

static async Task SlowWorkAsync(CancellationToken token)
{
    for (int step = 1; step <= 10; step++)
    {
        await Task.Delay(100, token);       // throws when the token is cancelled
        Console.WriteLine($"step {step}");
    }
}

static async Task FailingAsync()
{
    await Task.Delay(10);
    throw new InvalidOperationException("the server said no");
}
```

Pass the token down to every async call you make (`HttpClient`, `File`, `Task.Delay` and Entity Framework all accept one), and call `token.ThrowIfCancellationRequested()` inside long loops.

## Async streams

When results arrive one by one (pages of an API, lines of a file, messages from a queue), an **async iterator** returns `IAsyncEnumerable<T>`, and the caller consumes it with **`await foreach`**:

```csharp
await foreach (string page in FetchPagesAsync(3))
{
    Console.WriteLine($"got {page}");
}

static async IAsyncEnumerable<string> FetchPagesAsync(int count)
{
    for (int i = 1; i <= count; i++)
    {
        await Task.Delay(50);
        yield return $"page {i}";
    }
}
```

## The rules professionals follow

- **Async all the way:** if a method awaits, its callers should be async too. Never block on a task with `.Result` or `.Wait()`: in UI and older ASP.NET apps it can **deadlock**, and everywhere it wastes a thread.
- **Never write `async void`**, except for event handlers: nobody can await it, and its exceptions crash the process. Return `Task` instead.
- Name async methods with the `Async` suffix and accept a `CancellationToken` as the last parameter.
- async is for **waiting** (I/O). For heavy **computation**, the next lesson's `Task.Run` and `Parallel` are the tools.
- In libraries, `await task.ConfigureAwait(false)` avoids returning to the caller's UI thread; application code usually doesn't need it.

## Using every core

async is about *waiting* efficiently. **Parallelism** is about *computing* faster by using several CPU cores at once. .NET runs work on a **thread pool**, and gives you high-level tools so you rarely create a `Thread` yourself:

| Tool | Use it for |
|---|---|
| `Task.Run(() => ...)` | move one piece of CPU-heavy work off the current thread (keeps a UI responsive) |
| `Parallel.For` / `Parallel.ForEach` | split a loop over many items across cores |
| PLINQ: `.AsParallel()` | run a LINQ query in parallel |
| `Parallel.ForEachAsync` | process many items with async work, with a limit on how many run at once |

```csharp
long[] numbers = Enumerable.Range(1, 300_000).Select(i => (long)i).ToArray();

long sequential = numbers.Where(IsPrime).LongCount();
long parallel = numbers.AsParallel().Where(IsPrime).LongCount();
Console.WriteLine($"primes: {sequential} (sequential), {parallel} (PLINQ)");

long heavy = await Task.Run(() => numbers.Sum(n => n % 7));
Console.WriteLine($"computed on the thread pool: {heavy}");
Console.WriteLine($"this PC has {Environment.ProcessorCount} logical cores");

static bool IsPrime(long n)
{
    if (n < 2) return false;
    for (long d = 2; d * d <= n; d++)
        if (n % d == 0) return false;
    return true;
}
```

Parallelism only pays off when each item takes real work; for tiny loops the coordination costs more than it saves. Measure before and after.

## Race conditions

When several threads change the same data, their steps interleave in unpredictable ways. `count++` is really *read, add, write*: two threads can read the same value and one update gets lost.

```csharp
int unsafeCount = 0;
int atomicCount = 0;
int lockedCount = 0;
var gate = new Lock();

Parallel.For(0, 100_000, _ =>
{
    unsafeCount++;                          // race: updates get lost
    Interlocked.Increment(ref atomicCount); // atomic hardware instruction
    lock (gate) lockedCount++;              // one thread at a time
});
Console.WriteLine($"unsafe: {unsafeCount} (often less than 100000)");
Console.WriteLine($"Interlocked: {atomicCount}, lock: {lockedCount}");
```

- **`lock (obj) { ... }`** lets only one thread at a time run the block. Lock on a private object (`Lock` since C# 13, `object` before), never on `this` or a string; keep the block short; never `await` inside it.
- **`Interlocked`** (`Increment`, `Add`, `Exchange`, `CompareExchange`) does single updates atomically without a lock.
- **Deadlock:** thread A holds lock 1 and waits for lock 2 while B holds 2 and waits for 1. Avoid it by always taking locks in the same order, or by not holding two at once.
- The safest shared data is data that **doesn't change**: immutable records and collections need no locks.

## Thread-safe collections and channels

`List<T>` and `Dictionary` are **not** safe for concurrent writes. `System.Collections.Concurrent` has `ConcurrentDictionary`, `ConcurrentQueue`, `ConcurrentBag` and `BlockingCollection`. For **producer/consumer** pipelines, `System.Threading.Channels` is the modern, async-friendly choice:

```csharp
using System.Threading.Channels;

var channel = Channel.CreateBounded<int>(capacity: 2);   // the producer waits when it's full

Task producer = Task.Run(async () =>
{
    for (int job = 1; job <= 5; job++)
    {
        await channel.Writer.WriteAsync(job);
        Console.WriteLine($"queued job {job}");
    }
    channel.Writer.Complete();
});

int done = 0;
await foreach (int job in channel.Reader.ReadAllAsync())
{
    await Task.Delay(30);              // the consumer is slower than the producer
    done++;
}
await producer;
Console.WriteLine($"processed {done} jobs");
```

To limit how many async operations run at once (say, at most 3 downloads), use **`SemaphoreSlim`** (`await gate.WaitAsync()` … `gate.Release()` in a `finally`) or `Parallel.ForEachAsync` with `MaxDegreeOfParallelism`.

~~~check

+ It's a read, an add and a write, and threads can interleave between them
- Integers can't be shared between threads
- The compiler removes it
- It throws an exception
> Use Interlocked.Increment or a lock.
~~~

static ConcurrentDictionary<string, int> CountWords(string[] lines)
{
    var counts = new ConcurrentDictionary<string, int>();
    Parallel.ForEach(lines, line =>
    {
        foreach (string word in line.Split(' '))
            counts.AddOrUpdate(word, 1, (_, old) => old + 1);
    });
    return counts;
}

class Inventory
{
    private readonly Dictionary<string, int> _items = new();
    private readonly Lock _lock = new();

    public void Add(string item, int quantity)
    {
        lock (_lock) _items[item] = _items.GetValueOrDefault(item) + quantity;
    }

    public bool TryReserve(string item, int quantity)
    {
        lock (_lock)
        {
            int available = _items.GetValueOrDefault(item);
            if (available < quantity) return false;
            _items[item] = available - quantity;
            return true;
        }
    }

    public int Count(string item)
    {
        lock (_lock) return _items.GetValueOrDefault(item);
    }
}

- `_items.GetValueOrDefault(item)` returns 0 for an unknown item.
- In `TryReserve`, the check and the update must be in the **same** lock, or two threads can both see "1 left".
- `counts.AddOrUpdate(word, 1, (_, old) => old + 1)` adds 1 for a new word or increments an existing one atomically.

## Paths and quick file access

`System.IO` has static helpers for the common cases. Build paths with **`Path.Combine`** (it uses the right separator on Windows, macOS and Linux) and never with string concatenation:

```csharp
string dir = Path.Combine(Path.GetTempPath(), $"devquest-{Guid.NewGuid():N}");
Directory.CreateDirectory(dir);
try
{
    string file = Path.Combine(dir, "todo.txt");
    File.WriteAllText(file, "buy milk\n");
    File.AppendAllLines(file, ["write report", "call Ada"]);

    string[] lines = File.ReadAllLines(file);
    Console.WriteLine($"{lines.Length} lines, first: {lines[0]}");
    Console.WriteLine($"name {Path.GetFileName(file)}, extension {Path.GetExtension(file)}, exists {File.Exists(file)}");

    foreach (string path in Directory.EnumerateFiles(dir, "*.txt"))
        Console.WriteLine($"found {Path.GetFileName(path)} ({new FileInfo(path).Length} bytes)");
}
finally
{
    Directory.Delete(dir, recursive: true);   // clean up, even after an error
}
```

`ReadAllText`/`ReadAllLines` load the whole file into memory; **`File.ReadLines`** reads lazily, one line at a time, which is the right choice for large files. All of them have **async** versions (`ReadAllTextAsync`, `WriteAllLinesAsync`, …) for servers and UIs. Text is read and written as **UTF-8** by default.

## Streams

Under the helpers are **streams**: sequences of bytes you read or write in pieces. `FileStream` reads a file, and so do network streams, memory streams and compression streams, all through the same `Stream` API. For text you wrap them in a **`StreamReader`** or **`StreamWriter`**, always with `using` so the file is flushed and closed:

```csharp
using System.IO.Compression;

string path = Path.Combine(Path.GetTempPath(), $"log-{Guid.NewGuid():N}.txt.gz");
using (var file = File.Create(path))
using (var zip = new GZipStream(file, CompressionLevel.Optimal))
using (var writer = new StreamWriter(zip))
{
    for (int i = 1; i <= 1000; i++) writer.WriteLine($"event {i}: all good");
}
Console.WriteLine($"compressed size: {new FileInfo(path).Length} bytes");

using (var reader = new StreamReader(new GZipStream(File.OpenRead(path), CompressionMode.Decompress)))
{
    int count = 0;
    string? line;
    while ((line = reader.ReadLine()) != null) count++;
    Console.WriteLine($"read back {count} lines");
}
File.Delete(path);
```

Streams are **decorators**: each wraps another and adds behaviour (compression, buffering, encryption, text encoding). The same pattern appears in Java's I/O classes.

## JSON with System.Text.Json

JSON is how programs exchange data. **`System.Text.Json`** (built in) turns objects into JSON and back:

```csharp
using System.Text.Json;
using System.Text.Json.Serialization;

var options = new JsonSerializerOptions { WriteIndented = true, PropertyNamingPolicy = JsonNamingPolicy.CamelCase };
var user = new User("Ada", 36, ["admin", "dev"], null);

string json = JsonSerializer.Serialize(user, options);
Console.WriteLine(json);

User back = JsonSerializer.Deserialize<User>(json, options)!;
Console.WriteLine($"{back.Name}, roles {string.Join("/", back.Roles)}, same values: {back with { Roles = user.Roles } == user}");

using JsonDocument doc = JsonDocument.Parse("""{"city":"Oslo","temp":{"now":-3.5}}""");
Console.WriteLine($"Oslo now: {doc.RootElement.GetProperty("temp").GetProperty("now").GetDouble()}");

record User(string Name, int Age, List<string> Roles, [property: JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingNull)] string? Nickname);
```

- `Serialize` / `Deserialize<T>` map public properties; records work well. Bad input throws **`JsonException`**.
- Options control naming (`CamelCase`), indentation, case-insensitive reading, enums as strings (`JsonStringEnumConverter`).
- Attributes customise single properties: `[JsonPropertyName("user_name")]`, `[JsonIgnore]`.
- **`JsonDocument`** / `JsonNode` read JSON whose shape you don't have a class for.
- Reuse one `JsonSerializerOptions` instance: creating it each time is slow.

=== lesson cs-projects | Projects, namespaces and packages | 60
## From one file to a solution

Real programs aren't one file. .NET organises code like this:

- a **project** (`.csproj`) builds one **assembly**: an `.exe` (application) or a `.dll` (library);
- a **solution** (`.sln` or the newer `.slnx`) groups projects that belong together: for example `Shop.Api` (web API), `Shop.Core` (business logic, a class library) and `Shop.Tests`;
- projects reference each other (`dotnet add reference`) and **NuGet packages** (`dotnet add package`).

A modern SDK-style project file is short:

```
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Spectre.Console" Version="0.50.0" />
    <ProjectReference Include="..\Shop.Core\Shop.Core.csproj" />
  </ItemGroup>
</Project>
```

The commands you'll use every day:

```
dotnet new sln -n Shop
dotnet new classlib -n Shop.Core
dotnet new console -n Shop.App
dotnet sln add Shop.Core Shop.App
dotnet add Shop.App reference Shop.Core
dotnet add Shop.App package Spectre.Console
dotnet build
dotnet run --project Shop.App
dotnet publish -c Release
```

**NuGet** (nuget.org) is .NET's package registry, like npm or Maven Central. Before adding a package, check that it's maintained, widely used and licensed for your use; every dependency is code you trust.

## Namespaces

**Namespaces** group types and prevent name clashes: `System.IO.File` and a `File` class of your own can coexist. In normal files, use a **file-scoped namespace** that matches the folder: `namespace Shop.Core.Orders;` on the first line. In a file with top-level statements (like the examples here) the statements come first, followed by block namespaces:

```csharp
using Billing;
using ShippingLabel = Shipping.Invoice;      // an alias resolves a clash

var bill = new Invoice("INV-1", 99.90m);
var label = new ShippingLabel("SHP-7", "12 Harbour St");
Console.WriteLine($"{bill} / {label}");
Console.WriteLine(typeof(ShippingLabel).FullName);

namespace Billing
{
    public record Invoice(string Number, decimal Total);
}

namespace Shipping
{
    public record Invoice(string Number, string Address);
}
```

- `using X;` imports a namespace; **global usings** (`global using X;`) apply to the whole project, and **implicit usings** add the common ones (`System`, `System.Linq`, `System.Collections.Generic`, …) for you.
- **`internal`** (the default for top-level types) means visible within the same assembly only. A library exposes a small `public` API and keeps the rest `internal`.

## Extension methods

An **extension method** adds a method to an existing type without changing it. It's a static method in a static class, whose first parameter has `this`; it's available wherever its namespace is imported. All of LINQ (`Where`, `Select`, …) is extension methods on `IEnumerable<T>`.

```csharp
using TextTools;

Console.WriteLine("Hello, wonderful world".Truncate(10));
Console.WriteLine("  Hello World  ".IsBlank());
Console.WriteLine(new[] { 3, 8, 1 }.SecondLargest());

namespace TextTools
{
    public static class StringExtensions
    {
        public static string Truncate(this string text, int max) =>
            text.Length <= max ? text : text[..(max - 1)] + "…";

        public static bool IsBlank(this string text) => string.IsNullOrWhiteSpace(text);

        public static int SecondLargest(this IEnumerable<int> numbers) =>
            numbers.OrderDescending().Skip(1).First();
    }
}
```

Use them for small, obviously related helpers; they can't access private members, and too many make code hard to follow.

=== lesson cs-reflection | Attributes and reflection | 70
## Code that looks at code

Every .NET assembly carries **metadata**: a full description of its types, their properties, methods and attributes. **Reflection** reads that metadata at run time. It's how serializers know your properties, how test frameworks find tests, how ASP.NET finds controllers and how dependency injection builds objects.

```csharp
using System.Reflection;

Type type = typeof(Account);       // or obj.GetType() at run time
Console.WriteLine($"{type.Name} in {type.Namespace ?? "(global)"}, is class: {type.IsClass}");

foreach (PropertyInfo p in type.GetProperties())
    Console.WriteLine($"  property {p.PropertyType.Name} {p.Name} (writable: {p.CanWrite})");

foreach (MethodInfo m in type.GetMethods(BindingFlags.Public | BindingFlags.Instance | BindingFlags.DeclaredOnly).Where(m => !m.IsSpecialName))
    Console.WriteLine($"  method {m.Name}({string.Join(", ", m.GetParameters().Select(x => x.ParameterType.Name))})");

object account = Activator.CreateInstance(type, "Ada")!;         // create an object from a Type
type.GetProperty("Balance")!.SetValue(account, 100m);
type.GetMethod("Deposit")!.Invoke(account, [25m]);
Console.WriteLine(account);

class Account(string owner)
{
    public string Owner { get; } = owner;
    public decimal Balance { get; set; }
    public void Deposit(decimal amount) => Balance += amount;
    public override string ToString() => $"{Owner}: {Balance}";
}
```

Reflection is powerful but **slow** compared with normal calls, loses compile-time checking (a typo in `"Balance"` fails only at run time) and doesn't mix well with trimming and native AOT. Application code rarely needs it directly; libraries and frameworks use it for you. Modern libraries increasingly use **source generators**, which generate the code at compile time instead.

## Attributes

**Attributes** attach extra information to code, in square brackets. Some are understood by the compiler or runtime:

| Attribute | Effect |
|---|---|
| `[Obsolete("Use NewApi")]` | warning (or error) where it's used |
| `[Flags]` | an enum whose values combine as bits |
| `[JsonPropertyName("...")]` | used by System.Text.Json |
| `[Fact]`, `[Theory]` | test methods for xUnit |
| `[HttpGet]`, `[Route]`, `[Required]` | used by ASP.NET Core |

You can write your own by deriving from `Attribute`, and read them with reflection:

```csharp
using System.Reflection;

foreach (MethodInfo m in typeof(Commands).GetMethods())
{
    if (m.GetCustomAttribute<CommandAttribute>() is { } cmd)
        Console.WriteLine($"/{cmd.Name,-6} -> {m.Name}: {cmd.Help}");
}

var permissions = Permission.Read | Permission.Write;
Console.WriteLine($"{permissions}, can delete: {permissions.HasFlag(Permission.Delete)}");

[AttributeUsage(AttributeTargets.Method)]
class CommandAttribute(string name) : Attribute
{
    public string Name { get; } = name;
    public string Help { get; init; } = "";
}

class Commands
{
    [Command("help", Help = "show all commands")] public void ShowHelp() { }
    [Command("quit", Help = "leave the program")] public void Quit() { }
    public void NotACommand() { }
}

[Flags]
enum Permission { None = 0, Read = 1, Write = 2, Delete = 4 }
```

Attribute classes end in `Attribute`, but you may leave that off when using them (`[Command]`). `AttributeUsage` says where an attribute may appear.

## Caller information and nameof

Two compile-time cousins of reflection, cheap and safe: **`nameof(x)`** gives the name of a variable, member or type as a string (it's renamed with the code), and **caller-info attributes** let a method learn who called it:

```csharp
using System.Runtime.CompilerServices;

Log("starting");
int quantity = -1;
Check(quantity > 0);

static void Log(string message, [CallerMemberName] string caller = "", [CallerLineNumber] int line = 0) =>
    Console.WriteLine($"[{caller}:{line}] {message}");

static void Check(bool condition, [CallerArgumentExpression(nameof(condition))] string expression = "")
{
    if (!condition) Console.WriteLine($"check failed: {expression}");
}
```

Top-level statements are compiled into a hidden method named `<Main>$`, which is the caller name you see here; inside a class method you'd see its name. Logging libraries use these attributes to record where each message came from.

[AttributeUsage(AttributeTargets.Property)]
class RequiredAttribute : Attribute { }

[AttributeUsage(AttributeTargets.Property)]
class RangeAttribute(double min, double max) : Attribute
{
    public double Min { get; } = min;
    public double Max { get; } = max;
}

[AttributeUsage(AttributeTargets.Property)]
class ContainsAttribute(string text) : Attribute
{
    public string Text { get; } = text;
}

static class Validator
{
    public static List<string> Validate(object obj)
    {
        var errors = new List<string>();
        foreach (PropertyInfo p in obj.GetType().GetProperties())
        {
            object? value = p.GetValue(obj);
            if (p.GetCustomAttribute<RequiredAttribute>() != null && string.IsNullOrEmpty(value?.ToString()))
                errors.Add($"{p.Name} is required");
            if (p.GetCustomAttribute<RangeAttribute>() is { } range)
            {
                double number = Convert.ToDouble(value);
                if (number < range.Min || number > range.Max)
                    errors.Add($"{p.Name} must be between {range.Min} and {range.Max}");
            }
            if (p.GetCustomAttribute<ContainsAttribute>() is { } contains && value is string s && s.Length > 0 && !s.Contains(contains.Text))
                errors.Add($"{p.Name} must contain '{contains.Text}'");
        }
        return errors;
    }
}

=== lesson cs-testing | Testing your code | 70
## Why professionals write tests

A **unit test** is a small program that calls your code with known inputs and checks the result. Tests catch mistakes when you write code, and much more importantly, **every time you change it later**: they let you refactor without fear. Professional teams run thousands of tests on every commit (continuous integration).

In .NET the popular frameworks are **xUnit**, NUnit and MSTest. A test project sits next to the code it tests:

```
dotnet new xunit -n Shop.Tests
dotnet add Shop.Tests reference Shop.Core
dotnet test
```

```
using Xunit;

public class CartTests
{
    [Fact]
    public void Adding_an_item_increases_the_total()
    {
        var cart = new Cart();                 // Arrange
        cart.Add("pen", 1.50m, quantity: 2);   // Act
        Assert.Equal(3.00m, cart.Total);       // Assert
    }

    [Theory]
    [InlineData(0)]
    [InlineData(-3)]
    public void Quantity_must_be_positive(int quantity)
    {
        var cart = new Cart();
        Assert.Throws<ArgumentOutOfRangeException>(() => cart.Add("pen", 1m, quantity));
    }
}
```

- **`[Fact]`** is a test; **`[Theory]`** with `[InlineData]` runs one test with several inputs.
- **Arrange, Act, Assert:** set up, do one thing, check the outcome.
- Name tests after the behaviour they check, so a failure explains itself.
- Each test is independent: xUnit creates a **new instance** of the test class for every test, so tests don't share state.

## A test framework in 60 lines

There's no magic inside xUnit: it's attributes, reflection and exceptions, all from the last lessons. This runnable version finds `[Fact]` methods and reports failures:

```csharp
using System.Reflection;

int passed = 0, failed = 0;
foreach (MethodInfo test in typeof(MathTests).GetMethods().Where(m => m.GetCustomAttribute<FactAttribute>() != null))
{
    try
    {
        test.Invoke(new MathTests(), null);
        passed++;
        Console.WriteLine($"✓ {test.Name}");
    }
    catch (TargetInvocationException e)
    {
        failed++;
        Console.WriteLine($"✗ {test.Name}: {e.InnerException!.Message}");
    }
}
Console.WriteLine($"{passed} passed, {failed} failed");

class FactAttribute : Attribute { }

class MathTests
{
    [Fact]
    public void AddsNumbers()
    {
        if (Calculator.Add(2, 3) != 5) throw new Exception("2 + 3 should be 5");
    }

    [Fact]
    public void DividesNumbers()
    {
        if (Calculator.Divide(7, 2) != 3.5) throw new Exception($"7 / 2 should be 3.5 but was {Calculator.Divide(7, 2)}");
    }
}

static class Calculator
{
    public static int Add(int a, int b) => a + b;
    public static double Divide(int a, int b) => a / b;     // bug: integer division
}
```

The failing test found a real bug: `a / b` divides integers before converting.

## Testing code with dependencies

Code that reads the clock, the network or a database is hard to test. Make the dependency an **interface**, pass it in (that's **dependency injection**) and give the test a **fake**:

```csharp
var clock = new FakeClock { Now = new DateTime(2026, 3, 15, 9, 0, 0) };
var shop = new Shop(clock);
Console.WriteLine($"9:00 open: {shop.IsOpen()}");
clock.Now = clock.Now.AddHours(10);
Console.WriteLine($"19:00 open: {shop.IsOpen()}");

interface IClock { DateTime Now { get; } }

class SystemClock : IClock { public DateTime Now => DateTime.Now; }   // used in production

class FakeClock : IClock { public DateTime Now { get; set; } }        // used in tests

class Shop(IClock clock)
{
    public bool IsOpen() => clock.Now.Hour is >= 8 and < 18;
}
```

.NET 8 added a built-in `TimeProvider` for exactly this, and libraries like **Moq** and **NSubstitute** generate fakes for you.

## What to test

- the normal case, the **edge cases** (empty, zero, one, maximum, boundaries) and the **error cases**;
- business rules, not the language (no need to test that a property returns what you set);
- write a failing test **before** fixing a bug, so it can never come back. Writing tests first in general is **test-driven development** (red, green, refactor).

[AttributeUsage(AttributeTargets.Method)]
class FactAttribute : Attribute { }

class AssertionException(string message) : Exception(message) { }

static class Assert
{
    public static void Equal<T>(T expected, T actual)
    {
        if (!EqualityComparer<T>.Default.Equals(expected, actual))
            throw new AssertionException($"expected {expected}, got {actual}");
    }

    public static T Throws<T>(Action action) where T : Exception
    {
        try
        {
            action();
        }
        catch (T e)
        {
            return e;
        }
        catch (Exception e)
        {
            throw new AssertionException($"expected {typeof(T).Name}, got {e.GetType().Name}");
        }
        throw new AssertionException($"expected {typeof(T).Name}, nothing was thrown");
    }
}

static class TestRunner
{
    public static (int Passed, int Failed) Run(Type testClass)
    {
        int passed = 0, failed = 0;
        foreach (MethodInfo m in testClass.GetMethods().Where(m => m.GetCustomAttribute<FactAttribute>() != null).OrderBy(m => m.Name))
        {
            object instance = Activator.CreateInstance(testClass)!;
            try
            {
                m.Invoke(instance, null);
                Console.WriteLine($"PASS {m.Name}");
                passed++;
            }
            catch (TargetInvocationException e) when (e.InnerException is AssertionException a)
            {
                Console.WriteLine($"FAIL {m.Name}: {a.Message}");
                failed++;
            }
            catch (TargetInvocationException e)
            {
                Console.WriteLine($"ERROR {m.Name}: {e.InnerException!.GetType().Name}");
                failed++;
            }
        }
        return (passed, failed);
    }
}

## The web in one example

Most C# code in industry runs on servers. A web API receives an **HTTP request** (a method like `GET` or `POST`, a path like `/todos/2`, headers and maybe a JSON body) and sends back a **response** (a status code like `200 OK` or `404 Not Found`, headers and a body). This runnable example is a complete, if primitive, web server and client in one program, built on `HttpListener` and `HttpClient`:

```csharp
using System.Net;
using System.Text;

int port = Random.Shared.Next(20000, 40000);
using var listener = new HttpListener();
listener.Prefixes.Add($"http://localhost:{port}/");
listener.Start();

Task server = Task.Run(async () =>
{
    for (int i = 0; i < 2; i++)
    {
        HttpListenerContext ctx = await listener.GetContextAsync();
        string path = ctx.Request.Url!.AbsolutePath;
        (int status, string body) = path == "/hello" ? (200, """{"message":"hello"}""") : (404, """{"error":"not found"}""");
        byte[] bytes = Encoding.UTF8.GetBytes(body);
        ctx.Response.StatusCode = status;
        ctx.Response.ContentType = "application/json";
        await ctx.Response.OutputStream.WriteAsync(bytes);
        ctx.Response.Close();
    }
});

using var http = new HttpClient { BaseAddress = new Uri($"http://localhost:{port}/") };
foreach (string path in new[] { "hello", "missing" })
{
    HttpResponseMessage response = await http.GetAsync(path);
    Console.WriteLine($"GET /{path} -> {(int)response.StatusCode} {response.StatusCode}: {await response.Content.ReadAsStringAsync()}");
}
await server;
```

**`HttpClient`** is how C# code calls other services. Create one and reuse it (or use `IHttpClientFactory` in ASP.NET), because creating one per request exhausts network sockets.

## ASP.NET Core minimal APIs

Nobody writes servers on raw listeners. **ASP.NET Core** is .NET's web framework: fast, cross-platform and used for APIs, websites (Razor Pages, MVC, Blazor) and real-time apps (SignalR). A complete JSON API with **minimal APIs** (create it with `dotnet new web`):

```
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddSingleton<ITodoStore, InMemoryTodoStore>();   // dependency injection
var app = builder.Build();

app.MapGet("/todos", (ITodoStore store) => store.All());
app.MapGet("/todos/{id:int}", (int id, ITodoStore store) =>
    store.Find(id) is { } todo ? Results.Ok(todo) : Results.NotFound());
app.MapPost("/todos", (NewTodo input, ITodoStore store) =>
{
    if (string.IsNullOrWhiteSpace(input.Title)) return Results.BadRequest("title is required");
    Todo todo = store.Add(input.Title);
    return Results.Created($"/todos/{todo.Id}", todo);
});
app.MapDelete("/todos/{id:int}", (int id, ITodoStore store) =>
    store.Remove(id) ? Results.NoContent() : Results.NotFound());

app.Run();

record Todo(int Id, string Title, bool Done);
record NewTodo(string Title);
```

What the framework does for you:

- **routing:** matches the method and path pattern (`{id:int}` is a route parameter with a constraint) and calls your handler;
- **model binding:** fills handler parameters from the route, query string, headers or JSON body;
- **serialization:** return values become JSON with System.Text.Json;
- **dependency injection:** services registered in `builder.Services` are passed to handlers (`AddSingleton`, `AddScoped` per request, `AddTransient` every time);
- **middleware:** a pipeline every request flows through, for logging, errors, authentication, CORS and static files (`app.UseAuthentication()` …);
- **configuration** from `appsettings.json` and environment variables, and **logging** through `ILogger<T>`.

Larger APIs often use **controllers** (classes with `[ApiController]`, `[HttpGet]` …) instead; the concepts are the same.

## Data with Entity Framework Core

**EF Core** is .NET's ORM: you write classes and LINQ, it writes the SQL (you learned SQL in the SQL course; EF translates to it):

public class ShopDb(DbContextOptions<ShopDb> options) : DbContext(options)

    public DbSet<Product> Products => Set<Product>();

**Migrations** (`dotnet ef migrations add Initial`, `dotnet ef database update`) create and evolve the database schema from your classes. EF Core works with SQL Server, PostgreSQL, SQLite and MySQL.

## Professional habits for APIs

- Return the **right status codes**: 200 OK, 201 Created (with a Location), 204 No Content, 400 Bad Request (invalid input), 401/403 (not logged in / not allowed), 404 Not Found, 500 for bugs.
- **Validate** all input; never trust the client.
- Keep handlers thin: business logic belongs in services you can unit test.
- Never put secrets (connection strings, API keys) in source code: use configuration, environment variables or a secret store.
- Document the API with **OpenAPI** (`builder.Services.AddOpenApi()`).

class Router
{
    private readonly List<(string Method, string[] Segments, Func<Dictionary<string, string>, Response> Handler)> _routes = new();

    public void Map(string method, string pattern, Func<Dictionary<string, string>, Response> handler) =>
        _routes.Add((method, pattern.Trim('/').Split('/'), handler));

    public Response Handle(string method, string path)
    {
        string[] segments = path.Trim('/').Split('/');
        bool pathMatched = false;
        foreach (var route in _routes)
        {
            Dictionary<string, string>? values = Match(route.Segments, segments);
            if (values == null) continue;
            pathMatched = true;
            if (route.Method == method) return route.Handler(values);
        }
        return pathMatched ? new Response(405, "method not allowed") : Response.NotFound();
    }

    private static Dictionary<string, string>? Match(string[] pattern, string[] segments)
    {
        if (pattern.Length != segments.Length) return null;
        var values = new Dictionary<string, string>();
        for (int i = 0; i < pattern.Length; i++)
        {
            if (pattern[i].StartsWith('{') && pattern[i].EndsWith('}')) values[pattern[i][1..^1]] = segments[i];
            else if (pattern[i] != segments[i]) return null;
        }
        return values;
    }
}

record Order(int Id, string Customer, decimal Amount, string Currency);

record ImportReport(List<Order> Orders, List<string> Errors, List<(string Customer, decimal Total)> TotalsInEur, int RateLookups);

interface IRateService
{
    Task<decimal> ToEurAsync(string currency);
}

class FakeRates : IRateService
{
    private static readonly Dictionary<string, decimal> Rates = new() { ["EUR"] = 1m, ["USD"] = 0.9m, ["GBP"] = 1.2m };

    public async Task<decimal> ToEurAsync(string currency)
    {
        await Task.Delay(20);
        return Rates[currency];
    }
}

class OrderImporter(IRateService rates)
{
    private static readonly JsonSerializerOptions Options = new() { PropertyNameCaseInsensitive = true };

    public async Task<ImportReport> ImportAsync(string path)
    {
        var orders = new List<Order>();
        var errors = new List<string>();
        string[] lines = await File.ReadAllLinesAsync(path);
        for (int i = 0; i < lines.Length; i++)
        {
            try
            {
                Order order = JsonSerializer.Deserialize<Order>(lines[i], Options)!;
                if (string.IsNullOrWhiteSpace(order.Customer)) errors.Add($"line {i + 1}: customer is required");
                else if (order.Amount <= 0) errors.Add($"line {i + 1}: amount must be positive");
                else orders.Add(order);
            }
            catch (JsonException)
            {
                errors.Add($"line {i + 1}: invalid JSON");
            }
        }

        string[] currencies = orders.Select(o => o.Currency).Distinct().ToArray();
        decimal[] found = await Task.WhenAll(currencies.Select(rates.ToEurAsync));
        Dictionary<string, decimal> rate = currencies.Zip(found).ToDictionary(p => p.First, p => p.Second);

        var totals = orders
            .GroupBy(o => o.Customer)
            .Select(g => (Customer: g.Key, Total: g.Sum(o => o.Amount * rate[o.Currency])))
            .OrderByDescending(t => t.Total)
            .ThenBy(t => t.Customer)
            .ToList();
        return new ImportReport(orders, errors, totals, currencies.Length);
    }
}
