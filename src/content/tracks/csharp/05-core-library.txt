## try, catch, finally

```csharp
string[] inputs = { "42", "x7", "-3" };
foreach (string input in inputs)
{
    try
    {
        int n = int.Parse(input);
        Console.WriteLine($"square root of {n} = {SafeSqrt(n):F2}");
    }
    catch (FormatException)
    {
        Console.WriteLine($"not a number: {input}");
    }
    catch (ArgumentOutOfRangeException e) when (e.ParamName == "n")
    {
        Console.WriteLine($"invalid: {e.Message}");
    }
    finally
    {
        Console.WriteLine($"-- done with {input}");
    }
}

static double SafeSqrt(int n)
{
    ArgumentOutOfRangeException.ThrowIfNegative(n);
    return Math.Sqrt(n);
}
```

- The first `catch` whose type matches handles the exception; put specific types before general ones.
- **Exception filters** (`when (...)`) add a condition without catching and rethrowing.
- `finally` always runs.
- `throw;` (alone, inside a catch) rethrows the current exception **keeping its stack trace**; `throw e;` would reset it.

Unlike Java, C# has **no checked exceptions**: the compiler never forces you to catch or declare them. Document what a method throws (XML `<exception>` comments), and catch exceptions where you can actually handle them.

## Custom exceptions

```csharp
var wallet = new Wallet(30);
try
{
    wallet.Pay(50);
}
catch (InsufficientFundsException e)
{
    Console.WriteLine($"{e.Message} (short by {e.ShortBy})");
}

class InsufficientFundsException(decimal shortBy) : Exception("Insufficient funds")
{
    public decimal ShortBy { get; } = shortBy;
}

class Wallet(decimal balance)
{
    private decimal _balance = balance;

    public void Pay(decimal amount)
    {
        if (amount > _balance) throw new InsufficientFundsException(amount - _balance);
        _balance -= amount;
    }
}
```

Derive from `Exception` (or a more specific built-in type), name the class `...Exception`, and pass the original exception as the **inner exception** when wrapping (`new ServiceException("...", ex)`).

## using: releasing resources

Files, connections and streams implement **`IDisposable`**; their `Dispose()` must be called even when errors happen. The **`using`** statement does it automatically:

```csharp
using (var first = new Resource("database"))
using (var second = new Resource("log file"))
{
    Console.WriteLine("working with both");
}

void Work()
{
    using var r = new Resource("cache");      // using declaration: disposed at the end of the scope
    Console.WriteLine("inside Work");
}
Work();

class Resource : IDisposable
{
    private readonly string _name;
    public Resource(string name) { _name = name; Console.WriteLine($"open {_name}"); }
    public void Dispose() => Console.WriteLine($"dispose {_name}");
}
```

Resources are disposed in reverse order. `using var x = ...;` (C# 8) disposes at the end of the enclosing block, which avoids nesting.

## Good practice

- Don't catch `Exception` and ignore it; catch specific types where you can recover.
- Validate arguments early (`ArgumentNullException.ThrowIfNull`, `ArgumentException.ThrowIfNullOrEmpty`).
- Use the **Try pattern** (`bool TryX(..., out result)`) for failures that are expected and frequent, like parsing user input; exceptions are for exceptional situations.

## The main collections

`System.Collections.Generic` provides type-safe collections (imported implicitly):

| Type | Holds | Notes |
|---|---|---|
| `List<T>` | an ordered, growable list | the default choice |
| `Dictionary<TKey, TValue>` | key → value | fast lookups by key |
| `HashSet<T>` | unique elements | fast membership tests, set operations |
| `Queue<T>` / `Stack<T>` | FIFO / LIFO | |
| `PriorityQueue<TElement, TPriority>` | elements by priority | smallest priority first |
| `SortedDictionary`, `SortedSet`, `SortedList` | sorted by key | |
| `LinkedList<T>` | doubly linked list | rarely the best choice |

## List

```csharp
var tasks = new List<string> { "write tests", "fix bug" };
tasks.Add("deploy");
tasks.Insert(0, "coffee");
Console.WriteLine($"{string.Join(", ", tasks)} ({tasks.Count})");
Console.WriteLine($"{tasks[1]} {tasks.Contains("fix bug")} {tasks.IndexOf("deploy")}");
tasks.Remove("coffee");
tasks.RemoveAll(t => t.StartsWith("fix"));
tasks.Sort();
Console.WriteLine(string.Join(", ", tasks));

List<int> numbers = [5, 3, 8];          // collection expression (C# 12)
numbers.AddRange([1, 9]);
Console.WriteLine($"{numbers.Count} items, first {numbers[0]}, last {numbers[^1]}");
```

`Count` (not `Length`) gives the size. Changing a list while `foreach`-ing over it throws `InvalidOperationException`; use `RemoveAll` or loop over a copy.

## Dictionary

```csharp
string text = "the cat and the hat and the bat";
var counts = new Dictionary<string, int>();
foreach (string word in text.Split(' '))
{
    counts[word] = counts.GetValueOrDefault(word) + 1;
}
foreach (var (word, count) in counts.OrderBy(kv => kv.Key)) Console.WriteLine($"{word}: {count}");

var capitals = new Dictionary<string, string> { ["France"] = "Paris", ["Japan"] = "Tokyo" };
Console.WriteLine(capitals["Japan"]);
if (capitals.TryGetValue("Peru", out string? city)) Console.WriteLine(city);
else Console.WriteLine("Peru: unknown");
Console.WriteLine(capitals.ContainsKey("France"));
```

- `dict[key] = value` adds or replaces; reading a missing key with `dict[key]` throws `KeyNotFoundException`.
- `TryGetValue` (the Try pattern again) and `GetValueOrDefault` read safely.
- Iterating gives `KeyValuePair<TKey, TValue>` items, which deconstruct into `(key, value)`.
- A `Dictionary` has no guaranteed order; sort when the order matters.

{

    {

                break;

## Generic types and methods

```csharp
var text = new Box<string>("hello");
var number = new Box<int>(42);
Console.WriteLine($"{text.Value.ToUpper()} {number.Value + 1}");
Console.WriteLine(FirstOrDefault(new List<string>(), "none"));
Console.WriteLine(Max([3, 9, 4]) + " " + Max(["pear", "apple", "zucchini"]));
var pair = new Pair<string, double>("coffee", 2.5);
Console.WriteLine(pair);

static T FirstOrDefault<T>(List<T> list, T fallback) => list.Count == 0 ? fallback : list[0];

static T Max<T>(List<T> items) where T : IComparable<T>
{
    T best = items[0];
    foreach (T item in items) if (item.CompareTo(best) > 0) best = item;
    return best;
}

class Box<T>(T value)
{
    public T Value { get; } = value;
}

record Pair<TFirst, TSecond>(TFirst First, TSecond Second);
```

Type parameters (`T`, or descriptive names starting with `T` like `TKey`) are replaced by real types at each use, and the compiler infers them from arguments when it can.

Unlike Java, .NET generics are **reified**: the runtime knows the real type arguments. A `List<int>` stores real `int`s (no boxing), `typeof(T)` works, and `new T()` is possible with a constraint.

## Constraints

`where` clauses restrict what `T` can be, which unlocks operations on it:

| Constraint | Means |
|---|---|
| `where T : IComparable<T>` | T implements that interface (so `CompareTo` is allowed) |
| `where T : class` / `struct` | reference type / value type |
| `where T : new()` | has a parameterless constructor (`new T()` is allowed) |
| `where T : BaseClass` | derives from a class |
| `where T : notnull` | non-nullable type |

```csharp
var registry = new Registry<Plugin>();
registry.Create();
registry.Create();
Console.WriteLine(registry.Count);

class Registry<T> where T : class, new()
{
    private readonly List<T> _items = new();
    public int Count => _items.Count;
    public T Create()
    {
        var item = new T();
        _items.Add(item);
        return item;
    }
}

class Plugin { }
```

## Variance in generic interfaces

`IEnumerable<string>` can be used where an `IEnumerable<object>` is expected, because `IEnumerable<out T>` is **covariant** (it only gives `T`s out). `Action<in T>` is **contravariant** (it only takes `T`s in). `List<T>` is neither, since it both reads and writes. You'll mostly benefit from variance without thinking about it; when writing interfaces, `out` and `in` declare it (like Java's `? extends` / `? super`, but on the declaration).

```csharp
IEnumerable<string> words = new List<string> { "a", "b" };
IEnumerable<object> objects = words;            // covariance
Action<object> printAny = o => Console.WriteLine($"[{o}]");
Action<string> printString = printAny;          // contravariance
foreach (object o in objects) printString((string)o);
```

## Generic math

Since .NET 7, interfaces like `INumber<T>` let you write one method for every numeric type:

```csharp
using System.Numerics;

Console.WriteLine(Sum([1, 2, 3]) + " " + Sum([1.5, 2.25]) + " " + Sum([0.1m, 0.2m]));

static T Sum<T>(IEnumerable<T> values) where T : INumber<T>
{
    T total = T.Zero;
    foreach (T v in values) total += v;
    return total;
}
```

=== lesson cs-delegates-events | Delegates, lambdas and events | 70
## Delegates: methods as values

A **delegate** is a type-safe reference to a method. The built-in generic delegates cover almost every need:

| Delegate | Shape | Example |
|---|---|---|
| `Func<T, TResult>` | takes T, returns TResult | `Func<int, int> square = x => x * x;` |
| `Func<TResult>` | no parameters | `Func<DateTime> now = () => DateTime.Now;` |
| `Action<T>` | takes T, returns nothing | `Action<string> log = Console.WriteLine;` |
| `Predicate<T>` | takes T, returns bool | `Predicate<int> isEven = n => n % 2 == 0;` |

```csharp
Func<int, int> square = x => x * x;
Func<int, int, int> add = (a, b) => a + b;
Action<string> shout = s => Console.WriteLine(s.ToUpper() + "!");
Predicate<int> isEven = n => n % 2 == 0;

Console.WriteLine($"{square(7)} {add(2, 3)} {isEven(10)}");
shout("hi");

int Apply(Func<int, int> f, int value) => f(value);
Console.WriteLine(Apply(square, 4) + " " + Apply(x => x + 100, 4));

Func<int, int> compose = x => square(add(x, 1));
Console.WriteLine(compose(2));
```

A **lambda** (`x => x * x`) creates a delegate inline; a **method group** (`Console.WriteLine`) can be used where a matching delegate is expected. Lambdas **capture** variables from the enclosing scope (closures), and see later changes to them.

You can also declare your own delegate types (`delegate decimal PriceRule(decimal price);`), which gives the shape a name; modern code mostly uses `Func` and `Action`.

## Events: the observer pattern built into the language

An **event** lets an object notify any number of subscribers. Subscribers attach handlers with `+=` and detach with `-=`; only the owning class can raise the event:

```csharp
var sensor = new TemperatureSensor();
sensor.TooHot += (sender, e) => Console.WriteLine($"ALERT: {e.Celsius} °C");
sensor.TooHot += (sender, e) => Console.WriteLine($"logged reading {e.Celsius}");
foreach (double reading in new[] { 21.5, 31.0, 24.0, 35.5 }) sensor.Record(reading);

class TemperatureEventArgs(double celsius) : EventArgs
{
    public double Celsius { get; } = celsius;
}

class TemperatureSensor
{
    public event EventHandler<TemperatureEventArgs>? TooHot;

    public void Record(double celsius)
    {
        if (celsius > 30) TooHot?.Invoke(this, new TemperatureEventArgs(celsius));

```

- `EventHandler<TArgs>` is the standard event signature: `(object? sender, TArgs e)`.
- `TooHot?.Invoke(...)` raises the event only if someone subscribed (`?.` skips a `null` delegate).
- Events power UI frameworks (button clicks in WPF, WinForms, MAUI), file watchers, timers and domain events. Unsubscribe (`-=`) when a short-lived listener is attached to a long-lived publisher, or the publisher keeps it alive (a classic memory leak).

## Language-Integrated Query

**LINQ** is C#'s most loved feature: a set of query operators that work on any sequence (`IEnumerable<T>`): arrays, lists, dictionaries, files, databases (through Entity Framework) and XML. It's what streams are to Java, and more:

```csharp
var orders = new List<Order>
{
    new("ada", "book", 2, 12.5m), new("bob", "pen", 10, 1.2m),
    new("ada", "lamp", 1, 35.0m), new("cy", "book", 1, 12.5m),
};

var bigOrders = orders
    .Where(o => o.Total > 20)
    .OrderByDescending(o => o.Total)
    .Select(o => $"{o.Customer}:{o.Product}={o.Total}")
    .ToList();
Console.WriteLine(string.Join(", ", bigOrders));

Console.WriteLine($"revenue {orders.Sum(o => o.Total)}, books {orders.Count(o => o.Product == "book")}, any big {orders.Any(o => o.Total > 30)}");
Console.WriteLine($"first pen buyer: {orders.First(o => o.Product == "pen").Customer}");
Console.WriteLine($"cheapest: {orders.MinBy(o => o.Price)!.Product}");

record Order(string Customer, string Product, int Quantity, decimal Price)
{
    public decimal Total => Quantity * Price;
}
```

| Operator | Does |
|---|---|
| `Where` | filter |
| `Select` | transform each element |
| `SelectMany` | flatten nested sequences |
| `OrderBy` / `OrderByDescending` / `ThenBy` | sort |
| `GroupBy` | group by a key |
| `Join` | join two sequences on a key |
| `Distinct`, `DistinctBy`, `Union`, `Intersect`, `Except` | set operations |
| `Take`, `Skip`, `TakeWhile`, `Chunk` | slices and paging |

## Deferred execution

Most LINQ operators are **lazy**: building a query doesn't run it; enumerating it does (each time). Operators like `ToList`, `Count` and `First` run it immediately:

```csharp
var numbers = new List<int> { 1, 2, 3 };
var evens = numbers.Where(n => n % 2 == 0);   // nothing runs yet
numbers.Add(4);
Console.WriteLine(string.Join(",", evens));   // runs now: sees 4 too
var snapshot = evens.ToList();                // runs and stores the result
numbers.Add(6);
Console.WriteLine($"{evens.Count()} vs {snapshot.Count}");
```

Materialise with `ToList()` when you'll use a result several times, or when the source may change.

## Nullable value types

Value types can't normally be `null`. Adding `?` makes a **nullable value type**, useful for "unknown" values (an optional age, a missing reading):

```csharp
int? age = null;
Console.WriteLine($"{age.HasValue} {age ?? -1} {age.GetValueOrDefault()}");
age = 36;
Console.WriteLine($"{age.Value} {age + 1}");
double? reading = null;
Console.WriteLine(reading * 2 is null);       // arithmetic with null gives null
```

## Nullable reference types

Reference types could always hold `null`, and `NullReferenceException` was the most common .NET bug. **Nullable reference types** (C# 8, enabled in new projects with `<Nullable>enable</Nullable>`) make the compiler track nullability: `string` means "never null", `string?` means "may be null", and the compiler **warns** when you might dereference a null:

```csharp
#nullable enable
string name = "Ada";
string? nickname = null;

Console.WriteLine(name.Length);
Console.WriteLine(nickname?.Length);               // ?. : null if nickname is null
Console.WriteLine(nickname ?? "(no nickname)");    // ?? : a fallback
nickname ??= "Countess";                           // assign only if null
Console.WriteLine(nickname.ToUpper());             // the compiler knows it isn't null now

string? FindEmail(string user) => user == "ada" ? "ada@example.com" : null;
string? email = FindEmail("bob");
if (email is not null) Console.WriteLine(email.Length);
else Console.WriteLine("no email");
```

| Operator | Meaning |
|---|---|
| `x?.Member` | null-conditional: evaluates to null if x is null |
| `x?[i]` | null-conditional indexing |
| `x ?? y` | null-coalescing: x, or y if x is null |
| `x ??= y` | assign y only if x is null |
| `x!` | null-forgiving: "trust me, it's not null" (silences the warning; use sparingly) |
| `is null` / `is not null` | the reliable null tests |

The checks are compile-time **warnings** (they don't change run-time behaviour), but they catch most null bugs before they happen. Teams usually turn nullable warnings into errors. (DevQuest's runner builds without them, so lesson examples opt in with `#nullable enable`.)

## Numbers: decimal, Math and formatting

`decimal` (Module 2) handles money exactly; `Math` provides `Round` (with `MidpointRounding.AwayFromZero` for commercial rounding; the default is banker's rounding to even), `Floor`, `Ceiling`, `Abs`, `Clamp`, `Pow`, `Sqrt`...

```csharp
Console.WriteLine($"{Math.Round(2.5)} {Math.Round(3.5)} {Math.Round(2.5, MidpointRounding.AwayFromZero)}");
Console.WriteLine($"{Math.Round(19.995m, 2)} {Math.Round(19.995m, 2, MidpointRounding.AwayFromZero)}");
Console.WriteLine($"{1234567.891:N2} {0.075:P1} {42:D5} {255:X}");
```

Banker's rounding (2.5 → 2, 3.5 → 4) avoids bias in large sums, which is why .NET uses it by default; invoices usually want `AwayFromZero`.

## Dates and times

| Type | Represents |

string[] lines =
{
    "2026-03-15T09:58:00 INFO service started",
    "2026-03-15T10:02:11 ERROR payment timeout",
    "garbage line",
    "2026-03-15T10:15:40 WARN slow query",
    "2026-03-15T10:47:03 ERROR payment timeout",

var parsed = lines.Select(LogEntry.TryParse).ToList();
var entries = parsed.OfType<LogEntry>().ToList();
Console.WriteLine($"Malformed lines: {parsed.Count(e => e is null)}");
Console.WriteLine($"Levels: {string.Join(", ", entries.GroupBy(e => e.Level).OrderBy(g => g.Key).Select(g => $"{g.Key}={g.Count()}"))}");

record LogEntry(DateTime Time, string Level, string Message)
{
    public static LogEntry? TryParse(string line)
    {
        string[] parts = line.Split(' ', 3);
        if (parts.Length < 3) return null;
        if (!DateTime.TryParse(parts[0], CultureInfo.InvariantCulture, DateTimeStyles.None, out DateTime time)) return null;
        return new LogEntry(time, parts[1], parts[2]);
    }
}

- `OrderByDescending(g => g.Count()).ThenBy(g => g.Key).First()` breaks ties alphabetically.
